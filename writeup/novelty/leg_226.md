## 2. Repair-family precedent this leg follows

Legs 150–154 (the `collocation_newton.py` repair family), 221, 225. The controlling template is
**leg 150 / Route-CNR** (`experiments/p2_route_cnr_v1_repair.py`), whose structure is adopted
here substantially unchanged:

- **ARM A** — every failing case from the audit leg: pre-repair verdict vs post-repair verdict.
- **ARM B** — the **zero-regression** arm, which is the entire licence for the repair. The
  pre-repair module is read **out of git** (`git show <ref>:solver/profile_newton.py`),
  imported under a substituted module name, and run in the **same process** as the repaired
  module. Leg 150's `d871675` lesson applies: pin the module's own stable ancestor commit, not
  a hash a rebase can rewrite.
- **ARM C** — the two margins the threshold sits between, **both measured, neither assumed**.
- **ARM D** — blast radius: the consumers, and what can and cannot be checked on each.

Plus the repair-family rule named in this leg's dispatch and in legs 150–154/221/225: **fix AND
explicitly re-confirm the affected banked claims in the same pass.** A repair that lands without
re-deriving what it was supposed to protect is not a repair, it is a code change.

## 3. Candidate discriminators, and the scouting measurement that chose between them

Three candidates, all three named in leg 202's own recommendation:

- **D1 — the weighted defect**, exactly as Route-D v11 computes it: `sup w|R2|`, `w = (1+X²)^1.2`.
- **D2 — the gauge residuals**, `|Ω(0)+1|` and `|Ω(1)+½|`, which `converged` currently never consults.
- **D3 — the decay class**: far-field supremum of the returned `Ω` over the outer half of the
  grid, relative to **the anchor's own far-field supremum on the same grid**.

### 3.1 The correction this pass records against its own dispatch — D1 does not work

This leg was dispatched on the premise, stated in leg 202's journal and repeated in leg 223's
synthesis, that *"Route-D v11's OWN JSON already contains the rejecting signal (`weighted_defect`
spiking to 4788/73372 at a = 0.8/1.0) that never reached the verdict."* **Measured on leg 202's
own firing cases, that premise is false, and it is recorded here before the repair is built
rather than discovered afterwards.**

Scouting run, leg 202's ladder and grids, `n = 101`:

| a | `converged` | `relres` | **D1** `weighted_defect` | **D2** gauges | **D3** far-field inflation | on/off branch |
|---|---|---|---|---|---|---|
| 0.00 | True | 7.6e-16 | 5.63e-11 | 0.0e+00 | **9.89e-01** | on |
| 0.30 | True | 1.1e-09 | 5.92e-03 | 0.0e+00 | **1.63e+00** | on |
| 0.45 | True | 1.8e-15 | **9.42e-09** | 0.0e+00 | **2.08e+03** | **OFF** |
| 0.60 | True | 1.2e-15 | **3.61e-12** | 0.0e+00 | **1.24e+03** | **OFF** |
| 0.75 | False | 9.7e-05 | 5.82e+02 | 0.0e+00 | 1.29e+03 | (already rejected) |
| 1.05 | True | 4.2e-16 | **5.56e-08** | 0.0e+00 | **1.39e+06** | **OFF** |
| 1.50 | True | 6.1e-16 | **4.44e-08** | 0.0e+00 | **1.17e+06** | **OFF** |

**D1 is not merely weak on the off-branch cases — it is anti-correlated with them.** The
spurious roots carry weighted defects of `3.6e-12` to `5.6e-08`, i.e. *smaller* than the
genuine on-branch profile at `a = 0.30` (`5.9e-03`) by up to nine orders of magnitude. The
reason is structural and should have been predictable: an off-branch root nulls **every**
residual row to machine precision, so `sup w|R2|` is machine-epsilon multiplied by the
(large) local term size, which stays small no matter how badly the profile has left the decay
class. The v11 rows that do spike — `0.50 / 4788 / 73372` at `n = 401/1601`, `a = 0.5/0.8/1.0` —
have `relres` of `6.5e-08 / 1.1e-03 / 5.9e-03`, every one of which **already fails v11's own
`relres < 1e-8` test.** The weighted defect fires where the residual test has already fired.
It adds no independent rejecting power at all.

**D2 is measured dead on M1 as well**: every off-branch root satisfies both gauges to
`0.0e+00` exactly, which is leg 202's own headline. D2 is retained because it is the mechanism
that catches **M2**, where the gauge residual reaches 0.25.

**D3 separates cleanly** — and it is the one leg 202 recommended first. It is also the one with
an *independent in-repo physical warrant*, which matters because a discriminator chosen only
to fit the failing cases is a curve fit: **Route-D v12's T3 measures the genuine `a > 0`
profile as having a critical radius `X_c` with zero order `1/a`, i.e. the true branch is
compactly supported and decays FASTER than the `a = 0` anchor, not slower.** So a returned
profile whose far field is a thousand times *fatter* than the anchor's is off-branch on
grounds that were banked before this leg existed and were not chosen to fit these cases.

### 3.2 Threshold, pre-committed here

`100×` the anchor's far-field supremum — **leg 202's own pre-committed classifier threshold**,
adopted unchanged rather than retuned. The two margins are reported as measured (ARM C), not
assumed. On the scouting data the threshold sits ~1.8 decades above the largest on-branch
inflation (`1.63`) and ~1.1 decades below the smallest off-branch one (`1.24e+03`).

## 4. What this leg pre-commits to reporting even if it is inconvenient

1. That **D1, the diagnostic this leg was dispatched to incorporate, does not by itself reject
   a single one of leg 202's off-branch cases** — §3.1 above, frozen before construction.
2. If the three `a = 1.50` grids do **not** agree after the repair, that is reported as a
   disagreement, never resolved by choosing one. **Including the outcome that all three are
   correctly rejected and there is no genuine `a = 1.50` value at all** — which is agreement of
   a different kind and must not be dressed up as convergence to a common value.
3. The Route-D v11 re-derivation is reported as **three** numbers per headline, not two: the
   **banked** value, a **pre-repair re-run in this environment**, and the **post-repair** value.
   Item (6) measured this module's stalls moving **2.31 decades** across BLAS backends, so a
   two-number before/after cannot distinguish a repair-induced change from environment drift.
4. `GA_boundary` is reported for what it is: a **hardcoded literal** `[0.5, 0.55]` at
   `p2_route_d_v11_anchor.py` line 112, not a computed verdict. It cannot move under any repair
   to the module, and saying "unchanged" about it without saying that would be misleading.
