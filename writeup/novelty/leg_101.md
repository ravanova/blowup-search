## 2. The structural argument, stated BEFORE the run, so the run can refute it

`op_lower.py` looks sound by construction: every number it returns is an actually-evaluated
Rayleigh quotient `dom(A @ g) / cod(g)`, and `||A|| >= ||Ag||_X/||g||_Y` holds for every `g`.
Three static observations, recorded now so that the measurement is a test and not a rediscovery:

1. **NaN is skipped, not propagated to the headline.** Every accept step is `if r > best`, which
   is `False` for `r = nan`; `if n > 0` is `False` for `n = nan`. A NaN-poisoned case should
   therefore *under*-report (often exactly `0.0`), which is the **safe** direction.
2. **The gauge slot is forced to zero** (`g[0] = 0.0`) in all three routines, so the search runs
   over the subspace `{g : g_0 = 0}`, a subset of the full ball — again the safe direction, and
   the reason the reference norm below is computed **both** ways.
3. **The two float mechanisms that could break it anyway**, neither of which any existing test
   can reach: (a) `A @ g` **overflowing to `inf`** while the true norm is finite, giving a
   reported "lower bound" of `inf`; (b) the denominator `cod(g)` **underflowing** (denormal
   products flushed toward zero) faster than the numerator, inflating a finite ratio above the
   true norm. Whether either is reachable is a measurement, not an assertion.

## 3. Pre-committed decision rule (fixed BEFORE the run)

The gate is decided on this definition and no other:

> **SOUNDNESS VIOLATION** := on a case where the reference norm is **computable and finite**,
> `op_lower.py` returns a headline value `L` with `L > (1 + 1e-9) * N_ref`, where `N_ref` is the
> **exact induced operator norm over the same admissible subspace the module searches**
> (`{g : g_0 = 0}`, i.e. column 0 of `A` deleted), computed by a route that shares no code with
> `op_lower.py`.

Two reference pairs are used, chosen because for them the induced norm is **exactly** computable
rather than itself estimated:

- **`cod = weighted-l1(u)`, `dom = weighted-linf(t)`** — the extreme points of the `l1(u)` ball
  are `±e_j/u_j`, so `N_ref = max_{i,j} t_i |A_ij| / u_j`, a closed form.
- **`cod = weighted-l2(u)`, `dom = weighted-l2(t)`** — `N_ref = sigma_max(diag(t) A diag(u)^{-1})`,
  from `numpy.linalg.svd`, an independent computation.

Both are supplied as duck-typed objects exposing the two things `op_lower.py` actually consumes:
a callable norm and a `.w` weight array. That the module is generic in its norms is what makes an
**exact** reference possible at all; using the project's `HolderNorm` alone would mean comparing
one estimate against another, which cannot decide a soundness gate. `HolderNorm` is therefore
carried as a **secondary tier** (§4) rather than dropped.

Deliberately **excluded** from deciding the gate, and measured and reported separately anyway:

- **Under-reporting is a PASS.** `L = 0` where `N_ref = 1e12` is useless but *true*. A lower
  bound is permitted to be weak; it is not permitted to be wrong. Recorded as a magnitude (the
  `L/N_ref` ratio) so a reader can see how much is lost, but it never trips the gate.
- **Both-non-finite is OUT OF SCOPE.** If `N_ref` is itself `nan`/`inf` (e.g. `A` fully
  NaN-poisoned), the gate's own words — "on a case where both are computable" — exclude it. The
  count of such cases is reported so the excluded fraction is visible.
- **Raising an exception is a PASS.** Loud failure is the correct behaviour for a malformed
  operator; this leg does not grade the quality of the error.

**Discipline: magnitudes, never booleans.** Every case reports `L`, `N_ref`, and the ratio
`L / N_ref` in full precision; the headline is the **maximum ratio observed over the battery**,
not "sound / not sound".

### What §2's static argument predicted, and what the run did with it

1. **Mechanism (a) was predicted and is the dominant finding.** §2.3(a) named numerator overflow
   before any measurement; it accounts for **46 of 47** violations. §2.1's NaN prediction also
   held exactly: NaN is skipped, never propagated, **0 NaN headlines in 408 cases**, all three
   NaN-poisoned operators returning exactly 0.0.
2. **Mechanism (b) was predicted for the WRONG reason, and the run corrected it.** §2.3(b)
   guessed the denominator would *underflow*. Measured: the denominator is fine; the excess comes
   from **rounding in the numerator's denormal products**, amplified by the fact that the
   maximiser sits ON the extremal direction, so nothing absorbs it. Right phenomenon, wrong
   organ — recorded because a pass that only reports its hits is not a pass.
3. **The route §2 did NOT anticipate is the sharpest of the three.** `ascend` sizes its trial
   step **proportional to the bound found so far** (`solver/op_lower.py:130`), so on a large-norm
   operator the search **overflows itself** — with unit weights, all-finite entries, and a
   perfectly sound finite value from `family_lower` one line earlier. No degenerate input of any
   kind is needed; only a large operator. That is a structurally different failure from the two
   float mechanisms the pass listed.

### The two instruments this leg had to repair mid-run, both reported

- **The float reference underflowed and manufactured two violations** on denormal/`1e-300` input
  (true norm reported as exactly 0.0). Rebuilt in exact rationals; both spurious cases vanished.
- **The fixed 1e-9 relative tolerance pre-committed in §3 is the wrong instrument below the
  normal range**, where one ULP is already ~1e-6 relative; it flagged a correctly-rounded 0.383
  ULP case as a violation. Replaced by an ULP-measured criterion. This made the rule *stricter*,
  dropped the false finite violation to zero — and a dedicated denormal dimension sweep then
  found the **real** one (425 ULP at n = 32) that the single-dimension zoo had missed.

Neither repair touches the overflow class: `inf` against a finite true norm is not a rounding
question and not a reference question.

### The scope statement, measured

### 8.2 The design, stated BEFORE it is built, so the measurement can refute it

Leg 101 found **two distinct mechanisms** (its §7.3 corrected the pass's own guess about the
second). The repair addresses each at its root:

1. **Overflow (46 cases).** `A @ g` reaches `1e313` because the candidate carries `1/w = 1e300`,
   or because `ascend`'s step is sized proportional to `best`. Root cause: the quotient
   `dom(A g)/cod(g)` is **scale-invariant in `g` and exactly homogeneous of degree 1 in `A`**,
   yet it is evaluated at whatever absolute scale the inputs happen to carry. Fix: normalise both
   `A` and each candidate `g` by an **exact power of two** before evaluating, and recombine the
   `A` exponent afterwards. Powers of two are exact in binary floating point, so this changes the
   mathematics not at all — it moves the arithmetic into the range where float64 works.
2. **Finite exceedance, 425 ULP (1 case).** Denormal products carry ~1e-6 relative rounding, and
   the maximiser sits ON the extremal direction so nothing absorbs the excess. The same
   power-of-two rescaling lifts the whole evaluation out of the denormal range, restoring the
   full 53-bit mantissa. What remains is ordinary normal-range rounding, which is handled by a
   **downward deflation** of the quotient before it is returned.

Three further guards, each of which can only lower the reported value:

3. **No non-finite value ever reaches the headline.** A candidate whose image or norm is not
   finite carries no information about `||A||` and is *rejected*, not maximised over. This
   deliberately gives up the (sometimes correct) `inf` report on an Inf-poisoned operator,
   because that report is **unsound exactly when the infinity sits in the gauge column** — which
   the search excludes, so the true norm over the searched subspace can be finite while `A`
   contains an `inf`. Weak-and-true beats strong-and-sometimes-wrong.
4. **Saturation instead of `inf`.** If the recombined exponent genuinely exceeds float64's range,
   the true norm really is above `1.798e308`, so `finfo.max` is returned with a `saturated` flag
   — still a true lower bound, and one a caller can act on.
5. **Rejection instead of a number, when the arithmetic cannot be certified.** The matvec's
   relative error is bounded a priori by `gamma_n * (|A||g|)_max / |Ag|_max`; when that bound is
   not small the candidate is dropped.

**What is rigorous and what is calibrated, stated now so the writeup cannot blur it.** The
power-of-two rescaling is *exact* (verified by round-trip, not assumed). The matvec error bound
is *rigorous* (standard `gamma_n = n u /(1 - n u)` dot-product bound plus a subnormal term). The
allowance for the **norm functors' own internal rounding is NOT rigorous** and cannot be: `dom`
and `cod` are black-box callables, this module may not edit `solver/holder_norms.py` (outside
territory), and the repo has no exact-arithmetic norm. It is a fixed relative slack, and its
adequacy is a **measurement over the battery**, reported as a margin in ULP, not a proof. That is
why interval arithmetic is not the answer here: `solver/interval.py` cannot wrap a callable it
does not control.

**Pre-committed decision rule for the repair** (fixed before any post-fix number was seen), using
leg 101's own §3 definition of a violation and its own exact rational reference:

> **The repair PASSES** iff, over all 209 gate-deciding Tier-A cases, the count of soundness
> violations is **0** — no `L > N_ref` beyond **0 ULP** of the returned float (stricter than leg
> 101's own 1-ULP grading rule, which was a grading concession to correct rounding and is not
> needed once the arithmetic is deflated) — **and** the production bracket at J = 200/300/400
> moves by no more than **1e-9 relative**, downward only.

A repair that fixed soundness by returning 0 everywhere would satisfy the first clause and fail
the second; both clauses are load-bearing. The count of candidates rejected on the production
path is reported as a magnitude and must be **0**.

### 8.3 What could still be wrong after the repair, recorded now

- The norm-functor slack is calibrated, not proved (above). A norm whose float evaluation is
  worse than the slack would defeat it; the guard is that the slack is reported and the observed
  margin is measured on every case.
- Rejection is silent to a caller who does not read the returned dict. The repair therefore
  **reports counts**, and the gates assert on them.
- Under-reporting remains permitted and unmeasured against any optimality claim. This module was
  never an upper bound and still is not; nothing here becomes rigorous.

### 9.2 What §8.2's design predicted, and what the run did with it

1. **The power-of-two rescaling did what it was designed to do, on both mechanisms at once.** All

2. **The design was INCOMPLETE, and the measurement said where.** §8.2 argued the rescaling would

   the residue handled by deflation. It lifts the *arithmetic* — but recombining the exponent puts
   the *result* back among the subnormals, where `ldexp` itself rounds by up to half an ULP, and
   half an ULP there is ~1e-6 relative, so the 1e-12 deflation is a literal no-op. Five cases were
   left 0.2–0.4 ULP above the true norm by that final rounding alone. One `nextafter` down closes
   it (`sound_within_one_ulp` 5 → 0). Recorded because a pass that only reports its hits is not a
   pass, and because "the deflation handles what remains" was the sentence that was wrong.
3. **The cost of guard 3 was real and had to be measured, not assumed.** §8.2 committed to
   rejecting non-evaluable candidates and accepted that this gives up information. It does:
   `sound_but_zero` rose 41 → 48. But the far larger effect ran the *other* way and was not
   predicted — **40 of the 47 former violations became usable finite bounds**, so `sound, nonzero`

### 9.3 The correction the run forced on the repair, recorded rather than quietly applied

said "normalise both `A` and each candidate `g` by an exact power of two". Doing that

caller's own scaling is tried first whenever it is not itself the hazard. `sound_but_zero` came
back to 48. This is the same shape of error as leg 101's own two mid-run corrections: an
instrument that damages the regime it is meant to protect.
