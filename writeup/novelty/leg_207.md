## 2. What the existing test file does and does not cover

`test_dissipative_profile.py` has 20 tests. Eighteen of them are known-answer or property
checks on **legal, in-domain input**: Chen's constants are internally exact, the profile is
odd, the closed form nulls the steady residual, the floor converges under refinement, the
4th-order velocity beats the banked trapezoid, `nu` changes the residual, `newton` recovers
Chen's constants and converges quadratically, and `diffusion_consistency` is gauge-invariant
and *can report zero* (the lesson-90 two-sided control).

Exactly **two** are guard tests:

* `test_diffusion_consistency_refuses_a_vanishing_amplitude_exponent` — `c_omega = 0` and
  `c_omega = nan` both raise.
* `test_y0_measure_refuses_an_unknown_norm` — `norm="frobenius"` raises `ValueError`.

Both are recorded here as **lesson-90 positive controls**: this module *does* reject some bad
input, and the battery must say so, or a "no guard anywhere" finding would be an artifact of
not looking. Note also, and pre-registered before measurement, that the second of those two has
**no sibling for `z2_quadratic_constant`**, which takes the same `norm` argument in the same
file. That asymmetry is a place to look, not yet a finding.

Nothing in the file asks what happens when the input is **not** well formed.

## 4. Documented hypotheses the module states and may not check

These are pre-registered as *caveats already in the docstrings*, so that if the battery finds
them unchecked the report says "a stated hypothesis with no guard", not "a discovery":

1. **Two gauges must be fixed.** `newton`'s docstring: "Two gauges must be fixed, because the
   steady equation has two exact symmetries: amplitude ... and spatial dilation ... Fixing
   `c_omega` kills the first; `scale_gauge` (the value of `Omega_X(0)`) kills the second.
   `c_l` is then a genuine OUTPUT — the whole point, since `Delta` is built from it." The
   module therefore **asserts** that `c_l` is an output. Whether that survives a *degenerate*
   value of `scale_gauge` is the natural question and is exactly what this leg's dispatch names
   as "degenerate dilation-gauge parameters".
2. **`a` is the free unknown of `newton_gamma2`.** Its docstring: "it IMPOSES (ii) ... and asks
   whether (i) can then be solved at a given `nu > 0`, **with the advection `a` as the free
   unknown**." So `newton_gamma2`'s returned `a` is, by contract, **not** the constructor's
   `a`. Whether the module's *own* downstream consumers can express that is a question about
   the API's shape, not about the mathematics.
3. **`Delta` is measured, not assumed.** Header: "`Delta` is measured here, not assumed:
   `newton_profile` solves for `c_l` and it is free to land anywhere." A path on which `Delta`
   is *echoed from the input* would contradict this sentence directly.
4. **Chen's `delta` and `nu_0` are unquantified.** `chen_constants` records `value: None` for
   both, with provenance. That is already reported honestly and is **not** an audit target.
