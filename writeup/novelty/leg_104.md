## 2. Confirming the frozen script really cannot be reused as-is (measured, not assumed)

```
$ PYTHONPATH=. .venv/bin/python -c "
import experiments.p2_route_bva_v1_adversarial as bva
bva.family_malformed_boundary()"
Traceback (most recent call last):
  ...
  File ".../experiments/p2_route_bva_v1_adversarial.py", line 347, in family_malformed_boundary
    for v in sorted({c["verdict"] for c in cases})},
KeyError: 'verdict'
```

Mechanism: `interval_case("radial_interval_ascending", ...)` and
`interval_case("radial_interval_reversed", ...)` are both called; the ascending case's
`rec["verdict"]` is set only inside `if ok.get("rel_linf_global") and bad.get("rel_linf_global")`
— i.e. only if **both** succeed. Pre-repair both did. Post-repair the reversed case raises at
construction (the fix working as intended) and returns a `rec` with no `rel_linf_global` key, so
that `if` is false and the ascending case's `rec` never receives a `"verdict"` key at all — the
KeyError above. This is exactly what the script's own header predicts ("the script will not run
to completion... That is the fix working, not a broken script") and confirms this leg must write
independent code, not repair or reuse leg 99's frozen script.

## 5. Method, pre-committed before any number is seen

1. Re-implement leg 99's exact 22 cases (same manufactured field, same grid parameters, same
   `r_min` sweep points, same tolerances `LEG73_FIELD_TOL=5e-3`, `LEG73_ORIGIN_TOL=1e-3`) as
   fresh, independent code against the **current** (patched) module — not by editing or
   importing leg 99's frozen, now-non-completing script.
2. Classify every case by the same predicate leg 99 fixed before its own run: `RAISED` /
   `NONFINITE` / `SILENT_WRONG` / `SILENT_EMPTY` / `FINITE` / `BASELINE`, where
   `SILENT_WRONG := returns normally AND all finite AND unwarned AND wrong beyond the module's
   own tolerance`. **The gate's (a)-half is answered by counting `SILENT_WRONG` over the full 22,
   not a sample.**
3. Independently re-run leg 73's exact 3-level ladder (`LADDER = ((601,49),(1201,99),(2401,199))`,
   `radial_bc="robin"`) via `run_level` imported from `experiments/p2_route_bv_v1_velocity_benchmark.py`
   (a read-only import — that module is never called via its `main()`, so its own frozen JSON is
   never touched by this leg) and compare P1/P3 finest values and observed orders against the
   banked `writeup/data/p2_route_bv_v1_velocity_benchmark.json`, to a tolerance that separates
   "reproduces" from "floating-point BLAS-order noise" (empirically ~1e-10 relative between two
   runs of the *same* unmodified code on this machine — measured, not assumed, in §implementation).
4. `solver/boussinesq_velocity.py` is read only. No edit under either gate outcome.
