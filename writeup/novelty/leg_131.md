## 3. Scouting run (executed before design; three findings that fix the construction)

### 3a. The battery's `HNA_AUDIT_LIVE=1` path is broken, and has never been run to completion

The repair added `AUDIT_LIVE = os.environ.get("HNA_AUDIT_LIVE", …)` (line 82) so the battery
could be pointed at the working tree. `grep -rn HNA_AUDIT_LIVE` over the whole repo finds it in
**exactly one file — the battery itself** — in **2 lines**, one of them a docstring. Nothing
runs it, nothing tests it, no JSON records its output.

Running it is a **0.18-second crash**:

```
HNA_AUDIT_LIVE=1 python experiments/p2_route_hna_v1_adversarial.py
→ ValueError: alpha = nan is not finite …   (gate_A5, line 419)
```

The battery reaches gate `A5` and dies. So the sentence in DIRECTION.md's brief — "re-run the
battery from the battery's own driver" — cannot be executed as-is, and *this is itself part of
the finding*: **the one facility the repair added for independent re-checking does not work.**

### 3b. The mechanism, located: three unwrapped call sites, not a general failure

The battery's own instrumentation is already repair-aware. `call()` (line 114) catches
`Exception` and `classify()` (line 144) returns `FLAGGED_RAISE` — leg 100's pre-committed
criterion says verbatim that "Returning NaN, returning ±inf, raising, or warning ALL count as
FLAGGED, not silent", so **a raise is a correctly-classified pass, not an error**, for every
case routed through `probe()`. The crash comes from three sites that call the subject **bare**,
outside `probe()`, on input that used to be merely wrong and now raises:

| site | call | why it now raises |
|---|---|---|
| `gate_A5` line 419 | `decay_weight(np.array([0.,1.,10.]), NAN)` | non-finite `alpha` rejected |
| `gate_A6` lines 469–471 | `holder_H_constant(th, g, …)` for `g ∈ (0.0, 1.0, 0.3)` | the degenerate-exponent sweep; `gamma > 0` now required |
| `gate_A8` line 553 | `fn(*args)` × 3 with `theta[64]=+Inf` / `A[3,7]=+Inf` | non-finite grid / operator entry rejected |

These were written as *reads of a value*, not as probes, because pre-repair there was no value
they could fail to produce. The construction therefore re-runs **the battery's own gate
functions, unmodified and imported**, and routes exactly these three bare sites through the
battery's **own** `probe()`/`call()`/`classify()` helpers so their raises are classified by leg
100's own rule instead of aborting the run. No case is re-implemented and no criterion is
re-invented.

### 3c. The zero-regression test must be a SAME-PROCESS bitwise A/B, not a JSON comparison

The battery's own docstring records a reproducibility datum from the repair: against the pinned
pre-repair blob it reproduces every banked magnitude bit-identically **except two entries of
`A6.clean_per_degree`** — `0.8359515019975166 → …164` and `0.8548322678393498 → …497`, a **1–2
ULP** difference, deterministic on one machine (3/3), attributed to BLAS matmul reduction order
differing between runners. `runtime_seconds` was never reproducible at all.

This is leg 105's finding on a different module, and it has the same consequence: **comparing
against the committed `writeup/data/p2_route_hna_v1_adversarial.json` is the WRONG
zero-regression test** — it would report a 1–2 ULP "regression" that predates the repair and is
a property of the runner, not the code. Clause (b) is therefore measured as a **same-process
bitwise differential**: the pre-repair module (blob `b614a116…`) and the working-tree module are
loaded into **one interpreter**, so BLAS, numpy, seeds and reduction order are shared by
construction and any surviving bit difference is attributable to the patch alone. Literal-JSON
agreement is recorded **informationally** and excluded from the pass/fail criterion.
