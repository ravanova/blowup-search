# Leg 213 — Route-LGC2 novelty pass (light), committed BEFORE the audit runs

**Date:** 2026-08-06. **Agent:** LEG (Route-LGC2). **Branch:** `leg/213-lgc2-v1`.
**Verdict: `PROCEED_AS_AUDIT`.** This leg builds no mathematics, reads no PDF, and claims no
novel mechanism. It is a **ledger-hygiene** leg: it re-runs the leg-145 self-consistency
question against the two shared-ledger rows appended *after* leg 145 ran.

**Why the pass is light, and the reason is banked rather than asserted.** The novelty question
for a ledger-audit leg is not "has anyone proved this?" — nothing is proved. It is the narrow,
falsifiable one:

> **Has this repository already audited `solver/literature_gates.py`'s and
> `solver/viscous_novelty.py`'s post-append state for internal consistency, and if so, does
> that prior audit already cover the two rows this leg is pointed at?**

That is answered in-repo, by `git log` and `grep`, not on the web. No external literature is
consulted, because no external source can say whether *this repository's* ledgers are
self-consistent.

## 2. The existing automated gates, and why they cannot see this

- `test_literature_gates.py::test_8_ledger_does_not_rot` — **structural only** (leg 145's own
  finding, quoted in `experiments/p2_route_lga_v1_ledger.py`): it gates `CLAIM_LEDGER`'s shape.
  `EGM_PRIMARY_READ` is a **top-level dict outside `CLAIM_LEDGER`**, so no clause of test_8
  reaches it at all.
- `test_literature_gates_selfconsistency.py` — pins `len(CLAIM_LEDGER) == 12`,
  `len(described) == 4`, and (post-04476ff) asserts leg 145's three drifts stay **absent**.
  It says nothing about any block appended beside `CLAIM_LEDGER`.
- `test_viscous_novelty.py:50` — `assert fields <= set(p)`, i.e. the required seven keys are a
  **subset** check. A row carrying extra keys passes; a row whose prose has drifted from the
  leg that banked it passes; a duplicated `id` passes.

So all three existing gates pass on precisely the defects this leg is pointed at. That is not
a criticism of them — they check shape; this leg checks fidelity.

## 3. Negative controls are mandatory here (banked lesson 90)

A ledger audit that cannot fail is decoration. Every checker in
`experiments/p2_route_lgc2_v1_ledgeraudit.py` is re-run against a deliberately corrupted copy
of the same structure (a mutated arXiv id, a duplicated row, a paraphrased claim, an
un-stale-ed site list). Any checker that passes the corrupted input is reported in the JSON as
an **ornament**, not counted toward the gate.

## 4. What this leg does NOT do

  whether BCG is Grade B, are settled by those legs. This leg asks only whether the ledger
