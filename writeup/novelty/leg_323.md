## 0. What MF1 actually is, read from leg 303's own artifact before writing the table below

`writeup/data/p2_route_gaf_v1_sweep.json`, hit `2604.09949`: **`found_by`** lists two queries,
both containing `abs:"Navier-Stokes"` with a **single, plain hyphen** — and the paper's own
title/abstract spell it `Navier--Stokes` (LaTeX double hyphen). **The arXiv search API's
retrieval layer already matched a plain-hyphen query against a double-hyphen abstract.** MF1's
actual, narrower mechanism (`writeup/data/p2_route_gaf_v1_sweep.json` MF1 text, and
`experiments/p2_route_gaf_v1_adjudications.py:38-41`) is that leg 303's own **downstream
classification regex** `navier[- ]stokes` — a local Python string match run AFTER retrieval, to
score clause (c) `c_dissipative` — does not match `Navier--Stokes`, and mis-scored a true hit as
a mechanical near-miss. **That is a classification defect, not (necessarily) a retrieval
defect.** My leg's job is to test both, empirically, not assume either: (i) is the arXiv
abs:-field query itself dash-sensitive at retrieval (does a variant SPELLING in the query
string surface papers a plain-hyphen query misses)?, and (ii) fix the *reporting* side by
carrying every row as a link. Recorded here, before any query of my own runs, because it
changes what a "new hit" from my re-run would even mean: if retrieval is dash-insensitive
(which the evidence above already suggests), the yes-branch's bar is "genuinely new to any
plain-hyphen query", not "found only via a dash variant" — and I hold myself to that reading
rather than the more dramatic one.

## 2. Protocol, decided now, before a single result is seen

**Step A — mechanism calibration.** For every distinct hyphenated/proper term above, run a
standalone `abs:"<term-in-that-form>"` phrase query for each of its 5 new variant forms (3 for
De Gregorio, 1 for ALS) against the arXiv API. Record every returned link (not a count) and
diff each variant's result set against the term's plain-hyphen baseline (queried fresh in the
same pass, so the diff is same-session, not against leg 303's older snapshot). **This is the
direct test of whether the retrieval layer is dash-sensitive at all** — §0 above already gives
one data point (yes-normalizing) from a single already-landed hit; this step tests it broadly
and pre-committedly, across every term, rather than generalizing from n=1.

**Step B — compound re-run.** Re-run all 35 base queries (leg 174's 12 are a verbatim subset of
leg 303's 35 — confirmed by direct string comparison against `writeup/novelty/leg_174.md`'s
`SEARCH_LOG` transcription and `solver/viscous_novelty.py::SEARCH_LOG`) exactly as originally
worded (the baseline replication, itself a control — it must reproduce leg 303's counts before
anything else is trusted), **plus one variant pass per base query**: every hyphenated/proper
term present in that query is substituted, simultaneously, with its **double-hyphen** form (the
literal MF1 form, chosen as the single representative variant for the compound pass because
Step A tests the other four forms exhaustively at the per-term level already — running all six
forms combinatorially across all 35 compound queries is not proportionate given Step A's
coverage, and this decision is recorded here, before results, not after). Per-query delta =
arXiv IDs in the variant result set not in that query's baseline result set, reported row by
row.

**Step C — four-group author census.** Run each of the four groups' name string, baseline and
each accented/hyphen-variant form, as an `au:` (author) field query. Links, not counts, for
every row.

**Retry discipline (leg 303's own MF3 lesson, carried forward as binding on this leg too):** any
HTTP 429/503/timeout is retried at >=25s spacing, never banked as a zero. `n_unavailable` must
be 0 in the final JSON or the run is not done.

**Performance note (CONTINUATION_PROMPT.md's performance rule).** Estimated ~135 arXiv API
calls (Step A ~84, Step B ~70 [35 baseline replication + 35 variant], Step C ~17) at a >=3.2s
politeness delay between calls: **estimated ~7.5-11 min**, before any 429/503 retries. Run in
the background with progress checkpointing; actual runtime recorded in the journal.

## 3. What counts as a genuinely new hit (pre-committed, so it cannot be adjudicated after the
fact to fit a preferred answer)

A row from Step B or C is a **candidate new hit** only if: (i) its arXiv ID does not appear in
`solver/viscous_novelty.py::PRECEDENTS`, (ii) it does not appear in *any* of leg 303's 35
baseline result sets or leg 174's 12, (iii) it is not `arXiv:2604.09949` (leg 309's paper,
excluded from the gate's count by the dispatch's own wording — recorded, not adjudicated, not
read past its metadata), and (iv) it clears leg 303's own four-clause screen at abstract depth
(certificate, blow-up, dissipative, fluid model) well enough to be worth a human adjudication
line — mechanical near-misses are reported but do not by themselves answer the gate YES.
