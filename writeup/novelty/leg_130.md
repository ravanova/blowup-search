This leg repairs one *direction* defect in `solver/hilbert_pointwise.py` that leg 106 measured
and escalated. It builds no new mathematics, proposes no new majorant, and — this is the
binding constraint, not a courtesy — **makes no constant smaller**. The plan-of-record ban
*"another Route-D bound-sharpening leg"* applies to this leg literally: a repair that returned
a *tighter* number on any previously-passing input would be a claim change, not a repair, and
would be indistinguishable from the banned activity. Every admissible outcome here either
**rejects** an input or **inflates** a returned coefficient; the previously-passing surface must
come back **bit-identical**.

## 2. Is the *mathematical* content novel? No — it is Plemelj–Privalov, and this leg says so

The mechanism leg 106 found is that the sup-account integrand in `d(log s)` tends to a nonzero
constant as the offset `s → 0` (`|K|·s → 2`, `cS → 2cos^α(θ/2) ≠ 0`), so only `cT ~ s^γ → 0`
tames the endpoint — which needs `γ > 0`. That the conjugate-function/Cauchy singular operator
preserves Hölder classes exactly for `0 < γ < 1` and fails at the endpoint `γ = 0` is the
**Plemelj–Privalov theorem**, classical since Plemelj (smooth curves) and Privalov (the
circle); the modern generalized-Hölder statement is Karapetyants–Samko's
[*The Plemelj–Privalov theorem for generalized Hölder classes*](https://iopscience.iop.org/article/10.1070/SM1993v075n01ABEH003378)
(Sb. Math. 75 (1993) 1), with recent extensions in
[the polyanalytic setting](https://www.sciencedirect.com/science/article/pii/S0022247X18302294)
and [higher-order Lipschitz classes](https://www.sciencedirect.com/science/article/pii/S0022247X19306791).
**No novelty is claimed for the `γ > 0` condition** — this leg's guard is an implementation of a
classical hypothesis that the module never enforced, and the guard's docstring is written to say
exactly that. What the repo contributes is not the theorem but the *executable* enforcement of
it at the one call site where a violated hypothesis silently produced a finite number.

## 3. Is the failure mode novel in this repo? No — it is the fifth IEEE-754 comparison instance

Leg 117's novelty pass already recorded IEEE-754's unordered-NaN comparison silently defeating a
`<=` guard as *"a fourth instance of the same standard-level hazard legs 100/106/116 already
found"*, against the IEEE working group's own phrase that such values *"disappear without a
trace"*. `take_T = rho*cT <= cS` with `rho = NaN` is instance five. Nothing here is a new class
of bug and the journal will not present it as one.

## 4. What the pass actually *changed* about the plan — the part that was not known before

Leg 106's own escalation note prescribes the repair as: *"reject non-finite `rho` and
`gamma <= 0`"*. **The novelty pass falsifies that prescription as written**, before any code was
touched, and this is the pass's load-bearing finding:

* Leg 106's V1 explicitly includes `rho = 1e300`, which is **finite**. A "reject non-finite
  `rho`" guard would let it through, leaving the configuration leg 106 banked as violating
  still violating. The prescription is not sufficient for its own gate.
* The obvious alternative predicate — *does the payer rule select the seminorm account at the
  innermost quadrature node?* — was measured before adoption and is **wrong in both
  directions**: over 87,552 shipped-family configurations (`α=1.5, γ=0.5`, `ρ ∈ {1,…,25}`,
  `ε ∈ {1e-8 … 1e-16}`, four `θ` grids) it reports **2,418 false positives** in the far field,
  where the sup account is legitimately selected in the *intermediate* regime `c ≪ s ≪ 1` and
  the integrand still decays; and it **misses `γ = 0` entirely** (there `ρ·cT/cS → 0.5 ≤ 1`, so
  the *seminorm* account is selected and it is the seminorm integrand that fails to vanish).
  Adopting it would have broken gate (b) on 2,418 previously-passing cases and left V2 open.
* The predicate this leg will use instead is the **discarded inner head**, in closed form: the
  asymptotic payer crossover `s* = (2c^γ/ρ)^{1/γ}` (`c = cos(θ/2)`), with the configuration
  rejected iff the quadrature's inner endpoint `ε·L` does not already lie inside the tamed
  region `s < s*`. Measured before adoption over 4,188 shipped configurations: the sup-account
  head is **exactly 0.0 on every one of them**, and positive on the violators
  (`ρ=1e6 → 3.944`, `ρ=1e12 → 33.16`, `ρ=1e300 → +∞` by underflow of `s*`, `γ ≤ 0 → +∞` because
  no crossover exists). **Threshold-free**: the criterion is `> 0`, not `> tol`.
* That measurement also surfaced a configuration **leg 106 never tested**: `ρ ≈ 1e6` and above,
  finite and non-NaN, is unsound by the same mechanism as `ρ = 1e300`. Per the `first_integral`
  precedent (which closed *"the 6 escalated mechanisms plus a 7th found during repair"*), it is
  closed by the same guard and reported with its magnitude rather than left silent.

## 5. What is deliberately NOT touched (scope, stated in advance)

* **The majorant.** No inequality in `_side` is re-derived, retuned or replaced. The arithmetic
  producing `(a_sup, a_semi)` on an accepted configuration is untouched line for line.
* **The `ε`-truncation of the *seminorm* head.** It is nonzero on sound inputs too (up to
  `5.4%` of the returned pair at `θ = 1e-8`) and is the same optimistic direction gate 6 already
  pins at `2–5%`. It is a *pre-existing, in-scope-of-leg-106, out-of-scope-of-this-repair*
  understatement; inflating the bound to cover it would be a claim change on every previously
  passing case and would break gate (b). It is reported with its magnitude, not fixed.
* **`measured_pointwise`'s silence.** Leg 106's gate 9 pins `worst_ratio = 0.0` with an empty
  profile name on NaN-poisoned families. That is a *reporting* defect, not a bound-direction
  violation, and it is not among the two configurations this leg's gate names. It stays pinned,
  unweakened, and is named in the journal as still open.
* **`capabilities.py`'s validated line** (`"no known-answer gate; sampled"`, line 299) is a
  shared ledger and is not edited by this leg.
