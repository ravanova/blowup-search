**Committed BEFORE the census script is run.** Branch `leg/287-epa-v1`. Date 2026-08-07.

**Role: MEASUREMENT AUDIT, scoped wide.** No solver code is written; no certificate value is

## 0. What is already known (prior art inside this repo)

Leg 252, recorded in `DIRECTION.md` (DM update, 2026-08-07, "252 ESCALATED"), regenerated
`writeup/data/p2_route_d_v11_anchor.json` via its own runner
(`experiments/p2_route_d_v11_anchor.py`) with **zero code change since the file was banked**
(`profile_newton.py` has exactly one commit, the banking one — solver drift is ruled out) and
found:

- 202 of 359 banked leaves moved on regeneration (46 by >10%);
- one `converged` flag flipped `True -> False`;
- the movement is worst exactly where Newton's basin is decided at last-bit floating-point
  precision — i.e. this is not solver logic drift, it is environment-level float
  non-reproducibility (library version, BLAS backend, FPU mode, or similar) reaching into a
  basin-of-attraction decision.

That leg's own explicit open question, which this leg answers: **is that an outlier, or the
norm, across this repository's other banked artifact families?**

No other leg has run this comparison. A repo-wide grep for `environment-portab`,
`regenerat.*leaf`, and `banked.*bytes` (case-insensitive, `.git`/`.venv`/`Papers` excluded)
turns up only leg 252's own record and the DM's slot-I dispatch text — confirming this
census has not already been run under a different name.

## 1. The census set — N=10, enumerated BEFORE any number is regenerated

The repository holds 218 banked JSON artifacts under `writeup/data/`. To keep this leg
`standard` difficulty while still being representative, the census is restricted to families
whose runner and artifact share a basename 1:1 (`experiments/<name>.py` writes
`writeup/data/<name>.json` directly via a `ROOT = Path(__file__).resolve().parents[1]` /
`OUT = ROOT / "writeup" / "data" / "<name>.json"` pattern) — 182 of the 218 artifacts satisfy
this, so the restriction does not exclude a structurally distinct minority.

From those 182, ten were chosen by hand to stratify across the repo's genres of banked record,
deliberately including the structural closest analogue to the v11 anchor family (a
Newton-solve-heavy spectral family) and a pure-literature control expected to be maximally
portable:

| family | genre | why chosen |
|---|---|---|
| `p2_route_e_v1_spectrum` | Newton-solve-heavy | 4 `flow.newton(...)` call sites — closest structural analogue to the v11 anchor family (`profile_newton.py`'s own Newton solve is what leg 252 found non-portable) |
| `p2_route_mf2_v1_residual` | residual/floor | carries its own `worst_newton_residual_over_floor` diagnostic — another Newton-adjacent family |
| `p2_route_cvf_v1_classify` | convention census | leg 281's 32-row, 6-group numeric classification — heavy floating-point content, no Newton solve |
| `p2_route_l1rh_v1_construction` | interval/L1 construction | a different numerical method family (interval arithmetic-flavored, not shooting/Newton) |
| `p2_route_hhr_v1_repair` | repair record | hashes its own record (`json.dumps(rec, sort_keys=True)`) as an internal self-consistency check — lets the census see whether the artifact's own determinism check itself survives |
| `p2_route_h2i_v1_scoping` | scoping record | bordered-H2 lane scoping, distinct solver path from Route-D and Route-E |
| `p2_route_nka_v1_adversarial` | adversarial battery | stress-test genre |
| `p2_route_dpa_v1_adversarial` | adversarial, Newton-adjacent | built on `newton_gamma2` / `newton_profile` solves — another Newton-adjacent family, independent code path from Route-D and Route-E |
| `p2_route_cap_v1_audit` | text/structural audit | audits `capabilities.py` structurally (AST parsing), essentially no floating-point content — a **negative control**: expected fully portable, since there is nothing for an environment to perturb |
| `p2_route_alsl2_v1_lit` | literature-scope record | no solver call at all — a second **negative control** |

The `p2_route_d_v11_anchor` family itself is explicitly excluded (owned by the separate
236/226/252 consolidation rework, per `DIRECTION.md`'s territory note; leg 287 must not touch
`writeup/data/p2_route_d_v11_anchor.json`, `experiments/p2_route_d_v11_anchor.py`, or
`profile_newton.py`).

## 2. Falsifiable predictions, registered before running anything

1. **P1.** The two negative controls (`p2_route_cap_v1_audit`, `p2_route_alsl2_v1_lit`, neither
   of which calls a numerical solver) will classify PORTABLE (max relative move `< 1e-9`, zero
   flag flips). If either moves, that refutes the working hypothesis that non-portability tracks
   floating-point solve content specifically, rather than being a broader artifact of the
   regeneration harness (timestamps, dict ordering, etc.).
2. **P2.** The Newton-solve-heavy families (`p2_route_e_v1_spectrum`, `p2_route_mf2_v1_residual`,
   `p2_route_dpa_v1_adversarial`) will show measurably more leaf movement than the two negative
   controls and than the non-Newton numerical families (`p2_route_l1rh_v1_construction`,
   `p2_route_h2i_v1_scoping`) — i.e. leg 252's finding is not a Route-D-specific defect but
   tracks Newton's-method / basin-of-attraction sensitivity generically.
3. **P3.** At least one of the ten families will show verdict-bearing flag movement (not just
   quiet numeric drift) — because leg 252's own worst finding was exactly a flag flip
   (`converged: True -> False`), not merely a magnitude change.
4. **P4.** No family will be fully IRREPRODUCIBLE (crash / missing runner / import error) — all
   182 direct-match runners were exercised by their own legs recently enough that dependencies
   should still resolve. If any DOES fail to run at all, that is itself banked as a finding per
   the gate's NO branch, not smoothed over.

These are falsifiable and stated before `p2_route_epa_v1_census.py` is executed for a result;
§3 of `experiments/journal/leg_287.md` reports which held and which did not, with numbers.

## 3. Method (mechanics, not a claim)

For each censused family: copy the full repository into a throwaway temp directory (never the
banked worktree), run `experiments/<family>.py` there via its own `ROOT = Path(__file__)...`
convention (so it writes into the COPY's `writeup/data/`, never the real one), then recursively
diff every scalar leaf of the regenerated JSON against the real banked JSON — numeric leaves by
relative move, bool/string leaves by exact equality, with any leaf whose key looks
verdict-shaped (`gate`, `verdict`, `converged`, `classification`, `decision`, `flag`, `status`,
...) that flips flagged separately as the highest-severity category. Classification:
`PORTABLE` / `MINOR-DRIFT` / `DRIFT` / `NON-PORTABLE` (any verdict flip) /
`IRREPRODUCIBLE-AS-BANKED` (could not regenerate at all). Zero banked files are ever opened for
writing.
