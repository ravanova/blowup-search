## What is being checked, and why it is only two questions

Leg 185's novelty pass asked three questions (N1 existence-in-print, N2 dilation covariance
in print, N3 published stall-diagnosis protocol) and answered all three NOT FOUND. This leg
does **not** re-open them as open questions; it asks only whether the answers have **changed
in the eleven months of literature since**, because a verification leg that ratifies a number
must not ratify it against a literature snapshot that has moved.

* **(V-N1)** Has anything appeared that asserts existence **or** non-existence of a steady
  γ = 2 (full-Laplacian) self-similar gCLM profile — leg 125's "Object B" — or that reports
  the **sign of ν** recovered under a dilation-gauge-fixed reparametrization? If so, leg 185's
  `ν = +0.01799364` at `a = 0.30` / `ν < 0` at `a = 1/2` has an external answer key and this
  leg must read its own re-derivation against it rather than against leg 185 alone.
* **(V-N2)** Is there a published *independent-reproduction protocol* for numerically
  constructed self-similar profiles that this leg should be following instead of the
  three-tier design it plans (operator revalidation → independent discretization →
  algebraically distinct route via the dilation covariance)?

## Verdict

* **(V-N1) STILL NOT FOUND, either way, and now checked twice eleven months apart.** No
  source asserts existence or non-existence of a steady γ = 2 self-similar gCLM profile, and
  none reports a recovered ν or its sign. **There is no external answer key**, so leg 185's
  number can only be verified *internally* — which is exactly what makes an independent
  re-derivation the right instrument and a citation search the wrong one. Pre-committed
  consequence, written before any number was computed: **a confirmation here is a
  reproducibility statement about this repository's own computation, not an existence result
  about gCLM, and it must be reported at that altitude.**
* **(V-N2) NO published protocol.** So the verification design is this repository's own, and
  it is pre-committed here, before running, in the form lesson 90 demands — *not* re-executing
  leg 185's script and trusting its output:
  1. **V0 — operator revalidation against closed forms.** Every operator used is checked
     against an analytic answer (the exact `a = 0` CLM pair `Ω₀ = −4X/(1+4X²)`, `HΩ₀ =
     2/(1+4X²)`; Chen's exact pair `Ω`, `U_x = HΩ`, `U`), so a reproduction cannot be an
     agreement between two copies of the same bug.
  2. **V2 — an independently discretized re-derivation.** A second implementation of the
     residual and Jacobian, derived from the equation and not transcribed from leg 125's
     module: 6th-order derivative matrices instead of 4th, the second derivative assembled
     through the chain rule `∂ₓₓ = X_ρ⁻²∂_ρρ − X_ρρX_ρ⁻³∂_ρ` instead of as `D∘D`, and a
     degree-5 Lagrange panel quadrature instead of the 4-point Adams–Moulton rule. Two
     different discretizations must agree **in the continuum limit**, not digit-for-digit at
     one `n`, and the honest target is therefore the grid-refined/Richardson value.
  3. **V3 — an algebraically distinct route.** The dilation covariance `Ω(X) → Ω(X/μ)`,
     `ν → μ²ν`, `Ω_X(0) → Ω_X(0)/μ` implies `ν` at gauge `κ·g` equals `ν(g)/κ²` **exactly**,
     so re-solving at deliberately wrong gauges and rescaling must land on the same ν without
     ever solving the system leg 185 solved. It also implies the **sign of ν is a dilation
     invariant** of the branch — i.e. the sign claim is gauge-independent, which is a
     structural check leg 185 did not run.
  4. **V1 — replay, ranked last on purpose.** Re-executing leg 185's own code path is the
     *weakest* tier and is reported as a determinism/transcription check only, never as the
     verification.

**Standing ban discharged.** `capabilities.py` grepped before anything was written
(`grep -n -i -E "dissipat|gclm|profile|hilbert|sinh|newton" capabilities.py`), which returned
`solver/dissipative_profile.py` (leg 125's Object-B module, closed territory),
`solver/gclm_family.py`, `solver/line_hilbert.py` and `solver/gclm_rescaled.py`. This leg
**builds no solver module**: the independent implementation lives entirely inside the
experiment driver in `experiments/`, precisely so that it cannot be mistaken for, or reused
as, banked machinery. `solver/dissipative_profile.py` and all leg-185 artifacts are imported
and read **read-only** and are not edited.

**Ceiling, pre-committed.** Independently re-deriving a float measurement of a discretised,
truncated profile equation is not an existence proof, not movement on `L1→L4`, and not Clay;
Clay stays ~0.05%. The most this leg can produce is that one number is reproducible by a
second code path — or a precisely stated discrepancy, which per §210 is a priority escalation.
