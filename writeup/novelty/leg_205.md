### 0.4 The dealiasing-mask class (legs 129 / 188) — checked, and it is a *different* module

Legs 129/188 raise the dealiasing-mask question for `solver/boussinesq.py`, which is
FFT-based: `grep -rn "dealias"` puts `dealias_mask2d` in
[`test_boussinesq_postrepair.py`](../../test_boussinesq_postrepair.py) and `dealias_mask` in
[`solver/spectral_utils.py`](../../solver/spectral_utils.py) / `phase2_spike0_probe.py`.
**`solver/boussinesq_rescaled.py` imports neither, and contains no FFT, no spectral
truncation and no mask of any kind** — its transport is 3rd-order upwind finite differences in
physical space on the log-polar grid, and its only spectral object is the angular DST-I of the
sibling velocity module, which is an exact bijection on grid fields (`S @ S = (M/2) I`).
The mask question is therefore carried into the battery as an **input** (family F5 below:
does any reduction in this module lose information silently?), exactly as the directive
specifies, and it is *a priori* unlikely to be the defect found here.  If the defect this leg
finds is the leg-99 origin-fit-window class instead, it is a **genuinely different defect**
under the gate's own disjunction and escalates separately.

### 0.5 In-module guards — there are none

`grep -n "raise\|assert\|isfinite" solver/boussinesq_rescaled.py` returns **one** `isfinite`,
in `RescaledBoussinesq.run` (the divergence break `if not np.isfinite(res) or res > 1e8`), and
**zero** `raise` statements in the entire 280-line file.  There is no validation of grid
occupancy, of field shape, of `c_l` finiteness, or of fit-window rank.  The module's only
protection against a degenerate grid is inherited *accidentally* from the sibling
`u_x_at_origin`'s leg-99 guard, which uses a **different window** (`r_window=0.1` vs
`r_win=0.4`) and a **different parameter count** (2 vs 3) — so the inherited guard cannot be
tight, and the size of the gap it leaves is a quantity this leg must measure, not assume.

### 0.6 Live in-repo callers of the unguarded path

The unguarded reduction is a **public** function and is called directly, outside `modulation`,
by [`experiments/p2_route_l_v1_precond.py`](../../experiments/p2_route_l_v1_precond.py)
lines 222–229 — which additionally *divides* by its return value
(`fo = wx_t / odd_field_x_slope(o, grid)`), and by
[`writeup/3_spikes/spike1_stepB_evidence.py`](../../writeup/3_spikes/spike1_stepB_evidence.py)
lines 84–85.  So this is not a theoretical entry point.

**Novelty: confirmed.**  No file in the repository asks this question of this module; the one
place the repository *raises* it (leg 99 §4) explicitly declines to answer it and names this
leg's scope as the follow-up.

**Distinctness.**  From leg 89 (target `solver/boussinesq.py`), leg 99/104 (target
`solver/boussinesq_velocity.py`), and leg 188 (reads `boussinesq.py`, patches nothing) — three
different modules.  Lesson 75 applies in the other direction too: *two defects in the same
family are not automatically the same defect*, and §2 must establish which class this one is
before it may be merged into anyone's escalation.

## 1. The battery, declared before it runs

`experiments/p2_route_bvr_v1_adversarial.py`, five families, every case recorded with its
outcome in `writeup/data/p2_route_bvr_v1_adversarial.json` — negative results included.

| family | question |
| --- | --- |
| **F1 origin-read reduction** | does `odd_field_x_slope` fabricate a finite value when its fit window is empty or rank-deficient? |
| **F2 coupled entry point** | does the same degeneracy reach `modulation` / `rhs` / `run`, or is it intercepted — and if intercepted, how wide is the surviving gap? |
| **F3 NaN / Inf pass-through** | does a planted non-finite value propagate visibly, or get swallowed by a reduction or a mask? |
| **F4 degenerate & boundary parameters** | zero fields, constant fields, tiny `n_r` / `n_beta`, `c_l` extremes, `max_steps=0`, `tol`/`dt_frac` extremes |
| **F5 information loss in reductions (the mask question as an input)** | is any reduction in this module lossy in a way that returns a plausible wrong number rather than a visibly wrong one? |

**Outcome vocabulary** (leg 99's, reused so the two batteries can be read side by side):
`OK` (correct within tolerance), `RAISED` (rejected with an exception), `NONFINITE` (defect
visibly propagated as NaN/Inf), `SILENT_WRONG` (finite, plausible, wrong — the gate's yes),
`SILENT_EMPTY` (finite but structurally vacuous).

Only `SILENT_WRONG` answers the gate YES.
