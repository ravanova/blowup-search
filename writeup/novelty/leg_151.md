## 2. Prior art for the three guard forms — all established, no novelty claimed

**G1 (row-deletion degeneracy).** The method `gauged_jacobian` implements is *the classical row
deletion method*: delete a row of the discretized operator, substitute a boundary/gauge row.
Driscoll & Hale, *Rectangular spectral collocation*, IMA J. Numer. Anal. 36 (2016) 108–132 —
full text at
<https://appliedmaths.sun.ac.za/~nhale/publications/DriscollHale2015.pdf> — state that row
deletion "carries ambiguities … outside of two-point scalar boundary-value problems," and that
when several conditions must be imposed "there is little clarity in whether deleting multiple
rows from either the top or bottom is a sound idea." Their own remedy is structural (resample to
a rectangular differentiation matrix, then adjoin the conditions), not a validation guard — so
**the literature motivates the guard but does not supply its form**, and this leg claims no
priority for the form it adopts. The published fact this leg leans on is only that row deletion
is *known* to be ambiguous on non-two-point, non-scalar operators, which the gCLM operator is on
both counts (nonlinear, and non-local through `H`). Related later work restating the same
ambiguity: *The ultraspherical rectangular collocation method and its convergence*,
<https://arxiv.org/html/2401.03608>.

**G2 (1-D shape ambiguity).** NumPy's own reference for `numpy.atleast_2d`
(<https://numpy.org/doc/stable/reference/generated/numpy.atleast_2d.html>) documents,
unconditionally and by worked example, that a 1-D input of shape `(N,)` becomes shape `(1, N)` —
a **row**, never a column. The behaviour is documented and deliberate; what is undocumented is
`sup_op_norm`'s own axis convention against a 1-D argument. The guard form adopted here
(validate the post-`atleast_2d` shape against `(len(w_dom), len(w_cod))`) is ordinary defensive
argument validation, entirely standard, and no novelty is claimed for it.

**G3 (non-real `alpha`).** NumPy documents `numpy.exceptions.ComplexWarning` as a **`Warning`,
not an exception**, fired when a complex value is cast to a real dtype and the imaginary part is
discarded (<https://numpy.org/doc/stable/reference/generated/numpy.exceptions.ComplexWarning.html>).
Python's own `float()` raises `TypeError` on the same input. The guard adopted here simply moves
`w_domain`/`w_codomain` from the looser contract to the stricter one. Standard; no novelty
claimed.

## 3. **THE HEADLINE OF THIS PASS: leg 115's own prescribed G1 repair is MEASURABLY INSUFFICIENT for leg 115's own pins**

Leg 115's `experiments/journal/leg_115.md` §"What was NOT patched" prescribes, verbatim:

> `gauged_jacobian`/`graded_inverse_norm` should raise (or otherwise flag) when `rows` is empty
> (i.e. `J <= 1`) rather than silently proceeding with a gauge-only system

Run before writing a line of the patch, on the module as it stands on `main`
(`solver/decay_collocation.py` at `a595dcb`, its only commit), at `J = 1`, over exactly the five
`drop` values leg 115's own PIN `test_J1_ignores_drop_and_gauge` covers:

| `drop` | `len(rows)` | `rows` | is `rows` empty? | `graded_inverse_norm` |
|---|---|---|---|---|
| `0`   | 0 | `[]`  | **yes** | `1.681792830507429` |
| `1`   | 1 | `[0]` | **no**  | `1.681792830507429` |
| `-1`  | 1 | `[0]` | **no**  | `1.681792830507429` |
| `5`   | 1 | `[0]` | **no**  | `1.681792830507429` |
| `100` | 1 | `[0]` | **no**  | `1.681792830507429` |

**The prescribed predicate — "`rows` is empty" — is true for 1 of these 5 cases and false for 4,
while all 5 collapse to the identical value.** A repair implementing leg 115's prescription
literally would leave 4 of the 5 cases in its own inverted-PIN test still silently collapsing,
and the gate's clause (a) ("do all 3 of leg 115's failing cases now reject or visibly flag …
with every PIN inverted") would answer **NO** on a patch that did exactly what the finding leg
asked for.

**Mechanism, measured not argued.** The collapse is not caused by an empty `rows` list. It is
caused by the **assignment target** `M[1:, :]` having shape `(0, J)`, which at `J = 1` is
`(0, 1)`. NumPy broadcasts the right-hand side `col.jacobian_matrix(om, c)[rows, :]` — shape
`(1, 1)` when `rows == [0]` — into a `(0, 1)` destination, because a length-1 axis broadcasts to
**any** length including zero. So the assignment is a silent no-op *whatever* `rows` contains,
and the entire NaN-poisoned Jacobian is discarded either way. That is why the value is
bit-identical across all five `drop`s, and it is why the predicate has to be a **shape
invariant**, not an emptiness test.

**The predicate this leg adopts instead**, two clauses, each measured necessary above:

1. `J >= 2` — at least one real collocation row must survive the gauge substitution
   (catches `J = 1, drop = 0`, which clause 2 alone lets through since `len(rows) == J - 1 == 0`);
2. `0 <= drop < J` — the deleted row must be a row that exists
   (catches `J = 1, drop ∈ {1, -1, 5, 100}`, which clause 1 alone would also catch, but which at
   `J >= 2` is the clause that keeps the invariant `len(rows) == J - 1` honest).

Equivalently and in one line: **`len(rows) == J - 1 >= 1`**. This is the same shape-invariant
discipline leg 130 adopted for `hilbert_pointwise.py` (the discarded sup-account head, exact on
every shipped configuration and positive on every violator) rather than the finding leg's
proposed innermost-node predicate, which leg 130 measured wrong in both directions. **This is
the second time in this repository that a finding leg's prescribed predicate has failed its own
gate on measurement.** Both times the pass caught it before the patch, not after.

Note also that `drop = -1` is *not* Python's "last row" here and never was: `[j for j in
range(J) if j != -1]` retains **all** `J` rows. At `J >= 2` that already raises `ValueError`
from the shape mismatch (loud, if accidental); clause 2 only makes the refusal explicit and
gives it a message. No shipped caller passes a negative or out-of-range `drop` — the only
in-repo `drop` sweep is `experiments/p2_route_d_v4_graded.py:241`,
`drop in (0, 1, 2, J//4, J//2, J-1)`, all in range.

## 5. One deliberate scope decision, stated explicitly either way (the leg-152 convention)

Leg 130 shipped an **opt-in escape hatch** (`on_unsound='extrapolate'`) so leg 106's measurement
stayed reproducible through the module's own public API. **This leg deliberately ships no escape
hatch**, and the reasoning is recorded here rather than left implicit:

* leg 130 needed one because its violating band (`rho >= 1e6`) *was* a shipped configuration
  class that had to keep returning a number;
* leg 115's `J = 1` is used by **nothing** — no caller, no test, no banked run (leg 115's own
  downstream census: minimum `J` in use is 8, typical ladder `[125, 250, 500, 1000, 2000]`), so
  no shipped path needs the defective value back;
* the runner reproduces leg 115's `1.681792830507429` from the pre-repair module loaded out of
  git anyway, so the measurement survives without a mode inside the repaired module;
* a public mode that deliberately reproduces a value known to be independent of its own inputs is
  a footgun on a claim-adjacent module, and the licence for this whole patch is *minimality*.
