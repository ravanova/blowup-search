# Leg 289 — ROUTE-D1X — novelty / prior-art pass

**Committed BEFORE the formal runner exists.** Branch `leg/289-d1x-v1`, cut from `origin/main`.
Date 2026-08-07.

**Role: USE THE LAW, DON'T RE-DERIVE IT.** Leg 288 banked one clean exception inside an
otherwise convention-conflicted family (`writeup/data/p2_route_canon_v1_convention.json`):
`D1 = ‖ℓ‖_{X*}` obeys an **exact** closed-form law,

```
D1(κ) = 0.8873620087421942 · κ^{-1/2}
```

verified against a fresh probe out to `κ = 1e8` at `≤ 1.5e-16` relative error, on top of leg
281's own fit (`fit_max_relative_residual = 1.11e-16` over an 11-point sweep `κ ∈ [1e-4, 1e4]`).
"Exact law with a conversion table" is banked as a **fact**; whether it is **useful** — i.e.
whether it can stand in for a fresh certificate compute at an untested `κ` — is not yet tested.
That is this leg's entire job, using zero new certificate compute.

**Read-only inputs (no new solver/certificate compute performed by this leg):**
- `writeup/data/p2_route_canon_v1_convention.json` (leg 288) — the law statement, the 4-way

- `writeup/data/p2_route_cvf_v1_classify.json` (leg 281) — `S4_group_D_dual.D1_ell_dual_norm_N512`,

  X Gram once, so it is exactly homogeneous of degree −1/2 in κ. The border coordinate never
  enters` — an **analytic**, not merely empirical, homogeneity argument).
- Leg 249's sweep (`experiments/journal/leg_249.md` / referenced JSON) was checked directly: it
  sweeps the **border weight** for `σ_min` (the `A1` quantity), **not** `D1`. Leg 249 carries

  any computation is attempted — recorded here so the formal runner does not waste a search on

## 1. What "held out" can honestly mean here

Leg 281's own JSON already distinguishes the **anchor** from the **sweep**: `D1`'s quoted
headline value is `"pinned_by": "kappa = 1"` — i.e. only the `κ=1` measurement is used to fix
the law's multiplicative constant `C = 0.8873620087421942`. The exponent `−1/2` is not fit at
all; it is asserted as an **analytic consequence** of `D1` being a norm of a functional on the
`X`-block alone (mechanism quoted above). That means every *other* point in leg 281's own
11-point sweep (`κ ∈ {1e-4, 1e-3, 1e-2, 0.1, π, 2π, 10, 100, 1000, 10000}`) is a legitimate
held-out test of the law: **only κ=1 is used to derive it; the rest were independently
certificate-measured, not curve-fit.**

A second, stronger family of held-out points comes from leg 288's `N=256` probe at
`κ ∈ {1e2, 1e4, 1e6, 1e8}` — genuinely new `κ` values never in leg 281's `N=512` sweep at all
(which stopped at `1e4`), computed at a **different discretization** (`N=256` vs `N=512`).
This lets the leg test a second, harder question the brief does not require but which the
gate answer should not omit: **does the law transfer across `N`, or only within one `N`?**

## 2. Falsifiable predictions, committed before running the formal script

- **P1 (same-`N` holdout, leg 281's own sweep).** Anchor the coefficient at `κ=1`
  (`C = 0.8873620215869099`, leg 281's `N=512` value — note this differs from leg 288's quoted
  `0.8873620087421942` fit constant only in the 9th digit, itself within float noise). Predict
  every other one of the 10 remaining `κ` points in leg 281's sweep via `C·κ^{-1/2}` and compare
  to the independently-measured `sweep[κ]` value already in the JSON.
  **Prediction: relative error ≤ ~1e-10 at every point** (matching leg 281's own reported
  `fit_max_relative_residual = 1.11e-16` up to the precision the `κ` grid values themselves are
  recorded to in the JSON — the `π`/`2π` keys are stored to only 10 significant figures, which
  will itself set a visible ~1e-10 floor unrelated to the law's actual accuracy).
  **Falsified if:** any held-out point's relative error exceeds ~1e-6 (three orders above the
  rounding-floor expected from the truncated `π` key).

- **P2 (cross-`N` transfer, leg 288's probe).** Two sub-tests, both against leg 288's `N=256`
  data (`κ ∈ {1e2, 1e4, 1e6, 1e8}`, none of which is `κ=1`, so none was used to derive
  *anything* in this leg):
  - **P2a — same-`N` anchor.** Anchor a *fresh* coefficient at `κ=100` from the `N=256` data
    itself (`C_256 = D1(100)·√100`), then predict the other three `N=256` points
    (`κ = 1e4, 1e6, 1e8`). **Prediction: relative error ≤ ~1e-15** — this is the same kind of
    test as P1, just at a different `N` and reusing leg 288's own already-banked probe as the
    anchor instead of leg 281's `κ=1` point.
  - **P2b — cross-`N` transfer.** Use the **`N=512`-derived** coefficient from P1 to predict the
    `N=256` points directly (no `N=256` anchor at all). **Prediction: this will show a
    measurable, non-floating-point-scale error** (order `1e-5`–`1e-4`, i.e. discretization-scale,
    not machine-precision-scale) — because `D1` at fixed `κ` is itself an `N`-dependent quantity
    (a finite-dimensional certificate number), and the exact law's homogeneity in `κ` holds
    *at fixed `N`*, not as a way to skip the `N`-dependence altogether. **Falsified if** P2b's
    error is machine-precision-scale (`< 1e-10`) — that would mean the law is `N`-independent
    too, which would make it strictly more powerful than P1 alone implies.

## 3. Gate mapping

- If **P1 holds** (same-`N`, same-sweep holdout predicts to ~1e-16–1e-10): gate → **YES**, D1's
  law is a validated predictive shortcut *within a fixed discretization* — flag it (do not apply
  it) for any future sweep that already has one `D1(κ₀, N)` certificate point and needs `D1` at
  a different `κ` **at that same `N`**, without a fresh solve.
- If **P2b also turns out machine-precision-scale**: strengthen the flag — the law would need no
  same-`N` anchor at all, only the analytic constant, at any `N`. This is not the prediction (P2
  above expects P2b to fail at discretization scale), but the runner will report the actual
  number either way, not assume the falsifiable prediction is correct.
- If **P1 fails** (unexpected): the law is descriptive of its 281-derivation points only; bank
  that "exact" here meant "exact on the points it was checked against," not general-purpose,
  and do not let future legs cite it as `N`-free or apply-anywhere.
