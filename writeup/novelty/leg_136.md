## 3. THE PRE-NAMED FAMILY (fixed here, before measurement)

Five criteria. Each is a **single scalar** computed from the accepted per-step states of one
trajectory, each is **scale-free** in the same per-block sense the landed `state_growth` clause
uses (`b` against `max|b0|`, `mu` against `|mu0|`, never a joint norm — `|b| ~ 1` while
`mu ~ 2e-3`), and each has its **threshold placed after measurement by the same rule the bench
repair used** (the geometric middle of the gap between the largest legitimate value and the
smallest true-positive value), so that the *definitions* are pre-committed and only the
*numbers* are measured.

Window convention, fixed now: let the accepted states be `y_0 … y_n`. `TAIL` is the last 25 % of
steps, `PRE` is the 25 % immediately before it. Per block `j ∈ {b, mu}`, `v_j(i)` is
`max_k |b_k(i)|` or `|mu(i)|`, and `s_j` is that block's initial scale as `integrate` defines it.

* **C1 `TAIL_GROWTH_RATIO`** — a windowed growth-rate estimate in ratio form.
  `C1 = max_j ( max_TAIL v_j / max_PRE v_j )`. Flag if `C1 > T1`.
  Rationale: a trajectory with a limit has `C1 → 1`; unbounded growth keeps `C1 > 1` forever,
  *however slowly it grows* — which is exactly what `state_growth`'s magnitude bound cannot see
  on `mu_linear`.
* **C2 `TAIL_DRIFT_OVER_INITIAL_SCALE`** — the residual-to-state-scale ratio.
  `C2 = max_j ( max_TAIL |v_j(i+1) − v_j(i)| / dt ) / s_j`. Flag if `C2 > T2`.
  Rationale: the right-hand side is the residual the flow is still generating at the end of the
  run; a converged trajectory's is at roundoff *relative to where it started*. This is the one
  criterion in the family that should see `osc_sustained` (drift `~2π` forever at amplitude 1).
* **C3 `MONOTONE_TAIL_FRACTION`** — a monotone-tail detector.
  `C3 = max_j (#{i ∈ TAIL : v_j(i+1) > v_j(i)} / |TAIL|)`. Flag if `C3 > T3`.
  Rationale: the cleanest possible statement of "still going up at the end", blind to magnitude.
* **C4 `TAIL_RANGE_OVER_INITIAL_SCALE`** — a non-decay detector for the oscillatory pair.
  `C4 = max_j ( max_TAIL v_j − min_TAIL v_j ) / s_j`. Flag if `C4 > T4`.
  Rationale: `osc_sustained` has no limit and no growth; what it has is a tail *range* that
  never shrinks. This is the "tail test" commit `8572465` asserted was needed.
* **C5 `TAIL_EFOLD_RATE`** — the windowed growth rate as a *rate*, not a ratio.
  `C5 = max_j log(max_TAIL v_j / max_PRE v_j) / (tau_TAIL − tau_PRE)`. Flag if `C5 > T5`.
  Rationale: C1 conflates "grows fast" with "runs long". C5 separates them, and is included
  specifically so the leg can report *which* of the two the residual actually turns on.

**The falsifiable prediction, recorded before measurement.** The module's own well-behaved
battery contains `test_6` at `p = 5`: monotone, exponential, growth `4.06e2` in `tau = 3`. On
C1/C3/C5 that legitimate trajectory should score **at or above** `mu_linear` (which grows
`2.01e2` over `tau = 60`, i.e. *slower per unit tau*), so those three criteria are predicted to
have **overlapping** populations — a false positive on `test_6` at any threshold that reaches
`mu_linear`. C2 and C4 are the two that can separate the oscillatory pair, and they are
predicted to be the ones that fail in the *other* direction, on `damped_oscillation` /
`test_6`. **If any single criterion clears all five open cases with zero false positives, this
prediction is falsified and the gate answers YES.** That is the point of writing it down.

## 4. External literature queried (verbatim, with links)

**Q1.** `numerical ODE integrator detecting divergent solutions blow-up criterion state growth monitor`
* [Numerical validation of blow-up solutions of ODEs (ScienceDirect)](https://www.sciencedirect.com/science/article/pii/S0377042716305027)
* [Numerical validation of blow-up solutions with quasi-homogeneous compactifications (arXiv:1707.05936)](https://arxiv.org/pdf/1707.05936)
* [same, Numerische Mathematik](https://link.springer.com/article/10.1007/s00211-020-01125-z)
* [Nonlinear problems with blow-up solutions: numerical integration based on differential and nonlocal transformations (ScienceDirect)](https://www.sciencedirect.com/science/article/abs/pii/S0096300318303977)

  **Reading.** The rigorous literature does not build a *detector* at all: it changes
  coordinates (compactification) so the divergent object becomes a finite equilibrium, then
  applies a Lyapunov function *around the equilibrium at infinity*. That is a construction on
  the vector field, not a predicate on a trajectory — it is not available to a validity clause
  inside a general-purpose `integrate`, and it presupposes knowing the divergent direction. This
  **confirms rather than pre-empts** the leg's framing: the criteria in §3 are engineering
  guards, and none of them is claimed as a mathematical blow-up criterion.

**Q2.** `SUNDIALS CVODE "too much work" solver diagnostics detect solution growing unbounded stopping criterion monitor`
* [SUNDIALS CVODE mathematical considerations](https://sundials.readthedocs.io/en/latest/cvodes/Mathematics_link.html)
* [CVODE usage documentation](https://sundials.readthedocs.io/en/latest/cvode/Usage/index.html)
* [sundials/src/cvode/cvode.c](https://github.com/LLNL/sundials/blob/main/src/cvode/cvode.c)

  **Reading.** CVODE's failure returns are all *solver* observables (convergence failure, error
  test failure, too-much-work, too-much-accuracy-requested); the state-side facility is a
  user-supplied **monitor function** called after successful steps — i.e. the production answer
  to "watch the state" is *"write the predicate yourself"*. This is the same separation leg 83
  recorded, and it means there is no off-the-shelf named criterion this leg is duplicating.

**Q3.** `steady state detection ODE simulation "monotone tail" OR "windowed growth rate" OR "residual to state ratio" convergence to equilibrium criterion`
* [Steady state detection for computational fluid dynamics (arXiv:1709.03158)](https://arxiv.org/pdf/1709.03158)
* [A steady-state detection (SSD) algorithm to detect non-stationary drifts in processes](https://www.researchgate.net/publication/255568863_A_steady-state_detection_SSD_algorithm_to_detect_non-stationary_drifts_in_processes)
* [The F-t-Pj-RG method: an adjacent-rolling-windows based steady-state detector (OSTI)](https://www.osti.gov/servlets/purl/1495967)
* [Abaqus steady-state detection](https://abaqus-docs.mit.edu/2017/English/SIMACAEANLRefMap/simaanl-c-steadystatedetection.htm)

  **Reading.** This is the closest external prior art and it is a real one: *adjacent rolling
  windows* with a local-trend test is precisely C1/C5's shape, and the SSD literature's own
  standing caveat — **"there does not exist a universal rule for the length of this window"** —
  is a warning this leg must answer rather than ignore. Consequence recorded before measurement:
  the 25 %/25 % window convention in §3 is **swept**, not asserted, and the sweep is reported.
  Note the direction of use is inverted here (that literature detects *arrival* at steady state;
  this leg detects *failure to arrive*), so the thresholds do not transfer.

**Novelty verdict.** The criteria in §3 are **standard instruments** — rolling-window trend
tests and a drift-to-scale ratio — deliberately so. **Nothing in this leg is claimed as novel
mathematics.** What is novel to this repository is only the *measurement*: whether any of them
separates this module's divergent residual from this module's own legitimate trajectories.
Presume the instruments known; the number is the finding.
