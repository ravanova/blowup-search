## 1. What the object is, and where the hazards live

The first integral (FI') is `Omega(X) = -(E(X)/c)^{1/a}`, `E = c + a U`. The module's whole
structural story turns on **`E` changing sign at `X_c`**: for `X > X_c`, `E < 0`, `E^{1/a}` is
not real, and the true profile is *identically zero* — the module's own docstring, lines
29-33: *"beyond it `E < 0` and `E^{1/a}` is not real, so `Omega == 0`"*. That is not a
convention; it is the sentence that makes the profile compactly supported, and it is the
sentence the code has to honour numerically.

Three places in the implementation are where honouring it could go wrong, and they are the
three the battery targets:

| # | site | the shortcut |
|---|---|---|
| H1 | `omega_of` (line 229), `residual`/`jacobian`/`mass`/`outer_velocity`/`operator_norm` | the profile is formed as `-np.abs(e) ** self.p` — **`abs`**, five call sites. `abs` is what keeps the fractional power real; it also means a *negative* `e` (i.e. past the turning point) produces a real, finite, smooth-looking number instead of zero or a NaN. |
| H2 | `even_cheb` (line 160) | `np.arccos(np.clip(v, -1.0, 1.0))` — an evaluation point outside `[-1, 1]` is silently **clipped** to the edge, while the prefactor `(1 - v^2)` in `e_of` uses the *unclipped* `v`. The two halves of `e(v)` then disagree about which point they are at. |
| H3 | `first_integral_defect` (line 382) | `mask = (np.abs(Omega) > 1e-11) & (E > 1e-8)` — every comparison against NaN is false (IEEE-754 §5.11), so a NaN-poisoned sample point is **silently excluded from the mask** rather than propagated. The function's whole job is to answer "does the identity hold on this sample". |

Two more input axes are in scope because the gate names them: degenerate `a` (the guard at
line 200 is `if not 0.0 < float(a)`, whose behaviour on `nan`/`inf` is asserted by nobody),
and poisoned `(b, Xc)` state fed to `solve`, `mass`, `edge_amplitude`, `outer_velocity`,
`predicted_radius`, `operator_norm`.

`experiments/journal/leg_107.md`, every case in

**The finding in one sentence.** `omega_of` forms the profile as `-np.abs(e) ** self.p`, and
that `abs` erases the branch cut that is the entire reason the profile has compact support —
so past the free boundary the module returns the *mirror image of its own interior*, finite,
smooth, in range, and indistinguishable from a legitimate value by anything short of checking
`v` yourself.

**The scope boundary, which is the second result.** The *solver* is sound: `solve`'s line
search refuses `e <= 0`, and the residual on such a state is 4.5e14x the clean one. Where the
equation is **enforced** the `abs` cannot hide; the gap is confined to the **evaluation**
entry points, where nothing checks anything. That is why this is escalated as a latent trap
rather than as a contaminated result — and why the recommended repair (journal, §"Recommended
repair") is three lines in three functions, none of them in the Newton path.

**What was NOT claimed, as pre-committed above:** nothing about Route-D v14's correctness or
sharpness, no new `X_c`/exponent/amplitude/`U_0`/`||A||`, nothing about `a*`, and no patch.

## B2. Is the repair itself novel? No — and the template is in-repo

The bug class is the one already fixed once this session, in the same session's
`bench/fix-target-norm-domain-guard` (merged as `04f1407`): **silent domain
extrapolation** — a module continuing to return finite, plausible numbers for arguments
outside the window where its own answer is defined, with nothing in the return value
recording it. The repair shape adopted there is the template adopted here:

| element | `target_norm.py` (merged) | `first_integral.py` (this branch) |
|---|---|---|
| a named warning class | `TargetNormDomainWarning(UserWarning)` | `FirstIntegralGuardWarning(UserWarning)` + two subclasses |
| threshold | dynamic (`n_outside_grid > 0` against the caller's own `max|X|`), never a hardcoded constant | dynamic (`|v| > 1 + 4 eps`), and `1` is not a magic number — it is the *definition* of the scaled support, `v = X / X_c` |
| propagation | `domain_fields()` in every returned dict, in EVERY branch | `support_fields()` / `sample_fields()`, via an opt-in `detail=` on the two evaluation entry points |
| warning, not exception, by default | the module's own far-field ablations are MEANT to run outside the window | leg 107's own characterization battery is MEANT to evaluate outside the support, and an unconditional raise would make the audit that measures the guard unrunnable |
| strict mode available | `simplefilter("error", TargetNormDomainWarning)` | the same, plus an explicit `on_outside="raise"` argument |
| in-window numbers | bit-identical | bit-identical, and proved by an A/B against the pre-repair module loaded from git |

**Where the two differ, and it is not cosmetic.** In `target_norm.py` the out-of-window
answer is *unknowable* — the closure invents it, so the guard can only flag. Here the
out-of-support answer is **known exactly and is zero**, by the module's own docstring
(lines 29-33) and by `solver/turning_point.py`'s outer asymptotics. So this repair can do
something the template could not: **return the true value** (`0.0`) *and* flag, rather than
only flagging. That is why the default is `on_outside="zero"` and not `"nan"` — NaN would
be a rejection of a question the module can actually answer.
