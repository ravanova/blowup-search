## 2. Arbitrary-precision arithmetic: **IT ALREADY EXISTS. NOTHING IS BUILT.**

The grep the ban demands, performed and recorded:

```
grep -n "Interval" solver/*.py   →  solver/interval.py, solver/interval_mp.py,
                                    solver/interval_certificate.py, solver/nk_fourier.py,
                                    solver/dssp_decay_enclosure.py
.venv/bin/python capabilities.py interval   →  10 of 57 entries
.venv/bin/python capabilities.py mp         →  27 of 57 entries
```

Two substrates exist and **this leg writes neither**:

* **`solver/interval.py`** — hand-rolled outward-rounded float64 intervals, `Interval`,
  `ilog`, `_down`/`_up`, "no scipy, no mpmath". This is what leg 382's enclosure runs on
  and it is the reason the blind spot has a floor at all.
* **`solver/interval_mp.py`** (Route-APIA, leg 312) — **rigorous arbitrary-precision
  directed-rounded interval arithmetic backed by `decimal.Decimal`**: `MPInterval`,
  `mp_add/sub/mul/div`, `mp_isum`, `mp_dot`, and `_floor_ctx`/`_ceil_ctx` built on
  `ROUND_FLOOR`/`ROUND_CEILING`. Its own docstring declares Section 1 to be "genuine
  rigorous directed-rounded interval arithmetic" and Section 2 to be "HIGH-PRECISION, NOT
  RIGOROUS" — a distinction this leg respects: **only Section 1 primitives are used.**

**Had this pass not been run I would have written a `Decimal` interval layer that already
exists, which is precisely the failure the standing ban was written for (leg 45 nearly
rebuilt `RescaledHLScenario2`).** The ban is respected by *importing* `MPInterval` and
`mp_div`, not by re-deriving them.

What `interval_mp.py` does **not** have, checked function by function: **no logarithm**
(`dsin`, `dcos`, `dtan_ratio`, `mp_pi`, `_atan_small` only). The pre-registration's design
response — planting the curvature *additively in the log-log plane*, so the certified
object is a polynomial in `t = log r` and no logarithm is ever needed at high precision —
is a consequence of this grep, not a stylistic choice, and it is recorded here so it
cannot later be read as convenience.

Also **not** present anywhere: a `t`-space (log-coordinate) entry point to the
Fourier–Motzkin elimination. `certified_decay_from_cell_enclosures` takes radii and
magnitudes and takes logarithms *internally in float64*, which makes it structurally
unable to carry a high-precision arm. That single routine is re-expressed in `t`-space in
this leg's own `experiments/` file — the minimum that cannot be reused — and its float
backend is cross-validated against the landed instrument on the shared rungs (a
pre-registered agreement control). `solver/` is READ-ONLY on this branch.

## 5. What this pass changed in the plan, before any number existed

Four commitments follow from §§1–4 and are carried into the pre-registration verbatim:

1. **Import, never build.** `MPInterval`/`mp_div` from `solver/interval_mp.py`;
   `Interval`/`_down`/`_up` from `solver/interval.py`. New arithmetic written: **none**.
2. **Every width, half-width and threshold names its window** (leg 386): `0.8686` is
   `4/log 100`, a property of `[10,1000]`, and doubles on `[10,100]`. No bare constant is
   quoted in this leg's prose or JSON.
3. **The grid is varied, including a jittered non-geometric grid** (leg 385): a threshold
   measured on one fixed `N` cannot distinguish a precision floor from a commensurability
   artefact, and that is the most likely way this leg's bracket could be wrong.
4. **The ladder steps exactly one decade and the code asserts it** (leg 384): the
   bracket's separation is *computed from the κ values actually run*, never assumed from
   the ladder's nominal design.
