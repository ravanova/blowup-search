## 2. What is therefore NOT this leg's claim

Stated up front so the finding cannot be inflated:

1. **That the `converged` flag degenerates to an absolute `1e-6` RMS test is NOT new.** The
   algebra is written out in `test_profile_newton.py`'s own docstring, and leg 71 banked an
   instance of `converged=True` on a stall. This leg may **quantify** it and may pin it in a
   regression test, but it may not present it as a discovery.
2. **That the `a = 0.9` stall is host-dependent is NOT new** (2.31 decades, bench leg).
3. **That `Ω ≡ −1` is a spurious root of a one-gauge Newton is NOT new** (leg 114 M2). What
   is untested is whether *this* module's two gauges close it, as leg 114 predicts.

What no pass has ever asked is the input-contract question at the centre of this gate:
**does the module ever hand back a converged=True together with a materially wrong `c` or
`Ω`, under inputs a caller could plausibly supply?** Every existing gate on this file asserts
on well-posed input; the one flag-semantics note in the repo is about a *single* `a = 0.9`
ladder row's reproducibility across BLAS backends, not about what the flag guarantees.

## 3. The frozen probe list

Six groups. Each probe names, in advance, what would count as a failure. Verdict taxonomy is
leg 114's, deliberately, so the two audits of the two sibling Newton modules are comparable:
`SILENT_WRONG` · `SILENT_DEGRADED` · `NONFINITE` · `RAISED` · `CLEAN`.

**G1 — flag semantics under DEFAULT parameters.** Cold `solve()` at a ladder of `a`, no
arguments touched. Failure iff `converged is True` while the solve exhausted `max_iter`
without meeting `tol`, *and* the returned `relres` sits materially above the floor the same
equation reaches via `continuation` at the same `n`. Magnitude reported in decades, plus the
induced error in `c`.

**G2 — gauge blindness.** `converged` is computed from the residual history `hist` alone and
never consults the two gauge rows `F[n]`, `F[n+1]`. `R2` has an exact scaling degeneracy
(`Ω → λΩ` with `c → λc`), so the gauges are the *only* thing pinning which member of the
family is returned. Probe: λ-scaled warm starts with finite iteration budgets. Failure iff
`converged is True` with a gauge violated by O(1) and `c` wrong by O(1). **Also frozen:
whether `relres` can detect it** — `relres` is a ratio of two quantities that both scale as
λ², so it is predicted to be exactly λ-invariant and therefore blind too.

**G3 — spurious roots / poor initial guess.** Starts `Ω ≡ −1` (leg 114's M2 vector),
`Ω ≡ 0`, `1e-8 × anchor`, sign-flipped anchor, and a random start. Failure iff any is
returned with `converged is True` and a profile that is not the gauged solution.

**G4 — poisoned input.** NaN and Inf in `om0`; `c0` NaN/Inf; non-finite `a`; wrong-length
`om0`. Failure iff any is absorbed into a finite-looking converged answer instead of being
rejected or raising.

**G5 — degenerate parameters.** `max_iter = 0`, `damping = False`, absurd `tol`, tiny `n`,
tiny and huge `rho_max`. `max_iter = 0` is the sharpest structural probe: the flag is
computed from `hist[0]`, which is the residual of the **caller's own input**, so a
zero-iteration call can return `converged = True` having done no work at all.

**G6 — the API contract of the failure path.** The `LinAlgError` branch returns
`{"converged": False, "reason": ..., "Omega":, "c":, "history":}` — **without** the
`residual_rms` and `relres` keys every other return path carries. `continuation` reads
`r["relres"]` unconditionally at line 182. Failure iff that is a live `KeyError` rather than
a handled rejection. This is a *loud* failure, not a silent one, so it cannot by itself
answer the gate YES; it is banked as a robustness note either way.

**Controls (must stay clean, or the battery is measuring itself).** C1: the exact `a = 0`
anchor at `λ = 1` must still be reported converged. C2: the `a = 0.3` continuation row must
still reach the Newton floor. C3: the Jacobian must still match finite differences — if it
does not, every other verdict is about the derivative, not about the guards.
