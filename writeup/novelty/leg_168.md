must be measured, not asserted** — and this leg should measure where the boundary actually is
rather than trusting the `≈ 1` estimate, since `offset=True` shifts every node by half a cell.

## Q2 — Is leg 152's chosen G8 predicate the same one leg 117 prescribed, and does the
difference matter?

**It is not the same predicate.** Leg 117's prescription (`experiments/journal/leg_117.md`
line 126) is
`np.where(np.isfinite(X) & (X > 0.0), field, np.where(np.isfinite(X), 0.0, np.nan))` — an
**`isfinite`** predicate. Leg 152 shipped `np.isnan(X)` (`solver/hl_rescaled.py:339`) — an
**`isnan`** predicate. These are not the same function: they differ exactly on `±inf`.

NumPy documents the distinction directly — [`numpy.isfinite`](https://numpy.org/doc/stable/reference/generated/numpy.isfinite.html)
tests "not infinity and not Not a Number", while [`numpy.isinf`](https://numpy.org/doc/stable/reference/generated/numpy.isinf.html)
and `isnan` split that rejection in two. `isfinite` is the strictly wider guard.

This is precisely the shape the security-engineering literature calls an **incomplete fix**:
[PentesterLab, "CVE in Your CVE: When the Patch Doesn't Fix the Vulnerability"](https://pentesterlab.com/blog/when-the-patch-doesnt-fix-the-vulnerability)
describes the mechanism as a narrow report producing a narrow patch — the reported manifestation
is blocked while the root cause survives — and MITRE's CWE programme frames the same thing as
patching a manifestation instead of the weakness pattern
([Help Net Security, Apr 2026](https://www.helpnetsecurity.com/2026/04/07/alec-summers-mitre-cwe-vulnerability-mapping/)).
Leg 117 measured G8 **with a NaN**, so leg 152 guarded **against NaN**.

**Pre-registered, before running anything:** this leg will feed `-inf` and `+inf` abscissas to
`degenerate_ic` for all three kinds and record what comes out. **It will not assume the answer
is a finding.** There is a real defence available to leg 152's choice, and it must be weighed
honestly rather than argued away: `-inf` is a *known* location that genuinely satisfies `X <= 0`,
so returning `0.0` there is arguably correct under the module's own one-sided-support convention,
whereas a NaN abscissa has no location at all and `0.0` is a fabrication. If that defence holds,
the correct report is "narrower predicate than prescribed, defensibly so, recorded" — **not** a
gate-flipping incomplete fix. The distinguishing question is whether the `±inf` output is
*indistinguishable from legitimate physics* (leg 117's own G8 criterion) or merely *unguarded*.

## Q3 — Is "measure the distance from every shipped configuration to a newly added guard's
activation boundary" a named practice with prior art to inherit?

**No located name, and no novelty claimed either way.** The standard vocabulary
([BrowserStack](https://www.browserstack.com/guide/regression-testing),
[Harness](https://www.harness.io/blog/regression-testing-in-ci-cd-deliver-faster-without-the-fear))
splits post-fix work into *retesting* (does the fix fix it) and *regression testing* (did
anything else break), with *impact analysis* as the scoping step. What this leg does is a
quantitative impact analysis — the boundary is a number, so the distance to it is a number — but
it is an obvious engineering measurement, not a methodological contribution, and it is recorded
here only so the leg does not later mistake it for one. In-repo, `grep` for
`guard_margin|activation threshold|distance to the guard` across every `.py` and `.md` hits
exactly one file (`test_viscous_novelty_adversarial.py`) and not in this sense. **0 prior
in-repo instances.**

## Q4 — Is the IEEE-754 / `np.interp` material behind these mechanisms novel?

**No, and it was already not novel two legs ago.** Leg 117's own novelty pass
(`writeup/novelty/leg_117.md`) recorded the unordered-NaN-comparison hazard as the **fourth**
in-repo instance of a standard-level hazard (legs 100/106/116), and `np.interp`'s

any of it.** The method — git-loading the pre-repair module into the same process for a bitwise
A/B — is inherited verbatim from legs 129/130/152 and is likewise not claimed.
