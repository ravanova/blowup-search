# Leg 386 novelty pass — Route-DTOL: a *pre-registered* relative-tolerance mode for the certified decay enclosure

**Committed BEFORE any construction** (ORCHESTRATION.md §5a). This file is the pass; the
pre-registration, the module change, the test additions, the runner, the JSON, the figure and
the BLOG/TECHNICAL pair land in later commits on the same branch.

**Disclosure up front, so nothing below is read as more than it is.** This leg claims **no
novel mathematics whatsoever**, and less novelty than its predecessor even claimed. Leg 382
already wrote the tolerance parameter into `solver/dssp_decay_enclosure.py`
(`rel_tolerance`, plus `critical_tolerance`), explicitly labelled **POST-HOC and NOT
GATE-DECIDING**. This leg's contribution is **procedural, not mathematical**: pre-register the
mode's predicted behaviour, measure it *fresh* rather than inheriting leg 382's post-hoc
numbers, make δ an explicit and always-recorded interface field, and — the part that is a real
open question rather than bookkeeping — decide whether the composed condition on δ imposed by
`CLAY_OBLIGATIONS.md` §4's admissible-cutoff analysis can be satisfied at all.

The relaxation itself (a multiplicative tube `f/(1+δ) ≤ C r^{-p} ≤ f(1+δ)`, eliminated by
Fourier–Motzkin) is elementary two-variable linear programming. Presenting it as new would be
dishonest.
