## 3. Prior art for the failure modes (all documented; no mathematical novelty claimed)

- **Unguarded division by a user-supplied exponent** (`/gamma` at line 150,
  `(1.0 - g) ** (g - 1.0) * g ** (-g)` at line 170, `(1.0 - g)` in the denominator at line
  183) — IEEE-754 division/`ZeroDivisionError` semantics; nothing novel.
- **A fixed-point iteration whose non-convergence is reported by a magnitude cap**
  (`T_cap=1e7`, `max_iter=20000`, lines 209/237/242) — the classical hazard is the silent
  `max_iter` exhaustion path: this loop `break`s only on the tolerance test, so falling off
  the end of the `for` returns the last iterate **with `"closes": True`** and no iteration
  count in the returned dict. Standard iterative-solver anti-pattern (no convergence flag
  returned); named in the literature, not novel here.
- **A `sup` taken over a truncated log grid** (`hilbert_split_curves`, `X_lo=1e-3`,
  `X_hi=1e6`, `n_X=120`, consumed by `derivative_bound`'s `np.max`) — *"a sup sampled on a
  truncated grid is not an upper bound"* is the founding premise of interval
  branch-and-bound, and is the same clause leg 116 pre-registered for `nk_bounds.py`
  (`7ab1e37`). This module inherits it directly: `derivative_bound` feeds `seminorm_closure`
  feeds `operator_norm_upper`, the certificate-feeding quantity.
- **NaN absorption through `np.max` / comparison chains** — the `abs(nxt - T) <= tol` test and
  the `nxt > T_cap` test are both **False** for `nxt = NaN`, so a NaN iterate neither
  converges nor trips the cap; it runs `max_iter` and returns `closes: True` with
  `T_upper: NaN`. Same class as leg 107's NaN census on `first_integral.py` (`9c08287`).
