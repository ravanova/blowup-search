**On-topic finding for (N1) — DECISIVE, and it is the standard statement, not a novelty.**
An **additive term is required to cover underflow** in the error bound for a floating-point dot
product; the purely relative bound `γ_m Σ|x_j y_j|` is stated for the normal range and says
nothing once the individual products go subnormal. Rump's restatement carries the explicit `η`
term, and his statements are asserted to hold **in the presence of underflow** precisely because
that term is there. Consequently: a routine in this repository that adds `γ_m Σ|·|` and **no
`η` term** is not "slightly loose" — it is missing a term a 2012 paper says it must have, and
this repository *already knows that*, because leg 69 added exactly that term to `interval.py`
with this exact citation. Anything found here is a **conformance gap against a result already
banked in this repo**, never a new hazard.

  surveys; listed, not load-bearing.

**On-topic finding for (N2) — the phenomenon is named and studied, so nothing about it is a
discovery.** The literature's own phrasing is that when a bug is fixed in duplicated code it is
necessary to modify all clones, that in practice **fixes are often incomplete**, and that the
**inconsistent bug fix** is the particularly dangerous class of change to cloned code. So if
this leg finds a repaired routine whose clone was not repaired, the correct report is *"an
instance of a documented maintenance failure mode"* — with a **magnitude** attached — and never
*"a new defect class"*. It also tells me the right control to run: **the repaired original on
byte-identical input**, so the difference is attributable to the clone and not to the data
(standing discipline 90 — a control that cannot come out differently is not a control).
