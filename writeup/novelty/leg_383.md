The dispatch thesis (leg 359's flag at `a048de7`: leg 357's B7 screen tests only L³
convergence, missing Tsai Theorem 2's local-energy route and any SS/DSS ansatz check)
was **partially discharged after the flag was written**. `git log -- solver/dssp_screen.py`:

| commit | leg | what it added |
|---|---|---|

| `ec48622` | 362 | `decays_to_zero_at_infinity()`, `classify_ss_ansatz()`, `_ledger_nrs_tsai_three_way()` — the T2 route and the SS/DSS ansatz classifier, as **opt-in** arguments |

| `9a3dd41` | 370 | `morrey_ball_average_sweep()`, `ledger_morrey()` — Jiu-Wang-Wei Thm 1.2, also **opt-in** |

So the two routes named in the thesis exist as *functions*. **This leg does not rewrite
them and does not re-derive Tsai 1998.** Duplicating leg 362/370's mathematics would be
the failure mode this section exists to prevent.

**The gap that is still open, and is this leg's construction.** Both extensions were
landed as strictly opt-in parameters, defaulting to `None`, explicitly so that existing
call sites' return-dict key sets were unchanged. The per-candidate **report path** was
never rewired. As it stands on `104f5b3`, `solver/dssp_screen.py:1005`:

```python
    decay = fitted_far_field_decay_exponent(field_fn)      # computed ...
    ...
    ledger = machine_read_ledger(l3, lam)                  # ... then dropped
```

`screen_candidate()` — the single end-to-end entry point through which a candidate
report is produced — computes the far-field decay exponent, then calls
`machine_read_ledger()` with two positional arguments only. It never computes the
ansatz classification at all. The consequence is exactly leg 359's flagged
mis-classification, still live in the report path: a genuinely self-similar candidate
at this repo's measured decay rate (≈ −1, log-divergent L³) is reported by
`screen_candidate()` as **NOT EXCLUDED**, via leg 357's backward-compatible L³-only
branch, even though the machinery to read it as EXCLUDED-BY-T2 is sitting unused in the
same module. `grep -rn "screen_candidate"` shows no call site anywhere in the repo
passing the new arguments; `grep -rn "machine_read_ledger("` shows every caller using
the two-argument form.

The gate's yes-branch — "every future candidate report carries the two new columns" — is
therefore a statement about `screen_candidate()`, and it is currently FALSE. Closing it
is this leg's construction: the two columns become **unconditional** in the report path,
`machine_read_ledger()`'s own defaults are left untouched (so leg 370's and 362's
backward-compatibility guarantees are not broken), and a new adversarial test file
`test_dssp_screen_t2.py` carries planted controls that can fail in both directions —
which the existing `test_dssp_screen.py` battery does not have (legs 362/370's controls
are all fire-direction: a planted case that *should* be excluded and is).

## 4. Pre-registered planted controls — the deciding clauses, fixed in advance

Six controls. **Three must fire, three must stay silent.** An instrument that can only
fire is a tautology (leg 340's burn), so half of this battery exists purely to make the
screen *fail to exclude*.

### Direction A — the screen MUST fire (catches what it should catch)

**C1 — Tsai's headline example (the gate's clause (i)).** Planted static exact-SS field
`U(y) = A(y/|y|)/|y|` with a non-trivial angular profile A, no trajectory supplied.
*Required*: L³ ladder log-DIVERGENT (so T1 is NOT reached), fitted decay exponent within
0.05 of −1, `screen_candidate()`'s NRS_Tsai verdict = **EXCLUDED-BY-T2**, deciding clause
recorded as Theorem 2's finishing hypothesis "U → 0 at infinity" (Tsai 1998, p.49).
*Fails if*: the report reads NOT EXCLUDED (the pre-leg behaviour), or cites an L³ clause.

**C2 — this programme's DSS object (the gate's clause (ii)).** Leg 351's `field_uB`
Type-I Biot-Savart witness together with a genuinely periodic trajectory at λ > 1
(leg 357's own landed period detector). *Required*: verdict = **NOT-REACHED-BY-ANSATZ**,
with the deciding clause recorded as the **exact-SS ansatz hypothesis, Tsai 1998
eq (1.2)_1** — not any decay or L³ clause. *Fails if*: the verdict is EXCLUDED-BY-T1 or
EXCLUDED-BY-T2, or if the deciding clause names decay/integrability.

**C3 — T1/T2 discrimination.** Planted static exact-SS field decaying at exponent ≈ −2,
so the L³ ladder genuinely CONVERGES. *Required*: verdict = **EXCLUDED-BY-T1** (the
stronger, integrability route), not T2 — the two columns must be distinguishable, not
one flag wearing two names. *Fails if*: T1 and T2 cannot be told apart on this field.

### Direction B — the screen MUST NOT fire (refuses to over-claim)

**C4 — non-decaying exact-SS field.** Planted static field whose magnitude does NOT go
to zero at infinity (bounded away from 0 along the sampled ray, exponent ≈ 0).
*Required*: T2's finishing hypothesis is NOT confirmed, verdict = **NOT EXCLUDED**.
*Fails if*: the T2 column excludes it — which would prove the column excludes everything
and measures nothing.

**C5 — the ansatz clause is not a catch-all.** The C1 field again, viewed through the
ansatz column alone: a static, non-periodic exact-SS candidate. *Required*: ansatz =
**EXACT-SS**, `satisfies_theorem_ansatz = True`, i.e. the candidate is NOT deflected to
NOT-REACHED-BY-ANSATZ. *Fails if*: the ansatz clause fires on a non-DSS candidate, which
would make clause (ii)'s NOT-REACHED verdict in C2 vacuous.

**C6 — growing field, both columns silent.** Planted static field growing like |y|^{+1}.
*Required*: L³ divergent (T1 not reached) AND T2 not reached AND ansatz EXACT-SS, so the
whole NRS/Tsai row reads NOT EXCLUDED with no clause claimed. *Fails if*: any column
fires on a field no theorem in the ledger touches.

### Regression control (not part of the six; a guard on the territory)

**R — no collateral shape change.** `machine_read_ledger()` called with its original two
positional arguments must still return leg 357's exact key set (no `Morrey` key, the
backward-compatible `ledger_nrs_tsai()` branch), and legs 357/362/370's banked JSON files
must be byte-identical (sha256) before and after this leg. The *only* verdict shape that
changes is `screen_candidate()`'s own — which is the gate's yes-branch consequence, not a
side effect.
