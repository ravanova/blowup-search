# Leg 272 — Route-WESCV novelty pass

**Date:** 2026-08-07. **Agent:** LEG-A. **Branch:** `leg/272-wescv-v1`.
**Verdict: `NO MATHEMATICAL CLAIM IS AVAILABLE TO THIS LEG.`**

## What kind of leg this is

A **verification leg**, read-only on everything leg 263 touched. It computes nothing, imports
no `solver/` module, derives no constant, and produces no figure ("no measurement, no figure").
Its only writes are its own four territory files. Every magnitude it reports is either a **count
over committed blobs** or a **re-run of an instrument**; not one number is re-derived, and the
mathematics of the underlying correction is leg 178's, unchanged and untouched here.

**New to the world: nothing. New to this repository: one thing, and it is methodological** — a
named, reproducible account of *how* a phrase census in this repository fails, with the
magnitude of the failure measured rather than asserted. That is the product.

## The one thing that could go wrong, named before any check ran

The obvious failure mode of a verification leg is **agreeing by construction**: re-running the
audited leg's own instrument, getting the audited leg's own number, and calling that
independent. Leg 263's gate clause (a) is *"is EVERY occurrence pinned"* — a universal — and a
universal cannot be confirmed by the instrument that generated it.

So the method is pre-committed as **three instruments, deliberately non-overlapping**:

1. **I1 — a wrap-immune whole-file scan.** Leg 263 recorded, as one of its own two instrument
   failures, that a line-oriented grep cannot see the phrase where this repository's 100-column
   hard wrap splits it. It recorded the hazard and did not build an instrument immune to it.
   This leg does: each file is read entire, whitespace collapsed to single spaces, matched on
   that stream, offsets mapped back to original line numbers. A wrap is structurally invisible.
2. **I2 — reproduce leg 263's own instrument against its own published counts.** A census that
   cannot be reproduced is not a census. This is the check with real discriminating power,
   because it can *fail*.
3. **I3 — hand-read** every edited site, every correction block, and every `CORRECTIONS.md`
   entry against its source leg at full context. Clauses (b) and (d) are not regex-decidable
   and are not faked: the runner checks only that each cited magnitude is *present* in the
   cited source; the pinning judgements are written out in the journal with the instrument
   that decided each.

## Pre-registered predictions, recorded before the checks were classified

1. **Clause (c) holds.** Leg 263 states `plan_of_record.py` was never opened for writing, and
   that is the kind of claim git settles absolutely. *Prediction: byte-identical.*
2. **Clause (b) holds.** Leg 263 published a per-site pinning argument for each of the 8, two
   of them resting on *local enumeration* — the strongest instrument, independent of the ruling
   — so a mis-pin would require leg 141 or leg 165 to misquote its own body.
   *Prediction: 8/8 journal-triple, 0 mis-pins.*
3. **Clause (a) is where a defect will be, if there is one.** A universal quantifier over a
   134-occurrence hand census, run with two hand-written regexes, in a repository whose prose
   is hard-wrapped — that is the clause with the surface area.
   *Prediction: the census under-counts, and the miss is in a form the patterns cannot express
   rather than in a site the author overlooked.*

**All three held.** Prediction 3's second half is the substantive one and it held in a stronger
form than predicted: **two** distinct expressible-form failures, not one, and both structural.

## This leg's own instrument failure, recorded rather than smoothed

The first draft of this verifier's lexicon wrote `realis?a?tions?`, intending to cover both
spellings. It cannot match `realizations` at all — the `z` is not an optional `s` — so the
pattern that carried the whole clause-(a) check returned **0 hits** on its first run, and the
run *looked* clean. It was caught only because instrument I2 returned a number that could be
compared against a published one.

That is the same class of failure leg 263 recorded two of, it fired on the very first execution
of the leg auditing them, and it is the reason clause (a) is not decided by I1 alone. A phrase
audit in this repository should be assumed to have a broken pattern until some *independent*
count says otherwise.
