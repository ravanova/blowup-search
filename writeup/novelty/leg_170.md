## 3. THE TWO FAILURE SHAPES LEG 147 AND LEG 131 FOUND — DECLARED AS THIS LEG'S TARGETS, BEFORE MEASURING

**Shape (i) — an aggregate count hides a non-uniform case.** Leg 147: 17 of 21 false-closing
certificates rejected, and `capabilities.py` recorded exactly that. What the count hid was that
the surviving 4 are *not alike* — 3 return `closes=True` with `degenerate_ball=True` and an
explicit reason, while `P06_Z2_shrunk_1e-6` returns a positive-radius ball with
`degenerate_ball=False`, `reason=None`, `violations=None`: no signal of any kind.
**Applied here:** leg 154's clause (a) is banked as `15/15 refused (was 0/15)`
([`writeup/data/p2_route_cdr_v1_repair.json`](../data/p2_route_cdr_v1_repair.json),
`A_clause_a_refusals`). This leg does not accept the aggregate. Every refusal is re-measured
*per case and per entry point*, recording the **exception class** (is it the new
`CriticalDissipationDomainError`, or the pre-existing `p < 1` `ValueError` that would have
refused anyway?), whether it is still a `ValueError` for leg 121's own `except ValueError`
control, and whether the message names the requested exponent against the one that would have
been built. A case refused by the *old* check is not evidence for the *new* guard.

**Shape (ii) — the repair lands a guard the finding leg's own battery cannot run past.** Leg
147: leg 116's battery *aborts in 0.9 s* against the repaired module, and nobody noticed. Leg
131 found the same shape. Leg 154 anticipated it and designed the `on_noninteger="truncate"`
escape hatch per leg 135's rule (a repair that makes the escalating leg's battery unrunnable
destroys the record that authorised it). **But leg 121's banked driver,
[`experiments/p2_route_cda_v1_adversarial.py`](../../experiments/p2_route_cda_v1_adversarial.py),
predates the hatch and does not pass it.** Whether that driver still runs to completion against

before it is run, as this leg's first probe. It is re-run **unmodified**, from a scratch copy, so
that its own `parents[1] / "writeup/data/..."` write lands outside the repository and no file

## 5. CLAUSE (b)'s METHOD — INHERITED, NOT INVENTED

Git-loaded same-process bitwise A/B: the pre-repair module is read out of git at `9dba93f`,
`exec`'d in **this** interpreter so NumPy/BLAS are shared and any difference is the repair
rather than the environment, and compared with `==` on float64 (NaN counted identical to NaN),
**not** `np.allclose`. Inherited verbatim from legs 129/130/150/151/152/154. Leg 130's
correction `d871675` applies and is honoured: the pre-repair ref is pinned to the module's own
**creating** commit, a stable ancestor of `main`, not to any hash a rebase will rewrite.

**Lesson 90 control, stated before the run.** A differential whose two sides cannot come out
different is a tautology of the code. The control that voids this entire run unless it fires:
the pre-repair side must **accept** `p = 1.9` and reproduce leg 121's banked
`residual = 9.71445146547012e-16`, `alpha = 1.0`, `alpha_1 = 2.664535259100375e-14` while the
post-repair side **refuses** it. If both sides refuse, the pre-repair module did not load and
every "bit-identical" below is meaningless.

## 6. NO MATHEMATICAL OR METHODOLOGICAL NOVELTY IS CLAIMED

Regression-test-per-fixed-defect is ordinary engineering practice (Beck, *Test-Driven
Development by Example*, 2002, the "write a failing test for the bug first" rule; Fowler,
*Refactoring* 2ed §4 on the same). The guard's own predicate rests on SEI CERT
[FLP04-C](https://wiki.sei.cmu.edu/confluence/display/c/FLP04-C.+Check+floating-point+inputs+for+exceptional+values)
/ NUM08-J and PEP 357 `operator.index`, both already located and cited by leg 154's novelty pass
— this leg adds no new external rule and re-litigates none of them. In particular, leg 154's
deliberate divergence from NumPy (`is_integer()`, **not** `operator.index`, because leg 121's
C4 battery pins `p = 3.0` and `np.float64(3.0)` as correctly ACCEPTED) is a **settled design
decision under the repair's own licence**, not a defect for this leg to re-open.
