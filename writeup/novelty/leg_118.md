## 1. What the object is, and where the hazards live

`solver/turning_point.py` is a **classification / attribution** module. Its outputs are not
bounds; they are *statements about which mechanism is responsible*: where the profile ends
(`X_c`), with what exponent it vanishes there, with what exponent the outer mode grows, and
**what fraction of the extremal row's mass comes from near `X_c`** — the last being the
sentence that carries the whole attribution in the module's own docstring ("WHERE THE
OBSTRUCTION ACTUALLY IS: THE FAR FIELD, NOT THE TURNING POINT").

The module's entire structural story depends on **`X_c` existing**. When `E = c + aU` never
crosses zero — the `a = 0` anchor is the canonical case, and it is a case the module's own
test suite *runs* — there is no turning point, and every quantity defined relative to `X_c`
is undefined. `critical_radius` signals this by returning `inf`. The question this leg asks
is what `turning_point.py` **does with that `inf`**.

`critical_radius` is called at **three** sites in the module (lines 100, 126, 187). Exactly
**one** of them, line 101–102 in `homogeneous_far_field`, carries the `np.isfinite` guard:

```
    if not np.isfinite(Xc):
        raise ValueError("no turning point: E does not change sign (a = 0?)")
```

The other two do not. That asymmetry — the same check written once and omitted twice, in one
file, against the same upstream return value — is the leg's primary declared hazard, and it
doubles as the leg's **positive control**: the guarded site proves the module *can* flag this
input, so a wrong answer at the unguarded sites is an omission and not a design decision.

| # | site | the shortcut, declared before construction |
|---|---|---|
| H1 | `source_of_the_row` (line 187–190) | `Xc` unguarded. `near = np.isfinite(Xj) & (np.abs(Xj - Xc) <= 0.1 * Xc)`. At `Xc = inf` this is `inf <= inf`, which is **True** in IEEE-754 — so *every* node is classified as "near `X_c`" and `near_Xc_fraction` should return ≈ 1.0 for a profile that **has no `X_c` at all**. Predicted failure direction: the strongest possible *affirmation* of the attribution, produced precisely when the attribution is meaningless. |
| H2 | `inner_mode_exponent` (line 126–132) | `Xc` unguarded. `s = linspace(frac[1]*Xc, frac[0]*Xc, n)` with `Xc = inf` gives a degenerate abscissa; `X = Xc - s` and the subsequent `polyfit(log(s), logh, 1)` decide whether this raises, returns `nan`, or returns a finite plausible exponent. Only the third is a corruption. |
| H3 | `log_growth_exponent` (line 111–116) | `L = np.log(np.log(X / Xc))` takes `Xc` from the **caller**, with no check that it is the same `Xc` the `h` array was integrated from, and no check that `X > e·Xc` (below which the inner log is negative and `L` is `nan`). A mismatched or shifted `Xc` is a silent re-labelling of the abscissa. |
| H4 | `graded_norm_by_radius` (line 158–173), `source_of_the_row` (179) | `np.linalg.inv(M)` on the gauged matrix. `inv` raises only on *exactly* singular input; a matrix singular to working precision returns finite garbage. The function does return `cond` and `smin`, so it is partly self-reporting — the measurable question is whether the reported `by_cutoff` ladder stays plausible while `cond` blows up, i.e. whether a caller reading only the headline is misled. |
| H5 | `homogeneous_far_field` (line 100–108) | The integration starts at `X0 = 1.5·Xc` and assumes `E` has **no further sign change** beyond `Xc`. `critical_radius` returns only the *first* crossing. A second crossing inside `[X0, 1e8]` puts a pole in `f = Hp/E` that the trapezoid rule steps straight over. |
| H6 | `gauged_matrix` (line 140–147) | `drop` is a public parameter with no range check; `keep` silently produces a wrong-shaped or mis-assembled matrix for out-of-range values. |

Two further input axes are in scope because the gate names "poisoned derivatives": NaN/inf in
`om`, in the scalar `c`, and in `alpha`, fed to each of the ten public entry points.

**Lesson 90 is the reason H1 is first on the list.** The module's own gate
`test_turning_point.py::test_5_attribution` asserts `src["near_Xc_fraction"] > 0.5` at
`a = 0.3` and runs an `a = 0` control — but the control is applied **only** to the
`by_cutoff` ladder, never to `near_Xc_fraction`. So the headline attribution number has, in
the module's shipped test suite, no control that could come out differently. Lesson 90 says
that is the tell. Whether it *does* come out differently is a measurement this leg makes and
does not assume.

### The nearest prior leg, and the exact boundary against it

**Leg 114 (Route-CNA)** audited `solver/collocation_newton.py`, which is where
`critical_radius` and `effective_speed` are *defined*. Its finding **M3** —
"`critical_radius` has no magnitude test on the sign change" — measured the **upstream**
behaviour: one entry of `E ≡ 0.5` dipped to `−1e-16` returns a plausible finite radius
`15.025019` where the truth is `inf`, and the returned radius moves by only `1.0e-04` across
thirteen orders of magnitude of dip depth. Leg 114 also recorded that `E ≡ 0` is
indistinguishable from a healthy non-crossing field (`sign(0) = 0`, so `inf` is returned).

Leg 114 **explicitly left this leg's question open**, in its own words:

> "`critical_radius` is consumed at three sites in `solver/turning_point.py` and five in
> `experiments/p2_route_d_v12_defect.py`."

That sentence is a scope note, not a measurement: leg 114 counted the consumers and audited
none of them, because `solver/turning_point.py` was outside its declared territory. This leg
measures **what the three consumers do with the value**, which is a different question with a
different answer space — leg 114's `inf` is *correct* upstream output, and the corruption (if
any) is created downstream by consuming it without a guard. Nothing in leg 114's M3 is
re-measured, re-derived or revised here; it is cited as the upstream half of a two-module
story whose downstream half is this leg's.

**Leg 107 (Route-FIA)** audited the sibling `solver/first_integral.py` and found `abs()`
erasing the branch cut at the same free boundary (96/96 out-of-support values fabricated),
escalated rather than patched, and a later BENCH branch took the repair. That leg's target is
a *value* module; this one's is a *classification* module, which is why `DIRECTION.md` §118
records that "classification modules have not yet been covered by the audit family". Leg 107
is the precedent for the **method and the escalation discipline**, not for the finding.

### What `test_turning_point.py` does verify, and which this leg does not duplicate

Real, and not re-run here: the inner exponent's sign and value against `1/a`; the outer
log-growth exponent against `1/a` with no free constant; quadrature convergence of both fits
under 16× refinement; the exponent tracking `1/a` across `a ∈ {0.25, 0.3, 0.4}`; the cutoff
ladder's contrast against the `a = 0` control; and the square bordered system's singularity
at `a = 0`. Every one of those inputs is **well-formed and converged**. The gap is therefore
precise: the module has never been called on an input that is *degenerate or wrong* rather
than merely hard, and its one degenerate input that *is* exercised (`a = 0`) is exercised
only through the two entry points that happen not to divide by `X_c`.

## 3. External prior art

None claimed; every hazard class here is textbook and is quoted, not discovered:
`inf <= inf` evaluating True while `nan`-comparisons evaluate False (IEEE-754 §5.11 and the
ordered-comparison rules); least-squares fits on a degenerate abscissa returning a finite
slope; matrix inversion of a numerically-singular matrix returning finite garbage rather than
raising; and quadrature stepping over an integrable-looking pole. What is novel here is only
the **measurement on this repository's module**, with magnitudes, against an independent
reference or an exactly known truth.

## 4. What this leg MAY and MAY NOT claim

* **MAY claim:** the exact value returned by each entry point on each degenerate or poisoned
  input, against the truth where the truth is known exactly (`X_c` does not exist ⇒ the
  attribution fraction has no referent — lesson 73); the magnitude of the discrepancy where a
  finite wrong value comes back; whether the guarded site and the unguarded sites disagree on
  the *same* input, which is the leg's positive control; the count of entry points that flag
  versus return; the reachability of every gap from the paths production actually walks; and,
  if a silent wrong classification exists, the exact input that produces it.
* **MAY NOT claim:** anything about the correctness or sharpness of Route-D v13; any new
  value of `X_c`, either exponent, `‖A‖` or its cutoff ladder; that the far-field attribution
  is right or wrong as *mathematics* (only whether the *code* can report it when it is not
  entitled to); that a patch is warranted under this leg's own authority — the gate's
  yes-branch **escalates and does not repair**, and `solver/turning_point.py` stays
  byte-identical to `origin/main` under both branches.
