# Leg 223 — Route-PUB3: novelty / provenance pass

**Committed BEFORE any construction**, per DIRECTIVE 3. Links, not counts (leg 53's
withdrawal is the precedent this rule descends from).

This leg writes no code and measures nothing new. It bundles this cycle's audit-family
escalations into a publication-scoping note, the third such bundle after leg 179
(`ℓ¹_w`-death) and leg 186 (space-axis). So the novelty question has two halves, and they
have different answers:

1. **Is the general claim novel?** — *No, emphatically, and the note must say so.*
2. **Is the specific arrangement novel?** — *Only as arrangement*, the same standing this
   repository already granted 179 and 186.

---

## 1. The general claim is NOT novel, and there is a substantial literature saying so

The tempting headline — *"adversarial/degenerate input against numerical modules reliably
surfaces latent defects that ordinary use never triggers"* — is **established published
prior art**, not a finding of this cycle. Four independent literatures already own it:

| # | prior art | what it already establishes | link |
|---|---|---|---|
| P1 | Silent bugs in DL frameworks (Keras/TensorFlow), empirical study | The *silent* failure class — wrong behaviour with no crash, no hang, no error message — is a named, catalogued category with its own empirical incidence study | [arXiv:2112.13314](https://arxiv.org/pdf/2112.13314) |
| P2 | Franco et al., numerical bugs across scientific computing libraries | A 269-bug dataset drawn from six libraries **including NumPy, SciPy and LAPACK** — i.e. exactly this repository's own dependency stack | (cited in P1's literature and the survey below) |
| P3 | Metamorphic testing / the oracle problem for scientific software | The reason these defects survive construction-time testing is *named*: for most numerical code there is no independent ground truth to test against, so testing must use metamorphic relations instead of absolute oracles. Empirical studies span 4 scientific libraries / 189 functions | [Kanewala & Bieman (STVR 2016)](https://onlinelibrary.wiley.com/doi/10.1002/stvr.1594), [exploratory MT for scientific software](https://pmc.ncbi.nlm.nih.gov/articles/PMC7252536/), [overview](https://en.wikipedia.org/wiki/Metamorphic_testing) |
| P4 | The computer-assisted-proof reliability literature | The exact framing this repository operates under is already stated in print: *any computer-assisted proof implicitly carries as a hypothesis the statement that the software encountered no bugs.* Also carries the published retraction cases (five papers retracted from a single software bug; a sign error reversing an influential economics result) | [Mathematical reasoning and the computer, arXiv:2502.07850](https://arxiv.org/pdf/2502.07850); [refinement-type contracts for scientific software, arXiv:1909.00427](https://arxiv.org/pdf/1909.00427) |

**Consequence, pre-committed here before the note is written:** the note may **not** claim
that adversarial auditing finding latent defects is a discovery. P4 in particular means the
motivating premise ("a CAP's correctness is hostage to its code") is a *quotable standard this
repository is being measured against*, not an insight this cycle produced. The note is
written to that standard, citing it.

## 2. What is left that is actually this leg's own

Stripped of the above, the residue is narrow and is stated narrowly:

- **The hit-rate ledger itself.** A per-cycle, per-module census of an audit family run
  against a *claim-bearing* research codebase, where every finding is graded by a
  pre-committed contamination question ("does this move a banked number?") rather than by
  severity-to-the-code. P1–P4 grade defects by defect class; none of them grades by
  *whether the paper's numbers move*. That grading is the ledger's only original axis, and it
  is a bookkeeping contribution, not a scientific one.
- **The distribution of that grading.** That the overwhelming majority came back
  contamination-zero, one came back uncertain, one claim-adjacent, and exactly one materially
  exposed a banked headline — with those statuses assigned by the finding legs themselves
  under a pre-committed gate, not retrofitted — is the arrangement worth banking.

## 4. Provenance rule pre-committed for the construction

Every magnitude in the note is read from the escalating leg's **own** banked journal/JSON on
its **own** branch, or from `experiments/JOURNAL.md`'s orchestrator-audited pointer, and the
source is named inline. Where the two disagree, or where a later in-flight leg has re-measured
an earlier leg's number, **both values are printed and the disagreement is named** — it is not
silently resolved in favour of either. (This is not hypothetical: leg 218's in-flight novelty
pass re-measures two of leg 198's own `Z₁` ratios and contradicts the DM's caller-set framing.
See the note's §6.)
