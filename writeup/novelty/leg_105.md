## 3. The one methodological finding this pass makes, before any gate number is seen

**A literal-value comparison against the banked `writeup/data/p2_route_ka_v1_kawahara.json` is
the WRONG test for "zero regression," and this is checked here rather than assumed.** The
Kawahara certificate's `Y_0` sits at `~3e-17` — a converged Newton iterate's residual at the
float64 noise floor — and a scouting run (three independent process launches of the literal
pre-repair `solver/interval_certificate.py` **and** `solver/interval.py`, i.e. leg 61's own
original code, reconstructed from git) reproduces **one** value,
`Y_0 = 2.9616446211384186e-17`, deterministically and repeatably *in this environment*, but that
value is **not** the one recorded in the committed JSON (`Y0 = 3.024251708561549e-17`, a ~2%
difference) — despite being the literal same source code. Repeated 3/3 identically in fresh
processes, so it is not per-run noise; it is environment sensitivity (BLAS/LAPACK build, thread
count) at a quantity that is itself sitting at the edge of double-precision resolution, and it
predates both repairs. **Pre-committed consequence:** this leg's "zero regression" claim is
measured as a **same-process bitwise differential** — pre-repair module loaded via
`importlib` from `git show <merge>^1:solver/interval_certificate.py` side by side with the
current one, both run in the same Python process on the same machine — never as a comparison
against the static banked JSON. The banked JSON is read once, for an *informational* magnitude
only, explicitly labelled as environment-sensitive and excluded from the pass/fail criterion.
