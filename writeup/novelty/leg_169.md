## 4. Is the *method* novel? No, and none is claimed

Re-running a defect battery against a fixed module and banking it as a regression suite is
ordinary regression-testing practice, and the repo has done it twelve times. External prior art
for the practice, links not counts:

* [Regression testing — IEEE/ISTQB glossary entry](https://glossary.istqb.org/en_US/term/regression-testing)
* Y. Yu et al., [*An empirical study of the effect of test-suite reduction on fault detection*](https://dl.acm.org/doi/10.1145/1368088.1368113) — why the reduced/bundled sample (here: the repair's own test file) is a weaker detector than the full battery.
* [*Regression test selection techniques: a survey*](https://www.sciencedirect.com/science/article/pii/S0950584912001760) — the "run the original failing input again" baseline.

The mathematics is likewise not novel and this leg claims none: the `γ > 0` hypothesis is
**Plemelj–Privalov**, already surveyed at full depth in
[`writeup/novelty/leg_153.md` §2](leg_153.md). That survey is **not repeated** — re-doing it
would be a count, not a link. One check was made that it is still current: no result published
since leg 153's pass changes the `γ = 0` endpoint, and none would change what this leg
measures, because this leg measures *code*, not the theorem.

## 5. Lesson-90 control, pre-registered before construction

*"A control that cannot come out differently is not a control, and the tell is that its numbers
are identical."* The pre-repair arm of this leg's A/B must be able to report the other answer,
and here is the specific thing that must differ: at `γ = 0.0` the **pre-repair** module
(`07f2b03`) must **accept** and return a finite pair, and at `γ = −0.3` it must return the
silent finite `(46.7564, 4.9190)`-shaped value leg 153's message names, while the repaired
module raises `HilbertHolderDomainError`. **If both arms agree on those cases, the harness is
loading the same module twice and the entire run is void.** This is wired as a hard abort, not
a reported statistic.

Symmetrically, clause (b)'s bit-identity is only meaningful if the comparison can fail:
the pre-repair and post-repair leaves are compared with `==` on float64 (**not** `allclose`,
**not** a tolerance), per leg 153's own standard and leg 105's finding that a banked JSON is the
wrong referent for a noise-floor quantity.

## 6. Pre-registered: what makes this leg answer NO

Per DIRECTION.md §169's no-branch, *"an incomplete fix or a repair regression … report the exact
case and magnitudes; escalate as a priority finding, do not patch under this leg's own
authority."* Fixed before construction:

* **Clause (a) fails** if *any* of leg 119's failing configurations, re-driven from leg 119's
  own cases, returns a finite non-dominating pair — i.e. neither raises nor provably dominates.
  A configuration that raises counts as satisfied; a configuration that returns `(inf, inf)`
  counts as satisfied; a configuration that returns a finite value with `true/bound > 1` does
  not.
* **Clause (b) fails** if *any* previously-passing leaf moves at all under `==`.
* Leg 147's shape is explicitly in scope: a *heterogeneous* residue inside the satisfied set
  (e.g. some rejections loud and one silent) is a clause-(a) NO even if the headline count is
  clean. The per-case verdict table is produced for that reason, not the aggregate.

branch**.
