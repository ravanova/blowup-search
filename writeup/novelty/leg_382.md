# Leg 382 novelty pass — Route-DEXC: a certified far-field decay enclosure

**Committed BEFORE any construction** (ORCHESTRATION.md §5a). This file is the pass; the
module, the test, the runner and the JSON land in later commits on the same branch.

**Disclosure up front, so nothing below is read as more than it is.** This leg is *not*
claiming a novel piece of mathematics. The instrument it builds — eliminating an unknown
amplitude from a log–log tube by Fourier–Motzkin and reading off the surviving exponent
interval — is elementary linear algebra over interval arithmetic, and it would be
dishonest to present it as new. **The only novelty claim made here is a repository claim:
`CLAY_OBLIGATIONS.md` §6 item 1 asserts "NO KNOWN METHOD IN THIS REPOSITORY" for §4's
certified far-field decay, and this pass checks that assertion is (a) accurate as of
332cc2a and (b) not accidentally re-entering a banned lane.** That is the whole scope.

## 2. Ban clearance — `plan_of_record.py`

Read in full this leg. The clause that has to be cleared explicitly:

> re-attempting `ℓ¹`-Fourier/radii-polynomial machinery the repository measured DEAD in three
> realizations (`ℓ¹_w` coefficient basis leg 54, collocation basis leg 56, origin-`H²` capped
> at a=0 leg 163/176), on ANY model, fluid or otherwise … lifted by: never — unless a namable
> FOURTH space/basis …

**This build does not touch it, and the reason is structural, not a promise.** The banned
machinery is a *solution-existence* apparatus: a Banach space, a truncation, an approximate
inverse `A`, and `Y₀/Z₀/Z₁/Z₂` bounds whose radii polynomial proves a zero of `F` exists near
a numerical one. This leg builds **none of those five objects**. It has no function space, no
approximate inverse, no `F`, no Newton step and no radii polynomial. It consumes a profile
that is *given* — supplied as an interval-evaluable callable or as certified samples — and
answers a question *about* that given object (what exponents are compatible with it), rather
than proving anything exists. It is a measurement instrument, not a certification route. The
adjacency is real enough to be worth stating in these words rather than left implicit; the
distinction is that the ban's object is `∃ solution`, and this leg's object is
`{p : the supplied data is consistent with r^{-p}}`.

Cross-checked against the other live clauses: no gCLM measurement (object is a 3D radial
profile, and in fact no specific profile at all — see below), no DSS cheap-entrance or
bifurcation-off-a-fixed-point (nothing is being *found*), no GA compute, no `β` on the 2D
object, no scaling-gauge near-null direction, no truncation-gap-by-domain-extension (the
radial window is **pre-registered and fixed**, and widening it to make a control pass is
explicitly forbidden by this leg's own dispatch — the leg-361 lesson).

**Finding 2.** Clear of every ban in `plan_of_record.py`.

## 3. Published prior art — DISCLOSED HOLE

Attempted this leg, and **failed on infrastructure, not on reading**:

* arXiv API (`export.arxiv.org/api/query`), two queries — `"interval arithmetic" AND
  "decay rate" AND "self-similar"`, and `"computer-assisted proof" AND "asymptotic decay"
  AND "far-field"`: **HTTP 429 Too Many Requests**, both.
* Semantic Scholar graph API, query `rigorous enclosure far-field decay exponent
  computer-assisted proof`: **HTTP 429**.
* The same queries over plain `curl` from the sandbox returned empty.

So §3 rests on the repository's own **banked** literature record rather than a fresh external
search, and that limitation is stated here rather than hidden:

* `writeup/novelty/leg_261.md` Q7 already logged the closest banked neighbourhood — Gallay &
  Wayne, *Long-time asymptotics of the Navier–Stokes and vorticity equations on ℝ³*, and
  Gallay's *Existence and stability of viscous vortices* — reached by a query that explicitly
  contained "algebraic tail computer-assisted enclosure". Leg 261's own reading of those is
  about weighted spaces and stability of vortices, **not** about certifying an exponent from
  a computed profile.
* `LITERATURE_CHECK.md:383,391` records the repository's standing position that the relevant
  weights are algebraic on an unbounded domain, and `:664` records a query on tail estimates
  that returned 7 hits, none of them an exponent enclosure.
* `experiments/p2_route_tms_v1_scoping.py:243` is the repository asking, in its own words,
  whether *any* computer-assisted work has enclosed a decay of this kind — i.e. the
  repository has previously looked and left the question **open**, which is consistent with
  what §1 found but is not a substitute for a search.

**Finding 3, stated at its true strength.** Prior art almost certainly exists for the
*technique* (bounding a slope from an enclosed tube is standard validated-numerics practice,
and this leg claims no credit for it). What could not be checked this leg is whether a
published method exists for exactly the §4 obligation — certifying a 3D NS DSS profile's
far-field exponent — and **that question is left OPEN for a successor with working network
access**, not answered here. It does not gate the build, because the build's value is that
this repository can execute it, and §1 established this repository cannot today.
