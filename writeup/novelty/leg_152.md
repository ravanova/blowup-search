### R2. Is leg 117's own prescribed repair sufficient? **Three of four yes, one measured insufficient.**

Legs 150 and 151 both found the escalating leg's prescribed predicate *dead* on its own
pins, so this is now a standing check, not a courtesy. Taking leg 117's four "CORRECT
behaviour would be" clauses one at a time, read off `test_hl_rescaled_adversarial.py`:

* **G1** ("raise or warn when `np.diff(X)` is not everywhere positive, exactly the guard
  `RescaledHL.__init__` already has") — **the parenthetical is wrong, and it is the whole
  point.** `RescaledHL.__init__`'s guard is `np.any(np.diff(X) <= 0)`, which is precisely the
  form leg 117's *own* G4 characterization shows is defeated by a NaN. Copying it into
  `velocity()` would import the blind spot along with the fix. The two forms are not
  equivalent under IEEE-754: `np.any(d <= 0)` is False on a NaN (accepts), `np.all(d > 0)` is
  False on a NaN (rejects). The adopted predicate is `np.all(np.diff(X) > 0)` — same
  behaviour on every finite input, NaN-rejecting for free. This is the one clause where
  leg 117's prescription is measured insufficient for leg 117's own G4 finding.
* **G2** ("raise or warn when `X_ref` is outside the sampled range") — sufficient as written;
  the range test is exact and threshold-free (`X.min() <= X_ref <= X.max()`).
* **G3** ("raise, or take `abs(M)`, with a warning either way") — sufficient, and `raise` is
  the branch taken: silently substituting `abs(M)` is the *same class* of defect the
  `target_norm`/leg-94 precedent forbids (never silently substitute a different input for the
  one you were given). **In-kind extension, declared:** `delta` carries the identical
  mechanism (`X = Xc + delta*sinh(s)`, so `delta <= 0` mirrors the grid exactly as `M < 0`
  does) and is guarded in the same commit. Leg 117 did not measure it; leaving it is the
  incomplete-fix shape leg 147 caught on `nk_bounds.py`. Declared here and in the journal
  rather than smuggled in.
* **G8** ("propagate NaN through, exactly as `scenario2_ic` already does") — sufficient, and
  it comes with its own in-file oracle: `test_scenario2_ic_negative_control_propagates_nan`
  already asserts the target behaviour on the sibling function, so the repair has a
  same-module reference implementation rather than a judgement call.

## Queries, verbatim, with the links returned

### Q1
`validate strictly increasing grid before cumulative trapezoidal integration raise error unsorted x`

- https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.cumulative_trapezoid.html
- https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.trapezoid.html — SciPy
  states the mechanism explicitly and declines to defend against it: "the integration happens
  in sequence along the elements of `x` — **they are not sorted**." The routine integrates in
  array order, by design, and documents no monotonicity precondition and no error for
  violating one.
- https://www.mathworks.com/help/matlab/ref/cumtrapz.html and
  https://search.r-project.org/CRAN/refmans/pracma/html/trapz.html — MATLAB's `cumtrapz` and
  R's `pracma::trapz` describe the same algorithm with the same silence.

**On-topic; confirms and sharpens leg 117's Q3 negative.** Leg 117 recorded "no
domain-specific citation exists" as genuinely inconclusive. This pass can state it one notch
more precisely: it is not that the reference implementations forgot the check, it is that
they **document array-order integration as the contract** and push validation onto the
caller. So `velocity()`'s guard is not a fix to a bug numpy/SciPy have — it is this module
honouring a precondition its own docstring already asserts ("on a (sorted-ascending)
non-uniform grid") and never checked. No novelty claimed; the guard is the caller-side
obligation the upstream docs create.

### Q2
`scipy interpolate interp1d bounds_error default True raises ValueError out of range x_new numpy interp no bounds check`

- https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.interp1d.html — the
  direct prior art for the **choice of default** in the G2 repair: SciPy's `interp1d` sets
  `bounds_error` to raise by default, "a ValueError is raised any time interpolation is
  attempted on a value outside of the range of `x`", and extrapolation must be requested
  explicitly (`fill_value="extrapolate"`). Out-of-range is treated as an error condition by
  the reference library, not as a value.
- https://numpy.org/doc/stable/reference/generated/numpy.interp.html — `np.interp`, the
  function `velocity()` actually calls, has no `bounds_error` at all; `left`/`right` only
  choose *which* constant is silently returned. The two libraries disagree on the default,
  and `hl_rescaled.py` inherited the permissive one by accident rather than by decision.
- https://github.com/scipy/scipy/issues/12707 — a user report of the out-of-range fill
  behaviour surprising a caller, i.e. the footgun is live enough to generate bug reports.

**On-topic; settles the raise-vs-warn question by precedent rather than taste.** `raise` by
default matches `interp1d`; `on_invalid="warn"` matches `fill_value="extrapolate"` as the
explicit opt-in. This is the same shape as the in-repo `target_norm.py`/`first_integral.py`
guards, so the module is consistent both with its own repository and with SciPy.

### Q3
`numpy all(diff(x) > 0) NaN-safe monotonicity check versus any(diff <= 0) IEEE 754 unordered`

- https://wiki.sei.cmu.edu/confluence/display/java/NUM07-J.+Do+not+attempt+comparisons+with+NaN
  — SEI CERT's rule states the remedy in normative form: comparisons `<`, `<=`, `>`, `>=`
  **all** return false when either operand is NaN, so a validation written as "detect the bad
  case" (`any(d <= 0)`) fails open on NaN while one written as "confirm the good case"
  (`all(d > 0)`) fails closed. The rule's own guidance is to test for NaN explicitly rather
  than rely on ordered comparisons.
- https://github.com/ispc/ispc/issues/1548 and
  https://community.intel.com/t5/Intel-oneAPI-Data-Parallel-C/More-trouble-with-NANs/td-p/1485284
  — two independent compiler-level reports of the same unordered-comparison surprise.
- https://docs.factorcode.org/content/article-math.floats.compare.html — states the unordered
  relation directly ("every NaN shall compare unordered with everything, including itself").

**On-topic; confirms known hazard AND names the remedy.** This is the fifth in-repo instance
of the mechanism legs 100/106/116/117 already logged, so nothing is discovered here. What
this query adds over leg 117's Q1 is the *direction* of the fix, which leg 117 did not need
and this leg does: the polarity of the predicate is the entire repair for G1 and G4, and it
costs nothing on finite input. No novelty claimed — CERT NUM07-J is cited, not re-derived.

## What this pass changed about the leg before construction

1. **The G1 predicate flipped polarity.** Leg 117's own prescription ("exactly the guard
   `RescaledHL.__init__` already has") would have imported the NaN blind spot into the new
   guard. `np.all(np.diff(X) > 0)` is adopted instead — identical on finite input,
   NaN-rejecting, and it makes the G4 clause a one-token change rather than new code.
2. **The G4 clause is patched, not documented away — and the reasoning is recorded now,
   before the measurement, as the gate requires.** `DIRECTION.md` gives the leg author the
   call and demands it be stated explicitly either way. Patching wins on this specific
   module because the fix is not a new guard at all: it is the same polarity flip already
   required for G1, applied to a line that must change anyway for consistency between the
   free function and the class. The "higher-risk than the latent defect" escape exists for
   fixes that add machinery; this one deletes a footgun and adds nothing. The cost is that
   `test_CHARACTERIZE_nan_defeats_ascending_guard` must be inverted (it currently asserts the
   constructor must NOT raise), which is a PIN inversion in all but name and is done in the
   repair commit. **This is stated before the differential runs; if the differential moves a
   single clean value, the gate's no-branch fires regardless of how good the reasoning was.**
3. **`delta <= 0` is declared as an in-kind extension** rather than left as an incomplete
   fix (R2/G3 above) or slipped in unannounced.
4. **The escape hatch is designed in, not bolted on** (R3), so the repair cannot destroy the
   measurement that authorised it.
