## 2. Two things measured before the plan was fixed (not assumed)

**(a) Leg 89's frozen battery still runs to completion against the repaired module** — unlike
leg 99's, which leg 104 found dies with `KeyError: 'verdict'`. Measured:

```
$ PYTHONPATH=. .venv/bin/python -c "import experiments.p2_route_boa_v1_adversarial as boa; \
    [print(c['label'],'->',c['verdict']) for c in boa.family_a()]"
dealias_annihilated_vorticity_k15x15 -> raised   (ValueError: omega0 is numerically zero: ...)
dealias_annihilated_vorticity_k12x12 -> raised
dealias_annihilated_vorticity_k14x3  -> raised
dealias_annihilated_vorticity_houluo -> raised
denormal_vorticity_amp1e-300         -> raised
denormal_vorticity_amp1e-18          -> raised
CONTROL_exactly_zero_vorticity       -> raised   (ValueError: omega0 is identically zero)
CONTROL_constant_vorticity_psi_zero  -> benign
```

Reason it survives where leg 99's did not: `run_case` wraps every call in `try/except` and
classifies the exception as `RAISED`, so a fix that converts silence into a `ValueError` moves a
case between verdicts rather than crashing the driver. **This means the battery can be reused
as the instrument** — the leg does not need to re-implement 90 cases, and re-implementing them
would be *less* faithful to "leg 89's full original battery", not more.

**(b) The battery source is unchanged by the repair outside `main()`'s payload.** `git diff
4959e6b 0c54d8a -- experiments/p2_route_boa_v1_adversarial.py` is **+34 / −0 lines, entirely
inside the `payload` dict of `main()`** (a `"history"` block preserving the pre-fix numbers).
Every case constructor and the `run_case` classifier are byte-identical to leg 89's original.
So importing `family_a…family_f` from the file at `HEAD` **is** running leg 89's original
battery; this is verified in-run by the leg's own driver, not taken on trust.

**Consequence for independence, and the honest ceiling on it.** Re-using leg 89's classifier
means the *verdict predicate* is inherited, not independent. The leg therefore adds two arms
the repair's report does not have:

1. **A positive control that can come out differently (lesson 90).** The same 90 cases are run
   against the **pre-repair** module source, recovered from `git show 4959e6b:solver/boussinesq.py`
   and injected as `solver.boussinesq` before the battery imports it. If the harness cannot
   reproduce leg 89's `19 / 4 / 13` on the old source, the post-repair `0 / 0 / 0` is worthless —
   it would be measuring a broken harness, not a fixed module. Four identical zeros with nothing
   that could have made them non-zero is precisely the shape lesson 90 bans.
2. **Independent defect probes** written from the *defect descriptions*, not from leg 89's code,
   for all four defects — plus an independent re-derivation of the banked audit (call-site
   `kappa` scan, `blowup_candidate` scan over `writeup/data/`, and a fresh recomputation of
   `phase1_spike.json`'s N=128 column) that reads only the banked JSONs and the live module.
