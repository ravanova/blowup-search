## 4. The one live design decision, recorded because it decides a gate case

`Fraction` **is** `numbers.Real` (it registers as `numbers.Rational`). So is `bool`. Leg
199's M2 heading calls all four probe types "non-`numbers.Real`"; two of the four are not.
That matters for exactly one case, `B_nonreal_Fraction`, and the choice was:

* **Reject every non-`float` real**, closing the case and turning the gate YES — but that
  would refuse `Fraction(-1, 3)`, which leg 199 banks as its **M4 discrimination control**,
  *correctly refused by VALUE*, and whose whole point is that M4 "is a float-conversion
  boundary, not a `Fraction` blind spot". It would also refuse an exact rational bound, which
  is a *better* input than a float one.
* **Reject `bool` and non-real types only**, which is what M2 actually names — parity with
  the sibling guard in the same file — leaving `Fraction` accepted by *both* guards.

The second was taken. It repairs the mechanism as leg 199 defined it (the divergence between
siblings: **2 of 4 probe types disagreed before, 0 of 4 after**) and leaves one of leg 199's
16 counted cases still accepting. Buying a YES by re-litigating the finding leg's own control
is precisely what the repair-family precedent forbids, so the gate is reported NO instead.
That decision is stated here, before the result, rather than discovered in the journal.
