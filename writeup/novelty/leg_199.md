## Channel 4 — the audit template, and what does and does not transfer

The template is leg 116/128's **fabrication-acceptance** pattern: construct inputs
engineered to look like they should fail an accept condition, and confirm the module
rejects rather than silently accepts. It transfers, with one adaptation that must be stated
up front:

`certificate_guards.py` is **purely a rejection layer** — it returns *reasons*, never
numbers, and computes no bound. So the leg-92/117 style "the returned magnitude is X× below
the honest one" measurement **cannot be made at this module's own surface.** The honest
measurement here is two-part, and both parts are pre-registered:

  (a) **at the guard's surface** — does a case that breaks a hypothesis the guard's own
      docstring names come back with an **empty** violation list / a `None`?
  (b) **at the consumer** — for every (a) hit, drive the same value through the real call
      site in `nk_bounds.py` / `port_certification.py` / `interval_certificate.py` and
      report what number or verdict comes out, against the honest counterpart. A guard-level
      accept that no consumer can reach is **LATENT** and must be reported as latent, per
      leg 142's and leg 147's precedent, not inflated into an impeached certificate.

Leg 128's own scope limit is inherited and is NOT re-litigated: a hypothesis-**satisfying**
input that lies about a magnitude (leg 116's surviving 4, leg 147's `P06_Z2_shrunk_1e-6` at
714285.7×) is structurally invisible to any hypothesis guard. Finding it again here would
be a re-measurement, not a finding, and is out of scope.

## Channel 5 — pre-registered probes, declared before any number was computed

Five families, 6 controls. Each names what would make it a hit.

**A. `hypothesis_violations` — the type gate.** The docstring promises a `TypeError` on a
non-real value and a violation on NaN/±inf/negative.
  - A1 `bool` — `isinstance(True, numbers.Real)` is `True` in Python.
  - A2 huge Python `int` (`±10**400`) — `float()` overflow, on the line *before* the isinf test.
  - A3 `Fraction` whose magnitude is below the smallest denormal and whose sign is negative.
  - A4 `Decimal('-1')` — registered `numbers.Number`, not `numbers.Real`.
  - A5 numpy `float64`/`float32` NaN / inf / negative — **control, must reject.**
  - A6 empty `constants` iterable — vacuous pass.
  - A7 `str`/`complex` — **control, must raise.**

**B. `radius_violation` — no type gate at all.** Unlike (A) it calls `float()` with no
`numbers.Real` check first.
  - B1 numeric string, B2 `bool`, B3 `Decimal`, B4 `None`.
  - B5 smallest denormal `5e-324`, B6 `-0.0` — **controls.**

**C. `unit_range_violation` — the endpoints.** It has **no `isinf` test**; non-finiteness is
supposed to fall out of the two comparisons. The `alpha` call site passes
`lo=-float("inf"), lo_open=False`, so the lower comparison is `f < -inf`.
  - C1 `value=-inf` at the real `alpha` call site, C2 `value=+inf` at the real `gamma` call
    site, C3 `bool`, C4 numeric string.
  - C5 NaN, C6 in-range interior and both endpoints — **controls, must reject / must accept.**

**D. `positive_weight_violations` — the container.**
  - D1 empty iterable, D2 exhausted generator, D3 `dict`, D4 un-`ravel`ed 2-D array.
  - D5 an all-non-positive vector, D6 a single planted `-0.0` — **controls, must reject.**

**E. `invalid_input_reason([])`** — the sentence built from an empty violation list.

**Controls that could fail and would void the run.** The lesson-90 rule: if the honest
counterpart of a probe behaves the same as the probe, the probe measured nothing. Every (b)
consumer measurement is paired with the hypothesis-satisfying reference input, and a probe
whose reference produces the identical number is reported as **no discrimination**, not as a
hit.
