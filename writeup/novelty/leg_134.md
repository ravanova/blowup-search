## 3. Method commitments, fixed before any number is produced

1. **Leg 91's battery is re-run as leg 91's own code, not re-implemented.** This leg's runner
   *imports* `experiments/p2_route_fga_v1_adversarial.py` and calls its `a1`…`a5` functions
   directly. Leg 91's file and its JSON are **neither edited nor overwritten** — they are that
   leg's territory and the frozen pre-repair evidence; only `main()` writes, and `main()` is
   never called. This is what makes the re-run independent of the repair's bundled test.
2. **A THREE-WAY comparison, not two-way — and the third arm is a control that can come out
   differently (lesson 90).** A scoping probe run before this pass was committed showed that a
   two-way comparison (banked JSON vs today's post-repair run) is **not identifiable**: it
   cannot separate "the repair moved the number" from "the environment moved the number". The
   third arm is therefore the **pre-repair module reconstructed from history**
   (`git show 8d4fdec^:solver/fractional_gclm.py`, loaded from the scratchpad, never written
   into the repo), run in **this** environment on **the same** line. The three arms are:
   `BANKED` (2026-08-02 JSON) vs `POST` (today, `main`) vs `PRE` (today, `8d4fdec^`).
   `POST` vs `PRE` is the arm that isolates the repair; `POST` vs `BANKED` is the arm that
   includes everything else. Either arm can report either answer, and the two arms disagreeing
   is a possible outcome that this design can *name* rather than confuse.
3. **The environment is recorded as data**, not assumed: Python `3.12.3`, NumPy `2.5.1`. Any
   `POST`-vs-`BANKED` difference is quoted in ULPs and in relative terms, never as "identical".
4. **No threshold is re-tuned in the direction that flatters the fix.** Leg 91's own constants
   (`N_AUDIT = 512`, `NU_AUDIT = 1e-3`, `AMP = 3e3`, `MAX_STEPS = 20000`, `CLEAN_S`) are used
   as imported; Route-F's own constants (`N_DEFAULT = 8192`, `AMP = 1000.0`, the seven
   `s_values`) are used as imported.
5. **Magnitudes, never booleans**, in every reported line — including "how far did it move",
   in ULPs, wherever the answer is "not at all" (lesson: an identical number needs a stated
   resolution before it means anything).
6. **`writeup/data/p2_route_f_v1_viscosity.json` and `p2_route_fga_v1_adversarial.json` are
   READ-ONLY.** Rewriting a banked result is escalation #4 and this leg does not go near it.

**On-topic finding.** The corpus is unchanged since leg 91's pass and re-confirms the boundary
the repair encoded: dissipation is written `-Lambda^sigma` with `Lambda^sigma`-hat `= |k|^sigma`,
i.e. **`sigma = 2s`**; global-in-time existence on the circle is proved *"for `σ ≥ 1` and all
real values of an advection parameter `a`"* for small data; the **lowest** exponent treated
anywhere is the *"marginal"* `σ = 0`, with the Oldroyd-B stress reading. **No published work
treats `σ < 0`**, and **no published work imposes an upper bound on `σ`.** So the repair's
asymmetry — reject the low side, leave the upper wall to float64 — matches the literature and
is not this leg's invention to defend or attack. `s = 0` admissible is likewise the
literature's, which is what makes the repair's no-overshoot control the right control.

**On-topic finding, and it is what forced method commitment (2).** The established position is
that bitwise reproducibility is a property *within one implementation and one environment* —
*"strict bitwise reproducibility is not achievable across different code implementations, as
even tiny differences in floating-point operation ordering lead to round-off divergence"* — and
that its legitimate use is exactly this leg's: *"regression testing and bitwise reproducibility
verification for future code releases"*, and *"validating ported codes"* by comparing a new
build against *"a previously trusted (validated) implementation"*. The literature is explicit
that the *trusted reference must be re-run*, not read from a file. A gate phrased as
"reproduce the banked value bit-identically" is therefore under-specified unless the reference
arm is re-run in the same environment — which is precisely the `PRE` arm this leg adds, and
precisely why a `POST`≠`BANKED` result would **not** by itself implicate the repair. Nothing
found is a novel method and nothing this leg does is claimed as one.
