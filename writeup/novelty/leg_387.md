## 3. Prior art for this leg's own object — stated honestly, not waved through

This leg's object is "re-run three named queries and bank what comes back". There is no
meaningful published prior art for *that*; it is clerical work, and claiming a novelty
question here would be theatre. What is worth pre-registering instead is the **epistemic trap
specific to this leg**, because the standing rule this cycle is that no green may be reported
without a demonstrated red path:

> A query that errors and returns an empty result list must never read as "no prior art".

Leg 382's own §3 records the shape of that trap in this exact environment: "The same queries
over plain `curl` from the sandbox returned empty" — an *empty* body, sitting right next to a
429. An empty body and a controlled zero are indistinguishable to any harness that only counts
results. **Pre-committed, before running anything:** the harness must be tri-state —
`HITS` / `CONTROLLED-ZERO` / `REFUSED` — where `CONTROLLED-ZERO` may only be reached on an
HTTP 200 whose body *parses* as a well-formed result container that genuinely reports zero
results, and any non-200, any unparseable body, any transport error, and any empty body is
`REFUSED`. A positive control (a query with a known-nonempty answer) must return `HITS` in the
same run, or the whole run is `REFUSED` — because a harness that cannot demonstrate it can see
a hit has not demonstrated it can see a zero either. The red path is demonstrated explicitly,
not asserted.

**Finding 3.** No prior-art obstacle to this leg. The real risk is not novelty, it is a
laundered zero, and the control against it is pre-registered above rather than invented after
seeing the responses.
