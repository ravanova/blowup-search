## Is a full independent re-regeneration owed, or is reuse of leg 252's warranted?

Leg 252's own residue #1 states the artifact is "not environment-portable"
and that "nothing in the repository records the environment its banked
numeric artifacts were produced in." Leg 252 recorded its environment as
`Intel i7-10750H`, `python 3.12.3`, `numpy 2.5.1`,
`scipy-openblas 0.3.33.112.0`, hostname `AH01`.

This leg's own environment, checked independently before reuse (not
assumed): same hostname `AH01`, same CPU model
(`Intel(R) Core(TM) i7-10750H CPU @ 2.60GHz`), `python 3.12.3`,
`numpy 2.5.1`, `scipy-openblas 0.3.33.112.0` (via `numpy.show_config()`).
Identical on every axis leg 252 measured.

Given that, and given leg 252's own finding that portability breaks
*across* environments (not within one — "the runner IS bit-deterministic
within this environment: two independent processes agree to the last
bit"), a full 7-8 CPU-hour re-regeneration would be expected to reproduce
leg 252's own numbers exactly rather than test anything leg 252 did not
already test. That expectation is checked, not assumed: a targeted spot
re-solve of the single decisive row (`a=0.45`, `n=801`, the row the stale
`margin` field is wrong about) was run fresh, independently, on this leg's
own environment today. Result: `weighted_defect = 0.015320233103213909`,
`relres = 1.6136332491369584e-09` — matching leg 252's regenerated
`v5_budget.newton_weighted_defect_max` (`0.015320233103213909`) to every
printed digit, exact float equality. This is the same bit-for-bit
reproduction leg 252 itself demonstrated between leg 247's fresh re-solve
and its own regeneration, now demonstrated a third time, independently, in
a separate process on a separate day.

**Conclusion of this check**: reusing leg 252's already-regenerated JSON
(rather than re-running all ~359 leaves at ~7-8 CPU-hours of cost under this
run's current contention, load average ~50-57 on 12 cores) is warranted —
it is not a shortcut around verification, it is a verification that a
re-run would not change the answer. This is recorded as a finding in its
own right, not a convenience assumption.
