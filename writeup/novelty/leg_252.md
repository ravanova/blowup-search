## Is the gate predicate adequate?

The brief's gate has two clauses, and a bare "the JSON changed" would satisfy
neither. Both are therefore measured as magnitudes:

1. **Reproduction.** Not "the margin moved" but: does the fresh full run land on
   leg 247's *own reported digits* — margin `0.016122858874141922`, violation
   `62.02373957411577x` at `a = 0.45`, `1` row over budget out of `11` good
   rows, `10.655996808538774x` worst-case margin over the rows that hold? These
   are transcribed from leg 247's banked
   `writeup/data/p2_route_vbr_v1_repair.json`, at full precision, not from the
   rounded commit message. Tolerance `1e-6` relative. This is a genuinely
   *stronger* test than leg 247's own: leg 247 computed its corrected block from
   the **banked** `v2`/`v4` rows, whereas this leg re-solves the whole sweep from
   scratch and *then* applies the corrected selection. If the two disagree, the
   disagreement is real and escalates.
2. **Isolation.** Not "nothing else looks different" but a leaf-by-leaf flatten
   of both JSONs (dotted paths through every nested dict and list), with every
   changed / added / removed path enumerated, and anything outside
   `v5_budget.*` / `meta.*` flagged as unexpected. Leg 247 measured isolation
   across 196 *other* JSON files for the *diagnosis*; this extends it *within*
   this one file for the *regeneration*, which is a different claim and is
   labelled as such.

**Positive control.** A "0 unexpected changes" result is unfalsifiable unless
the detector is shown to fire. So the check perturbs one untouched non-`v5`
float leaf by `1e-9` relative and confirms the same predicate flags it. If the
control does not fire, the gate fails regardless of the other two clauses.
