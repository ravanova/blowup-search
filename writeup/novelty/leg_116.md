* **(N1)** Are `Y_0`, `Z_0`, `Z_1`, `Z_2` **hypothesised nonnegative and finite** in the
  published radii-polynomial theorem? If so, a negative constant is not a conservative input —

  the theorem does not cover.

* **(N3)** Is "a guard of the form `1/q if q > 0 else 0` silently substituting a *zero*
  contribution where the honest contribution is `+∞`" a recognised defensive-programming hazard?
* **(N4)** Is the *method* — an adversarial poisoned-input battery banked as a permanent
  regression test against certificate-adjacent code — standard practice?

**On-topic finding for (N1) — DECISIVE, and it is the standard statement, not a novelty.**
The bounds are *defined as upper bounds on norms*: `Y ≥ ‖T(x̄) − x̄‖`, and `Z_0`, `Z_1`, `Z_2`
as suprema of operator norms over the unit ball, with the conclusion drawn from `p(r) < 0` for
some `r > 0`. Nonnegativity and finiteness are **hypotheses of the theorem**, satisfied by
construction, not numerical accidents. Consequently a negative or non-finite `Y_0`/`Z_0`/`Z_1`/
`Z_2` is **not a pessimistic input** — it is an input the theorem says nothing about. This is
the same conclusion legs 79 and 98 reached against the two sibling modules; it is 2015-vintage
textbook material and this leg claims none of it. The second, sharper reading matters here:
the theorem's conclusion is *existence and uniqueness of a zero inside the ball of radius
`r_min`* — so a `closes=True` verdict with a **non-positive** `r_min` is not a conservative
verdict either; it asserts a zero inside a degenerate or empty set.

**On-topic finding for (N2) — DECISIVE, and it is standard, not a novelty.** The entire
interval branch-and-bound literature exists *because* evaluating a function at finitely many
sample points bounds the supremum only from **below**. A guaranteed upper bound requires an
enclosure over the whole (sub)domain — this is the defining premise of the field, and the
"invalidity of underestimators under limited sampling" is named as its central hazard. So when
this leg reports that `farfield_modelling_error_bound` takes `max` over 40 sampled `X` in a
**truncated** window `[X0, 10⁴·X0]` and returns it as "the bound", that is a *documented
hypothesis the module does not check* — never a discovery. `nk_bounds.py`'s own docstring
already states the hypothesis under which sampling is legitimate here ("For alpha < 2 both terms
decay, so the supremum sits at X0"); the audit's only question is whether the code **enforces**
it. Two further consequences are pre-committed here, before measurement, so they cannot be
retrofitted: (a) the function already computes `argmax_X`, so *"the argmax landed on the grid's
last point"* is an in-band self-diagnostic it has and discards; (b) by lesson 90, a grid that
"confirms the supremum sits at `X0`" **cannot come out differently** whenever the integrand is
monotone — so inside the documented scope that confirmation is a tautology of the code, and its
only informative regime is exactly the one the module does not guard.
