# Leg 104 -- Route-BVB v1: post-repair regression check across leg 99's FULL battery

**Date: 2026-08-06. Kind: regression check -- standard. No figure, no new physics, and none
claimed.** `solver/boussinesq_velocity.py` read only, edited under neither gate outcome.

## Gate, verbatim

> Post-repair, does `solver/boussinesq_velocity.py` (a) no longer return `-0.0` on any of leg
> 99's original failing degenerate-grid cases, and (b) still reproduce leg 73's Lamb
> corner-image benchmark with zero regression?

## Answer

**YES on both clauses.**

- **(a)** Re-ran leg 99's exact **22 cases across all three families** (not a sample) against
  the patched module. **0 `SILENT_WRONG`, 0 returned `-0.0`** -- versus leg 99's original **7
  `SILENT_WRONG`, 5 of which returned exactly `-0.0`**. The full 9-point `r_min` sweep in the
  origin-read family: the 6 points that used to fabricate a value (`r_min` in `{0.09, 0.099,
  0.15, 0.5, 1.0, 10.0}`, 1 or 0 nodes in the fit window) **all now raise `ValueError`** naming
  the window and its occupancy; the 3 well-resolved points (`r_min` in `{1e-3, 1e-2, 0.05}`)
  still return accurately (abs error 8.611e-3, 8.189e-3, 4.006e-3 -- **identical to leg 99's
  own measurements**, confirming the fix changed nothing for well-posed input). The reversed
  and collapsed radial intervals (family 2/1) now raise at construction, before any solve. The
  five cases the repair deliberately left untouched (`n_beta<=0` `SILENT_EMPTY`, three malformed
  shapes, two poisoned-vorticity cases, `n_r=1`) show **exactly their pre-repair behaviour**.
- **(b)** Independently re-ran leg 73's 3-level ladder via `run_level()` imported from
  `experiments/p2_route_bv_v1_velocity_benchmark.py` (never via its `main()` -- that module's own
  frozen JSON is untouched by this leg). P1 finest **1.758374e-04** vs banked
  **1.758374e-04** (rel diff **4.23e-12**), P3 finest **1.216306e-05** vs banked
  **1.216306e-05** (rel diff **6.03e-13**), observed orders **2.00, 2.00** unchanged. A
  same-code-twice control (the identical ladder run twice in the same process) measured a noise
  floor of **0.00e+00 to ~1e-16** from BLAS/threading order effects, so the ~1e-12 diff against
  the banked JSON is deep inside floating-point jitter, not a regression.

**Banked as a permanent regression suite alongside legs 73 and 99. No escalation.**

## Why this leg exists distinct from the bench-repair's own re-check

The repair commit (`26e6bd3`, merged `e3bdd9f`) re-ran **one** benchmark (leg 73's) and its own
bundled test update samples **three** representative cases from leg 99's 22-case battery
(`test_boussinesq_velocity_adversarial.py`: the empty window at `r_min=0.15`, the reversed/
collapsed interval, the single-node window at `r_min=0.09`). DIRECTION.md's leg 104 spec exists
because that is one benchmark and a sample, not the full battery. Confirmed empirically (see
`writeup/novelty/leg_104.md` sec.2) that leg 99's own battery script,
`experiments/p2_route_bva_v1_adversarial.py`, is frozen against the *unpatched* module on
purpose and **raises `KeyError: 'verdict'`** if called post-repair -- its
`family_malformed_boundary()` only assigns the ascending control's verdict inside a branch that
also requires the reversed case to have *not* raised, which is no longer true. So this leg
reimplements the 22 cases fresh and independently in its own territory
(`experiments/p2_route_bvb_v1_postrepair.py`), rather than editing or importing that frozen
script (out of this leg's territory in either case).
