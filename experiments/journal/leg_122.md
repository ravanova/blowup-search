## SITE 1 — the far-field probe fabricates four of its eight values, on the default path

`advection_split` returns `transport_at` and `stretch_at`, dicts labelled with the keys
`1e1, 1e2, 1e3, 1e4` and built by `np.interp(q, X, ...)` (module lines 184–187). `np.interp`
**clamps**: for `q` past the last node it returns the last node's value, silently.

On the default grid `X_max = 745.24`, so the keys `1e3` and `1e4` are both out of range:

```
transport_at = {1e1: 0.9198337662475536, 1e2: 1.6552382628493274,
                1e3: 2.2906076249428438, 1e4: 2.2906076249428438}
transport[-1] (the last node, at X = 745.24) = 2.2906076249428438
```

`transport_at[1e4] − transport_at[1e3]` is **exactly 0.0**, and each equals the last node's
value **exactly**. The same holds for `stretch_at` (`1e3 = 1e4 = 0.00384032871440196`). That
is **four fabricated numbers per call**, presented under labels that name an `X` the grid does
not have. This is lesson 90 read off the module's own output: two identical numbers where the
quantity is documented (§1) to *grow like log X* should have read as a bug.

**Magnitude, against control C2** — the same keys on `rho_max = 12`, whose last node
(`40688.70`) is genuinely past `1e4`:

| key | default grid (reported) | control grid (honest) | relative error |
|---|---|---|---|
| `1e2` (**in grid**) | 1.6552382628493274 | 1.6455306312659308 | **+0.59 %** |
| `1e3` (out) | 2.2906076249428438 | 2.3693471901537846 | −3.32 % |
| `1e4` (out) | 2.2906076249428438 | 3.0929575069687223 | **−25.94 %** |

The control came out the right way and could have come out the other way: the **in-grid** key
agrees to 0.59 % while the **out-of-grid** key is off by 25.94 % — a **44×** separation. If
the two grids had disagreed comparably at `1e2`, site 1 would have been arithmetic, not
corruption.

**Direction of the error, and the honest ceiling.** The fabricated value **under-states**
the transport piece by a quarter. The module exists to show that this piece *diverges*, so
the corruption is in the conservative direction: it cannot manufacture the module's negative
conclusion, only weaken it. **No banked result is contaminated** — `test_advection_scope.py`'s
helper `_solved(a, n=2401, rho_max=12.0)` uses `rho_max = 12` throughout, so every landed
number in that file was computed on a grid that contains `1e4`. This is a latent trap for the
next caller who uses the constructor defaults, not a live error in the record.

## SITE 2 — the reported fit window is the one that was *requested*

`velocity_log_rate` returns `"window": [lo, hi]` — the arguments, unchanged. On the default
grid it reports `[10.0, 1000.0]` while the fit actually ran on `[10.105645208399274,
745.2394128947751]`, 216 nodes: the requested upper end is **1.34×** the realized one.
`advection_split` is worse — it defaults `hi = 1e4`, fits over a realized upper end of
745.24 (a **13.42×** overshoot), and returns **no window key at all**, so the discrepancy is
not merely mislabelled but unrecorded.

A second, sharper reading of the same site. The docstring (lines 118–127) explains that
`predicted` (windowed mass) and `predicted_full_domain` are both returned "so the discrepancy
is visible rather than hidden", and quotes a 15 % gap at `a = 0.5`. But the mass selector is
`np.abs(X) <= hi` (line 131), and on the default grid the whole domain already satisfies
`|X| <= 1e3`. So:

```
predicted − predicted_full_domain = 0.0   (exactly)
mass_window − mass                = 0.0   (exactly)
```

The module's own discrepancy check is **inert on its own default path** — a control that
cannot come out differently (lesson 90). It only has content when `hi` is smaller than
`X_max`, which the defaults never arrange.

## SITE 3 — one `None` for two opposite physics

`stagnation_point` returns `None` for "no crossing", and the docstring explains that case only
for `a = 0`, "where `c_eff == c > 0`". Measured on the `a = 0.3` profile:

| case | `c_eff` range on `X > 0` | fraction negative | returned |
|---|---|---|---|
| `a = 0, c = +0.5822` (documented) | `[+0.5822, +0.5822]` | 0.00 | `None` |
| `a = 0, c = −0.5822` | `[−0.5822, −0.5822]` | 1.00 | `None` |
| `a = 0.3, c = −0.5822` | `[−2.2188, −0.5823]` | **1.00** | `None` |
| `a = 0.3, c = +0.5822` (contrast) | `[−1.0544, +0.5822]` | 0.58 | `7.12838418502464` |

The same `None` stands for "the effective speed never reverses" and for "the effective speed
is reversed **everywhere**, by as much as −2.22" — a span of **2.80** covering both signs. A
caller that reads `None` as the documented case gets the sign of the far-field motion exactly
backwards.

**Blast radius, measured not assumed.** `grep -rln advection_scope --include=*.py .` returns
four files: `test_advection_scope.py`, `capabilities.py`, `experiments/p2_route_cap_v1_audit.py`
and `solver/finite_support.py`. The last is the one that matters — its header (line 30) tells
the reader to "compare `solver/advection_scope.stagnation_point`, which measures the same
crossing", and this module's own §5 records that `finite_support.py` re-reads that crossing as
the **edge of support** `X_c`. But `finite_support.py` **does not import it**: the coupling is
a prose cross-reference, not a call. So site 3 is an exposure in the documentation, not a
contaminated number.

## SITE 4 — a hard-coded `0.0` published as a "predicted rate"

Lines 182–183:

```python
"transport_predicted_rate": float(a * abs(M) * alpha / np.pi)
if grading == "two_scale" else 0.0,
```

Under `one_scale` the key is the literal `0.0` — measured at five different `(a, alpha)` pairs
including `a = 0.9, alpha = 2.0` and `a = 2.0, alpha = 1.9`, it is `0.0` every time, while the
realized fit reads **−0.01832528938761544**. Nothing a caller can pass changes it (lesson 90).

The positive control is the same key under the *other* grading, where it is a real prediction:
`two_scale` reports **0.3166040527477967** against a realized fit of **0.317444646249374** —
agreement to **0.27 %**. So the key means something under one grading and is a placeholder
under the other, with no signal to the reader which one they are holding.

Both return a finite, plausible, *correct-looking* number — it is within 0.004 % of the honest

## SITE 6 — `transport_predicted_rate` ignores `h`

With `h` NaN-poisoned at one node, in a single call: `transport_log_rate` is `nan` (honest) and
`transport_predicted_rate` is **0.3166040527477967** — bit-identical to the clean-`h` value,
because the formula reads only `M` and `alpha`. A finite, unpoisoned number sits in the same
returned dict as the `nan` its input produced.

**Rider, inside frozen probe P8.** At `alpha = −1` the predictor's **sign is wrong**: reported
**−0.22614575196271194** against a fitted **+0.22674693723070877** (the measured quantity
carries an `abs()` the formula does not). And the header's stated working range — "DECAYS for
`alpha < 2`, which is the whole working range" — is left with no flag at all: the stretch rate
grows **567×** from `alpha = 1.4` (`4.6247e-04`) to `alpha = 2.5` (`0.26239`), silently.

## What is SOUND, and it is most of the surface

The gate asked whether the module *ever* corrupts silently, so the sites above answer it. The
rest of the surface held, and it held under probes designed to break it:

* **Non-finite poison propagates through every entry point, with zero absorption.** One NaN,
  one `+inf` or one `−inf` at an interior node: **0 of 21** poisoned calls across
  `profile_mass`, `velocity`, `velocity_log_rate`, `advection_split`, `grading_comparison` and
  `stagnation_point` returned a finite number. The dense `Hmat`/`Vmat` products contaminate
  **801/801** velocity nodes, so there is no partial-contamination path. This is the failure
  mode leg 107 found in `first_integral.py` (a mask that dropped NaN, 397/400 poisoned points
  still certifying) and it is **absent here**.
* **`stagnation_point` does not fabricate a root from a NaN bracket**, even though it could:
  `np.sign(nan)` is `nan` and `nan != 0` is `True`, so a NaN *does* enter the sign-change
  search — and the interpolation then yields `nan`, not a plausible finite `X*`. Verified with
  the poison placed both before (`X = 1.81`) and after (`X = 28.61`) the true crossing at
  `X* = 7.12838418502464`.
* **Four loud failures**, so the battery reached the guards: `grading="two-scale"` (a plausible
  typo) → `KeyError`, `grading=""` → `KeyError`, a wrong-length `h` → `ValueError`,
  `lo = −5` → `LinAlgError` from the least-squares fit on `log` of negative `X`.
* **Control C1 holds exactly.** At `a = 0` every advection quantity is *identically* zero —
  `max|transport| = max|stretch| = 0.0`, all four `transport_at` entries `0.0`, the predicted
  rate `0.0`, and `stagnation_point` returns `None`. The battery does not flag arithmetic.

## Ceiling

Float64, one module, one process; the module's own header says "nothing here is interval-
enclosed and nothing is rigorous". **No link of the `L1 → L4` chain moved**, and nothing here
can move one: every site either under-states a divergence the module reports as a *negative*,
or mislabels a window on a quantity no rigorous step consumes. `test_advection_scope.py`'s six
banked predicates are unaffected — it runs `rho_max = 12` throughout, so it never touches
site 1. The exposure is to future callers using the constructor defaults, and it is recorded
here rather than repaired, because the gate's yes-branch says escalate, do not patch.
