## The G4 clause — the call `DIRECTION.md` left to this leg, and the reasoning

The gate permitted documenting rather than patching the IEEE-754 NaN-comparison clause "if
the fix would be higher-risk than the latent defect it closes — leg author's call, stated
explicitly either way." **It is patched.** The reasoning, recorded in the novelty log
*before* the differential ran so it could not be retrofitted to the result:

The escape exists for fixes that add machinery. This one deletes a footgun and adds nothing.
`RescaledHL.__init__`'s guard was `np.any(np.diff(X) <= 0)`; the repaired predicate is
`np.all(np.diff(X) > 0)`. Those are the *same function* on every finite input. They differ
only on a non-finite gap, where — per SEI CERT NUM07-J and IEEE-754's unordered relation —
"detect the bad case" fails **open** and "confirm the good case" fails **closed**. And the
flip was not optional elsewhere: `velocity()`'s new G1 guard needs exactly this predicate, so
leaving the class laxer than the free function it calls would have manufactured a *new*
inconsistency in the same commit that removed four old ones. The cost is that leg 117's
`test_CHARACTERIZE_nan_defeats_ascending_guard` had to be inverted; it is, in the repair
commit, with both over-rejection controls promoted to assertions.

## The one place leg 117's own prescription was wrong

Legs 150 and 151 both found the escalating leg's prescribed repair predicate dead on its own
pins, so this is now a standing check. Here it half-fired: **leg 117's G1 prescription says
to add "exactly the guard `RescaledHL.__init__` already has"** — and that guard is precisely
the `np.any(d <= 0)` form leg 117's *own* G4 finding shows a NaN defeats. Following the
prescription literally would have imported the blind spot into the fix. Caught in the novelty
pass, before a line was written; the other three prescriptions (G2, G3, G8) are sufficient as
stated, and G8's even ships with an in-module oracle (`scenario2_ic`, which already
propagates, and which leg 117 had already banked as a negative control).

## Repair shape (house template, not invention)

Named error/warning types `HLRescaledDomainError` (subclassing `ValueError`, so the existing
`except ValueError` call sites keep working) and `HLRescaledDomainWarning`; raise-by-default
with an `on_invalid="warn"` opt-in on `velocity()`. Raise-by-default is settled by precedent
rather than taste: `scipy.interpolate.interp1d` raises on out-of-range by default and requires
an explicit opt-in to extrapolate, while `np.interp` — the function this module actually calls
— has no such switch, so the check has to live here. `sinh_grid_at` **rejects** a non-positive
scale rather than silently taking `abs()`: substituting a different input for the one you were
given is the defect class the `target_norm.py`/leg-94 precedent forbids, not a fix.

**The escape hatch is not a courtesy.** Leg 135's finding on `first_integral.py` is that a
repair which makes the escalating leg's battery unrunnable has destroyed the record it was
supposed to preserve. `on_invalid="warn"` therefore returns the *pre-repair number
bit-identically*, and the inverted pins assert that against the git-loaded pre-repair module,
so leg 117's 212.0356 and 1.4712 remain measurable **after** the repair.

object — leg 129 hit exactly that (its `sys.path` put the repaired tree ahead of the extracted
one and the *control* silently reported 0/33 too). So before any identical-count is believed,
`control_two_modules_really_differ` asserts, executably: the pre-repair side lacks
`HLRescaledDomainError` and `_is_strictly_ascending`, the two module objects are distinct, the
pre side **still launders a NaN to 0.0**, and the pre side **still accepts a permuted grid
silently and finitely**. All five hold; if any fails the run aborts and reports nothing. The
same control guards the in-battery differential.

## Residue — declared, not patched, and why

* `RescaledHLDynamic.gauge` and `max_speed_s` call `np.interp(1.0, self.X, …)` and
  `np.interp(0.0, self.X, Hg)`: the **same** silent-clamp shape as G2, at two more sites. Leg
  117 did not measure them and both are unreachable on every shipped grid (which is symmetric
  about `Xc` with `M ≫ 1`, so `X=0` and `X=1` are always interior). Left alone deliberately —
  guarding unmeasured sites is scope creep in the direction the `first_integral`/`nk_bounds`
  legs were repeatedly warned about. Named here so the next audit finds them already listed.
* `_solve_3x3`'s **absolute** `1e-14` pivot threshold still over-rejects a uniformly-tiny but
  perfectly well-conditioned matrix (leg 117's G6 false positive). Over-caution is not
  corruption, it is outside this gate, and rescaling the threshold would be a behaviour change
  on a surface the (4.2) gauge depends on. `test_CHARACTERIZE_solve_3x3_overrejects_tiny_
  wellconditioned_matrix` still pins it, unchanged.
* `sinh_grid_at` with `n < 2` still raises `IndexError` rather than a domain error. Cosmetic,
  visible, not silent; out of scope.
