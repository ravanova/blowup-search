## 1. V1 — a negative `C_sup` produces a negative operator-norm upper bound

`seminorm_closure` does `S = float(C_sup)` (line 227) with no validation. With `S < 0`,
`derivative_bound` returns `P < 0`, and `holder_interpolation_bound`'s guard

```python
if P <= 0.0:
    return 0.0, float("inf")
```

— written for the degenerate `P = 0` case — **swallows the negative `P`** and reports
`T = 0`. The iteration converges on its first iterate, `contraction_slope = 0.0`, and the
function returns `closes: True` with `A_upper = S + T = S`.

| `C_sup` | `closes` | `T_upper` | `P_upper` | `A_upper` | warnings |
|---|---|---|---|---|---|
| `−1.0` | True | 0.0 | −0.003337 | **−1.0** | none |
| `−5.5543` | True | 0.0 | −9.127135 | **−5.5543** | none |
| `−1.0e6` | True | 0.0 | −2003335.087 | **−1.0e6** | none |
| `−1e−12` | — | — | — | **raises** `TypeError: '>' not supported between instances of 'complex' and 'float'` | none |

**The refutation needs no computation:** `A_upper` is a claimed upper bound on
`‖A‖_{Y→X}`, an operator norm, which is `≥ 0` for every operator. `operator_norm_upper`
returns the same negative number.

The fourth row is a *different* failure at a *different magnitude* of the same poison, and
it is worth stating precisely: for small `|C_sup|` the bracket `1 + S + hil` stays positive,
so `P > 0`, and `holder_interpolation_bound` evaluates `(2.0 * S) ** (1.0 - gamma)` on a
**negative base with a fractional exponent** — which in Python is a **complex** number. The
complex iterate then reaches the loop's `nxt > T_cap` comparison and raises. So the
negative-`C_sup` path is unhandled in **three** distinct ways depending on magnitude
(silent-negative, silent-negative, complex-crash), which is the signature of a domain that
was never considered rather than one that was considered and dismissed.

## 2. V2 — a negative anchor speed silently deletes the seminorm part

The derivation solves `c h_X = −g − h X/(1+X²) − H(h)/(1+X²)` and bounds `|h_X|` by
dividing by `c`. `derivative_bound` divides by `c` **signed** (line 200). For `c < 0` the
returned `P` is negative — which is not a derivative bound at all; the correct estimate uses
`|c|` — and V1's `P <= 0` branch again returns `T = 0`. **The entire seminorm part of the
norm vanishes** and `A_upper` collapses to the sup part alone.

| `c` | `closes` | `T_upper` | `A_upper` | warnings |
|---|---|---|---|---|
| `+0.5` (`C_ANCHOR`, the shipped value) | True | 63.821317 | 69.375617 | none |
| **`−0.5`** | True | **0.0** | **5.554300** | none |
| `−1.0` | True | 0.0 | 5.554300 | none |
| `−1e−3` | True | 0.0 | 5.554300 | none |
| `1e−300` | False | inf | — | none |

**Magnitude: at `c = −0.5` — the anchor speed's own magnitude with the sign flipped — the
module claims `‖A‖ ≤ 5.554300` where the same module at `c = +0.5` claims `69.375617`. The
upper bound is understated by 12.4904×, silently.** The `1e−300` row is the control and it
comes out differently: an underflowing-but-positive `c` correctly takes the `T_cap` branch
and reports `closes: False`.

This is the sharpest of the four, because the wrong number is *plausible* — it is exactly
the sup part, a quantity the pipeline genuinely computes — and because `T = 0` reads as
"the seminorm contributes nothing", which is the answer six legs were hoping for.

## 3. V3 — NaN absorption: `closes = True` with `T_upper = NaN`

Both exits of the fixed-point loop are comparisons that are **False** for NaN:

```python
if nxt > T_cap:                        # False for NaN -> cap not tripped
if abs(nxt - T) <= tol * max(1.0, T):  # False for NaN -> never converges
```

A NaN iterate therefore neither trips the cap nor converges; the loop runs its full
`max_iter = 20000` and **falls off the end into the success return**, which has no NaN
check. `C_sup = NaN` and `c = NaN` both give `closes: True`, `T_upper = NaN`,
`A_upper = NaN`, silently.

**The control comes out differently and is why this is a NaN gap and not a magnitude gap:**
`C_sup = +inf` and `C_sup = 1e300` take the `T_cap` branch and are reported **honestly** as
`closes: False`, `reason: "no fixed point: the Hilbert feedback exceeds the interpolation
gain"`. The module handles overflow correctly and NaN not at all. Same class as leg 107's
NaN census on `first_integral.py` (`9c08287`).

## 4. V4 — `required_X0` accepts a negative contraction constant, and the chain fabricates

The acceptance test is `z <= target` with `target = 1`. `Z1` is a **contraction constant**,
so the intended predicate is `0 <= z <= target`; the missing lower side means any negative
`z` passes at the **first** grid point.

| case | `found` | `Z1` | `X0` | `J_needed` |
|---|---|---|---|---|
| `modelling_error < 0` | **True** | **−69.375617** | 100.0 | 78.54 |
| `A_upper < 0` (fed by V1), honest `1/X0` | **True** | **−0.01** | 100.0 | 78.54 |
| `modelling_error = 0` | True | 0.0 | 100.0 | 78.54 |
| `modelling_error = NaN` | False | — | — | — |
| honest control | True | 0.693756 | 100.0 | 78.54 |

**Chained with V1 this fabricates an entire certificate with no warning at any link:**
`seminorm_closure(C_sup = −1)` → `A_upper = −1` → `required_X0` → `found: True`,
`Z1 = −0.01`, `X0 = 100`, `J_needed = 78.54`, `dense_entries = 6168.5` — a complete,
actionable, cheapest-on-the-grid answer built from a quantity that cannot exist. The NaN row
is the control and it comes out differently (`z <= target` is False for NaN, so it walks the
whole grid and reports `found: False` honestly).

## 5. Recorded but NOT counted as violations

**V5 — the module's stated domain is enforced at one of four public entry points.**
`seminorm_closure` **does** raise `ValueError` for `alpha < 1` and for `gamma` outside
`(0,1)`. That answers the question leg 131 (`208c91c`) left open from the other side: leg
131 checked `holder_norms.py` against *this* module's stated `gamma = 1` exclusion and found
it not enforced there; **this module does enforce its own boundary — at that entry point.**
But `derivative_bound`, `hilbert_split_bound`, `interpolation_constant` and
`holder_interpolation_bound` are public, are called directly by `test_nk_seminorm.py` and by
`solver/hilbert_holder.py` (3 sites), and validate nothing: `derivative_bound(alpha=0.5)`
returns a finite `24.885087`, `hilbert_split_bound(gamma=1.0)` returns finite
`(0.578747, 0.642216)`, and `interpolation_constant(gamma)` returns a **complex** number for
`gamma` outside `[0,1]` — `(1−g)**(g−1)` with negative base and fractional exponent — which
propagates into `holder_interpolation_bound`'s returned "bound". Not counted: the complex
returns are loud enough to break any downstream comparison (they are exactly what raises in
V1's fourth row).

**V6 — monotone-from-below iteration with no convergence flag.** `T` starts at `0` and `F`
is increasing, so **every iterate is below the fixed point**. The loop breaks only on the
tolerance test; exhausting `max_iter` falls through to the success return, which carries no
iteration count and no convergence flag. At `max_iter = 1` the module returns
`closes: True`, `T_upper = 23.361926` against the converged `63.821317` — a claimed **upper**
bound that is 2.73× **below** the true fixed point. **Severity measured, not assumed:** at
the shipped default `max_iter = 20000` this is **not reachable** in the tested band — every
`gamma` up to `0.99` converges with relative gap `0.000e+00` against `max_iter = 200000`
(contraction slope `0.989997` at `gamma = 0.99`), and `gamma ≥ 0.999` is reported honestly as
`closes: False` via the `T_cap` branch. The path is reachable only when a caller lowers
`max_iter`. Recorded because the "upper bound" property rests entirely on convergence having
happened and the caller is handed nothing to check it with.

**V7 — the sup is a max over a 120-point truncated log grid.** `hilbert_split_curves` samples
`X` on `geomspace(1e-3, 1e6, 120)` and `derivative_bound` takes `np.max` over the samples. A
max over samples is not a supremum, so the returned `P` — and through it the claimed bound on
`‖A‖` — can only **understate**. This is leg 116's pre-registered clause on `nk_bounds.py`
(`7ab1e37`), inherited verbatim. **Magnitude, reported honestly as small at the shipped
setting:** `n_X = 120` understates the `n_X = 2000` value of `T` by **6.68e−05** relative
(`63.821317` vs `63.825580`). It is not small at coarser resolution — `n_X = 30` understates
by **3.1e−02**. Refining `X_hi` moves the answer **non-monotonically**
(`1e6 → 69.375617`, `1e10 → 69.270860`), which is the grid, not the integrand.

**V8 — `interpolant_far_field_defect` on a malformed window.** `np.linspace(theta_last,
pi − eps, n)` is not required to be increasing; for `theta_last > π` it runs backwards past
`π`, where `cos(θ/2) < 0` and the weight `cos(θ/2)**(−alpha)` is NaN for fractional `alpha`.
NaN `theta_last` gives the same. **It warns** (`RuntimeWarning: invalid value encountered in
power`), so by this leg's own pre-committed decision rule it is **not** a silent violation.
Mismatched `to_coef`/`h` shapes raise `ValueError` — the loud, correct behaviour.

## 7. The positive control, and why it can come out differently (lesson 90)

`test_nk_seminorm.py` runs **6/6 green** on this leg's checkout, and the runner and the
pinned battery both reproduce its banked fixed point independently: `T = 63.821317`,
`A_upper = 69.375617`, `contraction_slope = 0.444517`, fixed-point residual `2.35e−13`
(re-derived in the runner rather than trusted), `kappa*` residual `< 1e−9`,
`C(1/2) = 2` to `4.4e−16`. Had the harness perturbed the module — import order, warning
filters, the `curves` cache — these numbers would move and every violation above would be
suspect. They do not move.
