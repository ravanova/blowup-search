# Leg 100 — Route-HNA: adversarial audit of `solver/holder_norms.py`

**Agent:** LEG-E. **Branch:** `leg/hna-v1`. **Date:** 2026-08-06. **Claim-bearing.**
**Gate answer: YES — a silent-corruption gap, six distinct mechanisms.** Battery banked as
a permanent regression test that PINS the silence. `solver/holder_norms.py` was NOT patched.

## The gate, verbatim

> Under an adversarial battery (NaN/Inf-poisoned weight-class parameters, degenerate
> grading exponents), does `solver/holder_norms.py`'s norm or embedding-constant
> computation ever silently return a finite, plausible-looking wrong value instead of
> propagating or flagging the invalid input?

**YES.** Six mechanisms, each measured against the clean-input value of the same call.

## Scope, stated before the result

Not a Route-D bound-sharpening leg and not new machinery — a robustness stress test of
existing code, the leg-69 (IA) precedent for `solver/interval.py`. No constant is
re-derived, the weighted-ell^1 no-go is not re-scored, the dead B stage is not touched.
`solver/holder_norms.py` is byte-identical to `origin/main`; the gaps are pinned, not
patched. The novelty pass (`writeup/novelty/leg_100.md`, committed before construction)
returned **PROCEED_AS_AUDIT**: every mechanism below is a documented IEEE-754 hazard, so
nothing here is claimed as a discovery — only as an instance located in this code.

## The one mechanism, instantiated five times

**Every NaN compares unordered, so an ordered comparison used as a filter silently DROPS
the poisoned item instead of propagating it.** The module's four filters:

| site | line | guard |
|---|---|---|
| `jacobian_identity_error` | ~126 | `ok = np.abs(mid) * dth <= resolved` |
| `family_op_norm` | ~183 | `if ng <= 0: continue` |
| `family_op_norm` | ~186 | `if r > best:` |
| `holder_H_constant` | ~246 | `if den > 0:` and `best = max(best, ...)` |

plus one initialiser that survives an emptied filter as a plausible answer:
`jacobian_identity_error`'s `worst, xmax = 0.0, 0.0`, where `0.0` means *exact agreement*.

## The measured magnitudes

1. **The module's own self-validation routine certifies a poisoned grid as clean.**
   `conformal_check` on a 128-node grid with `theta[7]`, `theta[64]` or `theta[120]` set to
   NaN returns **1.517287054473293e-04 — bit-identical to the clean grid**, deviation
   exactly 0.0, no NaN, no warning, no exception. Same for the underlying
   `jacobian_identity_error` (5.058518860e-04, identical to the last bit). The docstring
   credits `conformal_check` with catching a wrong seminorm exponent in the first draft.

2. **A grid on which nothing was checked is certified as perfect.**
   `conformal_check(np.full(16, nan), 0.3)` returns **`(0.0, 0.0)`** — worst deviation from
   the exact conformal identity 0.0. Maximally invalid input, maximally reassuring output.

3. **One NaN entry collapses the operator norm to exactly zero.** A single NaN anywhere in
   a 48×48 operator turns **661.207572 into 0.0** (`arg = -1`), a 100% collapse returned as
   a legitimate finite lower bound and numerically indistinguishable from the zero
   operator. The only trace is the `-1` sentinel, which no caller in the repo inspects.

4. **The sharpest case: a poisoned true maximizer is dropped and the runner-up is reported
   as the answer.** Two clean test vectors give **221.978372**; put one NaN into that same
   maximizer and the call returns **105.435714** — a **2.1053× understatement**, finite,
   plausible, `arg` pointing at a perfectly legitimate clean vector. Nothing in the return
   value records that a test function was discarded. Inside the full family (sup
   extremizers on) the poisoned vector is **bit-identical-invisible**: 661.2075718521894
   either way.

5. **The embedding constant is reported as exactly zero.** `holder_H_constant`'s random arm
   returns **0.0** on all four of {NaN grading exponent, γ = −0.3, NaN grid node, Inf grid
   node}, against a clean **0.891421** — i.e. it says the Hilbert transform annihilates the
   Hölder space. Cause: `max(best, x)` is python's *builtin* `max`, and `max(0.0, nan)`
   returns `0.0`. The per-degree arm of the *same function* returns all-NaN on the same
   inputs, so the two arms disagree about whether the input was valid.

6. **The Inf twins are silent too, one warning wide.** Inf cases return the *same* wrong
   numbers and are flagged only by an incidental numpy `RuntimeWarning` — not the module's.
   Under python's default filter it fires **once per source location**: warnings over three
   identical calls are **[1, 0, 0]** with the returned value constant. In any caller that
   has already touched the line, Inf is exactly as silent as NaN.

**Structural cause, measured:** `solver/holder_norms.py` has **0 `raise` sites, 0 `assert`
sites and no `isfinite`/`isnan`/`isinf`/`warn` anywhere**, across 7 public entry points.
Nothing in the module ever asks whether its arguments are finite.

## What is NOT broken (pinned so it cannot be over-read)

The norm objects themselves. `HolderNorm.sup_part` / `.seminorm` / `.__call__` reduce
through `np.max`, which **does** propagate: `alpha=NaN`, `gamma=NaN`, `gamma=-0.5`,
`semi_alpha=NaN` and a NaN grid node all reach the caller as a NaN total norm (clean total
1.728737). The difference between gap 5 and this is one function name: `max` vs `np.max`.

One latent, not live: `decay_weight([0,1,10], alpha=NaN) = [1.0, nan, nan]` — the node
X = 0 keeps an exactly-unit weight by the IEEE-754 `pow(1.0, NaN) = 1.0` special case.
Harmless only because the sup still sees the other NaNs; it goes live the moment anything
evaluates the weight at a single origin node.

**Positive control:** 4/4 structurally malformed calls raise `ValueError`, so every silence
above is the module's, not the harness's. Byproduct: `holder_H_constant` is only callable
at all on grids with `J >= 64` (its random family draws degrees up to 63), an undocumented
precondition enforced by numpy rather than by the module.

## Disposition

Escalated, not patched — the leg's territory forbids editing the module under either gate
outcome. `test_holder_norms_adversarial.py` (17 gates, ~3 s) **pins the current silence on
purpose** and will FAIL the day a finiteness guard lands: **invert it then, keep every
magnitude and flip only the sign of the SIGNAL claim**, exactly as leg 84 did for
`solver/target_norm.py`. Gates 9–11 pin what already works and must never flip.

**Blast radius, honestly stated.** No live certificate in the repo currently feeds NaN into
this module — the gap is a robustness gap, not a retraction of any banked number. What it
removes is the right to treat `conformal_check` as a self-validation gate: it cannot detect
a broken grid, because a broken grid is exactly what its filter discards.

# THE BENCH REPAIR (appended 2026-08-06; everything above is leg 100's, unchanged)

**Branch:** `bench/fix-holder-norms-nan-blind-validation`. **Not a leg.**
**The gap above is CLOSED.** `solver/holder_norms.py` now rejects non-finite and
degenerate input at every public entry point, and `test_holder_norms_adversarial.py` has
been **inverted, not weakened**, exactly as leg 100's disposition instructed.

## What the repair does

One rule, applied at all seven entry points:

> a filter may drop a candidate only for a reason it can **state**; it may never drop one
> merely because a comparison against NaN was False.

Three module-private helpers (`_reject_nonfinite`, `_reject_nonfinite_array`,
`_reject_nonpositive_gamma`, plus `_reject_repeated_nodes`) raise `ValueError` with the
offending name, value, index and the measured consequence. The module went from **0 raise
sites, 0 assert sites, no `isfinite`/`isnan`/`isinf`/`warn` anywhere** to **26 raise sites**
across the same 7 public entry points.

Deliberately NOT guarded: `HolderNorm.sup_part` / `.seminorm` reduce the **caller's data
vector** `h` through `np.max`, which already propagates NaN honestly. Validating `h` on
every call would put an O(J²) scan inside `family_op_norm`'s inner loop to replace an
answer that was already right. Gate 17 of the inverted test pins that this path still
propagates, so the repair cannot quietly convert propagation into silence.

## A seventh mechanism, found while repairing

Leg 100 attributed the builtin-`max` hazard to `holder_H_constant` alone. It also sits at
`jacobian_identity_error` line ~130, where it is reachable **with no NaN anywhere in the
input**:

| input (all finite) | pre-repair returned | clean | factor |
|---|---|---|---|
| one **repeated** node, `theta[64] = theta[63]` | 8.127828757138467e-04 | 5.058518859734074e-04 | **1.6068×** |
| same, through `conformal_check` | 2.4376552996407952e-04 | 1.517287054473293e-04 | **1.6066×** |
| **descending** grid (reversed) — reported coverage `xmax` | **1019.8141148113144** | 1.9094999985985477 | **534.07×** |

Mechanism for the first two: a repeated node gives `dth = 0`, hence a 0/0 finite
difference whose offset-1 contribution is NaN, and `max(0.0, nan)` returns `0.0` — so the
**finest and most informative offset is deleted from the maximum in total silence**. The
third is the same ordered-comparison hazard in the mask itself: a descending grid makes
`dth < 0`, which satisfies `|mid| * dth <= resolved` for *every* pair, switching the
resolution restriction off entirely. That one matters because `test_holder_norms.py`
prints `xmax` as "verified out to X=…", i.e. the false number is a **coverage claim**.
