# BLOG — what a norm that can come back negative buys you

`solver/nk_fourier.py` is the file where the Route-D dress rehearsal actually lives: the
Fourier-basis form of the a=0 gCLM two-scale operator, its Jacobian in closed form, the
weighted ℓ¹ norms, and at the bottom the radii polynomial that decides whether a
Newton–Kantorovich ball closes. It has a good known-answer test file — six gates, an exact
anchor, a finite-difference Jacobian check, a grid cross-check. Every one of those six gates
hands the module input that is *correct*.

Nobody had ever handed it input that was *wrong*.

The novelty pass went first and came back with a useful constraint: there is nothing new to
discover here. The radii-polynomial theorem hypothesises its constants **positive** — they each
bound a norm, so nonnegativity is not a convention but part of the statement. Galerkin
truncation is textbook. Grey-box auditing of a library by injecting NaN and ±inf is published
method (there is a 2026 paper doing exactly this to differential-privacy libraries). A
weighted ℓ¹ space is only defined for a positive weight. So this leg could not claim a
discovery; it could only claim **magnitudes**. That is what it has.

**Five things.** The first is the family one. `radii_polynomial` checks exactly one of its four
hypotheses — `Z2 > 0`. Feed it a negative `Y₀` and it reports `closes=True` with a **certified
radius of −706.93**. A negative radius is not a subtle failure; it is a ball that cannot exist,
returned as a certificate, and the module never looks at the sign of the number it just
computed. Feed it a forbidden `Z0 = Z1 = −9` and the "certification budget" `Y0_max` — the
quantity the dress rehearsal quotes as *the* number deciding whether certifying a profile is
even arithmetically conceivable — inflates by **361×**. Nine out of nine forbidden
`(Y₀, Z₀, Z₁)` tuples close. NaN and inf, to the module's credit, are absorbed into an honest
refusal.

The second is the one I did not expect. `weighted_ell1_op_norm` divides by a caller-supplied
domain weight and never checks its sign. On the module's **own gauged Jacobian**, whose honest
ℓ¹ operator norm is **7.0**, a weight of `−1` returns **−1.251**. A norm. Negative. No warning,
no exception, a plain float that the caller will happily use as `Z₀` or `Z₁`. A mixed-sign
weight under-reports 6.75 as 4.25. A zero weight returns `inf`; an infinite weight returns
`0.0`.

Chain those two and you get the load-bearing case, built entirely out of this module's own
objects. Take the finite-section gauged system at N=8. Its exact zero is the anchor. Plant a
non-solution 10⁻³ away from it. Hand the certificate a deliberately wrong approximate inverse,
`A = −J⁻¹` — and the module does the right thing: the honest `Z₀ = 2`, the contraction budget
is negative, **it refuses**. That refusal is the control, and it is a control that can come out
the other way. Now push the *same matrix* through `weighted_ell1_op_norm` with the forbidden
weight `w = −1`. `Z₀ = −2`. The contraction budget becomes 3, the polynomial closes, and it
hands back a certified ball of radius 3.34×10⁻⁴ — a ball that lies inside the honest
uniqueness ball, excludes its only zero, and therefore **provably contains no solution at all**.
It misses the true zero by **1.99 ball radii**.

The remaining three are smaller and more specific. `ell1_op_norm` applied to a 1-D array reads
it as a row functional rather than a coefficient vector, so it returns `max|vₖ|` where the
caller wants `Σ|vₖ|` — an under-report by a factor of **n**, up to 1024× on a flat vector.
Both readings are mathematically correct for their own object, which is precisely why nothing
warns. `kernel_directions(1)` silently drops the dilation direction's second component (it
lives at index 2, behind an `if N >= 2`) and returns a vector that is **not** in the kernel,
while its own docstring still calls it exact: the residual is 0.0625, which is **6.25×10¹²
times** the tolerance its own known-answer gate uses at N=10 — and that gate only ever runs at
N=10. And `residual`'s `if w == 0.0: continue` fast path cannot skip a NaN, so a zero profile
with an infinite speed comes back with 7 NaN modes out of 12 where the honest answer is
identically zero.

**All of it is latent.** This matters and it is part of the finding, not a softener. Every
in-repo caller was traced: `p2_route_d_dress.py` forms `Y₀` with the correct ℓ¹ sum, never
imports `weighted_ell1_op_norm` at all, applies `ell1_op_norm` only to genuine matrices, starts
its N-ladder at 4, and compensates the Galerkin truncation with an explicit untruncated tail
term. No banked number in this repository is wrong. The finding is about what the module would
*accept*, not about what it has *produced*.

**And the honest ceiling** (Directive 3): this moves no link of the L1→L4 chain. It is an audit
of code that computes a structural negative, and the structural negative — the far field of
this operator is exactly marginal, so the radii polynomial cannot close at any truncation —
survived the audit untouched. The live path still reports "does not close", which the battery
asserts as a regression test.

## §4 `radii_polynomial` — the shared Y0/Z0/Z1 class

Published hypothesis (novelty pass Q1, re-derived independently of leg 116): the theorem is
stated with **positive** `Y₀, Z₀, Z₁` and `Z₂: (0,∞)→(0,∞)`, each bounding one of `‖AF(x̂)‖`,
`‖I−AA†‖`, `‖A(DF(x̂)−A†)‖`, `‖A(DF(x)−DF(x̂))‖` — norms, hence nonnegative by construction.

The code validates `Z2 > 0` and nothing else:

```
one_minus_Z = 1.0 - Z0 - Z1
disc  = one_minus_Z**2 - 4.0*Z2*Y0
closes = bool(one_minus_Z > 0.0 and disc >= 0.0 and Z2 > 0.0)
```

26 tuples were fed (22 forbidden, 4 admissible). 11 forbidden tuples close. The sharpest is
not "it closes" but the *shape of what it returns*:

| input | `closes` | `r_min` | `1−Z` |
|---|---|---|---|
| `Y₀ = −1e−3` | True | −1.4228e−3 | 0.7 |
| `Y₀ = −1` | True | −0.55344 | 0.7 |
| `Y₀ = −1e6` | True | **−706.93** | 0.7 |
| `Z₀ = −1` | True | 5.5590e−4 | 1.8 |
| `Z₀ = −9` | True | 1.0204e−4 | 9.8 |
| `Z₁ = −9` | True | 1.0101e−4 | 9.9 |
| `Z₀=Z₁=−1` | True | 3.3341e−4 | 3.0 |
| `Y₀=Z₀=Z₁=−1` | True | −0.28078 | 3.0 |
| `Y₀=−1, Z₂=inf` | True | **nan** | 0.7 |
| `Z₂ = 5e−324` | True | **0.0** | 0.7 |

`r_min < 0` is a self-evident tell available for free — the module computes it and does not
look at it. So are the last two rows: `closes=True` alongside `r_min = nan`, and `closes=True`
alongside `r_min = 0.0` (a ball of zero radius), both reported as certificates. NaN or inf in
`Y₀`, `Z₀`, `Z₁` alone closes nothing — the `disc >= 0` comparison is False for NaN. The two
edge rows come from the *one* check the module does make being the wrong shape: `Z2 > 0` is
true for `Z₂ = inf` (so `disc = 0.49 − 4·inf·(−1) = +inf ≥ 0`, `closes=True`, and
`r_min = (0.7 − inf)/inf = nan`) and true for the smallest denormal `Z₂ = 5e−324` (so
`r_min = 0.0`, `r_max = inf`, and the certification budget `Y0_max = inf`). A positivity test
that does not also test finiteness admits both ends of the float range.

**Budget inflation.** `Y0_max = (1−Z₀−Z₁)²/(4Z₂)` is a pure function of the Z's, unvalidated,
and `p2_route_d_dress.py` quotes it as the certification budget:

| (Z₀, Z₁) | `Y0_max` | inflation |
|---|---|---|
| (0, 0) | 0.125 | 1× |
| (−1, 0) | 0.5 | 4× |
| (−1, −1) | 1.125 | 9× |
| (−9, −9) | 45.125 | **361×** |

**This is the same guard class as legs 79/98/116**, and stating it that way is the gate's own
instruction. It is a fourth instance of an **open** class — leg 128 has not landed — and leg
128's shared validator would close it with no module-specific work.

## §5 `weighted_ell1_op_norm` — a norm that returns negative

```
cols = (np.abs(M) * w_cod[:, None]).sum(axis=0)
return float((cols / w_dom).max())
```

`w_cod` enters unsigned-absolute-free and `w_dom` divides. ℓ¹(w) requires w > 0.

| weight | returned | honest (|w|) |
|---|---|---|
| `w_dom = +1` | 6.75 | 6.75 |
| `w_dom = −1` | **−4.0** | 6.75 |
| `w_dom` mixed sign | **4.25** | 6.75 |
| `w_dom = 0` | **inf** | — |
| `w_dom = nan` | **nan** | — |
| `w_dom = inf` | **0.0** | — |
| `w_cod = −1` | **−4.0** | 6.75 |
| `w_cod = 0` | **0.0** | — |
| wrong length | *raises* | — |

On matrices the module builds itself, at N=8 with a 10⁻³ perturbation of the anchor:

| matrix | honest (w=+1) | w = −1 |
|---|---|---|
| gauged Jacobian `J` | 7.0 | **−1.251** |
| approximate inverse `A` | 7.818 | **−1.0006** |

The `max` over columns of a uniformly negative set picks the *least* negative entry, so the
returned value is `−min_k(weighted column sum)` — not merely a sign flip of the honest norm,
which is what makes it usable as a small negative `Z₀`/`Z₁` rather than an obvious absurdity.

## §6 `ell1_op_norm` on a 1-D array

`np.atleast_2d` promotes a 1-D array to shape (1, n) — a **row**, i.e. a functional — whose
induced ℓ¹→ℓ¹ norm is `max_k |v_k|`. A caller holding a coefficient **vector** wants `Σ|v_k|`.
Both are correct for their own object; the routine cannot see which one it was handed.

| n | returned | true ‖v‖₁ | factor |
|---|---|---|---|
| 2 | 1 | 2 | 2× |
| 16 | 1 | 16 | 16× |
| 256 | 1 | 256 | 256× |
| 1024 | 1 | 1024 | **1024×** |

On the vector the dress rehearsal actually forms for `Y₀` (`A @ G`, whose mass is concentrated
in one mode) the factor is a mild **1.0072×** at N=256 — the honest magnitude, and the reason
this is a *hazard* rather than an active corruption. The routine is exact on a genuine 2-D
matrix, which is how every live caller uses it.

## §7 Truncation: measured, and NOT called a defect

Per novelty-pass constraint 3, Galerkin projection is textbook and is reported as magnitude
only. `residual(a, c, M=N)` discards modes N+1…2K:

| N | ‖full‖₁ | discarded | fraction |
|---|---|---|---|
| 4 | 1.023 | 0.0309 | 3.02 % |
| 16 | 17.04 | 0.561 | 3.29 % |
| 64 | 269.4 | 9.194 | **3.41 %** |

`jacobian(a, c, M)` with an undersized M under-reports `‖DF‖_{ℓ¹}` by 5.0× at M=2 and 2.0× at
M=4 (full 5.0). **Tagged `NOT-A-DEFECT`**: the docstring says "pass M to truncate
deliberately", and the one live caller passing a small M does so to isolate the finite-section
block on purpose and compensates the tail explicitly.

**The single exception, and the only truncation this leg calls a defect**, is
`kernel_directions(N)`, whose docstring asserts exactness:

> "The two exact tangent directions of the a=0 scaling valley at the anchor … Both are
> annihilated by the un-gauged `[DF | dF/dc]`"

The dilation direction is `(1/8, 0, −1/8, 0, …)`; the `−1/8` sits at index 2 behind `if N >= 2`.

| N | worst `‖[DF|dF/dc]v‖_∞` | verdict |
|---|---|---|
| 0 | 0.0 | **vacuous** — `J` and `dF/dc` are *identically zero*, so annihilation cannot fail |
| **1** | **0.0625** | **not in the kernel**, docstring says it is |
| 2, 3, 5, 10, 40 | 0.0 | genuinely exact |

0.0625 is **6.25×10¹²** times the `1e-14` tolerance `test_nk_fourier.py` gate (3) uses — and
that gate runs at N=10 only. The N=0 row is recorded as *vacuous* rather than as a pass, which
is lesson 90 applied to my own battery.

Relatedly, `anchor(0)` returns `[-0.5]`, which is **not** Ω₂ = −(1+cos θ)/2 — the a₁ term is
dropped. Its residual is still exactly 0, but for the unrelated reason that every constant
profile is an exact traveling wave: a known-answer check that cannot fail there.

## §8 `tail_weight_obstruction` off its hypothesis, stated with the mechanism

The docstring proves no **positive** weight achieves uniform z_w < 1. Off that hypothesis:

| weight | sup z_w |
|---|---|
| `w = k` (affine u) | 1.0 |
| `w = k(1+k)` | 1.0 |
| `w = k²` | 1.0 |
| `w = e^{−k}` | 2.8409 |
| `w = −k` | **1.0** |
| `w ≡ 0` | **nan** |
| `w = 0` at one mode | **inf** |
| `w = k(−1)^k` | **−1.0** |

The `w = −k` row needs care, and lesson 90 is the reason. `z_w = (u(k−1)+u(k+1)) / (2u(k))` is
a ratio of linear functionals of w, hence **homogeneous of degree 0** — `w` and `−w` *cannot*
differ. Reporting "a negative weight gives the same answer as a positive one" as a surprise
would be reporting a tautology of the algebra. The correct statement is that the formula is
structurally blind to the sign of its own weight, and the *informative* rows are
`w = k(−1)^k → −1.0` (a negative column weight, silently) and the zero-weight rows
(`nan` / `inf`, silently). All four are unflagged.

## §9 The load-bearing case

Entirely inside this module's own objects. N=8, c=1/2, gauge `origin`, float64.

1. `a* = anchor(8)` is an **exact** zero of the gauged finite section: `‖G(a*)‖₁ = 0.0`.
2. `x̂ = a* + 10⁻³·e₄` — a planted non-solution at ℓ¹ distance **10⁻³**.
3. Honest certificate with `A = J⁻¹`: `Y₀ = 1.0016e−3`, `Z₀ = 3.97e−15`, `Z₂ = 15.636`,
   **closes**, `r_min = 1.0177e−3`, `r_max = 6.2935e−2`. So `a*` lies in the existence ball,
   and NK uniqueness makes it the **only** zero in `B(x̂, r)` for r in the negativity interval.
4. **The control.** With the deliberately wrong inverse `A = −J⁻¹`, the honest
   `Z₀ = ‖I − AJ‖ = 2.0`, the contraction budget is negative, and the module **REFUSES**. This
   is the assertion that can come out the other way.
5. **The fabrication.** The *same* matrix `I − AJ` through `weighted_ell1_op_norm` with
   `w_dom = −1` gives `Z₀ = −2.0`. Now `1 − Z₀ − Z₁ = 3.0`, and the polynomial **closes**:
   `r_min = 3.3443e−4`, `r_max = 0.19152`.
6. **The exclusion.** `r_min_fab = 3.3443e−4 ≤ r_max_honest`, so the fabricated ball sits
   inside the honest uniqueness ball; and `dist(x̂, a*) = 10⁻³ > r_min_fab`, so it excludes the
   only zero in there. **The certified ball therefore contains no zero of the gauged system**,
   missing the true one by **1.990 fabricated radii** (ratio dist/r_fab = **2.990**).

Float64 throughout: this demonstrates the *code's* behaviour, not a theorem about the operator.
