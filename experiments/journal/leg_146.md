## The correction the novelty pass made, before the battery rather than after

`DIRECTION.md` §146's thesis states this module "supplies the shape/class enumeration
that leg 54's battery and leg 58's theorem both range over", and builds its threat model
on that: a bug here could hole leg 126's "1,686 configurations, zero uncovered" count
without 126 detecting it. **The premise is false, and it is measured false rather than
argued** (CSA8):

* `SHAPES` — the seven-shape enumeration — is declared **once**, at
  `experiments/p2_route_mm_v1_shape.py:134` (leg 54's own runner).
* Leg 58 (`p2_route_ng_v1_nogo.py`) and leg 126 (`p2_route_bx_v1_stageb.py`) both
  **import** it: `from p2_route_mm_v1_shape import ADMISSIBLE, SHAPES, ...`.
* Legs 54, 58 and 126 import **0 names** from `solver/certificate_shapes.py`. There is
  no code path from the module under test into leg 126's count, so none of CSA1–CSA7
  can reach it.

So the direction's stated threat model has no mechanism. Rather than declare the clause
vacuous, the audit put the completeness question that *does* survive: membership cannot
drift because it is imported, but the **A21 partition** of those shapes is hand-written
**twice** — leg 58's `IN_CLASS`/`OUT_OF_CLASS` and leg 126's `a21_of_shape` — and leg
126 uses its copy to drop inconsistent `(shape, A21)` pairs from the product it
enumerates. A disagreement there would move the 1,686 directly. That is the real risk
and it is what CSA8 measures.

## The seven silent-corruption sites, as magnitudes

Every number below is in `writeup/data/p2_route_csa_v1_adversarial.json` and is
re-derived independently by `test_certificate_shapes_adversarial.py`.

**CSA1 — `is_counterexample` has no schema check.** Of seven malformed descriptors
applied to a row that IS a counterexample under the module's own predicate, **3 of 7
silently reclassify it as not-one**; the other 4 are caught, but only incidentally and
one function later, by `gate_answer`'s row-summary block using `r[...]` — the predicate
itself never objects. The three silent ones are `np.bool_(False)`, `0`, and a
lower-cased `"shift"`. The numpy case is the load-bearing one: the predicate tests
`row.get("tail_inverse_decays") is False`, an **identity** check, and
`classify_operator` is the function in this same module that *computes* that quantity.
The gate's banked answer is "no", so every one of these is invisible against the
expected result, while `n_rows_examined` still counts the row as examined evidence.

**CSA2 — one optional key stands between a fictitious row and the published record.**
`real_ledger()` filters on `r.get("is_fictitious", False)`. Delete that single key from
the shipped control row — whose own `note` reads "CONTROL ROW. Never counted as
evidence." — and Route-XS's gate flips **NO → YES**, citing `SYNTHETIC_CONTROL` as a
published counterexample with `arxiv: None` and `url: None`. The standing guard does not
catch it: `unlocated_rows` reports **0 flagged**, because it rejects a `where` that is
empty or contains "abstract", and this row's `where` is the non-empty string
`"(none -- this row is a control and cites nothing)"`. The row also carries a
`counterexample: True` field that **no function in the module reads** — the redundancy
that could have caught the drift is dead code.

**CSA3 — the two location guards are not the same guard.** `cp_unlocated_rows` requires
a non-empty `quote`; `unlocated_rows` never looks at `quote` at all. Of four mutations,
`unlocated_rows` misses **4/4** — including the two (`quote := ''`, `quote` deleted)
that its own sibling catches on the identical mutation. It also misses `where` values of
`"(none)"` and `"p. 3"`, neither of which names a section/assumption/proposition as the
module's own comment requires, and it **falsely flags** a legitimate section title,
`"section 2 (the abstract setting), Lemma 2.4"`, because the test is a substring match.

**CSA4 — `cadiot_covers` reasons from absence.** `covered = (not failing) or
bool(relaxed)`. An **empty scope answers "yes"** — Cadiot's construction covers our
operator — on **0 clauses examined**, inverting leg 62's banked answer on zero evidence.
An empty scope is indistinguishable from a scope every clause of which holds. The
sibling has the mirror-image weakness with the opposite sign: `gate_answer(rows=[])`
reproduces the banked **"no" over 0 rows**, so an upstream filtering bug would be
invisible against the expected result. Separately, a clause whose value is `None`
(unknown) is silently counted among `clauses_that_fail_for_our_operator` — an unknown is
tallied as evidence for the banked answer, 6 of 6.

**CSA5 — `bdl_admissible` drops a modulus.** BDL's assumption (5), quoted verbatim in
this module's own `SHAPE_LEDGER` row, bounds `|lambda_k/mu_k|, |beta_k/mu_k| <= delta <
1/2` — a modulus. `bdl_delta` returns the **signed** `1/(2 mu)` and `bdl_admissible`
compares it to `0.5` with no `abs`. Over a 13-point sweep, **4 are misclassified, all of
them `mu < 0`**; the worst is `mu = -0.001`, where `delta = -500.0` is reported
**admissible** against a threshold of `0.5` — `|delta|` exceeds it by **1,000×**.
`classify_operator`'s exported `shape` is a pure function of this predicate, so an
anti-dissipative operator is labelled `MULTIPLIER`: the word at the **opposite end of
this module's own shift-to-multiplier dial**.

**CSA6 — `max(0.0, nan)` is `0.0`, and `0.0` means "already dominant".**
`cadiot_shift_requirement` ends `sqrt(max(0.0, float(np.max(r**2/4 - lam**2))))`. With a
NaN anywhere, `np.max` is NaN, `nan > 0.0` is False, and Python's two-argument `max`
keeps its first argument. On the matrix this repository actually built
(`tail_block(K=8, M=512, mu=0)`), the clean value is **255.0** — Lemma 3.2's shift grows
linearly in the truncation, so no finite shift survives the limit, which is leg 62's
whole finding. **4 of 5 poisons return exactly 0.0**, and the function's own docstring
states that "0.0 means the unshifted matrix is already dominant". The NaN is not merely
absorbed; it is reported as the one value that says **Cadiot's Lemma 3.2 needs no shift
at all**. One level up, `shift_requirement_ladder` sees a zero rung, refuses the
exponent, and sets `saturates: True` — flipping the verdict word from `False` (clean,
exponent `+1.0085`) to `True`, which is precisely the verdict leg 62 measured for
Cadiot's **own Whitham operator**, i.e. the positive control's answer produced from a
poisoned version of ours. The fifth poison (`+inf`) returns `inf` and is loud.

**CSA7 — a guard exists in one function and is missing in its sibling thirteen lines
later.** `decay_exponent` refuses a non-positive or non-finite rung by name
(`"non-positive or non-finite rung"`). `m_divergence` does the same log-log fit with **no
guard at all**, and `classify_operator` turns that fit into the branch that decides
whether the operator is treated as invertible or as needing leg 52's bordering. At
`mu = 1.0`, an operator whose tail block genuinely IS boundedly invertible:

| field | clean | one NaN rung |
|---|---|---|
| `M_exponent` | `+2.377e-16` | `nan` |
| `tail_block_boundedly_invertible` | `True` | `False` |
| `needed_bordering` | `False` | `True` |
| `K_exponent` | **`-0.8089`** | **`+0.2659`** |
| `tail_inverse_decays` | `True` | `False` |
| `shape` (exported label) | `TRIDIAGONAL_DOMINANT` | `TRIDIAGONAL_DOMINANT` |

`nan < 0.25` is False, so the operator is silently routed down the not-invertible branch
and measured **bordered** — leg 52's `mu = 0` object — while the exported `shape` label,
computed from `mu` alone, still reads the `mu > 0` word. **The sign of the module's
headline dichotomy inverts**, from "the tail inverse decays as the split moves out"
(what a radii-polynomial tail estimate needs) to "it grows", on the exact input its
sibling function refuses by name. The label and the measurement disagree, and only the
disagreement is silent.

## For whoever repairs this module

The seven sites are independent and none of them is a tolerance question. Four are one
line each (`abs` in `bdl_admissible`; a finiteness guard in `m_divergence` mirroring the
one already written in `decay_exponent`; a NaN check before `max(0.0, ...)` in
`cadiot_shift_requirement`; a `quote` check in `unlocated_rows` mirroring the one
already written in `cp_unlocated_rows`). Two are a schema validator over ledger rows
(CSA1) and a required rather than optional `is_fictitious` (CSA2). One is a change of
polarity: `cadiot_covers` should require every clause to *hold* rather than infer
coverage from the *absence* of failures, so an empty scope refuses instead of answering
"yes" (CSA4). **In four of the seven cases the correct code is already present
elsewhere in the same module** — the repair is to make the siblings agree, not to invent
anything.
