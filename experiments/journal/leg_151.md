## 2. The finding that changed the leg: the prescribed predicate is not the right one

Leg 115's journal prescribes, verbatim:

> `gauged_jacobian`/`graded_inverse_norm` should raise (or otherwise flag) when `rows` is empty
> (i.e. `J <= 1`) rather than silently proceeding with a gauge-only system

Measured on the pre-repair module at `J = 1`, over exactly the five `drop` values leg 115's own
`check_J1_ignores_drop_and_gauge` pins:

| `drop` | `len(rows)` | `rows` empty? | caught by the prescription | `graded_inverse_norm` |
|---|---|---|---|---|
| `0`   | 0 | **yes** | ✅ | `1.681792830507429` |
| `1`   | 1 | no | ❌ | `1.681792830507429` |
| `-1`  | 1 | no | ❌ | `1.681792830507429` |
| `5`   | 1 | no | ❌ | `1.681792830507429` |
| `100` | 1 | no | ❌ | `1.681792830507429` |

**1 of 5. Four of leg 115's own pinned cases would have survived a repair that did exactly what
leg 115 asked for**, and clause (a) of this leg's gate ("with every PIN inverted") would have
answered **NO**.

**The mechanism, measured not argued.** Emptiness of `rows` is a coincidence of `drop = 0`, not
the cause. The cause is the **assignment target**: `M[1:, :]` has shape `(J-1, J)`, which at
`J = 1` is `(0, 1)`, and NumPy broadcasts a right-hand side of shape `(1, 1)` into a `(0, 1)`
destination without complaint — a length-1 axis broadcasts to *any* length, including zero. So
the Jacobian is discarded whatever `rows` contains, `M` is the gauge row alone, and the gauge
row (`GAUGES["origin"]`/`GAUGES["a0"]`) reads only `col.to_coef`, which depends on neither `om`
nor `c`. That is the whole of G1, and it is why the answer is a function of `alpha` alone.

The predicate therefore had to be a **shape invariant** — `len(rows) == J - 1 >= 1` — with both
clauses measured necessary: `J >= 2` catches `(J=1, drop=0)`, which the length clause alone
admits (`0 == J-1`); `0 <= drop < J` catches the other four. This is the same move leg 130 made
against leg 106's proposed innermost-node predicate. **Twice now, a finding leg's prescribed
predicate has failed on measurement, and both times the novelty pass caught it before the
patch** — which is the concrete argument for the "novelty pass FIRST" rule, on a leg where the
pass had no literature to overturn.

`drop = -1` is not "the last row" here and never was: `[j for j in range(J) if j != -1]` retains
all `J` rows. At `J >= 2` that already raised `ValueError` from the shape mismatch — loud, if
accidental. The guard only names the refusal.

## 5. Controls, and what would have had to change for them to report otherwise (lesson 90)

Three executable controls; the run raises `SystemExit` and is **VOID** if any fails.

1. **Identity.** The two modules must be distinct objects: pre `188` lines with **0** `raise`
   statements and **no** `DecayCollocationDomainError` symbol, post `298` lines with it. Guards
   against the leg-129 trap of accidentally comparing the repaired tree with itself.
2. **Must-move.** The pre-repair arm must **reproduce** leg 115's banked `1.681792830507429` on
   19/19 cases at exactly **1 distinct value**. If the harness were dead this would report zero
   and the run would void instead of quietly declaring success.
3. **Wrong-predicate.** Leg 115's prescribed predicate and the landed one are evaluated as
   functions over **25 rows spanning both regimes** — the 5 degenerate `J = 1` cases *and*
   ordinary shipped grids `J ∈ {2, 8, 64, 1000}` where the landed predicate must come out
   **False**. Measured: prescribed **1/5**, landed **5/5** on the pinned cases, and the landed
   predicate **does not refuse on 16 of the 25 rows**. That last number is the point: a control
   evaluated only at `J = 1` would have been constantly `True` and a tautology of how it was
   written — which is exactly lesson 90, applied to my own measurement. It is asserted, so the
   run voids if the landed predicate ever refuses everything.

## 6. Honest limits

* **No physics moved and nothing was sharpened.** Every number here is either a statement about
  code behaviour on degenerate input, or a bitwise identity on clean input. The `1672/1672`
  is the *absence* of a result. No banked Route-D quantity is impeached, re-derived or improved,
  and **no link of the `L1 → L4` chain moved.**
* **0 banked numbers were ever at risk.** Leg 115 measured that, and this leg re-measured it
  independently (census: 336 shipped configurations, 0 refused). The repair closes **latent**
  defects — a statement about the grid sizes, array shapes and parameter types in use *today*,
  not a property of the code that would survive someone calling `Collocation(1)`. The value of
  the patch is that it now *is* a property of the code.
* **`n_quantities` counts comparisons, not independent facts.** 1672 is a coverage figure over a
  configuration product; many entries share underlying arrays (e.g. `w_domain` at 9 alphas on
  one grid). It is reported as breadth of the no-op check, not as 1672 independent tests.
* **The inverse arm stops at `J = 1000`, the cheap arm reaches `J = 2000`.** `graded_inverse_norm`
  is `O(J³)` and the banked ladders' top rung (`2000`) is covered for every quantity *except*
  the dense inverse. Stated rather than papered over: if the guards could move a value, the
  mechanism would be visible at every `J`, since they are pure input validation on paths that
  do not touch the arithmetic — but that is an argument, and the measurement is `J <= 1000`.
* **G2's guard is strictly wider than G2's finding.** It refuses mis-sized *2-D* arrays too, not
  only the ambiguous 1-D case. No in-repo caller passes either, so the widening costs nothing
  measured — but it is a widening, and it is named here rather than hidden in the diff.
* **No BLOG/TECHNICAL pair and no registered figure**, matching this leg's declared territory
  and the direct precedent: leg 130 (`Route-HPR`), the repair this one is modelled on, shipped
  novelty + journal + runner + data and no figure, as did legs 69/115/116/120. There is nothing
  here a figure would show — the result is that a curve did **not** move.
