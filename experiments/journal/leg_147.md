## 1. The finding, in one paragraph

The repair is **sound and non-regressive**: nothing clean moved by a single bit, every gate on
both sides passes, and the 17 rejections are real and independently reproduced. The gate fails
only because it asked for 21 and the answer is 17 — a shortfall **leg 128 itself disclosed** and
banked as two honest `test_still_a_gap_*` gates. What this leg adds is that **`capabilities.py`'s
one-phrase description of the residue is true but flattening**. The ledger says the 4 survivors
"supply constants that are nonnegative and finite, i.e. that SATISFY the theorem's hypotheses and
lie about a MAGNITUDE, which no hypothesis guard can detect". That is correct about all four as
*inputs*. As *outputs* they split two ways, and the split is what a caller sees:

* **3 of 4** (`P02_Y0_fabricated_zero`, `P09_Y0_tiny_fabricated`, `A05_Y0_zero_fabricated`)
  return `closes=True` **with `degenerate_ball=True` and an explicit `reason` string**. All three
  have `r_min` exactly `0.0`. A caller that reads `degenerate_ball` is warned.
* **1 of 4** (`P06_Z2_shrunk_1e-6`) returns a **positive-radius** certified ball,
  `r_min = 0.50000035`, with `degenerate_ball=False`, `reason=None`, `violations=None` —
  **no signal of any kind.**

So the honest residue is not "4 undetectable magnitude lies" uniformly; it is **3 flagged
degeneracies and 1 silent positive-radius certificate**. That one case is the leg's finding.

## 2. `P06_Z2_shrunk_1e-6`, anatomised — magnitudes, not adjectives

Substrate is leg 116's: `F(x) = x² − 2` on `ℝ`, planted non-solution `x = 1.0` (residual `1.0`,
distance to the nearest true zero `0.41421356`). Honest constants at that centre give
`Y_0 = 0.35714286`, `Z_0 = 0.28571429`, `Z_1 = 0`, `Z_2 = 0.71428571`.

| quantity | honest | with `Z_2 = 1e-06` |
|---|---|---|
| `Z_2` | `0.71428571` | `1e-06` — understated **714 285.7×** (**5.854 decades**) |
| contraction budget `Y0_max = (1−Z_0−Z_1)²/(4Z_2)` | `0.17857143` | `127 551.02` — inflated **714 285.7×** |
| `closes` | **`False`** (honest `Y_0` is **2.0×** its own budget) | **`True`** |
| `r_min` | `nan` | `0.50000035` |
| `degenerate_ball` / `reason` / `violations` | — | `False` / `None` / `None` |

The mechanism is exact and unglamorous: `Z_2` is the **denominator** of the contraction budget,
so understating it by a factor buys budget by the same factor, and `1e-06` violates no hypothesis
— it is finite and strictly positive. A hypothesis guard is the wrong instrument for it, which is
precisely what `certificate_guards.py`'s own docstring says it is and is not for. **This is not a
defect in the shared guard.** It is the honest boundary of the guard's reach, and the leg's point
is that the boundary is currently described in a way that makes it sound uniformly harmless.

**Why it is still not a rescue, stated against myself (lesson 76).** The ball
`[0.49999965, 1.50000035]` **does** contain `√2 = 1.41421356`, so the *conclusion* this
certificate draws is true. But it is true by accident of a ball of radius `0.50000035`
(diameter `1.0000007`) thrown around a point whose residual is `1.0` and which sits `0.41421356`
from the nearest zero — not because anything was certified. This is Route-D v6's banked
**discrete-ball trap**: a bound that is true and useless. The defect is that the module returns it
with the same silence it returns an earned certificate with. `test_nk_bounds_postrepair.py`
pins exactly that, and the JSON records the containment fact alongside the complaint so nobody
can later read this leg as claiming a false certificate was produced. It was not.

**Reachability, the honest ceiling.** `Y0_passed_by_every_in_repo_caller` is `0.0` and all three
in-repo callers (`p2_route_d_v6_bounds.py`, `p2_route_d_v8_quadratic.py`,
`p2_route_d_v10_lower.py`) compute `Z_2` from the module rather than passing a shrunken one.
**The residue is LATENT: 0 of 3 in-repo callers can reach it, and 0 banked numbers are impeached.**

## 3. The harness, and a second finding nobody was looking for

DIRECTION.md asked for the re-run to come "from the battery's own driver, not the repair's
bundled self-report". **Leg 116's battery does not survive contact with the repaired module.**
`experiments/p2_route_nka_v1_adversarial.py` was not touched by the repair — it still imports the
live module — and it aborts in ~0.9 s, before writing anything:

```
ValueError: farfield_modelling_error_bound: alpha is 2.0, outside the required range [-inf, 2.0)
                                       (p2_route_nka_v1_adversarial.py:425, family_B)
```

So the repair landed a guard that the battery it was built against cannot run past, and **nobody
noticed, because nobody re-ran the battery.** That is the second finding, and it is the same
shape leg 131 found for `holder_norms.py` — which suggests it is a pattern of this repository's
repair legs rather than a fact about either module.

The blast radius is **exactly one loop**. `family_P` (10), `family_A` (27),
`family_B(out_alphas=())` (56) and `family_C` (8) all run clean = 101 of the banked 105. The
missing 4 are the **B2** loop, the only place in the battery calling a now-guarded producer
**bare**, outside a `try`. B5 and B6 *in the same family* already use the battery's own
`try/except → outcome "raised"` idiom, and leg 116's pre-committed criterion records `raised` as
*sound but loud*. B2 was written as a read of a value, not as a probe, because pre-repair there
was no value it could fail to produce.

`experiments/p2_route_nkb_v1_postrepair.py` therefore imports leg 116's `family_*` functions
**unmodified**, uses `family_B`'s own `out_alphas` keyword to hold back the four bare calls, and
re-issues exactly those four through the idiom its siblings already use. **No case is
re-implemented and no outcome rule is re-invented.** The case count returns to **105**.

### The positive control, which could have come out differently (lesson 90)

`solver/nk_bounds.py` has exactly two commits, so the pre-repair source is loadable as a
content-addressed git blob and run **in the same process** as the repaired one. The battery is
run twice, once bound to each. The PRE pass is the control, and it had to reproduce leg 116's
banked JSON or every POST number would be worthless:

* **105 cases replayed, 105 names matched.**
* **Totals agree on every one of leg 116's 7 banked keys**: 52 hypothesis-violating,
  **21** false accepts, 12 false bounds, **19** load-bearing, 14 degenerate balls, 4 raised.
  Had the harness's B2 re-issue perturbed anything, this is where it would have shown.
* **741 of 763 numeric leaves bit-identical.**

### The 22 leaves that did move, and why they are not the repair

Both sides of the control are the **same source**, so nothing leg 128 did can appear here. 20 of
the 22 are at **≤ 3 ULP** (worst relative difference `3.331e-16`). The 2 that look like `1e-12`
are both `relative_slack = (module − reference)/reference`, a cancellation quantity whose value is
~`8.4e-05`: a `1e-16` relative move in `module` is amplified by ~`1.2e4` into the `3.8e-12` seen.
**The same one-ULP move, read through a subtraction — not a second effect.** Decisively, **6 of
the 22 sit on `_I_out_reference` / `_reference_sup` paths, which are battery + numpy only and
never call `solver/nk_bounds.py` at all.** A quantity the module does not compute cannot have
been moved by a repair to the module. Verdict: **environmental float drift** between leg 116's
run and this one (numpy 2.5.1, Python 3.12.3), recorded in the JSON as
`control_drift_diagnosis`, **not** a repair regression.

## 5. What was banked, and one deviation stated plainly

`test_nk_bounds_postrepair.py` — 11 gates, all passing — banks leg 116's battery as a permanent
regression suite for this module, including two controls that can come out differently and a
gate pinning `P06`'s silence by name.

**The deviation:** banking was the **yes**-branch's instruction, and this gate answered **no**.
I banked anyway, and say so rather than quietly following the more convenient branch. The reason
is that the pin is *more* valuable under NO than under YES: an unpinned known residue is exactly
what decays at the rate of memory (lesson 68), and the suite fails **in both directions** — if a
future change makes the count worse, and also if it makes it better without anyone re-measuring.
The orchestrator should overrule this if it reads the branch more strictly than I have.

* **Nothing is claimed as novel.** The method (re-run a defect battery after the fix) and the
  theorem's hypotheses are both established prior art, with links in `writeup/novelty/leg_147.md`.
* **No repair was made**, under either branch, and no shared ledger was touched.
* **The residue is latent** — 0 of 3 in-repo callers reach it, 0 banked numbers impeached.
* **The one number this leg would most like to see checked by someone else** is the claim in §3
  that the 22-leaf control drift is environmental. The argument rests on 6 leaves that provably
  never call the module; if a verifier can show a seventh that does, the diagnosis changes.
