## 2. The magnitudes

Every number is in `writeup/data/p2_route_tsa_v1_adversarial.json` and pinned executably
in `test_target_selection_adversarial.py`.

**A — `y0_budget` is blind to the sign of `1 − Z1`.** It computes `(1−Z1)²/(2 Z2)` with no
check that `Z1 < 1`, so it is invariant under `Z1 → 2 − Z1`. **6 of 7** tested `Z1 ≥ 1`
return a strictly positive budget where the true budget is **0**.
Sharpest: **`y0_budget(2.0, 1.0) == y0_budget(0.0, 1.0) == 0.5`, bit for bit** — an
operator with `‖I − A·DF‖ = 2`, maximally *not* an approximate inverse, is assigned exactly
the residual budget of a **perfect** inverse. Overstatement: a finite positive number
against a true zero. The mirror is bit-exact at `x = 0.25/0.5/0.75` and differs by
`≤ 1.11e-16` at `x = 0.1/0.9` — that residue is the float representation of `0.9`/`1.1`,
not a property of the function, and the pin is set at that strength, not stronger.
`Z1 = 1.0` exactly is the one boundary it gets right (`0.0`).

**B — `radii_polynomial` validates no sign: 9/9 forbidden triples return `feasible=True`.**
The constants are norms — the module's own comment defines them as `‖A F(x)‖`,
`‖I − A DF(x)‖`, `‖A(DF(v) − DF(x))‖`. **5 of 9** come back with a **negative certified
radius**, i.e. a Newton–Kantorovich existence ball asserting a zero inside an empty set;
worst `r_min = −1413.71` at `Y0 = −1e6` (the quadratic root, not `−Y0` — the polynomial is
still a quadratic at `Z2 = 1`). And the `a ≤ 0` branch swallows **every** `Z2 < 0` into the
`Z2 = 0` case and then names the wrong one: `radii_polynomial(1e-3, 0.5, −1.0)` returns
`feasible=True` with `reason = "Z2 = 0, affine"` — a **false statement about its own
input**, for `Z2 = −1.0` and `Z2 = −1e4` alike.

**C — a correct refusal that still ships a favourable magnitude.** The `out` dict is
assembled *before* the `Z1 ≥ 1` guard runs, so the budget fields survive it. At
`Y0 = 0.1, Z1 = 2.0, Z2 = 1.0` the verdict is correctly `feasible=False` **and the same
dict reports `Y0_over_budget = 0.2`** — "a fifth of budget used, 5× headroom" — for an
operator with no budget at all. **3 of 5** `Z1 ≥ 1` refusals do this. This one matters
because this repository quotes `Y0_over_budget` as its *magnitude*
(`p2_route_l1_v1_interval.py:115`, `p2_route_port_v1_bordered.json`): the boolean is right
and the number a reader is told to trust is wrong, which is the harder failure to see.

**D — `unknowns` truncates a fractional dimension silently.** `int(n_per_dim) ** int(dim)`
under a docstring promising *"Exact unknown count … No fudge factors."*
`unknowns(1.9, 2, 600, 3) = 1203`, **identical to the `dim = 1` answer**, against `720003`
for `dim = 2` — a **598.5×** understatement of the quantity that *is* Q2's whole
discriminator. `unknowns(−1, …)` returns a **float** (`3.0033…`) from a function documented
as an exact count. `unknowns(nan, …)` raises `ValueError` — the one loud degenerate case,
pinned so a repair cannot quietly remove it.

**NaN/inf — the benign direction, reported and not inflated.** All refused
(`feasible=False`), but *by accident*: `feasible = r_min < min(r_max, r_cap)` is False
because every ordered comparison with NaN is False, not because anything checked. The row
still carries `reason = "ok"` with `r_min = nan`, and emits a `RuntimeWarning`.

## 4. Reachability — latent, or does it contaminate a banked result? (legs 201/204 separation)

Two independent arguments, and they agree.

**By construction.** Every caller builds its constants as maxima of **absolute values** —
`weight_search.certificate_constants`, `p2_route_c_pilot_v0`, `p2_route_l1_v1_interval`,
`p2_route_port_v1_bordered` all compute `Y0 = max(w·|A·Fz|)`,
`Z1 = max(w·(|I − A·J| @ 1/w))`, `Z2 = 2·A_norm·B` with `A_norm`, `B` sums of absolute
values. **A negative `Y0`, `Z1` or `Z2` cannot arise from any call path in this
repository.** The entire negative-constant family — the 9/9 and the 5 negative radii — is
unreachable.

**By audit of the banked record.** Every `Z1`-bearing record in every JSON produced by a
runner importing `target_selection.y0_budget` or `radii_polynomial`:
**85 of 85 lie inside `0 ≤ Z1 < 1`. 0 offenders.** The repo's **64** negative-`Z1` records
all live in *other legs' deliberate adversarial batteries* (`ica` 4, `nfa` 7, `nka` 14,
`nkb` 34, `nsa` 2, `pc` 3), fed to the **sibling** functions. Zero are measurements.

**The one regime that is reachable in principle is `Z1 ≥ 1`**, and what stops it is
measured rather than assumed — and it is **not** `target_selection`. `weight_search`'s own
capability entry records *"the admissible band shuts entirely at n ~ 3.2e3 because `Z_1` is
float conditioning"*, which is exactly `Z1` crossing 1. But
**`weight_search.fitness_many` re-implements the budget inline as
`np.where(Z1 < 1.0, (1−Z1)**2/(2*Z2), −1.0)`** — *with* the guard the shared function lacks
— and never calls `y0_budget` on the GA path. `y0_budget` survives there only as a
reporting field of `certificate_constants`. The containment is real, and it is the callers'
doing, not the module's.

**Verdict: LATENT. No banked number is contaminated.**
