## The four silent-corruption sites, with magnitudes

### SITE 1 — `margin_law` omits the anti-dissipation guard that `branch_in_kappa` documents

`branch_in_kappa` filters on **both** the residual and `-1e-6 <= eps < 1.0`, and its docstring
says exactly why:

> "past the branch's end the map has other zeros (with negative eps, i.e. anti-dissipation) and
> a continuation that does not check will happily report them as branch points."

`margin_law` re-solves with `solve_at_kappa` at `kappa* ± offset` using its own seeds, and
filters **only** on `hist[-1]`. There is no eps test at all. Given seed records that are legal
in shape but far from the fold, it returned **4/4 rows on the anti-dissipative continuation**:

| kappa | eps returned | `branch_in_kappa` verdict |
|---|---|---|
| 0.6346 | **−0.247302** | reject |
| 0.4746 | **−0.341559** | reject |
| 0.5946 | **−0.334897** | reject |
| 0.5146 | **−0.421061** | reject |

and fitted them into the divergence exponent the function exists to report:
**slope = −6.472178** against the module's own declared `expected_slope = −1.0` — a
**6.47× misreport**, with no exception, no warning, no NaN, and no flag in the returned dict.

This is the headline because it is the module doing the exact thing its own docstring warns a
continuation must not do, in the one consumer that skipped the check.

### SITE 2 — `integrate_from_zero` returns the initial condition for any `xi1 <= 1e-8`

The loop is `while xi < xi1` from a series start at `xi = 1e-8`, so **any** `xi1 <= 1e-8` —
including `xi1 = 0` and **every negative value** — exits immediately and returns `Q(1e-8) ≈ mu`
with `n_steps = 0` and no warning, while the docstring promises the IVP *"integrated to xi1"*.

Honest reference at `xi1 = 1.0`: `Q = 0.732818 − 0.127252i` after 100 steps.
Returned at `xi1 ∈ {1e-8, 0.0, −1.0, −1e6}`: `Q = 1.232038 − 2.28e-17i`, `n_steps = 0`, i.e.
**exactly `mu`**, wrong by **|ΔQ| = 0.515183** and *identical for all four* — including
`xi1 = −1e6`, six orders of magnitude outside the domain.

**Corollary:** `match_defect` unpacks `Q, dQ, _`, discarding `n_steps` — the one available
signal. At `xi1 = 1e-9` it returns a finite, plausibly-typed defect of **5.651456e+09** against
a scale of **2.037198e-08**, a relative defect of **2.774132e+17**.

### SITE 3 — `compare_to_published_branch` breaks on a tie in kappa

`np.interp` requires *strictly* increasing x. The module sorts (`np.argsort`), so **order** is
handled — but a **tie** is not, and its docstring's stated precondition is only monotonicity:

> "our sweep is monotone in kappa, so a plain interpolation is well-defined"

One duplicated kappa carrying a wild eps moves the published-agreement headline from
**4.494600e-04** to **9.634902e-01** — a **2143.7× inflation** — silently, in the very function
that produces the agreement number quoted in `capabilities.py`. Worst row: at `kappa = 0.800313`
it reports `eps_ours = 0.983809` against `eps_published = 0.020319`.

### SITE 4 — the ledger's verdict vocabulary is unenforced, and it holds the gate

`PRECEDENTS` documents exactly three verdicts — `PRE_EMPTS`, `ADJACENT`, `EXCLUSION` — and
`novelty_verdict()` selects on the exact string `"PRE_EMPTS"`. **Nothing validates the
vocabulary.** Changing one character (`PRE-EMPTS`, hyphen for underscore) flips stage V's gate
answer from **YES to NO** with no error whatsoever. A *missing* `verdict` key does raise
(`KeyError`) — so the failure is specifically the silent one: a value that is present, typed,
and outside the documented set.

This is the smallest defect by code size and the largest by blast radius: it is the function
that closes a stage and holds a live ban.

### SITE 5 (reported separately) — `hmax <= 0` cannot terminate

`h = min(hmax, period_step, xi1 - xi)`. For `hmax <= 0` the step is `<= 0`, `xi` never advances,
and the loop cannot exit. Step count scales exactly as `1/hmax` — 100 / 1 000 / 10 000 steps at
`hmax = 1e-2 / 1e-3 / 1e-4` — diverging as `hmax → 0`. **This is a hang, not a silent wrong
value**, so it is excluded from the gate's four sites and asserted on the loop's first step
rather than by execution, so the battery always terminates.

## Lesson 90 — the guards in this same module that DO fire

A "no guard here" claim is worthless without a "guard here, and it fired" case from the same
module that could have come out the other way. **5/5 controls fired:**

| control | outcome |
|---|---|
| `kappa = 0` → `asymptotic_coefficients` | `ZeroDivisionError` |
| `d = 0` → `integrate_from_zero` | `ZeroDivisionError` |
| `steps_per_osc = 0` → `integrate_from_zero` | `ZeroDivisionError` |
| `branch_in_kappa` with a NaN seed | 0/1 flagged converged — **rejected** |
| `margin_law` with a NaN seed row | `LinAlgError` from `np.linalg.cond` |

The fourth and fifth are the sharpest pair, and they are the reason the NaN story is reported
honestly rather than as a fifth site. The two filters test the *same quantity with opposite
polarity*: `branch_in_kappa` asks `hist[-1] < tol` (and `nan < tol` is False → **rejects**),
while `margin_law` asks `if hist[-1] > 1e-9: continue` (and `nan > 1e-9` is also False → **does
not skip**, i.e. **accepts**). So `margin_law` *does* absorb the NaN row at the filter — but it
does **not** silently return a number, because `margin_proxy`'s `np.linalg.cond` then raises on
the NaN Jacobian. **Visibly propagated, not silently returned.** My first reading had this as a
silent-corruption site; running it disproved that, and the disproof is in the battery as gate 3.

`fold_of` was also probed and **behaves**: on collinear and near-flat triples the parabolic
vertex stayed inside its bracketing kappas, and an unbracketable endpoint maximum is honestly
reported with `interior: False` rather than extrapolated.

## Disposition

**Escalated, not patched.** The four sites are real and the repair for each is small and named
in both the runner and the battery:

1. add `branch_in_kappa`'s `-1e-6 <= eps < 1.0` test to `margin_law`'s row filter, returning
   `slope=None` when too few rows survive;
2. reject `xi1 <= ` the series start in `integrate_from_zero` (and/or check `n_steps` in
   `match_defect`);
3. de-duplicate or reject tied kappa before interpolating;
4. validate every ledger `verdict` against the documented three-value vocabulary;
5. require `hmax > 0`.

None was applied here. Each pinned gate names the repair that flips it, so a later bench-repair
leg is forced to update this battery deliberately rather than by loosening a tolerance.

**No claim that stage V re-opens.** Stage V is closed by its own gate and its ban lifts only for
a fluid transport model. Nothing measured here bears on the gate's *direction* — that rests on
Dahne–Figueras' published theorems, not on our reproduction of them — only on how well the
gate's supporting evidence is computed, which G6 shows is currently computed correctly. No ban
lifted, no route promoted, no link of the L1→L4 chain moved.
