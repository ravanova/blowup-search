   which run is meant.
4. **Records why**, so the pin is a measured constraint rather than a rule someone has to
   remember the reason for.

## Why the pin is not arbitrary — leg 160's measurement, quoted from its own artifact

Leg 160 ran the frozen six-property gate on four fitness modes at `n = 201/401` and reported
**NO**. It then re-ran at `n = 101/151` and found:

| mode | `n = 201/401` | `n = 101/151` |
|---|---|---|
| `identity` (the unmodified, unrepaired leg-49 fitness) | FAIL 5/6, P3 `0.3421493449940881` | **PASS 6/6**, P3 `0.02007528568401651`, P2 `1.0000` |
| `hiprec` control | FAIL 5/6 | PASS, P3 `0.009516196830762214` |
| WVR-1 (defect-blind by construction) | FAIL, P3 `1.0000325577018077` | **unmoved**, `1.0000562750220603` (factor `0.99998`) |

and the mechanism, in magnitudes:

```
||rho||_inf = 4.790972900601766e-11   at n = 201   -- ABOVE the frozen eps grid's 1e-11 bottom
||rho||_inf = 4.640571829290985e-13   at n = 101   -- BELOW it, by 21x
```

WVR-1 is the control that makes this a mechanism rather than a grid artifact: a knob that moves
every defect-tracking score by `3.8×`–`34.9×` and leaves the one defect-blind score alone is
measuring the defect's floor, not the fitness's quality. So the pass at `n = 101/151` is P3's
probe descending below the residual floor and measuring arithmetic noise instead of the injected
defect. **Nothing was repaired.** The old wording — "a repaired fitness", no resolution — would
have been satisfied by that.

Every number above is asserted by the runner against `experiments/journal/leg_160.md` itself
(`leg_160_numbers_verified_against_its_journal`: 5/5 found verbatim), so the clause quotes a
landed artifact rather than this leg's reading of one.

## The check is executable, and it has a negative control that fails

Banked lesson 68: a check that is not executable decays at the rate of memory. Banked lesson 90:
a control that cannot come out differently is not a control. So the closure is a predicate,
`pins_resolution()`, with four independent requirements, applied to **two** inputs — the
pre-edit string (quoted verbatim in the runner from merge base `2d89233`) and the post-edit
string read live out of `plan_of_record.BANNED`:

| requirement | pre-edit wording | post-edit wording |
|---|---|---|
| R1 frozen resolution named (both grids) | **False** | True |
| R2 named as a PIN, not an example | **False** | True |
| R3 coarser grids excluded explicitly | **False** | True |
| R4 the excluded coarsening named by number | **False** | True |
| **verdict** | **does NOT pin** | **pins** |

`0/4` against `4/4`. Reverting the clause makes the runner fail on its first assertion, which is
what makes the file a check rather than a restatement.
