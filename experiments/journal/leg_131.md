## 2. The finding that came before the measurement: the repair's own re-check facility is broken

The repair added `HNA_AUDIT_LIVE` so leg 100's battery could be re-pointed at the working
tree. **It has never been run to completion by anything on `main`** — `git grep` finds it in
exactly one file, and running it **crashes immediately with returncode 1**, aborting at
`gate_A5` line 419. (Wall time is sub-second and varies run to run — `returncode` and the
abort line are the reproducible facts, and they are what the banked suite pins.)

The cause is not that the battery mishandles a repaired module. Leg 100's criterion says
verbatim that "Returning NaN, returning ±inf, raising, or warning ALL count as FLAGGED, not
silent", and its `classify()` already returns `FLAGGED_RAISE`. The cause is **three sites
that read the subject bare, outside `probe()`**, on input that used to be merely wrong and
now raises. All three were predicted in the novelty pass (commit `b5d6f1a`) and all three
were confirmed at the predicted lines:

| gate | line | call | shim raises |
|---|---|---|---|
| `A5` | 419 | `decay_weight(np.array([0.,1.,10.]), NAN)` | 1 |
| `A6` | 470 | `pd, rb = holder_H_constant(th, g, …)` (degenerate sweep) | 5 |
| `A8` | 553 | `val = fn(*args)` ×3 (Inf grid / Inf operator) | 3 + 3 |

Two passes get past it: pass 1 runs the gate unpatched and records the abort; pass 2 re-runs
with a **recording shim** that passes every value through unchanged and substitutes a NaN
sentinel only on a raise. The shim can only ever turn a `FLAGGED_RAISE` into a
`FLAGGED_NAN` — both FLAGGED — so **the SILENT count, which is the pass criterion, is
invariant under it**. The three sites then get their true, unshimmed verdicts from a direct
re-probe through the battery's own helpers.

## 6. The one residual: `gamma = 1`, and what it actually is

Across the whole battery the count is **18 → 1**. The single survivor is `gamma = 1`, the
Lipschitz endpoint, at two sites: `A5`'s `HolderNorm(gamma = 1)` row and the `A6:470` bare
sweep. It is **not** an incomplete fix and **not** a regression, for four measured reasons:

1. **It was never one of the six.** It lives only in `A5`, which leg 100's own `verdict()`
   files under `not_silent`. `A5`'s SILENT verdicts arise because `probe()` compares every
   row against one clean reference — the `gamma = 0.3` norm — and a different `gamma` is a
   **different norm**, so a difference from that reference is not by itself damage.
2. **The value is right.** Checked against an independent reference written from the
   module's **docstring formula**, not its code: **6/6 bit-identical** at
   `gamma ∈ {0.3, 0.5, 1.0}` for both `sup_part` and `seminorm`. At `gamma = 1`,
   `sup_part = 0.99968937983196482` and `seminorm = 0.49964385478570955` (against the
   `gamma = 0.3` reference `0.72904765898888058`). This control can come out differently: had
   it failed, the residual would be a real corruption and the gate's NO branch would fire.
3. **It is deliberate.** `_reject_nonpositive_gamma`'s own docstring says so — "Every gamma
   used anywhere in this repository lies in `[0.05, 0.9]`; no upper bound is imposed here,
   only positivity."
4. **It is not a regression.** The pre-repair arm accepts `gamma = 1` and returns the
   identical numbers.

**But there is a cross-module boundary worth recording.** `solver/nk_seminorm.py` (lines
89–97) gives **three independent reasons `gamma = 1` is excluded**: the closure feedback
becomes linear in `T`, turning a condition-free sublinear closure into a genuine contraction
condition; v5's U2, the Hölder–Hilbert constant blowing up at both ends; and the classical
failure of `H` on Lipschitz functions. `solver/holder_norms.py`'s repaired guard **admits**
that exponent. The boundary is stated in one module and not enforced in the other.

**Blast radius: LATENT, 0 exposed.** A call-site census measures the max `gamma` passed
anywhere in the repository at **0.5** (every Route-D/NK consumer fixes `GAMMA = 0.5`; the
production optimum in `p2_route_d_v12` is `0.15`; the dedicated test uses 0.5 and 0.3), and
**0** live call sites pass `gamma ≥ 1`. The module docstring's `[0.05, 0.9]` claim is
**confirmed by measurement**, not taken from the ledger. No banked number is exposed.

**Window caveat (lesson 84).** The discrete Hölder–Hilbert ladder does **not** resolve the
continuum divergence `nk_seminorm.py` names: over degrees 4…128 on a 256-node grid the
constant grows by **1.428×** at `gamma = 1` against **1.130×** at `gamma = 0.3` — faster, but
bounded. A finite grid cannot see an endpoint blow-up, so **no divergence is claimed**, only
the faster growth and the sibling module's stated exclusion. Reported, **not patched**: this
leg edits nothing.
