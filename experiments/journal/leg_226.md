## Answer: (a) YES · (b) honest disagreement, resolved by rejection · (c) **CHANGED — ESCALATED**

Two of Route-D v11's four headline numbers are carried by **spurious roots**: profiles that
reach a machine-precision residual while sitting far outside the traveling wave's decay class.
The numbers do **not** move under v11's own inline `relres < 1e-8` test — that test cannot see
the defect — so v11's *code* still prints what it always printed. They move under the repaired
verdict, which is the one that is actually right about what the object is.

| headline | banked | pre-repair, re-run here | post-repair, v11's own `relres` test | post-repair, **repaired verdict** |
|---|---|---|---|---|
| `a_max_machine` | 1.0 | 1.0 | 1.0 | **0.55** |
| `last_machine_precision_a` | 0.72 | 0.72 | 0.72 | **0.52** |
| `grid_converged_a_max` | 0.5 | **1.0** | **1.0** | **0.5** |
| `GA_boundary` | [0.5, 0.55] | hardcoded literal — cannot move under any module repair | | |

### The mechanism, stated exactly

An off-branch grid-scale root **nulls every residual row to machine precision**. The residual
therefore carries *no* information about whether the returned object is the physical branch —
the spurious roots routinely beat the genuine branch on `relres`. The three rows that carry
`last_machine_precision_a = 0.72` are the proof, all at v11's own `n = 801`:

| a | relres | far-field inflation `D3` | v11's own test | repaired verdict |
|---|---|---|---|---|
| 0.64 | 1.008e-14 | 1.139e+02 | pass | **reject** |
| 0.70 | 1.045e-14 | 2.146e+02 | pass | **reject** |
| **0.72** | **1.125e-14** | **6.778e+02** | pass | **reject** |
| 0.74 | 3.503e-06 | 1.674e+01 | fail | fail |

The banked `0.72` is a profile whose far field is **678× the anchor's** carrying a residual of
`1.1e-14`. The last genuinely on-branch machine-precision row is **`a = 0.52`**.

**Marginality, reported rather than buried.** `a = 0.64` sits at `D3 = 113.9`, only **1.14×**
above the 100× threshold. The corrected value is `0.52` if that row is off-branch and `0.64` if
it is not. `a = 0.70` and `a = 0.72` — including the banked value itself — are not marginal on
any reading.

### `grid_converged_a_max`: the repair *restores* the banked number

This row is the reason the pre-committed design demanded a **pre-repair re-run** rather than a
two-number before/after. In this environment v11's own unmodified test gives **1.0**, not the
banked 0.5, because at `a = 1.00` the `n = 401` and `n = 801` grids both reach machine precision
(`c = 0.793760` / `0.793188`, spread **5.72e-04**, inside the 1e-3 tolerance) while `n = 1601`
fails outright (`relres 8.290e-03`). Two grids agreeing is enough for v11's rule.

Under the repaired verdict every `a = 0.80` and `a = 1.00` row is off-branch (`D3` = 2.08e+03,
4.62e+03, 2.88e+04, 2.42e+03, 4.69e+04), so they contribute nothing, and the max returns to
**0.5** — the banked value. The repair is what makes this headline *stable against the
environment drift* that test item (6) measured at 2.31 decades.

`a = 0.50` itself survives cleanly at v11's grids: `n = 801` and `n = 1601` give `c = 0.636040`
and `0.636044`, a spread of **4.05e-06**, with `D3` = 14.55 and 6.52. (`n = 401` fails the
residual test identically before and after: `relres 6.476e-08`, a 40-iteration stall.)

**A correction to this leg's own early reading.** A cheap `n = 101/201` probe showed `a = 0.50`
massively off-branch (`D3` = 2.3e+05 / 2.4e+04) and looked like it threatened this headline
directly. It does not: those spurious roots live only on the **coarse** grids leg 202 used. At
v11's working grids `a = 0.50` is genuine. The threat to v11 is real but it is at `a = 0.64`
and above, not at 0.5.

## (a) Every leg-202 case now rejects — 0 slip through

61 cases; 44 expected-reject; **27 were silently accepted pre-repair; 0 still slip through**;
all 17 genuine on-branch cases still accept. The worst offenders carry machine-precision
residuals: `n=101, a=1.05` rejects at `relres 1.256e-16`, `D3 = 1.393e+06`; the `rho_max = 16`
degenerate case at `relres 1.580e-12`, `D3 = 5.112e+07`.

Grid refinement behaves physically: at `n = 301` the ladder finds the *genuine* branch at
`a = 0.60` and `0.75` (`D3` = 7.44, 24.06, accepted) where `n = 101/201` land on spurious roots
(`D3` = 1.54e+04, 1.78e+04). The repair is not a blanket rejection above some `a`.

## (b) The three `a = 1.50` grids — honest disagreement, then rejection

Pre-repair all three reported `converged` at **mutually contradictory** speeds:

| n | pre-repair `c` | post-repair | `D3` |
|---|---|---|---|
| 101 | 0.204265 | reject | 1.120e+06 |
| 201 | 0.237174 | reject | 6.256e+05 |
| 301 | 0.972819 | reject | 4.857e+03 |

A **163% relative spread** across three grids all claiming convergence. Post-repair **0 of 3**
are accepted. Per pre-committed clause 2 this is reported as what it is — there is no genuine
`a = 1.50` value on these grids — and is **not** dressed up as convergence to a common value.

## Zero regression, and why the comparison is trustworthy

ARM B: 28 on-branch rows, **0 regressions**, and `max |c_pre − c_post|` on rows both modules
accept is **exactly 0.000e+00**. The repair never touches the Newton iteration — the diff
changes only the returned dict — so this is bit equality, not agreement to a tolerance. The two
newly-rejected rows are both `a = 0.50` at `n = 101/201`, genuinely off-branch.

This bit-identity was verified again directly at `n = 801, a = 0.5`: `c_delta = 0.000e+00`,
`relres_delta = 0.000e+00`. That licences the measurement shortcut ARM D uses — v11's `v3`/`v4`
call only the cold `solve()`, so each row is computed **once** and both verdict tests are
applied to it, rather than running two numerically identical sweeps.

## The discriminators, head to head

- **D3 (decay class) separates.** Max on-branch `24.06`; min off-branch `197.30`; the
  pre-committed 100× threshold sits 0.62 decades above the former and 0.295 below the latter.
  Tighter than the scouting pass estimated (1.3 / 1.1 decades) — recorded because it is tighter,
  not despite it.
- **D1 (weighted defect) does not separate, at any threshold.** Off-branch range
  `9.535e-12 … 1.318e+06`; on-branch max `9.364e-03`. Its smallest off-branch value is nine
  decades *below* its largest on-branch value. This is the diagnostic the dispatch sent this leg
  to incorporate, and §3.1 of the novelty pass called it false **before** construction. Confirmed.
- **D2 (gauges) is exactly 0.0 on 24 of 44 off-branch cases** and exactly 0.0 on every genuine
  row. It costs no on-branch coverage and catches M2/M3, never M1.

### Lesson 90: the discrimination check was itself broken, and is now fixed

The falsification probe that was supposed to show D3 can report the *other* answer was
**vacuous**. It read `om = anchor + tail*ones; om = om − (om[i0] + 1.0)`, and since
`anchor[i0] = −1` exactly, the gauge renormalisation subtracted precisely the constant it had
just added. Every rung returned `D3 = 1.000` and `all_must_fail` was silently `False`. Caught by
reading the numbers instead of the flag — which is the whole content of lesson 90.

Replaced with a perturbation that vanishes at the origin by construction
(`anchor + tail·X²/(1+X²)`), so gauge 1 holds with no renormalisation:

| tail | `D3` measured | `D3` predicted | gauge | verdict |
|---|---|---|---|---|
| 1e-4 | 1.5164e+01 | 1.5442e+01 | 0.0 | passes |
| 1e-3 | 1.5414e+02 | 1.5442e+02 | 0.0 | fails |
| 1e-2 | 1.5439e+03 | 1.5442e+03 | 0.0 | fails |
| 1e-1 | 1.5441e+04 | 1.5442e+04 | 0.0 | fails |

Measured matches predicted to **1.8%** worst case and the crossing is **bracketed** between 1e-4
and 1e-3 — the test responds quantitatively to the far field it claims to measure rather than
firing on everything. The four must-pass probes (exact anchor, ×1.0001, smooth bump, 5% widened)
all pass at `D3` ≈ 1.0–1.1.

**Threshold provenance.** 100× is leg 202's own pre-committed classifier threshold, adopted
**unchanged**, not retuned here. It is also not grid-tuned: the anchor's far-field supremum
moves only `6.4759e-06 → 7.1570e-06` across a 16× refinement (`n = 101 → 1601`), all at
`X_max = 745.2`. `D3 ≥ 100` means `|Ω| > ~7.0e-04` somewhere in `|X| > 372.6`, where a branch
with critical radius ~`1/a` should be numerically zero.

## What this does and does not mean

The repair is a **rejector, not a certificate**: failing D2 or D3 proves the returned object is
not the physical branch; passing both proves nothing. Nothing here is rigorous, nothing is
interval-arithmetic, and no link of the L1→L4 chain moved. Clay stays ~0.05%. What moved is that
a tooling verdict which was **silently wrong on 27 of 44 adversarial inputs** is now right on all
44, and two banked headline numbers are now known to be carried by spurious roots.
