## 2. What 1308.3356 actually says (full quotes; see JSON for the complete set)

Full-text grep for hookstep/Newton/GMRES/continuation/converge matched 23 source lines; every match
read in its surrounding paragraph, not in isolation. Two distinct hookstep-failure instances found:

**Instance 1 -- P1's continuation-branch endpoints** (section 4.4, the instance leg 358 had
already extracted the Re numbers for but never read the mechanism of):

> "Once converged, P1 could be traced using arc-length continuation over the range 15.03 <= Re <=
> 26.68 (at either end the Newton-GMRES-hookstep algorithm fails to converge)."

Two sentences earlier the paper states P1 "is born in a saddle node bifurcation" -- so the failure
mechanism is a classic fold/turning-point Jacobian singularity, generic to ANY Newton-family
continuation method at a saddle-node, independent of which globalization sits inside the Newton
loop. Critically, this is a CONTINUATION failure (tracking one solution across a parameter sweep,
losing convergence at the sweep's endpoints) -- a task structure leg 358's retry spec does not use
at all (no continuation is proposed; the retry is ~100 independent single-shot attempts at one
fixed Re).

Domain: section 4 (where P1 lives) is the EXTENDED-domain material. 1406.1820's own methods section
(shared author pair, shared code, shared convention) states explicitly: "the aspect ratio of the
domain with alpha = 1 in section III and alpha = 1/4 in section IV" -- and figure 15's spatial axis
(x in [0, 8*pi]) is consistent with Lx = 2*pi/alpha = 8*pi, i.e. alpha = 1/4, for the P1 case. Re
range 15.03-26.68 does not touch Re=60.

**Instance 2 -- long-period non-convergence** (section 4, near figure 24, alpha=1/8, Re=22):

> "...repeats periodically in time, due to the periodic boundary conditions. The period was too
> large to converge using the Newton-GMRES-hookstep method."

This is task-type-closer to leg 358's retry (single-shot attempt, no continuation involved) but:
(a) still occurs in an even MORE extended domain (alpha=1/8) at Re=22, neither matching leg 358's
target; (b) supplies no period value to compare against UPO37's own T=19.334 (a short period,
already known to be within the range 1406.1820's own code successfully converged 81 times at
Re=60, alpha=1).

## 3. Regime-boundary comparison against leg 358's own target (see JSON for full table)

Leg 358's target: alpha=1 (square torus, per 1406.1820 section III header "RESULTS: SQUARE TORUS
(alpha = 1) AT Re = 60"), Re=60, single-fixed-Re Newton-hookstep attempts (no continuation), target
orbit UPO37 (T=19.334, s=0.375, a genuine RPO -- "a 2D relative periodic orbit with T = 19.33
(UPO 37 in Table IV) is a typical example" per 1406.1820's own text).

Both 1308.3356 failure instances fail the domain axis (alpha=1/4 and alpha=1/8, not alpha=1) and
the Re axis (15.03-26.68 and 22, not 60). Instance 1 additionally fails the task-type axis
(continuation vs. single-shot). Instance 2 is task-type-matched but gives no period number to
compare and occurs at an even more extreme domain aspect ratio. The one point of contact -- both
P1 and UPO37 are genuine relative periodic orbits (nonzero shift), the same ORBIT CLASS -- is not
sufficient by itself to intersect the regime: 1406.1820's own alpha=1/Re=60 dataset already
contains 81 solutions the SAME hookstep code converged successfully, with the RPO subclass's own
within-regime success rate (4.3%, Chandler & Kerswell 2013) already sourced and already banked as
leg 358's residual risk #1. 1308.3356 adds no additional WITHIN-REGIME failure evidence.

## 4. Classification: DISJOINT

The concretely-mechanism-explained failure (P1, continuation endpoints/saddle-node) is disjoint on
all three of domain, Re, and task-type. The task-type-closer failure (long-period, alpha=1/8) is
disjoint on domain and Re, and uninformative on the one axis (period) that could have connected it.

**Recommended amendment to leg 358's risk #2** (stop-packet risk table should cite this leg by
pointer, not be edited by this leg): NARROW. Risk #2 as banked ("hookstep is not universally
convergent even in the source's own hands") is true in the general/abstract sense but its cited
evidence is regime-disjoint from the retry's own target and should not be read as evidence hookstep
is expected to fail AT Re=60, alpha=1, on RPO-class targets like UPO37. The correctly-scoped risk
is: (a) hookstep is provably not a universal convergence guarantee (true, but via mechanisms --
saddle-node proximity, long period -- the retry's task structure is not positioned to trigger), and
(b) the evidence that actually bears on the target regime is Chandler & Kerswell's own 4.3% RPO
success rate at Re=60, alpha=1 -- already banked as leg 358's residual risk #1. Risk #2's best
evidence, once regime-checked, collapses into (is subsumed by) risk #1 rather than adding an
independent, multiplicatively-stacking failure mode.
