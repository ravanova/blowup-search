## The distinction this pass had to invent: landed ≠ merged ≠ parked

The single most error-prone thing in this window is that **"parked" means two different
things**, and a row that flattens them is wrong either way.

- `TECHNICAL_P2_ROUTENG_V1.md` line 12 says of leg 58: *"This branch is therefore parked, not
  merged."* Taken at face value, Route-NG should have no row. But that sentence scopes the
  **publication escalation**, not the route: the DM subsequently ruled it mergeable as-is
  (`ee5b2f4`), `plan_of_record.py` prints stage `NG` as `[x]` **DONE**, and all five quartet
  pieces are on `main` including `fig55`. Leg 58 is **landed with a parked escalation
  attached**.
- Leg 63 is the strict case: nothing merged, nothing on `main`.

Reading either file's own words without checking the tree gives the wrong answer for one of
them. Both rows now exist and say which case they are. This is the same shape as lesson 90 —
the check that cannot come out differently is not a check — applied to documentation: "the
writeup says it's parked" is not evidence about what is on `main`; `git ls-tree` is.

## The control, and it can report the other answer

An audit that edits the file it audits can trivially fake its own success, so the runner was
rewritten mid-leg to ask **every** existence question of the pinned tree
(`git ls-tree -r 3474862`) rather than the working copy — `exists()`, the figure listings, and
the `INDEX.md`/`README.md` text reads all go through `read_pinned`/`listdir_pinned`. The
control: the runner was executed **before** and **after** the `INDEX.md` edits, and printed
byte-identical verdicts both times (9 claims, same 4 FALSE / 2 MISSING / 3 TRUE, gate NO). Had
it read the working copy, `C8`'s `index_m2_mentions` and `index_parked_mentions` would have
moved from `0` to nonzero purely because this leg wrote the words — a number that changes when
its own author edits prose is exactly the tautological control lesson 90 warns about. It now
cannot: re-running this script after leg 138 lands reproduces the same ledger.
