## What "self-consistency" means here, and why it is auditable

`capabilities.py:354-357` validates this module as *"internally self-consistent across the
reduced space; explicitly NOT a proof — float64 throughout."* The module's one assembled
entry point is `rehearsal(a, K, Xc0)`, which returns a dict carrying `converged`,
`Y0_interpolant_defect`, `Z0`, `N2_sup_by_cutoff`, `N2_finite`, `Z1: None` and a prose
`verdict`. Self-consistency is therefore a property of **that dict**: the sentence it
reports and the numbers it reports must agree. That is a testable claim, and it is the one
the battery tests.

The float64 caveat is not the issue and is not being relitigated. Every finding below is a
disagreement between what the module *says* and what the module *itself computed*, at
magnitudes 8 to 10 orders of magnitude larger than float64 roundoff.

## FINDING A — the `verdict` is a constant, not a measurement (hazard H1)

`rehearsal` lines 230-237 build the `verdict` as a **hardcoded string literal**. It
asserts:

> *"Y_0 is at machine level and Z_0 is roundoff."*

Nothing in `rehearsal` reads `Y0_interpolant_defect` or `Z0` before emitting that sentence.
There is no input for which it can come out differently. This is **lesson 90's exact
shape** — *"before quoting a control, ask what would have had to change in the code for it
to report the other answer"* — applied to a claim rather than to a control. The answer here
is "nothing".

Swept over `a ∈ {0.3, 0.5, 0.8, 1.0, 1.2}` × `K ∈ {16, 32, 96}`:

| measurement | magnitude |
|---|---|
| converged cases | **15** |
| distinct `verdict` strings across all 15 | **1** (byte-identical) |
| cases asserting "Y_0 is at machine level" where `Y_0 > 1e-10` | **14 of 15** |
| span of `Y_0` beneath that one sentence | `1.23e-12` … `1.55e-2` = **10.10 orders of magnitude** (factor `1.26e10`) |
| worst case | `a = 0.3, K = 16`: **`Y_0 = 1.548e-2`** |
| cases asserting "Z_0 is roundoff" where `Z_0 > 1e-10` | **0 of 15** — that half of the sentence happens to be true everywhere tested |

The threshold `1e-10` is deliberately **two orders looser** than the module's own finding
(1), which claims `Y_0` *"falls to ~1e-12 by K ~ 96 at a = 0.3"*. Every case counted is
contradicting the sentence by a wide margin.

**The worst case is the module's own history.** At `a = 0.3, K = 16` the reported `Y_0` is
`1.55e-2` — the same `~1e-2` defect floor the module's docstring says *"sixteen legs
carried"* and that finding (1) claims to have beaten. The module reports that number and
the sentence "Y_0 is at machine level" in the same dict.

**This is already in a shipped artifact.** Read (not re-measured) from
`writeup/data/p2_route_d_v16_rehearsal.json`, which
`experiments/p2_route_d_v16_rehearsal.py:136` produced:

| `a` | banked `Y_0` | overshoot vs `1e-10` | verdict says |
|---|---|---|---|
| 0.3 | `1.485e-12` | 0.015× (true) | machine level |
| 0.5 | `1.182e-09` | **11.8×** | machine level |
| 0.8 | **`1.598e-06`** | **15975×** | machine level |

**2 of 3 banked rows** carry the sentence over numbers that contradict it, and all three
carry the identical string. This is not a hypothetical reachable only by adversarial input:
it is the module's normal output on its own headline sweep.

**Positive control (lesson 90 discharged).** At `a = 0.3, K = 96` the sentence is **TRUE**
(`Y_0 = 1.23e-12`). The probe can and does come out both ways, which is what makes "14 of
15" a finding rather than a broken build. Gate 0 of the regression battery asserts it.

## FINDING B — `N2_finite` certifies an all-NaN state at `a = 1/2` exactly (hazard H2)

`rehearsal` line 220:

```python
finite = bool(rp.p >= 2.0 and max(npp) / min(npp) < 1.01)
```

At `a = 1/2` exactly, `p = 2`, so `second_derivative_sup` evaluates `e ** (p - 2)` =
`e ** 0.0`. In IEEE-754 (and numpy) **`nan ** 0.0 == 1.0`** and `inf ** 0.0 == 1.0`. The
three cutoffs therefore return `|p(p-1)| × 1.0 = 2.0` for **any** `b` whatsoever, the ratio
is exactly 1.0, and `N2_finite` reports `True`.

| state fed as `b` at `a = 0.5`, `K = 32` | `N2_sup_by_cutoff` | `N2_finite` |
|---|---|---|
| all NaN | `[2.0, 2.0, 2.0]` | **True** |
| all inf | `[2.0, 2.0, 2.0]` | **True** |
| all zero | `[2.0, 2.0, 2.0]` | **True** |
| random garbage | `[2.0, 2.0, 2.0]` | **True** |

**4 of 4 poisoned states certified.** On those same all-NaN states every *other* field the
module computes is correctly non-finite — `interpolant_defect` → NaN, `z0_defect` → NaN,
`operator_norm` → NaN. `N2_finite` is the **one field that certifies garbage**, and it is a
`Z_2` ingredient.

**Positive control.** The same four vectors at `a = 0.3` (`p = 3.33`), where the code path
differs only in the exponent: all-NaN → `False`, all-inf → `False`, all-zero →
**`ZeroDivisionError`**, garbage → `True` (correctly — a finite state has a finite
`sup|N''|`). **1 of 4** certified, versus 4 of 4. The control comes out differently, so the
`a = 1/2` row is a property of `p == 2`, not of the check in general.

**Rider, and it is an uncaught crash rather than a corruption:** `max(npp) / min(npp)` is
unguarded. For `a > 1/2` Python short-circuits on `rp.p >= 2.0` and never divides; for
`a ≤ 1/2` with an identically-zero `e` it raises `ZeroDivisionError` instead of reporting.
That is the *right* direction (loud, not silent), and it is recorded, not repaired.

## FINDING C — the three-cutoff ladder never decides anything (hazard H2 rider, lesson 90)

`second_derivative_sup`'s docstring presents the cutoff comparison as the evidence:

> *"FLAT across cutoffs => finite (p >= 2, i.e. a <= 1/2). GROWING with cutoff => the sup
> is infinite…"*

It is not evidence. Over 12–16 converged cases spanning `a ∈ [0.1, 1.2]`:

| measurement | magnitude |
|---|---|
| converged cases | **16** (runner) / **12** (battery) |
| cases where the ladder changed `N2_finite` away from `(a ≤ 1/2)` | **0** |
| cases where the ratio was evaluated at all | **10** — the other 6 short-circuit on `p >= 2.0` |
| distinct cutoff ratios among those 10 | **{1.0}** — exactly 1.000000, ten times |

**The mechanism, not just the effect** (lesson 85). For `p > 2`, `e^{p-2}` is an *increasing*
function of `e`, so its supremum is attained where `e` is largest — in the **interior** —
and moving the edge cutoff from `1e-3` to `1e-10` cannot touch it. For `p < 2` the
`rp.p >= 2.0` conjunct returns `False` before any cutoff is read. So `N2_finite` is a
restatement of the analytic condition `a ≤ 1/2`, computed from `a` alone, dressed as a
three-point numerical measurement.

Ten identical `1.000000`s should have read as a tautology, not as a confirmation — which is
lesson 90 word for word. This does not make `N2_finite`'s *answer* wrong (the analytic
condition is correct and is the module's finding (3b)); it makes the *evidence* for it
decorative.

## The two sites that did NOT corrupt, with their magnitudes

**Hazard H3 — `Y_0` is a sup estimated by sampling.** `interpolant_defect`'s evaluation
grid size `n` is a caller-settable argument on a quantity that is a supremum, with no
resolution check.

| | `a = 0.5, K = 96` | `a = 0.8, K = 96` |
|---|---|---|
| default `n = 997` | `1.182e-09` | `1.598e-06` |
| refined `n = 9973` | `1.218e-09` | `1.677e-06` |
| **default under-reports the refined limit by** | **2.9%** | **4.7%** |
| adversarial minimum (`n = 5`) | `1.99e-12` | `1.26e-09` |
| **max depression achievable by choosing `n`** | **611×** | **1335×** |

**The default is honest** — within 5% of the refined limit, and monotone in `n`, so it is
not accidentally sampling where the residual vanishes. The hazard is latent: **0 repo call
sites pass `n`**. Recorded as a trap, not as a corruption.

**Hazard H4 — which inversion residual `z0_defect` reports.** `np.linalg.inv` solves
`M X = I`, so the classical backward-stability result (Higham, *ASNA* 2nd ed., ch. 14)
covers the **right** residual `‖M A − I‖`. The module computes `A @ M - I`, the **left**
one.

| `a` | `K` | reported (left) | right | left/right | `cond(M)` |
|---|---|---|---|---|---|
| 0.3 | 32 | `1.699e-12` | `8.50e-15` | **199.9×** | `5.82e3` |
| 0.3 | 96 | `1.423e-11` | `5.12e-14` | **277.7×** | `3.44e4` |
| 0.5 | 96 | `4.319e-12` | `5.34e-14` | **80.9×** | `6.05e3` |
| 0.8 | 96 | `9.657e-13` | `5.30e-14` | **18.2×** | `1.25e3` |

The reported quantity is **larger** than the unreported one in **6 of 6** cases, by 9.6×–278×.
The module reports the *conservative* side, and `cond(M) ≤ 3.4e4` — nowhere near singular.
**Not a corruption site**, and the gate that says so is a soundness gate.

**Input axis — poisoned `b` away from `p == 2`.** Single-entry NaN and inf poison at three
indices, through four entry points: **24 probes, 0 silently finite.** The module propagates
correctly everywhere except the `p == 2` case of finding B.

**Input axis — degenerate `a`.** `ReducedProfile.__init__`'s guard is
`if not 0.0 < float(a)`. Of 8 values tested it **admits 4** (`inf`, `1e300`, `1e-300`,
`1e-12`) and rejects 4 (`nan`, `-inf`, `0.0`, `-1.0`) — `a = inf` gives `p = 1/a = 0.0`, a
nonlinearity `e^0`. But `rehearsal` reports `converged = False` on **4 of 4** of them and
emits **0** verdicts. The constructor guard is incomplete; the assembled entry point catches
every case. Reported as an incompleteness, not a corruption.

## Recommended repair (for whoever holds patch authority — NOT applied here)

Three changes, none of them in the Newton path, none of them changing a number on a clean
in-domain call. Listed so the escalation is actionable; leg 109 did not apply them.

1. **Derive the verdict from the dict it ships with.** Replace the string literal at
   `rehearsal:230-237` with a sentence assembled from the measured `Y0_interpolant_defect`
   and `Z0` — e.g. quote the values and state whether each meets its stated level, rather
   than asserting it. The template is in-repo: the `target_norm.py` / `first_integral.py`
   bench repairs both propagate a *measured* field rather than a claimed one. Any repair
   must keep `test_reduced_certificate.py`'s 7 gates and re-run the v16 sweep, because
   `writeup/data/p2_route_d_v16_rehearsal.json`'s three `verdict` fields would change text
   (no numeric field moves).
2. **Guard `N2_finite` on the finiteness of what it measured.** `p == 2` is a real special
   case (`sup|N''| = 2` exactly, and that is finding (3b)'s boundary), so the fix is not to
   remove it but to require `np.all(np.isfinite(e))` before certifying — the `nan ** 0.0`
   path is the entire mechanism. Guard the division against `min(npp) == 0` at the same
   time.
3. **Make `step_adversary`'s `kind` explicit.** `if kind not in ("step", "single"): raise
   ValueError(...)`. The control must not be reachable only by exact string match.

A fourth, optional: have `interpolant_defect` refuse or warn below some `n` relative to `K`,
so a sup cannot be quietly under-sampled by 3 orders of magnitude.
