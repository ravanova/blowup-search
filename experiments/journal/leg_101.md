# Leg 101 — Route-OLA: adversarial soundness audit of `solver/op_lower.py`

**Gate.** "Under an adversarial battery of degenerate or NaN-poisoned operator inputs, does
`solver/op_lower.py` ever return a value that is NOT a true lower bound on the dense operator
norm (i.e. exceeds the true norm on a case where both are computable)?"

**Answer: YES.** 47 of 209 gate-deciding cases, two distinct mechanisms.
**Escalated, not patched — `solver/op_lower.py` is byte-identical to what this leg found.**

## The result in one table

| | cases | magnitude |
|---|---|---|
| Tier A total | 408 | 209 gate-deciding, 199 excluded (reference not computable) |
| **VIOLATION, overflow** | **46** | reported `inf` against a finite true norm; 38 of the 46 have a true norm that is an ordinary float64 (smallest: **1.0e13**) |
| **VIOLATION, finite** | **1** | **425.2 ULP = 6.04e-04 relative** above the exact true norm, as an ordinary finite number |
| sound, within one ULP | 3 | max 0.383 ULP — correct rounding, not a defect |
| sound, nonzero | 118 | max finite `L/N_true` over all decided cases = **1.000604187** |
| sound but `L = 0` | 41 | weak-but-true: under-reporting is a PASS by the pre-committed rule |
| Tier B (real `HolderNorm`) | 19 | 12 nonzero headlines, **12/12 reproduced to 1e-12** by their named family member; 7 report exactly 0.0; **0** not-reproduced, **0** nonzero-nonfinite |

Runner `experiments/p2_route_ola_v1_adversarial.py`, 48 s. Data
`writeup/data/p2_route_ola_v1_adversarial.json`. Regression test
`test_op_lower_adversarial.py` (7 checks, all passing; 1, 2 and 4 pin the live defect).

## The three failing cases, precisely

**(A) Degenerate codomain weight → `inf` on a norm of 1.0e13.** `A = inv(M)` with `M = I` except
`M[3,3] = 1e-13`, so `A[3,3] = 1e13` and `A` is the identity elsewhere. Weights `t = u = 1e-300`
(uniform). Exact true norm over the searched subspace `{g : g_0 = 0}` is **exactly 1.0e13**.
`op_lower.best_lower` returns **`inf`** — and so does `sign_pattern_lower` on its own, so this is
not a quirk of one routine. Mechanism: `smooth_family` builds every candidate as `iv = 1/cod.w`
times a shape, here `1e300`; `A @ g` reaches `1e313`, past the `1.798e308` ceiling; the codomain
norm meanwhile stays a benign `32.0`, so the quotient is `inf/32`.

**(B) `ascend` overflows on its own step — no degenerate weight required.** `A =`
Hilbert `× 1e200`, **all weights 1**, every entry of `A` finite. `family_lower` returns a sound
finite `5.0e199`; `best_lower` returns **`inf`**. Mechanism: `solver/op_lower.py:130`,
`step = scale * best * (rng.normal(size=K) @ basis) / sqrt(K)` — the trial step is sized
**proportional to the bound found so far**, so once `best ~ 1e199` the ascent's own candidates
are `~1e199`, their images overflow, and `best_lower`'s `max(...)` promotes `inf` to the
headline. Any operator with norm above roughly `1e154` is exposed, whatever the weights.

**(C) A finite number above the true norm, in the denormal range.** `A = ` Gaussian `× 1e-320`
(n = 32), the project's decay weights. Exact true norm **3.476720e-318**; reported
**3.478820e-318** — above it by **425.2 ULP, 6.04e-04 relative**. Verified three ways so the
fault cannot be blamed on the reference: the exact rational true norm, the exact rational ratio
**of the same witness vector** (which is correctly ≤ the true norm), and the float ratio (which
is not). The excess is created by the float evaluation of the quotient itself. This is the more
insidious class — `inf` announces itself, an ordinary-looking finite number does not.

## SCOPE — no banked number is contaminated

Measured, not argued (check 7): on the real J-collocation operator that Route-D actually uses,
the largest image the candidate family produces is **2.380**, i.e. **307.9 decades** below the
overflow ceiling, at J = 200/300/400 alike (`max|A|` grows only as `1.95e2 → 3.90e2`). The
operator's entries sit ~300 decades above the denormal range as well. **Both mechanisms are
unreachable from anything this project feeds the module**, and Tier B confirms it directly: on
the real `HolderNorm` pair every nonzero headline is finite and exactly reproduced by its named
family member. The banked bracket is not in question. What is in question is
`capabilities.py`'s unqualified validated-clause, "brackets the dense operator norm from below
wherever both are computable" — as written it is false, and the honest form carries the range
caveat. **That edit is the orchestrator's to make, not this leg's** (`capabilities.py` is outside
this leg's territory and was only read).

## What held up

- **NaN never produces a plausible number.** All three NaN-poisoned operators (generic entry,
  whole row, and the gauge column the module zeroes) return **exactly 0.0** — the safe direction.
  `if r > best` and `if n > 0` are both `False` on NaN, so NaN is skipped rather than propagated;
  0 NaN headlines in 408 cases.
- **Inf-poisoned operators returning `inf` is correct**, not a violation: their true norm really
  is unbounded. Graded as a pass, and the check asserts only that no *finite plausible* value is
  invented.
- **The witness discipline holds under hostile input.** 12/12 nonzero Tier-B headlines reproduce
  to 1e-12, including on `1e200`- and `1e-320`-scaled operators. The bookkeeping is honest even
  where the arithmetic is not.
- **Everything in the normal float range is sound**, to within one ULP, across 14 operator ×
  weight combinations including rank-1, zero, near-defective, Hilbert and zeroed-gauge-column.

## Two corrections this leg made to itself, both recorded rather than quietly applied

1. **The first reference was wrong, and it manufactured two violations.** The float expression
   `max |A_ij| t_i / u_j` **underflows to 0.0** on denormal and `1e-300` input — so the run-1
   reference reported a true norm of exactly zero and duly flagged `L > 0` as a violation on
   `denormal/tiny_all` and `huge_col0_only/tiny_all`. Both were artifacts **of the reference**,
   not of `op_lower`. The reference was rebuilt in **exact rational arithmetic** (`Fraction`) for
   the `l1→linf` pair, and pow-2-rescaled (exact in binary) before the SVD for the `l2→l2` pair;
   both spurious cases then correctly disappeared. A soundness audit whose own instrument
   underflows in the regime it is auditing is worth nothing, and this one did until it was fixed.
2. **The pre-committed tolerance was the wrong instrument below the normal range.** The novelty
   pass fixed a fixed *relative* slack of 1e-9. In the denormal range one ULP is already ~1e-6
   relative, so a correctly-rounded quotient can sit up to half an ULP above the exact value
   through no fault of the module — and run 2 flagged exactly such a case (**0.383 ULP**) as a
   violation. It is not one. Exceedance is now measured in **ULPs of the returned float**, and
   only a > 1 ULP excess counts. This *reduced* the finite-violation count from 1 to 0 — and then
   a dedicated dimension sweep of the denormal range found the real one at n = 32 (**425 ULP**),
   which the single-dimension zoo had missed. The stricter rule found more, not less.

The overflow class is untouched by both corrections: `inf` against a finite true norm is neither
a rounding question nor a reference question.

## What this leg did NOT do

No bound was sharpened, no candidate direction was added to the family, no new machinery was
built (the ban check is `writeup/novelty/leg_101.md` §5). `solver/op_lower.py` was read and never
edited, under the yes-branch exactly as under the no-branch. The audit can only withdraw
confidence or bank a test; it adds no mathematical result.

## The mechanism of the repair

The cause of both classes is one thing: the quotient `dom(A g)/cod(g)` is **scale-invariant in
`g` and exactly homogeneous of degree one in `A`**, yet it was evaluated at whatever absolute
scale the caller's inputs happened to carry.

1. **Exact power-of-two normalisation.** `A` is scaled once into `[0.5, 1)`; each candidate `g`
   likewise when its own scale threatens the exponent range. The `A` exponent is recombined at
   the end. Powers of two are exact in binary floating point — verified by bit-for-bit round trip
   (check 8), not assumed — so the mathematics is untouched and only the exponent range the
   arithmetic happens in moves. This kills the overflow class outright (`|A g| = 1e313` never
   forms) and restores the full 53-bit mantissa in the denormal range, where the finite exceedance
   came from ~1e-6 rounding per product.
2. **Downward deflation.** What survives is ordinary normal-range rounding, removed before the
   number is returned: the standard dot-product bound `gamma_n = n u/(1 − n u)` scaled by the
   matvec's own cancellation ratio, plus a subnormal `eta` term, plus a fixed slack for the norm
   functors. On the production path the total certified bound is **1.407e-12**.
3. **One further step down in the subnormal output range.** This was not in the design and the
   measurement forced it. Rescaling `A` fixes the *arithmetic*, but `ldexp` recombining the
   exponent lands the result back among the subnormals, where it is no longer exact — it rounds,
   by up to half an ULP, and half an ULP there is ~1e-6 relative, far more than a 1e-12 deflation
   of a subnormal can remove (that deflation is a literal no-op). Five cases were left sitting
   0.2–0.4 ULP above the true norm by this alone. One `nextafter` down closes it: the run went
   from `sound_within_one_ulp = 5` to `0`, and max `L/N_ref` from 1.000000265 to 1.000000000.
4. **Rejection instead of a number**, when a candidate's image or norm is not finite, or when its
   certified error bound exceeds 1e-6.
5. **Saturation instead of `inf`.** An operator whose true norm is genuinely past 1.798e308
   (check 9 builds one at ~1e401) returns `finfo.max` with a `saturated` count — still a true
   lower bound, and one a caller can act on.

**The ascent's step law is deliberately UNCHANGED**, even though it is mechanism (B)'s proximate
cause. Sizing the step differently would change which directions the search visits, i.e. it would
sharpen or blunt the bound — the banned act (novelty §8.4). What changed is only that a step that
runs out of exponent range now yields a *rejected candidate* instead of an `inf` headline.

## The correction the measurement forced on the repair itself, recorded rather than quietly applied

**The first version of the `g` rescaling was unconditional, and it cost 37 cases their bound.**
Normalising every candidate into `[0.5, 1)` is exact and safe for the matvec — but the norm
functors are black boxes with their own exponent limits, and a weighted `l2` *squares* its
argument, so it dies two orders of exponent sooner than the matvec does. With `w = 1e-300`, a
candidate renormalised down to `~1e-3` makes `(w g)^2` underflow to zero, the denominator becomes
0, and the candidate is rejected. Result: `sound_but_zero` jumped 41 → 78 while soundness was
already perfect. The fix is that the rescaling is a **fallback, not a policy** — the caller's own
scaling is tried first whenever it is not itself the hazard, and the renormalised one is used only
if that fails. `sound_but_zero` came back to 48 and `sound, nonzero` rose to 161. A repair that
buys soundness by throwing away the answer is not free, and the cost has to be measured, not
assumed away.

## What is rigorous here and what is calibrated

Stated in the novelty pass before the build, and the measurement did not change it:

- the power-of-two rescaling is **exact** — verified bit-for-bit by round trip (check 8), not assumed;
- the matvec deflation is **rigorous** (Higham Thm 3.5 plus a subnormal term);
- the allowance for `dom` and `cod`'s own internal rounding, `NORM_SLACK = 1e-12`, is **calibrated,
  not proved**, and cannot be proved from inside this module: they are black-box callables it does
  not own, and the repo has no exact-arithmetic norm. Its adequacy is a measurement over 209
  cases against an exact rational reference — max `L/N_ref = 1.000000000` — not a theorem. This is
  also why `solver/interval.py` is not the answer here: interval arithmetic cannot wrap a callable
  it does not control.

Nothing in this module became rigorous in the sense the certificate lane means. What became true
is that the number it returns is **below** the true norm rather than sometimes above it.

## Tier B, and one classification that had to be re-thought

Tier B's witness check compared the headline to a re-evaluation of the named family member's raw
quotient at 1e-12. Post-repair the headline is a *deflation* of that quotient, so the criterion is
now directional — headline ≤ its own witness — with the gap bounded in whichever unit is coherent:
**≤ 1.010e-12 relative** over the 10 normal-range cases.

The subnormal case cannot be graded that way and is reported as its own regime rather than forced
into a threshold. There, the naive witness quotient **is the quantity leg 101 caught being wrong**;
the module's value is computed after the exact lift into the normal range and is the *more*
accurate of the two. The gap runs the other way and measures the denormal inflation the repair
**removes** from the witness: **458.0 ULP (3.53e-04 relative)** at n = 48. Soundness in that regime
is decided by Tier A's exact rational reference, not by a witness that is itself contaminated.
Inventing a ULP cap there would have been a threshold chosen to make a number pass.

## What this repair did NOT do

No bound was sharpened. No candidate direction was added to the family, no shape family extended,
no ascent lengthened, no operator changed, no step law retuned. Every guard it adds can only move
the reported number DOWN — deflation, rejection, saturation-below-`inf` — and the production
bracket moved down on all seven banked rows, by at most 1.648e-12 relative. Correcting the *sign
of a bound's error* is not sharpening it, which is the same distinction that cleared leg 101 itself.
