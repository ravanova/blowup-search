### 4.3 The measurement leg 221's headline did not make

"18 → 0" is a count, and a count cannot see a repair that buys its zero by breaking something
else. The **full transition matrix** can:

```
OK -> OK                    29        SILENT_WRONG -> OK          13
RAISED -> RAISED            11        SILENT_WRONG -> RAISED       5
NONFINITE -> NONFINITE       9        OK -> RAISED                 3
RETURNED -> RETURNED         9        NO_REFERENT -> NO_REFERENT   2
```

The 18 SILENT_WRONGs split **13 → OK** (the value is now right) and **5 → RAISED** (the module
now refuses rather than fabricating). Both are the repair working.

**Three cases move OK → RAISED, and leg 221 did not report them.** A refusal is neither
automatically a regression nor automatically correct, so each is **adjudicated against the
module's own documented precondition** rather than waved through: the case's grid is rebuilt
from the battery's own recorded parameters, and the window occupancy and the lstsq **rank** of
the (r, r³, r⁵) design matrix are measured. A refusal counts as justified only if the stated
precondition genuinely fails.

| case | window nodes | rank | σ_min/σ_max | pre-repair returned | pre rel err | verdict |
|---|---|---|---|---|---|---|
| `F1 r_min sweep: 2 nodes -- UNDER-determined` | **2** (< 3 params) | 2 | 2.40e-2 | `1.9995773690878733` | 2.113e-4 | JUSTIFIED_REFUSAL |
| `F1 r_win sweep: r_win=0.0003` | 21 | **2 of 3** | **4.13e-16** | `2.0009994415183723` | 4.9972e-4 | JUSTIFIED_REFUSAL |

**0 UNJUSTIFIED_REGRESSION.** Two of these are worth stating plainly, because they are a finding

## 5. Clause (b) — does the zero-contamination re-confirmation itself reproduce? **YES**, over the scope stated here

### 5.1 Method, and why a "0 moved" from this leg means more than a "0 moved" from leg 221

Leg 221's clause (b) and this leg's share a shape — a differential shim replaces
`odd_field_x_slope` with a wrapper that calls the **pre-repair** and **post-repair**
implementations on identical arguments, compares the results bitwise (NaN treated as equal to
NaN), and **returns the pre-repair value**, so the trajectory the artifact script follows is
exactly the banked one. If every call agrees bitwise, the repaired module reproduces the run by
determinism, and no banked value can have moved *because of the repair*.

Three things make this run a verification rather than a repetition:

1. **The shim is written in this leg's runner and imports nothing from
   `experiments/p2_route_bvrr_v1_repair.py`.** A bug in leg 221's comparison — say, a `==` that
   silently swallows NaN, or a shim that never actually installs — could not have been detected
   by re-running leg 221's own code. It is re-derived here from the module's documented
   behaviour, and the derivation is itself tested (§4.1 and the probe self-test).
2. **NO CACHE.** Leg 221's sweep was resumable and cache-backed, and its re-confirmation
   replayed in **66.1 s** against a **~34 h** original. A cache replay is not an independent
   re-run. There is no cache-read path anywhere in this leg's runner — the string appears only
   in the header stating its absence. Every artifact below carries `ran_live` and
   `from_cache` explicitly.
3. **A sharper measurement than "did anything move?".** A bitwise-agreement count of zero is
   necessary but weak on its own: it is equally consistent with "the repair is correct on this
   trajectory" and with "the guard was never reached, so nothing was tested." So each call is
   additionally instrumented for **guard reachability** — whether the DEFECT-B window cap
   actually **binds** (`r_win_eff < r_win`), the window's node count, and the fitted residual.
   That converts the zero from an observation into an *explanation*.

### 5.4 A fabricated zero in THIS LEG'S OWN instrument — found, repaired, and scoped honestly

`max_rel_residual_seen` was initialised to `0.0` in the shim's state dict and **never written to
by any code path**, so it reported exactly `0.0` for every artifact — a plausible number that
measured nothing. This is the same failure class as leg 205's DEFECT A (an unguarded `lstsq`
silently returning exactly `0.0`), occurring in the auditor rather than the audited module. It
was caught by noticing that a least-squares relative residual is never exactly zero on real data
across 95 068 calls.

The probe now actually solves the (r, r³, r⁵) fit on the capped window and returns
‖Ax − y‖ / ‖y‖. Re-measured live, it is demonstrably alive — `spike1_stepB_rescaled` 2/2 calls,
max **1.296e-05**; `p2_route_brs_v1_status_audit` 62/62 calls, max **1.469e-01**. **0 of 64
exceed the module's 0.5 backstop**, and the 0.1469 is the informative one: it sits within a
factor of **3.4** of the backstop, so the backstop is set at a scale the data approaches rather
than being unreachable by construction.

The four heavy sweeps were already in flight when this was found and cannot be retrofitted
without ~30 CPU-hours of re-running, so **the merge step strips the fake `0.0`** from any record
lacking `n_residual_measured` and marks it `residual_instrumented: false` with an explicit NOT
MEASURED note. The residual is instrumented on **2 of 6 artifacts / 64 of 340 233 calls**, and
that is stated as a scope limit rather than smoothed.

**The gap is covered, and the covering argument is itself a measurement:** the residual backstop
can only manifest as a **refusal**, and `raise_post = 0` across all **340 233** calls. A backstop
that never refused never fired. So the residual magnitude was a sharpening this leg wanted, not a
load-bearing input to the gate.
