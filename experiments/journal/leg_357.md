## What "every candidate" means here, honestly

B6 — the Newton-Krylov/multiple-shooting layer that would actually produce a non-trivial
periodic-orbit candidate — is user-gated and has not landed. So there is no genuine
Newton-iterate trajectory anywhere in this repository to point the screen at. I considered
three options: (a) wait for B6 (violates the plan's own "parallel with B6, no dependency"
framing and would strand this brick indefinitely), (b) build a screen against an abstract
interface and test it only with synthetic data (leaves the "does it work on landed DSSP
objects" question unanswered), (c) build the real screen and exercise it on the two DSSP
objects that HAVE landed — leg 351's closed-form witness and leg 354's Galerkin trajectory
— being explicit in every doc string and in this journal that neither is literally "a
Newton step". I took (c). The mechanism (four quantities computed per step, ledger
machine-read against them) is exactly what a live NK trajectory would need; nothing about
`screen_candidate()` assumes the candidate came from a Newton solve specifically — it takes
any callable field and, optionally, any `(s, c(s))` trajectory.

## Building the four screen quantities

`l3_norm_ladder` and `fitted_far_field_decay_exponent` reuse the spherical-quadrature
scheme legs 332/351/354 already established (Gauss-Legendre in `r` and `cos θ`,
trapezoid in `φ`) rather than inventing a new one. Run on leg 351's witness (Type-I decay,
`u_B ~ C/|x|` by the module's own docstring, verified there by `a(r)*r -> -1`): the fitted
exponent came back `-0.9971` (expected `-1`, and correctly NOT leg 332's `-3`, a different
Gaussian-vorticity witness), and the `L³` shell ladder does **not** converge — successive
shells stay roughly constant per decade (`87.82, 87.82, 87.82` across the last three
decades) rather than shrinking, the textbook signature of a logarithmic divergence
(`∫|V|³ dx ~ ∫(1/r) dr` for a `1/r` tail). This is the concrete, worked contrast the plan's
no-branch warning describes in prose: a well-behaved witness (leg 332's Gaussian one) lands
inside `L³` by default; this family's own Type-I witness, screened with the same
instrument, does not.

`axisymmetry_residual` samples `V` on `φ`-rings at a ladder of `(ρ, z)` and checks that the
cylindrical components `(V_ρ, V_φ, V_z)` don't depend on `φ`. **A real bug was caught while
building this**, not hypothetically: the first version normalised each component's spread
by its OWN max value. For leg 351's swirl-ansatz witness, `V_φ` is analytically zero
everywhere (a short algebra check: `u_1 cos φ` and `u_2 sin φ` cancel exactly in the `φ`
transverse combination for this ansatz), so both the spread and the scale in that first
version were pure floating-point roundoff (~`1e-16`), and dividing roundoff by roundoff
produced a false-positive residual of `2.0` — a residual that looks like total failure for
a field that is, in fact, axisymmetric to machine precision. Fixed by normalising every
component's spread by the RING's overall field magnitude (`max|V|` on that ring) instead of
each component's own scale; after the fix, the same witness reports `7.9e-16`. This is
recorded as a fixed bug, not a loosened tolerance (leg 318's lesson): the instrument was
wrong, not the threshold. A regression test (`test_normalisation_fix_matters_on_
identically_zero_component`) pins the corrected behaviour. A planted control — an explicit
`x1`-aligned perturbation that genuinely breaks axisymmetry — registers a residual of
`1.0`, confirming the diagnostic is not vacuously zero for everything.

`lambda_from_trajectory` needed one iteration too: my first version looked for any sample
after `s=0` whose `|c(s)|/|c(0)|` came back within tolerance of `1`, which fires
immediately on a smooth curve's own neighbourhood of `s=0` (values just after the start are
close to the start by continuity, regardless of whether a genuine period exists). Fixed by
requiring the trajectory to first LEAVE the near-`c0` band before a later return counts.
Tested two ways: on leg 354's own landed decaying trajectory (`α = -19/16`), it correctly
reports `λ` **undefined** ("relaxes toward the trivial state... matches leg 354's landed B4
gate finding") rather than silently returning `0` or `1`; on a synthetic trajectory built to
genuinely return to its initial amplitude after a known period `S0=2`, it detects
`λ = exp(S0/2) ≈ 2.634` against the true `2.718` (within the coarse `return_tol` used, and
correctly labelled `measured: true`) — the detector can succeed, not just always refuse.

## Runner

`experiments/p2_route_dsspb7_v1.py` screens (A) leg 351's static witness at unit amplitude
as "step 0", (B) five checkpoints along leg 354's landed Galerkin RK4 trajectory (screening
`V = c(s_i)·u_B` at each checkpoint — this is the "at every step" mechanism, exercised on
the only per-step trajectory this repository has), and (C) leg 332's landed `L³`
measurement as a read-only contrast run through the same ledger function. Every claim above
is an assertion in that runner, not just a printed number: divergence, decay exponent near
`-1`, axisymmetry near machine-zero, the planted control's non-zero residual, all three
ledger verdicts on this family's own candidate, and both directions of the leg-332 contrast
and the synthetic Pineau-Vicol inside/outside routing.

## Gate verdict

**YES.** Every screened candidate (the static witness and every trajectory checkpoint)
carries all four quantities, computed by quadrature/fit/detector rather than assumed, and
`machine_read_ledger()` derives each of the three exclusion verdicts by parsing legs
326/330's landed JSON clause fields plus this leg's own `L³`/`λ` measurements — no ledger
entry is a retyped sentence. Consequence: candidates from this family are reportable with
their exclusion status attached, per the plan's yes-branch. The no-branch's warning (leg
332's `‖u_B‖_{L³} = 0.7307683991070311`, landing in `L³` is the default) is demonstrated,
not just quoted: run through this leg's own instrument, that exact landed number still
reads `EXCLUDED`, while leg 351/354's own Type-I witness, run through the identical
function, reads `NOT EXCLUDED`.

**CEILING: TIER 2, stated explicitly.** Surviving this screen means "not already excluded
by a published theorem reachable on this repository's record" (NRS/Tsai; Chae-Tsai;
Pineau-Vicol). It is NOT evidence for existence of a genuine DSS blow-up profile and NOT a
proof or a Clay claim. Nothing here changes Clay odds (~0.05%, unchanged).
