| file | bytes | what |

| `experiments/programme_r4/seedbank/manifest.json` | 123,799 | one row per field: row, arm, field index, snapshot index, selection rule, **SHA-256 of the field bytes**, plus `R_seed`, `T`/`|s|` candidate values and deltas, window flag, pool sizes |
| `experiments/programme_r4/seedbank/demo_attempt.json` | 3,571 | gate (iii)'s record |

**THE SELECTION-RULE EXTENSION, and it is a choice, declared as one.** `E` drew ONE field per
`(row, arm)`; the ensemble needs ten. Stage 1 runs `e_hhard_diagnostic.select_seeds()`
**imported verbatim** and reserves its 16 snapshots as `field_index = 0`. Stage 2 continues
`E`'s own per-arm rule for `field_index = 1..9`, row-major in `TABLE_IV` order, arm S before arm
Q, with every already-drawn snapshot excluded — the same `used` bookkeeping, continued.
`E`'s rule had to be **re-expressed** for a single draw (`_pick()`), because `select_seeds()` is
monolithic, and **a re-expression is a second realization unless it is checked**: selftest `T1`
drives `_pick()` through `E`'s own loop and requires all 16 snapshots, rule strings, `R` values
and `n_shift_matched_available` counts to match. `T1` passes **16/16** and the build refuses to
write if it does not.

**Row-major ordering lets early rows take contested candidates first.** A round-robin would
spread the contention differently. It is recorded per field whether the `|s|`-matched subset was
still non-empty at the moment of the draw, so the contention is visible: **all 80 arm-S fields
came from a non-empty `|s|`-matched subset — zero fallbacks to the "no `|s|`-matched candidate"
branch.** The tightest row was `UPO35` (14 `|s|`-matched candidates for 10 draws).

## §2. THE GATE ANSWER

### (i) **YES — 160 of 160.**

Every banked field is **bit-identical**, in the sense of byte equality of its IEEE-754 float64
C-order buffer under SHA-256, to what `u2_m2_dns_recurrence.regenerate` produces from the same
snapshot index. **Zero mismatches.** The check was run **twice, two ways**:

| how | n bit-identical |
|---|---|
| **one snapshot per `regenerate()` call** — the shard case | **160 / 160** |
| **all 160 in one `regenerate()` call** — the case `E` actually ran | **160 / 160** |

The second is not decoration. `regenerate()` walks snapshots in sorted order and only restarts
from a checkpoint when the block changes, so *batch context is a live confound*: `E` regenerated
its 16 seeds in one call and a shard will ask for one. Measuring both makes batch-independence a
measurement instead of an assumption. It holds.

`writeup/data/p2_r_bank_v1.json` → `gate.i_bit_identical_to_regenerate`.

### (ii) **YES — 16 of 16, against `E`'s banked ledger.** And its ceiling is stated.

All 16 of `E`'s original fields verify against `experiments/programme_r4/e_hhard_ledger.json`.
Separately, all **16 of 16** also verify against `writeup/data/p2_prog_r4_e_v1.json`
(`snapshot_earlier`, `selection_rule`, `R_seed`, and **both** seed residuals `±|s|`, each at
exact float equality).

**CEILING C1, and it is the sharpest thing in this leg. Gate (ii) is NOT a byte comparison and
must not be reported as one.** `e_hhard_ledger.json` is a per-Newton-iteration ledger. It holds
**no field bytes at all** — `run_attempt` pops `_w0`, and `E` saved state only for the 2 attempts
that converged. So bit-identity *against the ledger* cannot be byte equality of a field. What the
ledger supports, and what was checked, is **exact float64 equality of the iteration-0 record**:

- `residual_before` == `‖R(w₀, T_published, s_seeded)‖` recomputed from the **banked bytes**
  through `E`'s own `seed_residual`;
- `T_before` == `T_published`;
- `s_before` == `s_seeded`, i.e. **the sign `E` measured** rather than assumed.

Three exact floats per attempt, 48 in all, every one equal with a zero ULP gap. A one-ULP change
anywhere in the field would move `residual_before`, so the check has teeth — but it is a
**functional** check of the field, not a byte check, and the two are different statements. I have
recorded that as ceiling `C1` rather than let the count carry more than it can.

### (iii) **YES — bit for bit, with the DNS artefacts absent.**

`E`'s **attempt 15** (`UPO9`, arm Q — the cheapest of the 16 at 0.22 h banked, and one of only
two that converged, so it exercises `T_converged`/`s_converged` as well as the failure path) was
re-run in a **12 MB scratch tree at
`.../scratchpad/nodns`** containing `solver/`, `experiments/programme_r4/` and three
`writeup/data/p2_prog_r4_*.json` files, and **no `u2_dns_ckpt.npy` and no `u2_dns_feat.f32`** —
their absence is asserted by the script itself and banked in the record as
`dns_artefacts_absent_in_this_tree: true`.

| | |
|---|---|
| scalar fields exactly equal to `E`'s banked record | **16 / 16** |
| per-Newton-iteration ledger entries byte-equal (canonical JSON) | **12 / 12** |
| `reason` | `converged` (as banked) |
| `final_residual` | `2.0552353500244844e-10` — **every digit** |
| `T_converged` | `16.536902623501312` |
| `s_converged` | `-0.09939218012637738` |
| `s_seeded` (the **measured** sign) | `-0.29499999999999993` |
| wall | 1173.3 s vs `E`'s banked 798.3 s |

The 1.47× wall inflation is **contention** — three sibling units were running on this 12-core box
at load average ~15 — and it changed **nothing** about the computation: the result is identical to
the last bit. That is the demonstration the gate asked for, and it is the whole point of the unit:
**a shard now needs a `git clone` where it used to need 3.44 h of DNS.**

## §4. WHAT I COULD NOT ESTABLISH — stated by me, not left for the Conductor

- **C1 (above).** Gate (ii) is a functional check against the ledger, not a byte check. The
  ledger has no field bytes to compare against. Nothing can fix that retrospectively; `E` did not
  bank its fields, which is exactly the defect this unit exists to stop repeating.
- **C2 — the artefact is now the DEFINITION of the seed, not a cache of a machine-independent
  one.** Gate (i) ran in *this* tree against *this* copy of `u2_dns_ckpt.npy`, on this CPU and
  this FFT build. It establishes that the banked bytes are what `regenerate()` produces **here**.
  It does **not** establish that another machine's `regenerate()` would agree. That is an
  argument *for* banking, not against — but it means a future disagreement between a shard and
  `regenerate()` should be read as a portability finding, and the bank, not the re-integration,
  is the reference.
- **C3 — gate (iii) is one attempt of sixteen.** The other 15 are covered only by gate (ii)'s
  iteration-0 check, which pins the seed and not the solve.
- **C4 — the 144 non-original fields have never been fed to the solver by anything.** They are
  verified as *bytes*. No attempt has been run from any of them and this unit estimates nothing
  about their seed residuals.
- **C5 — the row-major draw order is a choice**, declared in the module docstring, not forced by
  `E`'s rule. A round-robin would have produced a different 144. Nothing here measures whether it
  matters; it is recorded so that `E-FE`'s null, if it gets one, names its own realization
  (**lesson 91**).

the standing rule (W3 ruling Q3, *a banked datum gets a correction record beside it, never an
edit*), **the existing line is not rewritten**; a correction record sits in this unit's own
appended block of the same file. The restatements in `WAVE7_PLAN.md` are the Conductor's and were
left alone.

## §6. RESOURCING (§3d) — NOT under-resourced

`UNDER_RESOURCED = false`. Briefed at ~10⁰ core-h; measured **≈1.06 core-h** (build 230.0 s;
`--verify` 1166.87 s × 2 runs; the demo attempt 1173.3 s; ~900 s exploration and scratch-tree
setup). **Bit-identity did not require re-running the 3.44 h DNS** — the checkpoint archive was
present in this working tree and one `regenerate()` call costs ~2.3 s under load. The §3d escape
hatch was available and was not needed.

**What the artefact buys `E-FE`:** at 8 shards the DNS prerequisite was **~27.5 core-h of
duplicated overhead on a 90.9 core-h job — 30%** — and it gets worse with shard count. It is now
zero. The second benefit is not a number: the seedbank is **tracked**, so it cannot die with a
container, which the DNS checkpoints have now done twice.

## §7. §3k — THE EXEMPTION IS STATED, NOT ASSUMED SILENTLY

Rule 3 asks a construction unit to name the published method it implements. **This unit
implements none.** It re-executes this repository's own existing code — `regenerate`,
`select_seeds`, `seed_residual`, `run_attempt`, `solve_with_stall_exit` — and hashes the bytes
that come out. The only external machinery is **SHA-256 (FIPS 180-4)** and **IEEE-754 binary64**,
neither of which is a method this programme could have found already built and skipped. **No new
external source is relied on, so `writeup/SOURCES.md` gains no row** — that is a deliberate
non-edit, recorded here so it is not read as an omission. Depth of what this unit did lean on:
**`RECOMPUTED`** (own code, re-executed and byte-compared).

## §8. WHAT THIS RESULT DOES NOT LICENSE

- **No `L1 → L4` link moved. No wall moved. Clay stays ~0.05%. Tier 2 is never a proof.** This
  unit produced no candidate, no certificate and no statement about Navier–Stokes.
- **Scale is not evidence.** 737 KB of committed fields is a *portability* fact. It says nothing
  whatever about the object, and 160 fields is not 10× more evidence than 16 — it is 10× more
  draws, which is `E-FE`'s question and not mine.
- **It does not say the ensemble will find anything.** It says `E-FE` can launch 160 attempts
  without paying the DNS 8 times. `E`'s 0-of-16 is untouched; `E-iv`'s realization gap and the
  `N = 24` resolution limit are untouched; the no-grinder and no-new-supply prohibitions are
  untouched — **no seed supply was added**, the 160 fields come from the *existing* banked
  `u2_recurrence_library.json` and the admission window is not applied, exactly as `E` had it.
- **It does not certify the seed fields as correct**, only as *the same bytes* the existing
  re-integration path produces (see C2).

Reproduces every count in §2 and §3 and rewrites `writeup/data/p2_r_bank_v1.json` with the same
`self_hash` — the hash recipe deliberately **excludes `verify_seconds`** (and itself), so a
