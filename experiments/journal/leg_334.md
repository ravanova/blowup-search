## 3. The reasoning, claim by claim, with what could have falsified each

### 3.1 The `2p+s>d` criterion and its control

**Claim.** For `|f| ~ |y|^{-p}` in `ℝ^d` against `(1+|y|)^{-s}`, the far field is square-integrable
iff `2p+s > d`; against a Gaussian growing weight, never, for any algebraic `p`.

**Why it is not circular.** It was written from the exponent alone, and then checked against a
measurement it was not fitted to. With the Type-I bound `|V| ≤ C/(1+|y|)` (`p=1`, `d=3`) it predicts
the crossing at **`s = 1`**. Leg 313 **measured** the crossing at `s = 1.0` (shell ratio 1.000216),
with 0.9 diverging and 1.1 finite — computed by a different leg, on shells from `R = 1e4`, for a
different purpose. **Had the criterion produced `s = 0` or `s = 2`, §2.3's space choice would be
wrong and the plan would have had to say so.** It is a control that could have come out differently.

A second consequence fell out and is reported because it is a design argument independent of leg
332's: with `p = 2` (vorticity of a Type-I profile), `2·2 + 0 = 4 > 3`, so **`Ω ∈ L²(ℝ³)` unweighted,
with margin 1** — the vorticity formulation buys a full unit of weight. Two independent arguments
(this one, and leg 332's Leray finding) reach the same formulation; recorded as two, not merged.

Third: applying the criterion to **leg 331's own measured tails in `d=1` at `s=0`** gives
`3.015 / 4.024 / 5.036 > 1` — **every tail leg 331 measured is Lebesgue-square-integrable.** So the
`0.9655 → 1.869e22` divergence is **100% weight-driven**, which is leg 331's own reframing restated
as an inequality with margins.

### 3.2 The nonlocal-output rule

**Claim.** The nonlocal operator's output is fatal as a **standalone summand** in the weighted norm
and harmless as a bounded **multiplier** against a decaying factor. Derived by reading 331 and 332
**together**: 331's fatal quantity is `‖Λ^{2α}ψ_m‖_{L²(μ)}` (alone); 332's finite quantity has every
term carrying `ω` or `∇ω`, with `u = BS(ω)` entering only through `‖u‖_∞`, `‖∇u‖_∞`, and its ratios
measured **0.10094** and **0.13863**, strictly inside `(0,1)` — i.e. the bound holds and is not
vacuous.

**This is lesson 87** (*a certification method has a SHAPE, a property of the OPERATOR: multiplier or
shift?*). **It survives both branches of the narrowing** because it is a statement about how an
operator is *used*, not about which weight is chosen. Enforced as brick B3's gate.

**What is NOT claimed.** That `‖∇V‖_∞ < ∞` for the actual numerical profile. That is a hypothesis,
and it is B3's gate rather than a result.

### 3.3 The dichotomy and the Tier-2 ceiling

Algebraic weight ⇒ target in the space, linearisation has **continuous** spectrum (Route-E §26's own
measurement in this repo's model: only two grid-converged isolated eigenvalues 0 and −1, planted
positive control +1.083 / +4.578). Gaussian weight ⇒ **discrete** spectrum, target not in the space.

**This is why the ban and the function space are the same fact**: *"a continuum has no eigenvalue to
move"* is Entry A's own stated reason, and it is also the reason the entrance must be a seeded search.
**No report from leg 341 revives the cheap entrance** — Entry A's lift condition is `never`.

## 7. The prose-vs-JSON check, and what it caught

Because the JSON is hand-curated, an ad-hoc checker was run from the scratchpad (not committed — no
runner path is in territory). It verifies four things: every load-bearing number in the prose appears
in the JSON **and vice versa**; 20 arithmetic identities the prose asserts; that **every** drafted
brick gate contains an explicit `CEILING: TIER 2` line; and that no Clay-progress phrasing appears.

**It caught three real defects, all fixed:**

1. `arXiv:2405.10916` (Hou) appeared in the prose but only as a JSON **key** with underscores
   (`hou_2405_10916_...`), so the identifier was not machine-findable. An explicit `hou_id` field was
   added.
2. `arXiv:2404.04054` (Breden–Chu) was quoted in §2.8 and **absent from the JSON entirely**. Added.
3. The prose writes `−3.0000000000000027` with a **Unicode minus** (U+2212) while the JSON uses
   ASCII, so an identical number read as a mismatch. The checker now normalises typographic variants.

**And then the checker itself broke, which is the finding worth recording.** Adding that
normalisation replaced the em-dash in the brick headers, so the brick regex matched **zero** bricks —
and the ceiling check **passed vacuously**, reporting "without a CEILING line: NONE" over an empty
set. **This is lesson 90 exactly: a control that cannot come out differently.** It was caught because
the printed brick list was empty. Fixed by matching the normalised text and by adding
`assert len(gates) == 9`, so the control now fails loudly if it stops seeing the bricks.

Final run: **all four checks PASS, 9 bricks found, 9 carrying the ceiling, 20/20 arithmetic
