## 2. Part (a): the float64 mechanism, re-measured

Leg 318's banked story (`experiments/p2_route_decr_v1_scoping.py` comments, and the mirrored
prose in the two writeup files) was: FT1's diagnostic float64 residual
(`5.329070518200751e-15` at the worst γ = 1.075 on the 45-point grid) is "~25 ulp of
catastrophic cancellation between two `≈1`-sized operands, `(r−1)/α` and `(r−2)`" — leg 302's
failure mode, verbatim.

Re-measured directly, at the worst γ = 1.075 (`gammas = np.linspace(1.05, 2.15, 45)`,
`alpha_of(gamma) = (gamma-1.0)/2.0`, `r_crit(gamma) = 2.0*gamma/(gamma+1.0)`,
`delta_dis(gamma, r) = (r-1.0)/alpha_of(gamma) + r - 2.0`):

```python
from fractions import Fraction
import math

g = 1.075
r = r_crit(g)                 # 1.0361445783132528  (the float64 value)
alpha = alpha_of(g)           # 0.03749999999999998  (the float64 value)

gq = Fraction(g)               # exact value of the double g
rq_exact = 2*gq/(gq+1)          # true rational r_crit(g), no rounding
aq_exact = (gq-1)/2              # true rational alpha_of(g), no rounding

r_err  = Fraction(r) - rq_exact       # -1.9606580516170205e-16
a_err  = Fraction(alpha) - aq_exact   # 0.0  (EXACT)

r_err_ulp = float(r_err) / math.ulp(r)        # -0.8830018870663376
a_err_ulp = float(a_err) / math.ulp(alpha)    # 0.0

# sensitivity of delta_dis to each operand at the root:
dD_dr = 1/alpha + 1          # 27.666666666666682
dD_dalpha = -(r-1)/alpha**2  # -25.702811244979795

# reconstructing the residual from r's error alone (alpha treated as exact-for-its-own-double-value):
delta_if_alpha_exact = (Fraction(r)-1)/aq_exact + Fraction(r) - 2   # -5.424487276140427e-15
# reconstructing the residual from alpha's error alone (r treated as mathematically exact):
delta_if_r_exact = (rq_exact-1)/Fraction(alpha) + rq_exact - 2       # 0.0

delta_dis(g, r)   # the actual observed float64 residual: -5.329070518200751e-15
```

**Findings:**

* `alpha_of(gamma)` at γ = 1.075 is computed with **exactly zero** rounding error:
  `Fraction(alpha) - aq_exact == 0`. This holds because `gamma - 1.0` is an exact subtraction
  under Sterbenz's lemma (the two values are within a factor of 2 of each other), and halving
  a float64 is always exact in binary floating point. `a_err_ulp = 0.0` exactly.
* `r_crit(gamma)` carries essentially all of the error: `r_err_ulp = -0.883`, i.e. about `0.88`
  of one ulp (from the addition `gamma+1` and the subsequent division, two roundings inside a
  single expression).
* `delta_if_r_exact = 0.0` — if `r` had zero error, the identity would be exactly `0` (as it
  must be, since it's the algebraic identity being tested).
* `delta_if_alpha_exact = -5.424487276140427e-15` — reconstructing the residual using the
  *actual* float64 `r` (with its `-0.88 ulp` error) but a mathematically exact `alpha`
  reproduces almost the whole observed residual (`-5.329e-15`); the small remaining gap
  (`~0.095e-15`, ~1.8% relative) is the extra rounding inside `delta_dis`'s own float ops
  (the division and addition in `(r-1.0)/alpha_of(g) + r - 2.0`), not a contribution from `alpha`.
* The amplification factor is `d(delta_dis)/dr = 1/alpha + 1 = 27.667` at this γ, dominated by
  the `1/alpha = 26.667` term (the `+1` is a ~3.7% correction). `r_err * dD_dr = -1.961e-16 *
  27.667 = -5.424e-15`, matching `delta_if_alpha_exact` exactly (by construction — this is the
  same first-order reconstruction).

**Checked across the full 45-γ grid** (not just the worst point):

```
g=1.0750 resid=-5.329e-15  r_ulp=-0.88  alpha_ulp=+0.00  1/alpha=26.667
g=1.1500 resid=-2.220e-15  r_ulp=-0.70  alpha_ulp=+0.00  1/alpha=13.333
g=1.1750 resid= 2.665e-15  r_ulp=+0.97  alpha_ulp=+0.00  1/alpha=11.429
...  (22 nonzero-residual points total; alpha_ulp is 0.00 at EVERY one)
g=2.0000 resid=-2.220e-16  r_ulp=-0.33  alpha_ulp=+0.00  1/alpha=2.000
```

`alpha_of` never carries nonzero ulp error at any grid point; `r_crit` always does (when the
residual is nonzero at all), and the residual tracks `r`'s ulp error times `1/alpha_of(gamma)`
throughout — the amplification grows as γ approaches the low end of the range (small `alpha`),
exactly matching the shape of the original diagnostic residual across the grid.

**Corrected mechanism statement:** it is not cancellation between two `≈1`-sized operands. It
is **1 ulp of pre-existing rounding error in `r` (from `r_crit`'s own float64 division),
amplified by the reciprocal of the other operand, `1/alpha`** (dominant term of
`d(delta_dis)/dr = 1/alpha + 1`). "Leg 302's failure mode" as a category label — an IEEE-double
cancellation masquerading as a transcription error — does not describe this case; this is
ill-conditioning under amplification near a root (a small input perturbation blown up by a
large derivative), not loss of precision from subtracting two nearly-equal numbers. **FT1's
verdict is unaffected**: it was, and remains, decided in exact rational arithmetic
(`fractions.Fraction`), where the residual is identically `0` for both the corrected and the
original account — the mechanism correction touches only the *diagnosis*, never the
*measurement* or the gate.
