## 3. The "86x tolerance" arithmetic does not check out — an errata note, not a gate finding

Leg 221's own passage uses three other magnitude call-outs in the same docstring/journal
passage ("2000x", "93.9x", "1731x"), each of which divides the stated relative error by the
module's `5e-4` acceptance tolerance and lands within rounding of the quoted multiplier
(checked all three independently: `1.0/5e-4=2000`, `4.694e-2/5e-4=93.9`, `0.865/5e-4=1730`).
The two-scale case's own "86x" does not follow that pattern: `0.4324/5e-4 = 864.9`, an order
of magnitude off the stated "86x". The same "86x" wording appears identically in both
`experiments/journal/leg_221.md:162` and `solver/boussinesq_rescaled.py`'s DEFECT B docstring
paragraph — the two sources agree with **each other**, not with the tolerance basis used three
lines earlier in the same passage, which reads as an arithmetic/transcription slip carried
from one into the other rather than two independent errors. **This does not change the gate
answer.** The primary reproduced quantities (returned value, percent error, fitted residual)
all match exactly regardless of this multiplier; it is recorded here because leaving an
internally-inconsistent multiplier unflagged in a load-bearing docstring is exactly the kind
of thing a later leg would otherwise re-derive from scratch.

## 4. Mechanism, independently re-derived (not merely cited)

`d1(r)` was re-derived by a second, independent implementation of the same trapezoid
cos(beta)-projection `odd_field_x_slope` computes internally (not an import of its internals).
Measured, on the two-scale field:

* `|d1(r)|` peaks at `r_peak = 0.7073332`, matching (0.03% relative difference) the single-
  field peak radius `1/sqrt(2) = 0.7071068` of the **outer** scale (`lam=1`) alone — i.e. the
  peak genuinely resolves to the outer scale, exactly as leg 221 describes, and this leg
  confirms it by direct computation rather than by trusting the description.
* The resulting `r_scale = sqrt(2)*r_peak = 1.00032`, so `r_win_eff = min(0.4, 0.5*r_scale) =
  0.4` — **identical to the uncapped default `r_win=0.4`**: the window cap is measured
  non-binding, confirmed directly rather than inferred.
* The `(r, r^3, r^5)` fit over `r<0.4` then straddles both scales (outer envelope scale 1.0,
  inner envelope scale `1/sqrt(400)=0.05`, a 20x separation) without isolating either, and the
  3-parameter truncation cannot represent the inner-scale contribution — the systematic 43.2%
  error, at a residual (8.12e-2) that sits comfortably under the 0.5 backstop.

## 5. Genuine vs artifact — measured, not argued

Two checks independent of leg 221's own 256,233-call census (which is cited, not re-run — see
§6):

* **Every real field this repository actually banks or evolves through this guarded
  function** — Step-C's converged `profile_ansatz` omega and eta, the fields every banked
  relaxation run rests on — was checked for the same property the two-scale probe field has
  (multiple local maxima in `|d1(r)|`). Both have **exactly one** local maximum: single-scale.
  There is no second scale in either real field for the cap to mis-resolve. Neither field
  binds the window cap either (`r_win_eff = 0.4` for both, same as the two-scale probe, but
  for the different reason that there is no second scale to detect in the first place).
* A **fresh, live 30-step transient** of `RescaledBoussinesq.run()`, started from
  `profile_ansatz`, routed through the **unmodified** guarded function at every step (init
  reads plus three RHS evaluations per SSPRK3 step, ~120 calls total), raised no exception and
  produced no NaN/Inf. This samples that the guard behaves over real dynamics, not just at the
  converged endpoint — a small independent sanity check, not a substitute for a full sweep.

**Leg 221's own full per-call census is cited here as input, per this leg's own thesis, not
re-run**: 256,233 `odd_field_x_slope` calls across every banked artifact and test suite that
reaches the module, compared bitwise pre/post-repair on the actual banked trajectory, found
**0 moved**. Since the window cap is the only behavioural addition the repair makes beyond
defect A's refusal guard, 0 moved implies the cap never bound differently on any banked call —
no banked call ever encountered a two-scale-shaped input the cap could mis-resolve. Re-running
that 34h sweep is outside this leg's scope (and outside its own gate, which asks for
independent reproduction of *the flagged case*, not a re-run of leg 221's clause (b)); this
leg's own fresh checks above corroborate it at smaller scale rather than repeating it whole.

## 6. Conclusion

The mechanism is real, and now **doubly measured independently** (leg 221, and this leg with
its own re-derivation of `d1(r)`, its own bisection of the residual, and its own reachability
checks) — but its **realization** requires a hand-constructed synthetic two-scale field that
this repository's own physics does not produce anywhere this leg or leg 221 has looked. That
places the mechanism in **the probe's realization**, not in any banked result's reachability:
**yes-artifact**, per the gate's own vocabulary. Leg 221's flag closes on that basis. The
mechanism itself remains correctly documented in `solver/boussinesq_rescaled.py`'s own
docstring (DEFECT B paragraph) as a named, un-fixed limitation of the peak-based window-cap
heuristic — this leg changes nothing there, since its territory reads that file, it does not
edit it.
