## What "silently" means — fixed before the run

Following leg 80's own precedent of a predicate committed in advance. A return is
**SILENT-WRONG** iff all three hold: it returns normally **and emits no warning**; every
returned value is **finite** (a returned NaN/Inf is *visible propagation*, which the
gate's wording excludes); and the value is **materially wrong** — for a norm that means
**understated**, since understatement is the direction that fabricates a certificate. An
**overstated** constant is conservative: recorded with its magnitude, does **not** decide
the gate. A **negative** value returned for an operator norm counts, in the strongest
available sense — no operator norm is negative.

## THE FINDING — four silent-corruption sites

### BHA-1 (headline). A negative scalar border weight yields a negative "operator norm"

`induced_sup_norm(M, w_row, w_col)` computes

```
max_i  w_row_i * sum_j |M_ij| / w_col_j
```

which is the induced norm of the weighted sup norm `||z||_w = max_i w_i |z_i|` — and that
is a norm **only for w > 0**. With any negative `w_col_j` the inner row sum can go
negative, `np.max` selects it, and a negative number is returned as an operator norm.
Nothing in `weights()` or `certificate_constants()` checks the sign of a weight.

**Isolated against a hand-computable known answer.** For `M = [[1, 100], [3, 4]]` with
`w = (1,1)` the weighted norm is `max(1+100, 3+4) = 101` exactly:

| `w_col` | returned | true |
|---|---|---|
| `(1, 1)` (control) | **101.0** | 101.0 |
| `(1, −1)` | **−1.0** | 101.0 |
| `(1, −1e−9)` | **−3.99999999700e+09** | 101.0 |
| `(−1, −1)` | **−7.0** | 101.0 |

No exception, no warning, all finite.

**What it costs at the level the certificate is actually read.** The clean statement is a
**sign-flip differential**: same magnitude, one sign changed, nothing else touched.

| weight | Z_1 understated | ‖A‖ understated | Z_2 (+) | Z_2 (−) | radii root (+) | radii root (−) |
|---|---|---|---|---|---|---|
| `w_r = ±1e−6` | **1.198e+09 ×** | **6.671e+09 ×** | +1.18861e+17 | **−1.77946e+07** | **none** | **2.217e−11** |
| `w_om = ±1e−9` | **2.651e+12 ×** | **6.066e+10 ×** | +2.42652e+20 | **−1.99997e+09** | **none** | **2.171e−11** |
| `w_l = ±1` | 1.004 × | 1.003 × | +2.47849e+08 | **−2.09206e+07** | 9.589e−14 | 9.589e−14 |

Read the last two columns. At the honest weights the radii polynomial
`p(r) = (Z_2/2) r² − (1 − Z_1) r + Y_0` has **no real root** — the certificate does **not**
close at this `(n, p)`, which is this object's documented ceiling (legs 46/47). Flip one
sign on one scalar and a root appears. **A single character understates Z_1 by up to
2.65e12×, ‖A‖ by up to 6.07e10×, drives Z_2 negative, and converts a non-closing
certificate into a closing one — finite, unwarned, unraised.**

A negative `Z_2` also inverts the polynomial's curvature, so `p(r) ≤ 0` for all large `r`:
the fabricated certificate does not merely close, it claims an unbounded validation radius.

**Two controls, both of which could have failed (lesson 90):**
* **0 of 200** random *positive*-weight draws (`w_l, w_om, w_r ∈ [1e−3, 1e3]`,
  `p ∈ [−1, 3]`) produced a negative constant. The mechanism does not fire on admissible input.
* **Zero weights are REJECTED** — `w_l = 0`, `w_om = 0`, `w_r = 0` each raise
  `ZeroDivisionError` (3 of 15 weight probes). This asymmetry is the sharpest form of the
  finding: **the module already halts at the boundary of the admissible set and walks
  straight through it just past.** (The rejection is incidental — Python float division in
  `1.0/w_om` — not a designed guard, which is why it does not extend to the negative half.)

**Reachability: not hypothetical.** `test_interval_certificate.py:86` already calls
`b.certificate_constants(z, p=P_STAR, w_l=w[2 * b.n])` — `w_l` supplied by the caller,
read out of a weight vector. Nothing on that path asserts the entry is positive. Whether
any *banked* number is impeached is **not** claimed here and was not measured; the
exposure is **LATENT** on the evidence this leg gathered.

### BHA-2. `velocity_matrix` accepts a permuted / non-monotone grid

`velocity_matrix` is a trapezoidal antiderivative and assumes an **ascending** grid.
Against the known answer `U = W @ cos = sin` on `X ∈ [−2, 2]`, `n = 401`, pinned `U(0)=0`:

* sorted grid: max error **8.333e−06** (the instrument works)
* randomly permuted grid: max error **7.4723** — a factor of **896,675×**, all finite, no
  warning, no exception.

This is the **exact** gap leg 117 found and leg 152 closed in the sibling module
`solver/hl_rescaled.py`, where a permuted grid now raises `HLRescaledDomainError`. The
same shape sits unclosed here. Also accepted silently: descending grids, duplicate nodes,
all-zero grids, and a single node.

### BHA-3. `BorderedHL(pin=...)` silently truncates a pin of the wrong arity

`self.pin = tuple(float(t) for t in pin)` does not check length. An **arity-5 pin is
stored whole** and `F` reads only `pin[0..2]`, so two supplied border targets are
discarded with no signal — `F` is bit-identical to the arity-3 call. Arity 2 and 0 are not
caught at construction either; they surface later as an `IndexError` from inside `F`.
NaN/Inf pins propagate visibly, and an unset pin raises properly.

### BHA-4. `tail_exponent` silently drops NaN samples

The mask `(np.abs(f) > 0)` is **False for NaN**, so NaN samples are *excluded from the
fit* rather than propagating. With **14 of 28** window samples set to NaN, the reported
exponent moves from `−0.399999999998886` to `−0.399999999998350` — a shift of
**5.358e−13**. The module's own docstring calls this function an *internal known-answer
check* ("the measured tail exponent must reproduce the ratio the border rows never saw"),
so a diagnostic that launders poison into a perfect-looking power law is worse than none.
Related: on duplicate abscissas, where **no slope exists**, it returns a finite
`0.6906890595608515` (only a `RankWarning`).

## What came back CLEAN — the negative results, which are half the value

These four families are banked as SOUNDNESS gates so they cannot regress.

* **The fabrication-acceptance probe answers NO.** `certificate_constants` takes the
  approximate inverse `A` from the caller — the leg 116/128/146 shape — but
  `Z_1 = ‖I − A J‖` is a *real* check: **8 of 8** planted inverses (halved, doubled, zero,
  identity, transposed, from a different state, border columns zeroed, one entry ×1e6)
  raise Z_1 by more than 100× (minimum observed rise over all planted cases **22.0×**),
  and the exact `A` is not flagged (`Z_1 = 4.760e−09`). The scalar rescalings `A → sA` are
  **not** corruption: they move `Y_0` and `Z_1` in exactly compensating directions and
  leave the radii root invariant. That is the estimator being self-consistent, not blind.
* **The degenerate matching condition propagates VISIBLY — the gate's own named
  configuration, and the best possible answer to it.** Making the `Omega_X(0)` border row
  collinear with the `Omega(0)` row degenerates the matching condition *in the border
  block*: `cond(J) = 8.625e+17`, rank 204/205. `Y_0` goes to **1.6508e+17** against a
  control of **1.1606e+02** — an inflation of **1.422e+15×**. It **explodes rather than
  shrinking**, across the whole near-singular ladder (`eps = 1e−4 … 1e−14`). A degenerate
  matching condition that quietly produced a *small* `Y_0` would have been the worst
  finding available on this module; it does not happen.
* **Poisoned states propagate.** 7 positions × 4 poisons (NaN, ±Inf, 1e300) =
  **28 of 28** reach the reported constants; **0 silently absorbed**.
* **The exact-quadratic identity is real and discriminating.**
  `F(z+v) − F(z) − DF(z)v = Q(v,v)` holds to relative **1.6e−16** across `|v| ~ 1e−3…1e150`,
  and a 1e−6 relative corruption of `Q` is separated from the true `Q` by **~1.75e+09×**,
  so the module's own known-answer check is not vacuous. `constants_vs_weight` reproduces
  per-`p` calls with worst relative disagreement **exactly 0.0**, confirming (not assuming)
  that reusing one inverse across the `p`-curve is correct.

Also measured and **not** gate-deciding: extreme decay exponents `p` **overstate** —
`p = 2` inflates `Y_0` by 59.7×, `p = 60` by 2.34e+168 — which is conservative, and `p` at
±200/±inf/NaN goes non-finite, which is visible.

## One claim WITHDRAWN, recorded rather than dropped

Family I first appeared to show a fifth site: `rho_max = −8` returns `Y_0 = 1.79` where
`rho_max = +8` returns `Y_0 = 116.06`, a **64.81×** gap that looks exactly like a silent
understatement. **It is not one, and the check that kills it is cheap:**
`np.array_equal(np.sort(X₊), np.sort(X₋))` is **False** — the two grids are not the same
node set, so `rho_max = −8` is a *different discretization*, not the same object
relabelled, and the two `Y_0` are not two answers to one question. The claim is withdrawn
in the JSON (`I_construction.withdrawn_claim`) rather than deleted.

What survives the withdrawal is smaller and true: the grid is **descending** and
`velocity_matrix`'s antiderivative therefore runs backwards — `sum(Uop) = +2247.365595`
ascending against `−2247.365595` descending, an **exact sign flip**. **5 of 14**
constructor probes yield a non-ascending grid with no exception. Whether that makes the
*assembled* system wrong is not settled by this leg and is not claimed; what is settled is
BHA-2's direct known-answer measurement.

## Blast radius

**LATENT.** No banked number is impeached by this leg, and none is claimed to be. Every
mechanism requires a caller to supply something the module does not check — a negative
scalar weight, a permuted grid, a mis-sized pin, or NaN-bearing tail data. What the
finding removes is the *assumption* that the estimator would catch such a thing: it does
not, and for BHA-1 it fails in the certificate-fabricating direction with no signal of any
kind. `w_l` is already caller-supplied at `test_interval_certificate.py:86`.

This is **not** the leg 128 `Y_0/Z_0/Z_1` guard class (those defects were in the
certificate's own arithmetic); the nearest templates are **leg 142/NSA V2** — a negative
scalar silently deleting part of a norm — and **leg 152's G1/G3** — the permuted-grid and
non-positive-scale guards, already written for the sibling module and directly reusable here.

## For the repair leg (not this one)

The characterization gates are written so a repair **inverts** them, per this file's
leg-80 convention — they pass because they describe today's code and must start failing
when a guard lands. The three guards, in priority order:

1. **`weights()` / `certificate_constants()`: reject non-positive `w_l`, `w_om`, `w_r`**
   (and non-positive `nu`). `w = 0` is already rejected incidentally; extending to `w ≤ 0`
   is the same one-token polarity move leg 152 used (`np.any(d<=0)` → `np.all(d>0)`),
   which is NaN-rejecting for free. Highest priority — it is the certificate-fabricating one.
2. **`velocity_matrix`: require a strictly ascending grid.** Leg 152 already wrote this
   guard for `solver/hl_rescaled.py`; port it.
3. **`BorderedHL.__init__`: require `len(pin) == 3`**, and consider whether
   `tail_exponent` should reject rather than drop non-finite samples.

Per leg 135's rule, a repair must not make this leg's battery unrunnable: the
characterization gates should be **inverted in the repair's own commit**, at these
thresholds, never weakened.
