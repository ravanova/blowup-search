# Leg 209 — Route-SCA2: adversarial audit of `solver/spectral_certificate.py`

**Gate, in its pre-committed wording:** *"Under adversarial and degenerate inputs
(near-singular weight classes, boundary-of-admissibility `A`, NaN/Inf), does
`spectral_certificate.py` ever silently return a wrong `Z_1`/`sigma_min` value rather than
reject or visibly propagate the defect?"*

## GATE ANSWERS **YES** — four mechanisms, 24 of 46 cases silently wrong

**And, separately and just as importantly: Theorem NGX's own PROOF is NOT at risk, and
0 banked numbers are contaminated.** Those are three different questions and this leg
answers all three, on the three axes fixed in `writeup/novelty/leg_209.md` §5 *before* any
measurement was taken. The module is **NOT patched** by this leg, under either branch.

| axis | question | answer |
|---|---|---|
| **(a)** | does the module silently return a wrong value on adversarial input? | **YES**, 4 mechanisms |
| **(b)** | is any *banked* number reachable from the shipped path? | **NO** — 0 contaminated, **LATENT** |
| **(c)** | does any mechanism touch Theorem NGX's *analytic argument*? | **NO** |

**46 cases: 24 `silent_wrong`, 16 `sound`, 6 `boundary_accepted`.**
Permanent battery `test_spectral_certificate_adversarial.py`: **24/24 pass**
(15 characterization pins, 9 soundness gates).

## The headline, with magnitudes

**M1 — one NaN in 262 144 entries inverts the no-go's conclusion, with no defect signal
surviving.** `l1_bounded_below_constant` ends

```
nrm = float(colsums[j])
return (1.0 / nrm if nrm > 0 else float("inf")), j, Li[:, j]
```

The `nrm > 0` guard was written for `nrm == 0`. Under IEEE 754 a comparison with a NaN
operand is **unordered** — the fourth relation, `? U` — so `nan > 0` is `False` and the
function takes the branch returning the **largest possible `sigma_min`**. On leg 127's own
shipped corner `(K, M_extra, class) = (8, 512, algebraic s=0.3)`:

| quantity | clean | one NaN anywhere (4/4 positions tried) |
|---|---|---|
| `sigma_min` | `0.034914733291684645` | `+inf` |
| `counterexample_norm_floor(Z1=0.5)` | `14.3206020170024` | **`0.0`** |
| `general_class_tradeoff(...)` | `holds=True`, `rhs=-2.4915` | `holds=True`, `rhs=-inf` |

One poisoned entry is `3.815e-06` of the matrix. Two calls downstream the Inf is fully
laundered into a **finite, plausible `0.0`** — which states that a counterexample to
Theorem NGX reaching `Z_1 = 0.5` requires `‖A‖_w ≥ 0`, i.e. that **any** bounded `A` will
do. That is the theorem's general-class conclusion exactly inverted.

**And the NaN is manufactured by the module's own documented API, not only injected**:
`_scaled_tail` returns `4096/4096` NaN for a `geometric` `param ≤ 0`, which
`weight_vector`/`log_weight_vector` accept with no check despite a docstring that says
`nu > 1`. Same for `algebraic` with `param = nan` or `inf`. 5/5 such calls end at
`floor = 0.0`.

**M2 — a `rigorous=True` bound that is 20.35× *below* what it bounds.** `weight_vector`
accepts a negative geometric `nu` and returns sign-alternating "weights"
(`[-1.1, 1.21, -1.331, 1.4641]`). `weighted_l1_upper` then sums them **with their signs**:

- `weighted_l1_opnorm` on the module's own `bordered_linearization(4)`:
  **`1.652892561983471`** returned against the true **`5.301550440543678`** for the same
  magnitudes — understated **3.2074×**, and positive and plausible.
- `rigorous_finite_block(8,"geometric",-1.1)` returns
  **`A_norm = 0.8347107438016543`** with **`rigorous: True`**, against
  `16.98613838786245` at `nu=+1.1` — understated **20.349730×**, and *below 1* — while
  `finite_section_inverse_norm` on **identical arguments** returns `NaN`. The module
  carries two representations of the same weights (`weight_vector` vs
  `log_weight_vector`) and they disagree outside the documented domain.
- **Control comes out both ways**: 200 random **positive**-weight draws are
  `0/200` non-containing (tightest `ub/exact = 1.0000000000000009`); the *same* draws with
  **exactly one sign flip** are `200/200` non-containing, worst `ub/exact = -5.82e-04` —
  the "rigorous upper bound" comes back **negative**.
- `algebra_constant` returns **bit-identically** `0.9132231404958678` for `nu = +1.1` and
  `nu = -1.1` (lesson 90's tell), reporting "Banach algebra holds" for a weight class that
  is not a norm.

This is an **independent, unrepaired instance of leg 198's `bordered_hl.py` negative-border-weight
mechanism** in a second module, and of leg 201's non-containing-enclosure-flagged-`rigorous=True`
shape. Two prior legs found the same class; nobody had looked here.

**M3 — `kernel_membership_ladder` misclassifies convergent cases as not-in-space.**
`in_l1_w` is hypothesis **(H2)** of leg 58's proposition. The verdict is read off a
hard-coded `r < 0.95` increment-ratio threshold, so the whole band of convergent exponents
with `r ∈ [0.95, 1)` is reported divergent. Bisected: the band is
**`s ∈ [0.9638520205415261, 1)`**, width **`0.0361`** in the weight exponent — every `s`
in it *is* in `ℓ¹_w` (`Σ m^(s−2)` converges for `s<1`) and is reported as not. At `s=0.99`:
`verdict='log_divergent'`, `r = 0.9850625857063293`. Separately, **all four** geometric
cases return `indeterminate` with `r = NaN`, because increments underflow to exactly `0.0`
(`nu<1`) or overflow so `inf−inf = NaN` (`nu>1`) and `incr[i] if incr[i] else nan`
collapses both — and the geometric class is the one this module's own docstring calls
*"the literature's default"*.

**Direction stated honestly:** M3 errs **conservatively** for the no-go — it refuses to
apply (H2) rather than wrongly applying it. It is counted because it is a wrong
classification of a documented hypothesis returned as a clean boolean, not because it
weakens the theorem.

**M4 — the same unordered-comparison mechanism, second site.**
`weight_window(nan, 0.3)` returns `empty = False` — the *favourable* answer ("the window
is not empty, a certificate can still close") — because `bool(nan >= nan)` is `False`.
`gap` is a visible NaN, but `empty` is the boolean a caller branches on. Control: `empty`
comes out both ways on clean input (`False` at `s_operator=0.3`, `True` at `1.0`).

Plus **M5 (low magnitude, pinned for completeness)**: `bordered_linearization(4.9)`
silently becomes `K=4` — leg 198's "pin of arity 5 truncated to 3" shape.

## (b) Blast radius: LATENT, 0 banked numbers contaminated

Measured, not asserted. Census over every parameter appearing in
`test_spectral_certificate.py`, `p2_route_ngx_v1_general.py`, `p2_route_l1_v2_spectral.py`,
`p2_route_t_v1_border.py`, `p2_route_ng_v1_nogo.py`:

- **0** shipped `(class, param)` pairs produce a NaN or Inf in `_scaled_tail`
  (`flat 0.0`, `algebraic 0.0/0.3/0.7/1.0/1.5`, `geometric 1.05/1.1/1.2` — all clean).
- **0** shipped parameters produce a negative weight. Every shipped `mu` is `≥ 0`.
- Nearest shipped `s` to M3's band is **0.7** (`r = 0.6590`) against a band starting at
  **0.963852** — margin **0.263852** in `s`. `S6` gates this executably.
- On clean input `float64` agrees with **exact rational Gauss-Jordan** arithmetic to
  **`7.24e-16`** worst over `K = 8, 16, 32, 64` (banked lesson 86). This is what bounds
  the radius: the module is *sound where it is used*.

So all four mechanisms require an input the shipped path never produces. **No banked
number moves. Leg 127's `sigma_min` ladder, its fitted `M^-(1-s)` exponent (0.6985 vs a
predicted 0.7000), leg 58's proposition and leg 54's battery are all untouched.**

## (c) Theorem NGX's proof is **not** at risk — stated precisely, because the difference is the whole point

Theorem NGX's proof has two steps and **neither is a float computation**:

1. `Z₁ ≥ 1 − ‖A‖_w · σ_min(L)` — an exact three-line folklore inequality which the
   module's own NGX header explicitly disclaims as *not this repository's*. No code.
2. `σ_min(L) → 0` like `M^-(1-s)` — established by the **explicit sequence**
   `v_M = (z_M; h^(M))` whose entire residual is the single truncation-edge row of size
   `|1 − M/2|·|h_M|·w_M ~ M^(s−1)`, against `‖v_M‖_w` bounded uniformly because
   `Σ m^(s−2)` converges for `s < 1`. An **analytic** estimate on the *infinite* tail.

Leg 58's companion result on `A21 = 0` is likewise a three-line argument off the block
structure of `(I − AL)x` at `x = (0; h)` with `T h = 0`.

All four mechanisms require an input outside the documented domain (`nu ≤ 0`, an injected
NaN, a negative weight, or `s ≥ 0.963852`) which **no step of either proof uses** and which
the shipped path never produces. **A numerical module having an adversarial-input bug does
not make an analytically-proved theorem wrong. This leg found the former and explicitly
did NOT find the latter**, and the escalation is on the former's grounds only.

What *is* at risk is the module's ability to report a correct `σ_min`/`‖A‖_w if a future
leg ever drives it outside its documented domain — e.g. by sweeping the geometric class
through `nu ≤ 1`, which `weight_vector` accepts silently. That is a code defect of the
leg-201/204 class.

## Negative results, recorded at equal weight

Six families came out **clean** and are gated so they stay that way:

- **Inf** input to `l1_bounded_below_constant`, an exactly singular column, and an
  all-zero matrix all **raise `LinAlgError`** — the finding is about NaN specifically,
  not non-finite input in general.
- `weighted_l1_upper` **contains** on positive weights, 200/200.
- Degenerate index domains reject visibly **6/6** (`M == K`, `M < K`, one-row tail,
  `tail_left_null` at `n=1`, `bordered_tail_inverse_norm` at `n=1`, degenerate polyfit
  abscissae).
- A NaN in the profile **propagates** through `clm_residual`, 0 absorbed.
- `sigma_min` is **exactly right** (`2.0`) on `diag(2,4)`, where the answer is known
  independently of the code.
- `kernel_membership_ladder` is **correct on every shipped exponent**.

### Three cases filed as `boundary_accepted` rather than counted — deliberately not inflating the headline

- `geometric nu = 0.5 / 1.0` and `algebraic s = -2.0` are accepted outside the documented
  domain, but the returned number is the **correct** norm for the weight actually built.
- `K = 0` likewise.
- **`mu < 0` and the positive control (lesson 90 applied to the control itself).**
  `dissipative_control`'s stated contract is *"`mu > 0` must saturate in `K`, in every
  class"*. At `mu = -0.1` and `mu = -1.0` — **anti**-dissipation, physically inadmissible —
  it saturates just as cleanly (`ratio_last = 1.0000`, against `1.1045` at `mu = 0`).
  Each returned norm is the correct norm of the matrix actually built, so this is **not**
  a silent-wrong. What it means is that the control establishes *"any **diagonal**
  restores boundedness"*, which is **weaker** than *"dissipation restores boundedness"* —
  the honest reading of legs 51–58's positive control. Recorded as a **characterization**,
  not a defect.

## Disposition

**ESCALATED, not merged to `main`; branch `leg/209-sca2-v1` pushed alone.** The module is
byte-identical and **not patched** — the dispatch forbids it under the YES branch.
`capabilities.py` is **untouched**: appending a passing-battery entry is the **NO**
branch's instruction and this gate answered YES (leg 198's precedent). No figure — 0 of 61
registered figures come from an audit leg. No ban engaged, no GA compute, no mathematical
claim, and **no link of the `L1→L4` chain moved**.

**For a future repair leg**, the guards are: (i) reject a non-positive/non-finite `param`
in `weight_vector`/`log_weight_vector` at the documented domain; (ii) replace
`nrm > 0` with an explicit `np.isfinite(nrm) and nrm > 0`, returning a defect signal
rather than `+inf`, at both `l1_bounded_below_constant` and `weight_window`; (iii) reject
non-positive weights in `weighted_l1_upper`/`weighted_l1_opnorm` — leg 152 already wrote
the analogous guard for `hl_rescaled.py`, and leg 198 named it for `bordered_hl.py`;
(iv) make `kernel_membership_ladder` decide on the *fitted decay exponent* rather than a
hard-coded increment-ratio threshold, and distinguish an underflowed increment from an
absent one. The 15 characterization pins in
`test_spectral_certificate_adversarial.py` **must be inverted in the same commit** as any
such repair.
