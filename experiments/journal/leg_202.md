## The three mechanisms

### M1 — off-branch roots are returned as converged, with a machine-zero residual

`R2` has spurious **grid-scale** roots that satisfy **both gauges to `0.0e+00` exactly** and
every residual row to machine precision. Neither `solve` nor `continuation` computes any
decay-class or smoothness diagnostic, so these are indistinguishable from the physical branch
in *every field the module returns*.

The module's own docstring fixes the referent: `continuation` exists because *"the a != 0
profile (if it exists) is a deformation of the exact a = 0 anchor, so the honest test is to
FOLLOW it"*. That anchor decays — on the default sinh grid its far-field supremum over the
outer half is `6.48e-06` against an origin amplitude pinned by the gauge at exactly 1.

| | a | n | `converged` | `relres` | far-field sup | inflation | gauges |
|---|---|---|---|---|---|---|---|
| first departure | 0.45 | 101 | **True** | 1.77e-15 | 1.35e-02 | **2079×** | 0.0e+00 |
| worst | 1.05 | 101 | **True** | 4.17e-16 | **9.02** | **1.39e+06** | 0.0e+00 |

At `a = 1.05` the returned profile's supremum is **attained in the far field** — it is 9× larger
at the domain edge than at the origin — with node-to-node oscillation **0.80** against the
anchor's 0.09. It is a lattice artifact, not a traveling wave, and the module reports it with
a *better* residual than the physical branch has.

**The first departure is the dangerous one**: `a = 0.45`, reached on a **warm start with no
retry involved**, `relres = 1.77e-15`. Nothing anywhere in the returned dict is anomalous.

**Consequence for the banked quantity.** `c(a = 1.50)` is returned as **0.20427 / 0.23717 /
0.97282** at `n = 101 / 201 / 301` — all three with `converged=True` and `relres` at machine
zero (6.0e-16 / 5.8e-16 / 4.1e-15). **79% relative spread; 376% between the extremes.** Grid
refinement does not converge these; they are different branches.

**The delivery vehicle is `continuation`'s own rescue clause** (lines 182–189). When the warm
start stalls it retries from the cold anchor, accepts the result because
`alt["relres"] < r["relres"]` — which the spurious root satisfies *better than the physical
branch does* — and then re-seeds the entire remainder of the ladder from it via
`if r["relres"] < 1e-10: om, c = r["Omega"], r["c"]`. A rescue written to make the sweep more
robust is what walks it off the branch and keeps it off.

### M2 — the scaling family is escaped at DEFAULT parameters, and the gauges pay for it

`R2` has an exact scaling degeneracy (`Ω → λΩ` with `c → λc`). The two gauge rows are the only
thing pinning which member is returned — and they are **2 rows against `n`** in an
*overdetermined least-squares* solve, so they are tradeable. From `om0 = 1e-8 × anchor` at
`n = 201`, **nothing else touched**:

| eps | `converged` | `Ω(0)` | gauge residual | `c` | rel. error vs 0.49797 |
|---|---|---|---|---|---|
| 1e-8 | **True** | −0.750000 | **0.25** | −6127.94 | 1.23e+04 |
| 1e-9 | **True** | −0.750000 | 0.25 | −30641.68 | 6.15e+04 |
| 1e-10 | **True** | −0.750000 | 0.25 | −306421.26 | **6.15e+05** |

`c ~ 1/eps` exactly, which identifies the scaling family as the mechanism rather than
roundoff. The returned wave speed is wrong by up to **six orders of magnitude and a sign**,
the returned profile does not satisfy the gauges the module solved for, and `converged` is
`True`.

Neither returned field can detect this: **`converged` never consults the gauge rows**
(it is computed from the residual history `hist` alone), and **`relres` is exactly
scale-invariant** — measured spread `1.6e-11` across `λ = 1, 2, 10` while `c` runs 0.5, 1.0,
5.0. This is the gate's "poor initial guess" clause, answered in the affirmative.

*Correction recorded against this leg's own scouting notes.* An intermediate reading held that
gauge blindness was structural but **unreachable** at the default budget, because λ-scaled
starts return `gauge residual = 0.0e+00` at `max_iter = 40`. That was wrong, and the runner's
G2 `reading` field says so in the artifact rather than quietly dropping it: the λ route alone
would have been a negative, and the small-amplitude route reaches it with no parameter touched.

### M3 — `c0` is never range-checked

`solve(om0=anchor, c0=1e9)` returns `converged=True` with `c = 1.000000e+09` handed straight
back — the caller's own garbage returned as a converged wave speed, 9 orders from the true
0.498. Also fires at `c0 = 1e6` and `1e12`.

## What came back CLEAN, reported at equal weight

Frozen in advance, so these are results, not omissions.

* **leg 114's M2 vector is killed, exactly as leg 114 predicted.** `writeup/novelty/leg_114.md`
  §M2 states *"one gauge kills the scaling symmetry; it does not kill the constant. Two gauges
  do."* `profile_newton` is the two-gauge design, and `om0 = −ones` and `om0 = zeros` both
  return `converged=False` at `relres = 2.79e-03`. **The prediction holds — and M1 shows it is
  not sufficient**: a *different* spurious root survives both gauges.
* **No NaN/Inf input is absorbed.** All five poisoned cases reach `np.linalg.lstsq`, which
  raises `LinAlgError`, which the module catches and turns into an explicit `converged=False`
  with `reason='singular Jacobian'`. (LAPACK prints `DLASCL parameter number 4` to stderr on
  this path; that is noise from the caught exception, not a second failure.)
* **G5 degenerate parameters**: tiny grids (`n = 11/21/51`), both `rho_max` extremes
  (0.5/2/16), `damping=False`, and both `tol` extremes are all handled without a false
  convergence claim. The `max_iter = 0` hole is real but only reachable when the caller's own
  input already has a small residual, and **no caller in the repository passes `max_iter`**, so
  it carries no banked claim.
* **Controls C1/C2/C3 all hold**: the perturbed anchor still converges on-branch
  (relres 4.8e-15, inflation 0.99), `a = 0.30` still reaches the floor (8.4e-15), and the
  analytic Jacobian still matches finite differences to 9.5e-11 (leg 71 measured 6.7e-11 on a
  different host). Had C3 moved, every other verdict would have been about the derivative.

**One contract gap, loud not silent** (G6). The `LinAlgError` branch returns a dict *without*
`residual_rms` and `relres`, which every other return path carries, and `continuation` reads
`r["relres"]` unconditionally at line 182 — so a poisoned profile anywhere in a sweep raises
`KeyError` rather than being handled. Because it is loud it cannot answer the gate YES; it is
banked as a robustness note, exactly as the novelty pass pre-committed.

## Recommendation to the DM (not acted on here)

The module is **not** patched by this leg. The cheapest honest repair is not a better tolerance:
it is to make `solve` return the decay-class diagnostic it already has the data for
(far-field supremum relative to the anchor's, plus the two gauge residuals it already computes
in `F`), and to make `converged` consult the gauge rows it currently ignores. That would close
M2 outright and make M1 *visible* without the module having to decide which branch is physical.
`continuation`'s retry clause additionally needs a branch-continuity check — accepting a
strictly better `relres` is what walks the sweep off the branch.
