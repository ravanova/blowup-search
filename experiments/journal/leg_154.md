## The defect, restated in one paragraph

`self.p = int(p)` and `K, p = int(K), int(p)`. The module's docstring says "2s = p, a positive
integer" as though it were guaranteed; it was never checked. Leg 121 measured what that cost:
`CriticalDissipativeFlow(0.0, mu=0.1, p=1.9, K=64)` — a request for `s = 0.95` — silently
built `p = 1` (`s = 0.5`), converged to residual `9.71e-16`, and returned `alpha`, the
residual and `alpha_1` **bit-identical** to an honest `p = 1` run. Not a plausible-looking
wrong answer. An **indistinguishable** one, for a **different input**, at machine precision.
CWE-197. Leg 121's gate said escalate, not patch; this leg is the patch.

## What the novelty pass changed about the leg

**It rejected leg 121's own prescribed predicate, before the patch was written.** Leg 121's
journal prescribes:

> `if float(p) != round(float(p)): raise ValueError`, before the existing `p = int(p)`

Run over 19 inputs (executable as runner section `N1`, not recalled), that predicate has two
failures:

* **`±inf` raises `OverflowError`, not `ValueError`** — from `round()`'s internals, not from
  the guard. It escapes leg 121's own CONTROL's `except ValueError` and any caller written
  against the module's documented failure mode.
* And the obvious tightening, `p == floor(p)`, is **not merely imprecise on infinity — it is
  blind to it**, because `np.floor(inf) == inf` is `True`. An integrality-only guard would
  **admit** `inf` outright.

So the landed predicate is **two clauses, each measured necessary**:

```python
if not np.isfinite(pf):   # NECESSARY: floor(inf) == inf, integrality alone ADMITS inf
    raise CriticalDissipationDomainError(...)
if pf != np.floor(pf):    # NECESSARY: the gate's subject, p = 1.9
    raise CriticalDissipationDomainError(...)
```

[SEI CERT FLP04-C](https://cmu-sei.github.io/secure-coding-standards/sei-cert-c-coding-standard/recommendations/floating-point-flp/flp04-c/).
`check_non_finite_p_refused_as_a_domain_error` pins that ordering so nobody simplifies it
back. **This is the fourth consecutive repair leg whose finding leg's prescribed predicate did
not survive measurement** — legs 150, 151, 152, and now 154. That is no longer a coincidence
and belongs in the standing discipline: *a finding leg's prescribed repair is a hypothesis,
not a specification.*

**It settled a design question against the better library practice, on the gate's own
arithmetic.** [PEP 357](https://peps.python.org/pep-0357/) / `operator.index` — what NumPy
uses for [`np.linspace`'s `num`](https://github.com/numpy/numpy/issues/15345) — is the
stricter and frankly better design, and it **rejects even exactly-integral floats**. It would
satisfy clause (a) and **fail clause (b)**, because leg 121's C4 battery pins `p = 3.0` and
`np.float64(3.0)` as *correctly accepted*. Not adopted, and the reason is recorded in the
module so it is not silently rediscovered as an improvement (leg 129's discipline when it
refused a 6%-faster `velocity_hat`).

**For the same reason the guard reaches only `float`/`np.floating`.** Every other type stays
on the original `int(p)` path. `'3'` is still accepted; `'3.0'` is still refused **by `int()`
itself**. Widening the guard to strings would **newly ACCEPT `'3.0'`** — a behaviour change on
an input that was previously refused, which the no-op licence forbids. The adversarial test
asserts that `'3.0'` is refused by `int()` and **not** by the new guard.

## Clause (a) — and the pins, inverted in the repair's own commit

`15/15` refused, was `0/15`: C1's five `lambda_power` inputs, C2's nine full-pipeline requests
across all three integer bands, C3's realistic near-miss `2.0*(2.5 - 1e-12) = 4.999999999998`
which silently built `p = 4`, a full unit below the intended `5`. The refusal message **names
both** the requested `p` and the integer that would have been substituted — the substitution
is the finding, so the repair says it out loud rather than only refusing. C4's type-coercion
row is `7/8` unchanged; the one that moves is `p = 3.5` (float), by design.

**PINs E1a, E1b, E2, E3 inverted in commit `3851dbc`, at leg 121's own thresholds, never
weakened.** Every magnitude leg 121 measured is still asserted — only the default verdict
flipped. That is possible because of the escape hatch:

**`on_noninteger="truncate"` reproduces the pre-repair result bit-identically behind exactly
one `RuntimeWarning`** (`Lp`, `Lam`, `residual`, `jacobian`, `alpha`, `c_omega`, `s`; `3/3`
bands). Leg 135's rule: *a repair that makes the escalating leg's battery unrunnable destroys
the record that authorised it.* The bit-identity between a corrupted run and an honest one
**is** leg 121's finding, and it survives its own repair.

**E4, E5, E6 are NOT inverted and NOT repaired,** and their pins stay live and passing. The
gate licensed the exponent-truncation repair and nothing else. Negative `mu`,

classification of a `NaN` `alpha_1` are unchanged and still escalated — now recorded in the

## Two residues, declared before construction, not patched

**(1) `solver/marginal_flow.py` carries the identical `int(p)` one level up — and it is
MEASURED, not assumed.** Five sites, including `AugmentedFlow.__init__:139`
(`self.a, self.p, self.K = float(a), int(p), int(K)`). The runner constructs
`AugmentedFlow(0.0, p=1.9, K=16)` and it **still builds `p = 1`**: the truncation happens
there, *before* the value ever reaches this repair's guard. `marginal_flow.py` is outside this
leg's declared territory and editing it would fail the merge gate's territory check. Named in
the novelty pass **before** the patch so it could not surface later as a discovery. This is
the incomplete-fix shape leg 147 caught, declared rather than hidden.

**(2) `p = 1e300` is accepted.** Finite and integral, so the guard admits it, and
`lambda_power`'s loop becomes a resource exhaustion (unbounded matmul chain, growing `n`,
eventual `MemoryError`). Deliberately not patched: that failure is **loud**, not a silent
substitution of a different exponent, which is the only thing this repair is licensed to
close — and any cap on `p` would be an arbitrary threshold with no measurement behind it (leg
130's threshold-free-predicate discipline).
