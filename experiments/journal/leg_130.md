## 1. What was wrong, in one sentence

The sup-account integrand in `d(log s)` tends to a **nonzero constant** as the offset `s → 0`
(`|K|·s → 2` and `cS → 2cos^α(θ/2) ≠ 0`), so the sup route is logarithmically divergent at the
endpoint; the only thing that tames it is `cT ~ s^γ → 0`, which needs `γ > 0` **and** needs the
payer rule to actually select the seminorm account near `s = 0`. When it does not, the number
the module returned was finite only because the quadrature started at `s = ε·L` — the
ε-truncation of a divergent integral, presented as a bound.

That `γ > 0` is exactly the hypothesis under which the conjugate operator preserves Hölder
classes is **Plemelj–Privalov**. No novelty is claimed for the condition, only for the fact
that this module never enforced it. The novelty log (`writeup/novelty/leg_130.md`) carries the
citations.

## 4. The two predicates that died before reaching the module

This is the part of the leg worth carrying forward, and both deaths happened in the novelty
pass, before any code was written.

**(i) Leg 106's own prescription is insufficient for leg 106's own gate.** Its escalation note
says the repair is *"reject non-finite `rho` and `gamma <= 0`"*. But its V1 explicitly includes
`ρ = 1e300`, which is **finite**. A guard written to that prescription would have left one of
the two banked failing configurations still failing — and would have reported success.

**(ii) The obvious mechanism predicate is wrong in both directions.** "Does the payer rule
select the seminorm account at the innermost quadrature node?" was measured over **87,552**
shipped-family configurations before adoption: it produces **2,418 false positives** in the far
field, where the sup account is legitimately selected in the intermediate regime `c ≪ s ≪ 1`
and the integrand still decays — and it **misses `γ = 0` entirely**, because there
`ρ·cT/cS → 0.5 ≤ 1`, so the *seminorm* account is selected and it is the seminorm integrand
that fails to vanish. Adopting it would have failed clause (b) on 2,418 cases while leaving V2
open.

**(iii) And the first replacement was wrong too, which is recorded rather than quietly fixed.**
The novelty log's first draft claimed the closed-form discarded head is *"exactly 0.0 on every
one"* of the 4,188 shipped configurations. That was read off the five worst rows of the
scouting table, not the table; **44 of 4,188** have a positive head (all at `ρ = 25`,
`ε = 1e-10`, `π − θ ∈ [1.00e-08, 9.97e-08]`, worst `6.895e-05` of the returned pair against
gate 5's measured `≈2e-04` margin — thin, but not violated). The correction is committed as its
own commit (`e95d0d2`) *before* the construction commit, so the record shows the pass catching
its own error rather than the error never having existed.

**What landed instead.** Reject iff the discarded head **fails to vanish as `ε → 0`** — i.e.
the asymptotic payer crossover `s* = (2cos^γ(θ/2)/ρ)^{1/γ}` is not a representable positive
float, or `γ ≤ 0` (no crossover exists at any ε), or an argument is non-finite or outside
`θ ∈ (0, π)`. Threshold-free, and it fires on 0 of 4,188 shipped configurations.

## 5. What this leg did NOT close, named with magnitudes

**The `ρ ≳ 1e6` band.** Leg 106 never tested it. Its head is a large share of the returned pair
at the default ε — `0.162` at `ρ=1e6`, `0.762` at `1e9`, `1.363` at `1e12`, `18.97` at `1e100` —
so the number returned there is materially understated. It is **not rejected**, deliberately:
its exact majorant is *finite*, so the defect is under-refinement, and rejecting a
configuration whose bound merely needs a smaller ε would be a claim about a sound object.
It is closed instead by a `HilbertPointwiseTruncationWarning` that **changes no returned
value** — which is what keeps clause (b) true — at a relative tolerance of `1e-3`, sitting
`14.5×` above the worst accepted configuration (`6.90e-05`) and `164×` below the worst violator
(`0.162`). That tolerance is this leg's one free constant; it governs a warning only, never a
rejection and never a number, and both sides of its margin are in the JSON.

**`measured_pointwise`'s silence.** Leg 106's gate 9 pins `worst_ratio = 0.0` with an empty
profile name on 3/3 NaN-poisoned families *and* on an empty family — `0.0` reads as "no
violation anywhere", the most favourable possible answer. That is a **reporting** defect, not a
bound-direction one, and it is not among the two configurations this leg's gate names. **The
pin is NOT inverted** and the defect is still open.

**`n_quad ≤ 1` returns `(0, 0)` with no complaint**, and the default `n_quad = 400` understates
its own majorant by `2.68%`. Both are gate 6's, both pre-existing, both untouched: inflating
the bound to cover them would move every previously-passing number and fail clause (b).

**The `+∞` from `inflate` on `ρ = 1e300` is cruder than it needs to be.** The head is `+∞`
there only because `s*` underflows in *linear* space; computed in log space the head would be
finite. Not done, because the guard's predicate is stated in linear space and changing it to
log space would accept `ρ = 1e300` — one of the two configurations the gate requires be
rejected. Named here so the next leg on this module does not mistake it for an oversight.
