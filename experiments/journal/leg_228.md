## 0. Why this leg exists, and what would have made it worthless

Leg 198 (Route-BHA) measured that `solver/bordered_hl.py` silently accepted an
inadmissible border weight, corrupting the certificate constants in the
**certificate-fabricating** direction. Leg 218 (Route-BHR) shipped the guard and
self-reported GATE YES on both clauses. Nobody had checked it: leg 223 (PUB3) is
explicit that it is *not* a verification, and it banks legs 198's and 218's disagreeing
`Z_1` ratios side by side as an unresolved disagreement, "neither adopted".

Lesson 90 is the whole design constraint here. Re-running
`experiments/p2_route_bhr_v1_repair.py` and reporting that it still passes would be a
control that cannot come out differently — the same code deciding twice. So this leg
never imports or executes leg 218's runner. Four things are re-derived instead:

1. **The pre-repair module** is loaded by a *different loader path* — the blob is
   materialised to a temp file and imported with `spec_from_file_location`, where leg
   218 used `spec_from_loader` on a string plus `exec` into a bare module dict. Both
   blob hashes are asserted at startup (`0c075b8`/`a6ab17df…` pre,
   `d9a20fb`/`92e1c670…` post, the module's only two states in repository history), and
   the loaded "pre" module is checked to **not** carry `_check_weights` — so "pre-repair"
   cannot silently degrade into "the same file twice".
2. **The adversarial cases** are generated from the norm's *definition* and the weight
   *formula* — the cross product of (entry point) × (inadmissibility class) — not copied
   from either leg's case list. This is what turned up the cases neither leg had.
3. **The caller set** is re-enumerated from the callers themselves.
4. **The `Z_1` disagreement** is not re-litigated by a third run of the same arithmetic.
   Leg 218's explanation is treated as the falsifiable variance claim it is, with the
   falsification condition fixed in advance (§4).

## 1. Clause A — the rejection battery. **PASS.**

The weight surface has six reachable entry points: `induced_sup_norm`'s `w_row` and
`w_col`, `weights`'s three named scalars `w_l`/`w_om`/`w_r`, and the decay weight `nu`,
which no caller passes directly but which `p` controls. Crossed with the
inadmissibility classes that follow from the definition of `||z||_w = max_i w_i |z_i|`
(negative at several magnitudes, zero, negative zero, both infinities, NaN), and with
both placements (whole vector vs a single bad entry among many):

| | |
|---|---|
| cases generated | **67** |
| silently accepted by the pre-repair module | **67** |
| **leaked by the post-repair module** | **0** |
| post-repair rejections that are the guard's own `BorderedHLDomainError` | **all 67** |

**`nu` via `p` is an entry point neither leg listed.** `(1 + X^2)^(p/2)` is positive for
every finite `p`, but on this object `|X|` reaches ~745, so a large `p` **overflows the
weight vector to `+inf`**, which deletes those components from the induced norm's column
sum. It is reachable through a plain numeric argument. Derived here from the weight
formula rather than from any caller, and the guard catches it.

**The fabrication measure.** At the honest weights (`Y_0 = 1.1942e−10`,
`Z_1 = 5.3458e−09`, `Z_2 = 3.0862e10`) the radii polynomial's discriminant is
**−6.3713** — **no real root**, the certificate does not close, which is this object's
documented ceiling (legs 46/47). Pre-repair, **9** of the probed inadmissible
configurations produce a certificate that **does** close, and `Z_2` **changes sign** in
**7** of them. That is the blast radius restated independently, and it is the direction
that matters: an understated `Z_1`/`Z_2` manufactures a real root the problem does not
have.

Magnitudes are reported against **two different baselines**, and the journal says so
because they are otherwise easy to misread as contradicting each other:

* against the **default-weight** honest constants: `Z_1` understated up to
  **8.1356e6×**, `Z_2` up to **1.5694e4×**.
* against **leg 198's own same-magnitude sign flip** (`+w` vs `−w`, the ratio legs 198
  and 218 actually report): `Z_1` understated up to **1.8015e9×**, `‖A‖` up to
  **6.6712e9×** — the latter reproducing legs 198 and 218's agreed `‖A‖` column
  (6.6712e9×) to **5 significant figures**, which is the strongest available evidence
  that this leg is measuring the same object they were.

Every negative half of every sign-flip pair is refused post-repair; every positive half
is accepted.

## 4. THE `Z_1` DISAGREEMENT IS RESOLVED — leg 218's explanation **stands**, now measured

The banked disagreement (`experiments/journal/leg_218.md:182`, `leg_223.md:69`): on leg
198's `w_r = ±1e-6` configuration, leg 198 reports the `Z_1` understatement as
**1.198e9×**, leg 218 re-measures **2.2867e8×** — **5.24× apart** — while their `‖A‖`
(6.6712e9×) and `Z_2` (+1.188608e17) columns agree to 4–6 significant figures. Leg 223
banks both and adopts neither.

Leg 218's explanation is lesson 86: `Z_1 = ‖I − A·DF‖` with `A = inv(DF)` is a near-total
cancellation, so the **flipped** `Z_1` sits at the round-off floor and the **ratio** is
environment-dependent while the **verdict** is not. A third run of the same arithmetic
answers nothing, so this was tested as a variance claim with the condition fixed before
the numbers were looked at:

> perturb only in ways that provably cannot change the mathematics — algebraically
> identical re-associations of the same matrix products, and BLAS thread counts — and
> measure the spread **of the disputed quantity itself**. If it brackets 5.24×, leg
> 218's explanation stands. If it is stable to within a few percent, the explanation is
> wrong and one of the two banked numbers is a real defect to escalate.

Aiming this at the *disputed* quantity rather than at `Z_1` on an admissible weight is
the point. `Z_1` at an admissible weight is not a cancellation and barely moves — that
would have been a lesson-90 control that could not come out differently.

**Result: the spread BRACKETS the disagreement, by more than 2×.** Across seven
algebraically identical forms of the same residual matrix and four BLAS thread counts,
the understatement ratio spans **11.77×** — from **2.6422e8** to **3.1108e9** — against a
disagreement of only **5.239×**. Two illustrations of how little it takes:

* the `einsum` form alone moves the ratio from **1.8015e9** to **3.2766e8**, having
  changed nothing but the reduction order;
* **thread count alone** spans the entire disagreement and then some — 1 thread gives
  **2.6422e8**, 4 threads **3.1108e9**. Same code, same machine, same inputs.

Leg 198's banked **1.198e9×** falls **inside** the observed band. Leg 218's **2.2867e8×**
falls just **outside** it, 1.16× below the observed minimum — reported precisely rather
than rounded into agreement, since the perturbation set here is finite and obviously not
exhaustive of the environments the two legs ran in. The claim under test is that the
quantity is round-off-floor noise, and an 11.77× band from reduction order alone
establishes that whether or not both points land inside this particular sample.

The mechanism is measured, not argued, and the asymmetry is the evidence:

| quantity | spread under the same math-neutral perturbations |
|---|---|
| the ratio's **denominator** (flipped `Z_1`, ~1e-15…1e-16, a cancellation) | **6.407×** |
| the ratio's **numerator** (honest `Z_1`) | **1.165×** |
| `Z_1` at an admissible weight | **1.022×** |
| **control:** the `‖A‖` ratio, the column both legs *agree* on | **1.0000000000072×** |

The control is what rules out the alternative reading, and it is the sharpest number in
this leg: the `‖A‖` ratio — the column legs 198 and 218 reproduce to 4–6 significant
figures — moves by **7.2e-12 relative** under the very perturbations that swing `Z_1`'s
ratio by 11.77×. If these perturbations were simply breaking the computation rather than
exposing a cancellation, that control would have moved too. It did not.

**Recommendation to integration: the leg-198/leg-218 `Z_1` disagreement can be closed as
explained.** Neither number should be adopted as *the* ratio, because there is no such
number to adopt — the quantity is round-off-floor noise in its denominator, and this
leg's own third measurement (1.801e9×, again on the same configuration) is a third point
in the same band, not a tie-breaker. The `‖A‖` and `Z_2` columns are the reproducible
ones and are the ones any prose should quote. **Both legs' verdicts are unaffected.**

## 5. `test_bordered_hl_postrepair.py` — leg 198's gates, inverted, never weakened

Leg 198's two weight-surface characterization gates were written to **fail** once a guard
landed ("WILL FAIL when a positivity guard lands on the weights"). They live only on the
unmerged `leg/198-bha-v1`; `main`'s `test_bordered_hl_adversarial.py` is leg 80's 370
lines and carries none of them, so there was **nothing on `main` to invert** and that
file is outside this leg's territory in any case. They are re-stated here, inverted, at
leg 198's own numbers:

* the hand-computable control `M = [[1,100],[3,4]]`, `w = (1,1) → 101.0` still returns
  **exactly** 101.0;
* `w_col = (1,−1)` and `(1,−1e-9)`, which returned `−1.0` and `−3999999997.0`, both now
  **refuse**, with the error naming the vector *and* the offending entry index;
* leg 198's exact corrupted magnitudes are **re-pinned through the escape hatch**
  (`−1.0` and `−4.000000e+09`), so the repair is shown to have removed the *default path*
  to them without changing the arithmetic underneath — and the guard cannot be
  "verified" by a test that merely stopped measuring;
* leg 198's `> 1e8` understatement thresholds for `Z_1` and `‖A‖` are re-asserted, not
  weakened, against the hatch: **1.801e9×** and **6.671e9×** (the latter reproducing legs
  198 and 218 to 4 significant figures);
* `w_row` is gated too — leg 198 only ever probed the column side, and pre-repair the row
  side was correct *by luck*.

Three gates were added that leg 198 never posed:

* **every inadmissible class at every entry point, NaN included.** NaN is the case that
  makes the guard's polarity load-bearing rather than stylistic: every ordered comparison
  returns False on NaN, so a "detect the bad case" guard (`any(w <= 0)`) fails **open** on
  it, while leg 218's `all(isfinite & > 0)` fails **closed** (SEI CERT NUM07-J). This gate
  fails if anyone ever flips it back.
* **the guard's own contract**: `BorderedHLDomainError` must subclass `ValueError`, and
  `on_nonpositive` must itself reject an unrecognised spelling — an escape hatch that
  silently accepts a typo would be a second silent-corruption site inside the repair for
  the first one.
* **admissible input is bit-identical** between the guarded path and the hatch.

`5/5` gates hold.

### A measured behaviour change, recorded rather than escalated

Leg 218's docstring says the new error shares the `ValueError` base "so callers already
catching `ValueError` are unaffected". True — but the **zero-weight** path previously
raised `ZeroDivisionError` (from `certificate_constants`'s scalar `Xmax/w_l` and
`1.0/w_r`), and `ZeroDivisionError` is **not** a `ValueError`. So a caller catching
`ZeroDivisionError` *would* be affected. Measured: **no live caller of this module catches
it** — the only site that does is leg 198's own unmerged characterization gate, which was
written to fail post-repair by design. The repository also has direct precedent for
exactly this narrowing (`test_nk_bounds_adversarial.py:228`, "now a named `ValueError`,
was `ZeroDivisionError`"). Recorded as a magnitude; not a defect, not escalated.
