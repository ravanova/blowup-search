## The finding

The ledger's `EXCLUDED-BY-T1` branch (`_ledger_nrs_tsai_three_way()`, `solver/dssp_screen.py`
lines 534–539) fires whenever `l3_norm_ladder()` — which computes the **exact cube-root norm**,
i.e. `q = 3` precisely, hardcoded (`L3_cubed`, `cube ** (1.0/3.0)`, no other exponent anywhere in
the function) — converges. Its attached `deciding_clause`, quoted verbatim from the code:

> "Tsai 1998, p.30 (restating/generalising NRS 1996): \"Theorem 1. If a weak solution U of (1.3)
> belongs to L^q(R^3), for some q in (3,infinity], then it must be constant (and hence identically
> zero if q < infinity).\""

The same quote, word-for-word, appears again in the module's leg-362 header comment (lines
364–367), also captioned "(Tsai 1998, p.30, restating/generalising NRS 1996)".

**Both obtainable sources read at primary/secondary text (below) show this caption is inaccurate.**
Tsai's Theorem 1 hypothesis is `q ∈ (3,∞]` — an interval **open at 3**, i.e. it explicitly
**excludes** `q=3`. NRS 1996's own hypothesis, per Tsai's own restatement of it on the very same
page (immediately before stating Theorem 1) and per the independent Bradshaw–Tsai survey, is `U ∈
L³(R³)` — exactly `q=3`, the case Theorem 1's stated range excludes. Tsai's paper does not restate
NRS's `q=3` result as part of Theorem 1; it deliberately does NOT re-prove the already-known `q=3`
case and instead proves the new, disjoint, harder range `q>3`. So a candidate whose `L³` (`q=3`)
norm converges is excluded by **NRS 1996's own theorem**, not by "Tsai 1998 Theorem 1" — and
Theorem 1's own quoted hypothesis range, taken literally, does not cover that candidate at all.

This is a citation/attribution mismatch, not a numerical-logic bug: the code's *operational* test
(exact `L³` convergence) is the mathematically correct test for NRS 1996's actual result (both
obtainable sources agree on this), and the module's plain-English header (lines 64–68: "u in
L^3(R^3) forces u=0... Machine-read directly against THIS candidate's OWN l3_norm_ladder()
result") states this correctly, without over-claiming Tsai's Theorem 1. The mismatch is
specifically in the `deciding_clause` text leg 362 attached to the `EXCLUDED-BY-T1` verdict (and
the identical header-comment quote): it cites Tsai's Theorem 1's own words as though they were (or
straightforwardly restated) NRS's `q=3` result, when the two obtainable sources both show Theorem
1's stated range is disjoint from `q=3`.

## Verdict

**(ii) DISCREPANCY-FOUND**, with the caveat that this is a citation/attribution discrepancy rather
than a computational or logical error: the operational `L³` test and its plain-English module-level
description (lines 64–68) are correct against both obtainable sources; the `deciding_clause` text
in `_ledger_nrs_tsai_three_way()`'s `EXCLUDED-BY-T1` branch (lines 534–539) and the identical
header-comment quote (lines 364–367) mis-cite Tsai's Theorem 1 (whose own stated hypothesis range
`q ∈ (3,∞]` explicitly excludes `q=3`) as "restating/generalising NRS 1996" and as the deciding
clause for a test that actually measures `q=3` — the case Theorem 1 does NOT cover and which is
covered instead by NRS 1996's own (unobtainable, but reliably attested at two independent obtainable
sources) result. Flagged here, in this journal and the JSON, for leg 357/362's ledger ownership
(routed to the DM per this leg's territory restriction) — **not implemented as a code change**;
`solver/dssp_screen.py` is untouched by this leg.
