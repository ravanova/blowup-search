### Three previously-`OK` cases now `RAISED`, declared rather than absorbed

`RAISED` went up by 8, not 5. The other three were `OK` before, and all three are genuinely
under-determined fits whose pre-repair value was **`lstsq`'s minimum-norm solution being right
by coincidence of the basis, not by fitting**:

| case | pre-repair value | why it now raises |
| --- | --- | --- |
| 2 nodes vs 3 parameters | 1.9995773690878733 | occupancy: 2 < `min_points=3` |
| `r_win=5e-4` on the leg-73-class grid | 2.000999441518362 | **rank 2 of 3** over 32 nodes |
| `r_win=3e-4` on the leg-73-class grid | 2.0009994415183723 | **rank 2 of 3** over 21 nodes |

The last two are worth stating precisely because they look like over-rejection and are not: at

## Clause (b) — the banked record, RE-RUN. This is the gap leg 205 left open.

Leg 205's own escalation note 3 says: *"This leg did not re-run any banked result and does not
claim any banked number moves... the profiles in play there use `exp(-r²)`-class envelopes,
i.e. the safe scale, which is a reason to expect no movement but is not a measurement of it."*

**That reasoning was not just unmeasured, it was factually wrong about the fields.** Spike-1
Step C's `profile_ansatz` — the initial condition every banked relaxation in this family runs
on — uses the **rational** envelope `r/(1 + r^{1−α})`, not `exp(−r²)`. Leg 205's conclusion
survives, but for a different and stronger reason than it gave: that envelope peaks at
`r ≈ 2.22`, so the field's own radial scale is `≈ 3.1` and the 0.4 window sits at 13% of it —
even further inside the safe regime than an `exp(−r²)` field, whose scale is 1.0.

### How "bit-identical" was established — a proof over the call sequence, not a sample

For each artifact, its **own generating script** was executed end to end with
`odd_field_x_slope` replaced by a shim that calls the **pre-repair and post-repair
implementations on identical arguments**, compares them with `==` on float64 (exception-type
equality when either side raises), and **returns the pre-repair value** — so the trajectory the
run follows is exactly the banked one. If every call in the sequence agrees bitwise, the
repaired module reproduces the whole run by determinism. The regenerated artifact was then
compared leaf-by-leaf against the committed one as an independent second check; wall-clock keys
are excluded and named in the JSON, because a timing field is not a result. The committed
artifacts are restored from a backup after every run and are byte-unchanged on this branch.

## What the re-run found that the argument-from-dormancy could not have

Leg 205's expectation — no banked number moves — is **confirmed**. But the first two passes of
this clause **failed**, and both failures were in this leg's own repair, not in the banked
record. Neither was reachable by reasoning about envelope shapes; both required executing the
banked scripts. This is the concrete value of the clause the orchestrator and DM asked for.

1. **The scale estimator mis-fired on a field with no radial decay.** `argmax` returns the
   *first* maximum, so a `d1` that is exactly constant in `r` — which is what leg 81's status
   audit and `test_boussinesq_rescaled_status.py` drive `run()` with, a `np.ones((16,8))`
   marker field on a deliberately tiny grid — resolved its "peak" to the innermost live node
   and shrank the window to 0.0446, emptying it. 62 calls in
   `p2_route_brs_v1_status_audit` and 142 in `test_boussinesq_rescaled_status.py` went from a
   value to a `ValueError`. **Fix:** take the **outermost** radius attaining the maximum, so a
   tie or a flat run resolves *outward* — the direction in which the cap is non-binding and
   nothing moves. Shrinking a window on a field that has no small scale is a fabrication of the
   opposite sign to the one being repaired.
2. **The residual backstop's first threshold rejected a precondition-violating field the
   repository's own harness feeds.** At `max_rel_residual=0.1` the same constant marker field
   raised at a measured relative residual of **0.1469**. The threshold is now **0.5**, read off
   the evidence set rather than tuned: worst legitimate in-repository fit **4.4e-3** (Step-C's
   `profile_ansatz` `omega` read), worst precondition-violating harness field **0.147**, leg
   205's headline fabrication **8.6e-1**. The backstop is deliberately the looser of the two
   guards; the window cap is what closes the measured mechanism, and the residual only catches
   shapes the peak heuristic does not describe.
3. **A non-numeric contamination the differential caught anyway.** Leg 81 banked
   `test_module_exposes_exactly_one_status_predicate`, which asserts the module contains zero
   occurrences of `stable`, `plateau`, `success`, `steady_state_reached`, and exactly one each
   of `converged=res < tol` and `if res < tol:`. The first draft of the repair's **docstring**
   used the word "plateau" and flipped `A4_edge_cases[3].status_words_in_module.plateau` from
   0 to 1 in `p2_route_brs_v1_status_audit.json`. Reworded; all six invariants verified.

## The repair itself, and why it can be bit-identical at all

Both guards live inside `odd_field_x_slope` and nowhere else. `git diff origin/main...HEAD --
solver/boussinesq_rescaled.py` is two hunks, both in that function.

**Defect A** is leg 99's guard, ported with 3 as the parameter count rather than 2, exactly as
leg 205 prescribed: count the mask against `min_points`, then check the rank `lstsq` returns.
The novelty pass found leg 205's *other* suggestion — gate on the residual — cannot carry this
half at all: `numpy.linalg.lstsq` returns an **empty** `residuals` array whenever `rank < N` or
`M <= N`, which is precisely defect A's regime. The occupancy/rank guard must come first.

**Defect B** is the one leg 205 deliberately left as a module-owner decision. The adopted form
is `r_win_eff = min(r_win, ½ · r_scale)`, with `r_scale = √2 · r_peak` read off `d1` itself
(for the `d1 = a r e^{−λr²}` class the module is validated on, `r_peak = 1/√(2λ)`, so
`√2 r_peak` is the envelope scale `1/√λ`). Three properties make it compatible with a
bit-identical banked record:

- it is **one-sided** — it can only shrink the caller's window, never widen it;
- it is **non-binding at and above the validated scale** — at `λ=1` the cap is 0.5 against a
  window of 0.4, so `min` returns the caller's `r_win` *as the identical float*, the mask is
  the identical boolean array, and the `lstsq` call is bit-identical arithmetic;
- ties resolve **outward**, so a field with no small scale is never shrunk.

Movement is therefore possible only on fields concentrated *below* 0.4 — which is precisely
defect B's regime and nothing else. Leg 205's recovery control read as a rule, rather than
quoted as an observation.
