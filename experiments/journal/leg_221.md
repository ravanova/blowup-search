* **`zero_contamination` now requires `len(runs) == len(BANKED)`.** A partial sweep can no

written into the runner **before any baseline was run**: a moved leaf counts against **this
repair** only if a pre-repair-world regeneration — the repaired function never on the call path
at all — fails to reproduce the same movement.

Every one of the four artifacts reproduces its movement exactly with the repair absent: **525 /

`p2_route_brs_v1_status_audit.json` carries `"generated": "2026-08-06"`. The prior session ran

## 4. Verifying the inherited repair — and one overclaim found and corrected

The repair was re-derived against leg 205's escalation rather than accepted. Both mechanisms
are addressed, and only those; the diff touches `odd_field_x_slope` and nothing else.

An **independent probe on shapes leg 205's battery does not contain** confirmed the repair
recovers across five decades of concentration (`lam` = 4 … 1e4, all at rel. err ≈ **3.9e-4**,
inside tolerance), is amplitude- and sign-independent, handles the Step-C rational envelope
(**3.5e-4**), propagates NaN visibly, and refuses empty windows and precondition-violating
constant fields.

**But one row failed, and it is a real residual gap.** A **two-scale** field,
`r cos(b) [exp(-r²) + exp(-400 r²)]` — smooth, odd-in-x, fully in contract — is read as
**1.135121 against a truth of 2.0: 43.2% error, 86x the module's own tolerance, silently.**
Mechanism: the window cap reads the field's scale off the radius at which `d1` **peaks**, and
for a two-scale field the peak resolves to the **outer** scale (deliberately — resolving inward
would shrink the window on fields with no small scale, a fabrication of the opposite sign), so
the cap goes non-binding and the inner scale is never resolved. The residual backstop is then
the only guard left, and it does not fire.

**Where the backstop actually sits, measured through the public API** (by bisecting
`max_rel_residual` to locate the residual — no re-implementation of the fit):

| field | returned | rel. err | rel. residual |
|---|---|---|---|
| module's own validated field, `lam=1` | +2.000940 | 4.698e-4 | 1.198e-5 |
| Step-C `profile_ansatz` omega (every banked relaxation runs on this) | +0.975919 | — | **4.301e-3** |
| Step-C `profile_ansatz` eta | +1.494255 | — | 1.311e-3 |
| leg 205's headline defect-B field, `lam=400` | +2.000776 | 3.880e-4 | 4.632e-5 |
| **two-scale, `exp(-r²)+exp(-400 r²)`** | **+1.135121** | **4.324e-1** | **8.125e-2** |
| **two-scale, `exp(-r²)+exp(-1e4 r²)`** | **+1.006197** | **4.969e-1** | **1.910e-2** |

Worst legitimate residual **4.301e-3**; tightest uncaught bad case **1.910e-2**; **separation
4.44x**. The landed threshold is **0.50** — roughly 26x above the tightest bad case, so it
cannot fire on either. A threshold anywhere in `(4.3e-3, 1.9e-2)` would catch both.

**This was not tuned in.** Changing the threshold is a behaviour change this leg's gate did not
scope — clause (b)'s bit-identical sweep was run at 0.5, and a new threshold would invalidate
it and risk raising on legitimate banked calls, which would be a regression against the gate's
own zero-clean-movement driver. So the gap is **banked with its magnitude and handed to the
postrepair-verification leg**, which is the flag the gate's yes-branch already calls for.

What *was* corrected: the inherited docstring claimed the residual was "a fit-quality backstop
for shapes the peak heuristic does not describe." That is an overclaim — measured false by the
two rows above. The docstring now states the heuristic is exact for the single-scale class and
**not claimed beyond it**, names the two-scale counterexample with its magnitude, and calls the
backstop partial. Prose only; no behaviour change, so clause (b) remains valid as run.
