## 1. What the novelty pass changed about the design, before it was built

The pass is the reason the repair is parameterised rather than flattened. The WET
counter-argument to DRY — *"duplication is far cheaper than the wrong abstraction"* — bites
exactly here, because the two existing copies of `_hypothesis_violations` are **not**
textually identical and the differences are load-bearing:

* `port_certification` accepts `None` (= NOT MEASURED, its `BLOCKED_AT_STEP_ONE` kill-switch);
  `interval_certificate` raises on it.
* The NaN parentheticals cite different comparisons, because the three modules guard the
  contraction in different senses (`Z₁ ≥ 1` rejects / `Z₁ < 1` accepts / `Z₀ + Z₁ < 1` accepts).
* `nk_bounds.budget` has a fourth slot, `Z₀`, that neither sibling has.

All four survive as parameters (`allow_none`, `nan_hint`, `(name, value)` pairs), and the two
existing message strings are reproduced **byte-for-byte** as module constants. Writing that
down before construction is what kept it from being discovered as a regression during it.

The pass also recorded a **non-finding** honestly: no external package
(RadiiPolynomial.jl, CAPD, Arb, INTLAB, ValidatedNumerics.jl) documents an equivalent shared
layer, and RadiiPolynomial.jl's README documents no coefficient validation at all — but that
is a README-level absence, not a source audit, and in those libraries the constants are
produced *inside* the library from interval enclosures, so there is no external slot to
poison. Recorded as "no external design to copy", never as priority.

## 2. Instruments, and why each is the one it is

* **Gate (a)** runs leg 116's battery **unmodified**, both sides, via a
  `sys.modules['solver.nk_bounds']` substitution (leg 105's technique). Leg 116's territory
  file is never edited or copied. The pre-repair side reproducing 21/19/14 exactly is the
  control — lesson 90, the instrument reports both answers.
* **Gate (b)** is a **same-process bitwise differential**, not a comparison against a banked
  JSON. Leg 105 already established that the banked comparison is the wrong instrument in this
  repository (leg 61's literal original source gives `Y₀ = 2.9616e-17` today against the
  committed `3.0243e-17`, ~2.1%, environment-sensitive at the noise floor and predating every
  repair). Cited, not rediscovered.
* **Gate (c)** is checked three ways — identity, source-level absence of inline copies, and
  behavioural agreement on a drift battery — because "they share a guard" is otherwise
  unfalsifiable, and identity alone would not catch a call site that holds the shared function
  and ignores it.

## 3. THE DRAFT THAT WAS REVERTED — the most useful thing this leg produced

An early draft refused `r_min == 0.0` whenever `Y₀ > 0`, on the reasoning that the theorem's
`r_min` is strictly positive there, so a computed `0.0` must be cancellation.

It **is** cancellation, and refusing it is still wrong. The differential caught it as
36/36 → 35/36 on `(Y₀, Z₀, Z₁, Z₂) = (1e-30, 0.5, 0.4, 2.0)`, where the honest radius is
≈ 1e-29 — a genuine certificate whose radius is below float resolution against
`one_minus = 0.1`. Refusing it is a false negative on a valid proof.

Reverted rather than tuned, per the gate's own no-branch. What survives:

* `r_min == 0.0` is **flagged**, never refused, with the `reason` naming which of the two
  mechanisms produced it (honest `Y₀ = 0`, or underflow with `Y₀ > 0`). Refusing it was never
  available anyway: the banked clean gate `test_nk_bounds.py::test_decay_and_budget` is
  `budget(0.0, 1e-12, 0.3, 13.0)`, whose `r_min` is exactly `0.0`, and leg 116 recorded that
  *every* in-repo caller passes `Y₀ = 0.0` literally.
* The genuine degeneracy underneath it — leg 116's `A21`, where `Z₂ = 1e-320` overflows
  `Y0_max = one_minus²/(4Z₂)` to `+inf` — is refused on the **budget**, which is where the
  defect actually is.

**The lesson, in the repository's own idiom: the symptom and the defect were in different
places, and the first fix went to the symptom.** This is lesson 88 ("the minimum of a failure
curve is not where to repair it") wearing different clothes.

A second, smaller instance of the same thing: the first draft of `two_point_dual`'s weight
guard validated per-entry in pure Python. `seminorm_part_upper` calls it once per chunk on a
J×J kernel with J up to 1600, so the guard would have cost more than the bound it guards. It
is now a vectorised numpy screen with the shared message builder behind it — numpy decides
*whether* anything is wrong, the shared guard is only asked to say *what*.

## 4. The clause that is flagged rather than recomputed, with its magnitude

DIRECTION.md's repair list said *"lower `_I_out`'s bulk floor **or** bound the `[0, eps]`
panel"*. Neither is available under this leg's own gate, and the reason is measured rather
than argued: lowering `eps` from `1e-12` to `1e-18` rebuilds the geomspace bulk grid and moves
**15 of 15** clean live-range values, worst **1.08e-04 relative**. Any clean-input result
moving is the stop condition.

So the value is untouched and `X > 1e10` warns. Margin: the live range tops out at `X = 3.2e7`,
**3.49 decades** below leg 116's measured first crossover at `1e11` (worst under-report 2.12%
at `1e12`). The pin survives as a `test_still_a_gap_*` gate that keeps leg 116's 2.12%
assertion *and* asserts the warning fires at `1e12` and stays silent across the live range.

Both `test_still_a_gap_*` gates name what would close them. Neither is silently dropped.
