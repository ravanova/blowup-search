## 2. Item (i) — the `VOLATILE_TOKENS` gap, verified before editing

Read `experiments/p2_route_epa_v1_census.py` and located `VOLATILE_TOKENS` at (pre-edit) line
161: it contained `"generated_at"` but not the bare substring `"generated"`. Confirmed the bug
is real, not just asserted by the dispatch spec: `is_volatile("generated")` returned `False`
before the fix (checked by importing the module directly). Confirmed the bare `"generated"`
field is real production content, not a hypothetical: grepped every `experiments/p2_route_*.py`
runner for `"generated":` and found roughly two dozen families (including
`p2_route_e_v1_spectrum.py:425`) writing exactly `"generated": time.strftime(...)"` with no
`_at` suffix.

**Fix:** added bare `"generated"` to `VOLATILE_TOKENS`, plus a code comment explaining the
one-directional-substring failure mode (a suffixed token is not a substring of its own bare
root, so matching only catches the family that happens to write the longer field name).

**Sibling audit (one genuine gap found, not a broad refactor).** Checked every other token in
the list for the same shape — "suffixed/underscore-bounded form present, bare root absent" —
against the ACTUAL leaf names of all ten CENSUS families (not guessed), by flattening each
family's banked JSON and testing `is_volatile()` on every leaf whose name matched a
timestamp/environment-ish regex, then hand-checking each survivor against the real field's
semantics (to avoid masking genuine content, e.g. `novelty_pass_commit` and
`gate_answer.pre_committed_wording` matched the regex on substrings like "commit"/"committed"
but are real content, correctly left alone).

One real sibling gap: `VOLATILE_TOKENS` had `"seconds_"`/`"_seconds"` (underscore-bounded on
one side) but not bare `"seconds"`. `p2_route_cap_v1_audit.json` (one of the two NEGATIVE
CONTROL families, expected to classify PORTABLE) writes `rows[i].run.seconds` — genuine
per-test wall-clock runtime (e.g. `26.12`, `947.92`) — and that leaf name is exactly `seconds`
with no underscore, so it fell through both existing tokens and would be counted as numeric
drift (a false DRIFT/NON-PORTABLE risk on a negative control, purely from CPU-speed variance)
until this fix. Verified the plural `"seconds"` token does not collide with unrelated content
(`E8b_second_resonance`, `S7_secondary_axes` in `p2_route_cvf_v1_classify.json` contain
`"second"`/`"secondary"` but never the substring `"seconds"`, checked directly). Added.

No other candidate in the sibling audit turned out to be a real gap — `"host"` already a
substring of `"hostname"`, `"created"` already a substring of `"created_at"`, and widening bare
`"run"` or `"date"` further was rejected as too broad (would risk swallowing real content like
`rungs`/`run.seconds` labels themselves via the wrong direction, or "updated" fields in
non-CENSUS families that carry real external-source publication dates, not run metadata — those
live outside this census's family list and were left alone rather than pre-emptively "fixed"
for families this instrument does not even touch).
