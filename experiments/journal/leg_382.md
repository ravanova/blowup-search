## 1. The instrument, stated before it exists

The certified object is defined so it can be checked without reference to how it is
computed. Let `f : [R₀,R₁] → (0,∞)` be the supplied profile magnitude. Define

> **`P_cert(f, R₀, R₁)` := { p ≥ 0 : ∃ C > 0 such that C·r^(−p) = f(r) for all r ∈ [R₀,R₁] }**

— the set of exponents for which the profile is *exactly* a power law on the window. The
instrument must return an **outer enclosure** `[p_lo, p_hi] ⊇ P_cert`, or the verdict
**EMPTY** (certified: no power law of any exponent fits the profile on this window), or
**INCAPACITY** (the enclosure ran into the search bracket or a hypothesis was unmet).

Soundness requirement, pre-committed: if `f(r) = C·r^(−p₀)` exactly on the window then
`p₀ ∈ [p_lo, p_hi]`, unconditionally, for every cell count. Emptiness is a **proof** that
no exponent works; a nonempty interval is **not** a proof that one does.

Substrate: `solver/interval.py` (`Interval`, `ilog`, outward-rounded arithmetic — the
existing capability, per the standing grep-`capabilities.py`-first requirement; grep
performed, four modules import `Interval`, none of them touches decay). No new interval
arithmetic is written; `isqrt` is the single added primitive and it is one outward-rounded
`np.sqrt`, needed only by the *planted-profile generator*, not by the enclosure.

## 2. Two modes, and which one decides the gate

* **`cells` mode (GATE-DECIDING).** The window is partitioned into `N` geometric cells and
  `f` is evaluated *over each whole cell* in interval arithmetic, so the enclosure covers
  every `r` in the window with no gap for the profile to wiggle through. This is the mode
  whose statement is "on a stated radial window".
* **`nodes` mode (REFERENCE ONLY, never gate-deciding).** `f` evaluated at exact nodes. Its
  statement is only "consistent with `r^(−p)` at these nodes" — strictly weaker, since a
  profile may match at every node and be wild between them. Recorded to show how much of
  the certified width is cell-coverage and how much is floating-point.

The elimination is exact Fourier–Motzkin in two variables. Writing `t = log r`,
`g = log f`, a power law is `g(t) = c − p·t`; each cell contributes `g ∈ [g_lo, g_hi]` at
its two endpoints, giving `4N` linear inequalities in `(c, p)`. Eliminating `c` pairwise
yields, for every pair of constraint points `(k, m)`, a single linear inequality
`A·p ≤ B` with `A = t_k^- − t_m^+`, `B = g_hi_m − g_lo_k`. The surviving `p`-set is the
exact projection of the feasible polygon (Fourier–Motzkin is exact in 2 variables), so the
only conservatism is directed rounding: lower bounds rounded **down**, upper bounds
rounded **up**, emptiness therefore proved on the *relaxed* system and so proved a fortiori
on the true one.

**Domain restriction, declared as a limitation not hidden:** the search is over `p ∈ [0, 12]`.
The sign of `p` is fixed so that `max_{t∈T}(p·t)` is attained at a fixed endpoint and every
constraint is linear in `p`; `R₀ = 10 > 1` makes every `t` positive. A feasible set touching
either bracket end is reported as **INCAPACITY**, not as a bound.

| K3 | `f = 0.25·r^(−5/2)`| **2.5** | `p₀ ∈ [p_lo, p_hi]` |

## 5. Perturbation ladder — reported, NOT gate-deciding

`K2ε`: `f = r^(−2)·(1 + ε·s(r))` with `s(r) = (r/R₁ − 1/2)` bounded in `[−1/2, 1/2]`,
`ε ∈ {0, 1e-12, 1e-9, 1e-6, 1e-3, 1e-2}`. Truth `p₀ = 2.0` must stay inside for every `ε`
(this is a **soundness** requirement, and a violation is a defect in the instrument, to be
reported as such). **Pre-committed prediction:** width ≈ `max(2p₀/N, ~4ε/W)`, i.e. flat at
the cell floor until `ε ≈ 1e-3` and linear in `ε` above it. This ladder is what tells a
future consumer how clean a numerical profile has to be.

## 6. Gate controls — MUST FIRE. A control that does not fire is a STOP.

"Fire" = the instrument returns **EMPTY**, or returns an interval **excluding** the claimed
truth. Both controls are planted mismatches whose claimed truth is `p = 2.0`:

* **C1 — two-power mixture.** `f = r^(−2) + 0.01·r^(−1)`. Crossover at `r = 100`, which is
  **inside** the pre-registered window (this is the whole point: a mixture whose crossover
  lay outside the window would be an un-fireable control, and would be a leg-340 tautology).
  Log-log slope runs from ≈2 at `R₀` to ≈1 at `R₁`.
* **C2 — rational far cutoff.** `f = r^(−2)/(1 + (r/300)^4)`. Slope runs 2 → 6 across the
  window. Rational on purpose: it needs no `exp`, so its interval extension uses only
  `solver/interval.py`'s existing exact operations.

**If C1 or C2 does not fire, this leg STOPS and reports the failure verbatim.** The window
is not widened, the cell count is not raised to rescue it, and the control is not swapped.

## 12. Where the pre-registration was WRONG — recorded, not amended

**Two of its predictions failed, and the second one is the leg's real finding.**

### 12a. §4's width prediction: REFUTED

Predicted `width ≈ 2p₀/N` (`4.0e-3` at `N = 1000`) with log-log slope `−1.00 ± 0.05`.
**Measured slope `−0.0295`**: the width sits at the rounding floor (`1.75e-14` down to
`1.55e-14` across `N = 50 → 2000`) and is essentially independent of `N`. The log-tube width
*does* fall as `1/N` exactly as expected (`1.842e-1 → 4.605e-3`), but it does not propagate
into the projection: for a monotone profile the cell enclosure's endpoints coincide with the
exact pointwise values at the cell edges, so the binding Fourier–Motzkin pairs are already
sharp. The instrument is better than predicted. The prediction stays on the record as wrong.

### 12b. §5's soundness claim: it was a MIS-STATEMENT, not a defect

The pre-registration wrote that for the perturbed ladder "truth `p₀ = 2.0` must stay inside
for every `ε`… a violation is a defect in the instrument". At `δ = 0` the instrument returns
**EMPTY at every `ε > 0` down to `1e-12`**, with contradiction gaps `−6.675e-13` … `−8.564e-3`.

**That is correct, not a defect.** A profile perturbed at any level is not exactly
`C·r^(−p)`, so `P_cert` is genuinely empty. What was wrong was the pre-registration's
description of the certified object, and it is recorded here rather than silently corrected.

**The consequence is the finding.** No numerical profile is ever exactly a power law, so the
zero-tolerance instrument would answer EMPTY for every real input it was ever handed:
rigorous and useless. This is now a regression test
(`test_zero_tolerance_rejects_any_perturbation`) so a future change cannot make it quiet.

## 13. The post-hoc extension, flagged as post-hoc everywhere

The tolerance parameter `δ` was **not pre-registered**; it was added after the run in response
to §12b, and it **decides nothing about the gate**, which was answered on the zero-tolerance
runs. It is labelled post-hoc in the module docstring, the runner docstring, the JSON
(`post_hoc_tolerance_extension.status`) and the TECHNICAL write-up.

Magnitudes: certified **width ≈ 0.8686·δ** (i.e. half-width `≈ 0.434·δ`), measured
`8.928e-13 → 8.320e-2` across `δ = 1e-12 → 1e-1`; critical tolerances
`δ* = 3.352868` (C2), `0.315697` (C1), `0.069739` (C3), and `0` for an exact power law, which
is the direction-sensitivity check that stops the instrument being merely fail-happy.

The guard against `δ` becoming a knob is that it is monotone (widening only enlarges the
feasible set — tested) and that every enclosure is quoted with the `δ*` of the mismatches it
would stop excluding.
