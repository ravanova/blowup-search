`confirmation_evidence.py` failed once, on `phase A: 11251 jobs`. The check asserted the literal
`11251 jobs` against each phase's `jobs` field; phase A banks `11251/11251, 724 built in this phase`, and
phase B-local banks `11250/11251`.

Prereg §4 pre-commits the remedy: **on FAIL the document is corrected to the artefact, never the artefact
to the document.** The artefacts were read before anything was changed. All three phases carry
`Build completed successfully (11251 jobs)` in `gate.a_build_completes` — the build's own completion line
— and `CORRECTIONS.md` §77 already records that the `11250/11251` per-target counter is **not** an error
(lake prints no line for the root job) and that the verifier's flag on it was overstated. So the
**document's claim was correct and the check was citing the wrong field.** The check now cites
`gate.a_build_completes`, which is the field the document quotes. Nothing in any artefact was edited.

This is the third time this arc that a banked datum was corrected beside rather than in place (§77, §79,
and this). The rule held each time.
