**Classification: stale test, not a module or data defect.** Named as a rework candidate

`check_banked_stage1_5_t_stars_are_unmoved` pins all 20 production `T*` values as literal bit
patterns via `float.hex`. `bump(kappa=2)` now returns `6.412705280348239` against the banked

grid, refined by bisection of the (band-limited, spectrally interpolated) w0" — i.e. it uses
`np.fft.rfft`. ULP-level drift of this magnitude is consistent with FFT-backend/NumPy-version
differences, the same class of phenomenon this repo already documents for BLAS backends
elsewhere (`test_profile_newton.py`'s extensive docstring on "leg 71's audit," ~2.31 decades of
cross-host variability attributed explicitly to backend, not module defect).

**Classification: fragile test tolerance, not a module regression.** All 19 other production `T*`
values in the same check passed bit-identical; only the FFT-derived one drifted. Named as a
rework candidate concerning `solver/gclm.py`'s postrepair suite (the
`check_banked_stage1_5_t_stars_are_unmoved` check in `test_gclm_postrepair.py`). Per territory,
not edited — whether the right fix is a documented relative-tolerance floor (as this repo already
models for the BLAS case) or something else is a judgment call this leg's territory excludes.
