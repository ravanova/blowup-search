# Leg 244 — Route-PCRO: `stall_verdict` made order-immune; margin 0.0 → structural

**Branch:** `leg/244-pcro-v1`. **Date:** 2026-08-06. **Role:** LEG (repair family).
**Territory:** `stall_verdict`'s array-order handling only. `krylov_ladder`,
`attribution_summary`, every call site and every banked artifact are untouched.

## The gate, verbatim and pre-committed on both branches

> Does making `stall_verdict`'s verdict robust to array order (rather than relying on the
> current incidental ordering) preserve every currently-correct verdict (Route-L's headline
> included, re-checked explicitly) while removing the order-dependence leg 243 found?

**Answer: YES.** Normal landing straight to `main`. A **light** postrepair check should be
queued (see below).

## The repair, in full

```
-    first, last = rows[0], rows[-1]
+    first, last = by_m[min(by_m)], by_m[max(by_m)]
```

plus the dictionary that builds `by_m`, and a `ValueError` for the one case keying introduces
that positional indexing never had to answer (below). Everything downstream of those two
names — the gain, `work_ratio`, `flat`, the `reading` string, the division semantics — is
byte-for-byte what it was.

**`krylov_ladder` is deliberately NOT touched.** The directive offered it as a second place
to canonicalise. It is not needed and would be worse: `m` is already carried in every row
`krylov_ladder` emits, so keying the *verdict* on `m` makes the *producer's* row order
irrelevant. Canonicalising both would be two mechanisms guarding one invariant, with the
usual failure mode that neither is then the one you check. **0 call sites changed**, and
that includes the deep rung's inline `dims=(240, 320)`.

## What the repair had to preserve — G1, and it moved nothing

Every published quantity, recomputed through the repaired function from the banked ladders,
compared under `==` on **raw float64** — never `allclose`:

| published block | rows | moved |
|---|---|---|
| `L3_preconditioners/stalls` (4 verdicts × 8 keys) | 4 | **0** |
| `L1_attribution/ranked` (6 rows × 6 keys, via `attribution_summary`) | 6 | **0** |

**Largest absolute difference anywhere: exactly `0.0`.** The published L1 ranking
`[pure dilation, angular transport OFF, velocity in s_rho OFF, reaction terms OFF, velocity
feedback OFF, full]` reproduces in exactly that order. All three module suites
(`test_port_certification{,_postrepair,_regression}.py`) green.

|---|---|---|---|

Two of four components were order-sensitive; **both now are not**, and neither moved.

## What the repair had to remove — G2, measured not asserted

Order-immunity is not read off the source. **1682 permutations** across **15 banked ladders**
(11 Route-L + 4 Route-K), exhaustive for every ladder of ≤ 7 rows:

| | pre-repair positional read | repaired |
|---|---|---|
| ladders with any permutation disagreeing | many | **0 of 15** |
| worst residual-gain spread across permutations | **3795.25×** (the deep rung, 2 rows) | **exactly 1.0** |
| Route-L's line-sweep ladder, reversed | 9.7245 → 0.1028, **94.565×**, `flat` inverts | identical to as-stored |
| the same ladder, shuffled `[40,10,160,20,80]` | **1.4163 (flat)** vs 9.7245 (bending) | identical to as-stored |

The 94.565× and 1.4163 reproduce leg 243's reported 94.565 and 1.4163 — checked here against
*their* numbers, as controls, not taken as inputs.

**The deep rung is covered (G4).** AST enumeration finds **6** `krylov_ladder` call sites:
five routed through `DIMS` (lines 133, 176–179) and **line 180's own inline `(240, 320)`**,
the one leg 241's cited line-49 literal never covered. Reversing it pre-repair inverted the
gain by **3795.25×**; post-repair, 0 of its 2 permutations disagree. The repair reaches it
without knowing anything about it, because it keys on the row's `m` and not on any `dims`
literal.

## The control column (lesson 90), and the one it failed to be

The negative controls fire: the pre-repair function still flips at 94.565× on the reversed
ladder and still errs 6.87× on the shuffle, so the battery has teeth.

**And one control came out the way I did not design it to, which is the sharper finding of
the gate and is banked as measured rather than engineered away.** I built a *mis-keyed*
repair — keying on `k` (iterations used) instead of `m` — expecting the permutation battery
to catch it. **It does not.** Keying on `k` is exactly as order-invariant as keying on `m`;
the battery passes both. What separates them is G1: fed a ladder with an early Krylov
breakdown (`m = 40` but `k = 12`), the mis-keyed variant reads the `m = 20` row as the top
rung, giving gain **1.8 (flat)** against the correct **45.0 (bending)** — an inverted verdict
that only the preservation comparison sees. **Order-immunity is necessary and not
sufficient**, and this leg's two halves are load-bearing separately rather than one implying
the other. Any future postrepair suite that keeps only the battery would be weaker than it
looks.

## The one case keying introduces

Positional indexing never had to say what a repeated `m` means. Two rows at the same Krylov
dimension with different residuals have no order-free reading, so `stall_verdict` **raises**
rather than silently picking one (lesson 58 — do not manufacture an answer the data does not
contain). Duplicates that agree exactly are accepted; an empty ladder raises; a single-row
ladder returns gain **1.0 (flat)**, which is what `rows[0]`/`rows[-1]` returned for it too.
**No banked ladder has a duplicate `m`**, so this branch is unreachable from the bank and
changes nothing that exists.

## What this leg does NOT say

* It does **not** say any published number was wrong. Leg 243 established none were; G1
  re-establishes it at difference exactly `0.0`. What changed is *why* they are right.
* It does **not** repair the one positional read that survives: `attribution_summary`'s
  `ladders["full"][-1]["rel_residual"]`, which feeds the **`worse_than_full` boolean
  side-column only** — no published magnitude and no headline component reads it, and it did
  not move in **0 of 40** permuted trials. That line is outside this leg's declared territory,
  so it is **measured and handed on, not edited**. The fix is one line in a follow-up leg
  holding `attribution_summary` in territory: read
  `stall_verdict(ladders["full"])["rel_at_max_dim"]`, which is order-immune as of this leg.
* Nothing is re-run and nothing is re-banked, because nothing moved. **No link of the L1→L4
  chain moved; Clay odds unchanged at ~0.05%.**
