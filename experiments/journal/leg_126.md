## Two bugs my own controls caught, and both are the standing lessons

**(1) The covering predicate was a tautology, and lesson 90 is exactly why I looked.** A
predicate that cannot return NOT COVERED is a tautology of the code presented as a finding.
The control is the `μ > 0` operator, where a certificate demonstrably closes — the predicate
is *required* to answer NOT COVERED there. **It answered "covered."** Not one of the twelve
clauses referenced `μ`; each silently claimed authority over an operator its evidence had
never seen. Scoping all twelve to `μ = 0` is just writing down what they measured, and it is
what makes the audit falsifiable. Without that control I would have shipped a table that
could not come out any other way.

**(2) The control's own realization was wrong first, and the repository already had the
lesson written down.** My first dissipative measurement gave `Z₁ = 5904.13` against leg 58's
banked `0.1740` — off by `33,927×`. The standing rule ("when a control contradicts the
mechanism, suspect the control's REALIZATION first") is right: I had bordered the `μ > 0`
object with the analytic far-field direction, exactly as the inviscid object is bordered.
A dissipative tail is **already invertible** and has no far-field kernel to border — the
wrong operator, not the wrong answer. This is verbatim leg 53's first-positive-control
failure, repeated. Rebuilt as leg 58's `NG3` built it (`K = 16`, `border=None`,
`far_field=False` for `μ > 0`), it reproduces leg 58's **entire twelve-entry dial
elementwise to `1.25e-15`**.

**A third, smaller correction found in review:** `BX5` first derived the proof-strength gap
from "strongest coverage == MEASURED", which also picks up the `A21 = 0` shapes under the
`far_field_in_tail` placement (whose covering clause happens to be a measurement). The gap
is a property of the `A21` **axis** and is now read off that axis: `ff_lift`, `gs_lower`,
`schur` — not all seven shapes.
